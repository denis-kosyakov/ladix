## §1 Концепция

**Ladix** — язык для описания и исполнения операционной системы бизнеса. Объединяет три парадигмы в одной грамматике: **декларативную** (источники данных, метрики), **императивную** (переменные, выражения, функции, циклы) и **процессную** (последовательности шагов с исполнителями и сроками). Одна программа описывает, какие данные читать из бизнеса, какие KPI считать и какие процессы запускать в ответ на изменения KPI.

**Область применения:** ключевые метрики (выручка, конверсия, удержание), регулярные процессы (адаптация сотрудников, обработка заявок, отчётность) и связь между ними через триггеры. Ladix **не язык общего назначения** — на нём не пишут веб-серверы и алгоритмы.

**Ключевые идеи:** (1) три парадигмы под одной грамматикой, метрика и процесс — равноправные конструкции верхнего уровня; (2) бизнес-понятия первоклассны — `источник`, `метрика`, `процесс`, `шаг`, `исполнитель`, `срок` суть ключевые слова; (3) русский синтаксис, идентификаторы могут быть на кириллице; (4) процессы переживают перезапуск — состояние хранится на диске; (5) минимально полная версия 1, расширения — §12.

```ladix
# Считаем месячную выручку из источника «заказы»
метрика месячная_выручка:
    источник:  заказы
    где:       статус == "оплачен"
    агрегат:   сумма(сумма_заказа)
    период:    ежемесячно
    по_дате:   дата(дата_заказа)

процесс разбор_падения:
    шаг подготовка_отчёта:
        исполнитель: "аналитик"
        срок:        2дн
    шаг встреча_с_руководителем после подготовка_отчёта:
        исполнитель: "директор"
        срок:        1дн

# Если выручка упала ниже порога — запускаем процесс
когда метрика месячная_выручка < 5_000_000:
    запустить процесс разбор_падения

# Императив: функция с условием и рекурсией доступна везде
функция средний_чек(заказы):
    если длина(заказы) == 0:
        вернуть 0
    вернуть сумма(заказы) / длина(заказы)
пусть оплаченные = [1500, 2300, 4100, 800]
печать(средний_чек(оплаченные))   # 2175.0
```

**Что Ladix НЕ делает:** не язык общего назначения; нет UI / визуального редактора (исходник — текстовый `.ladix`); нет встроенной СУБД задач (состояние — через интерфейс `Store`, см. ARCHITECTURE.md); нет распределённого выполнения. Полный список ограничений — §12.

## §2 Лексика

**Кодировка и идентификаторы.** Файл — UTF-8 без BOM, расширение `.ladix`. Регистр значим (`заказ` ≠ `Заказ`). Идентификатор начинается с Unicode-буквы (включая кириллицу) или `_`, далее — буквы, цифры, `_`; длина не ограничена. Лексер читает идентификатор жадно, затем сверяет с таблицей ключевых слов по полному совпадению строки — поэтому `тип_клиента` корректен при зарезервированном `тип`.

**Комментарии.** Только однострочные: от `#` до конца строки. Блочных нет.

**Литералы:**
- **Целые** — `0`, `42`, `5_000_000`; `_` только между цифрами. Знак не часть литерала (`-5` = унарный `-` и `5`). Без научной нотации, hex, binary.
- **Дробные** — `3.14`, `0.5`, `1_234.56`; точка обязательна между цифрами с обеих сторон (`.5`, `5.` некорректны).
- **Строки** — только двойные кавычки; экранирование `\n`, `\t`, `\\`, `\"`; многострочных нет.
- **Булевы** — `истина`, `ложь`. **Пусто** — `пусто`.
- **Длительность** — число + слитный суффикс без пробела: `сек`, `мин`, `час`, `дн`, `нед`, `мес` (`3дн`, `5мин`, `1_000сек`). Суффиксы не ключевые слова вне литерала (`пусть мин = 5` корректно).
- **Дат-литералов нет** — даты через `дата(...)`, `сегодня()`, `вчера()`, `завтра()` (§8).

**Значащие отступы.** Пробелы значимы только в начале строки; одна ступень — **4 пробела**. **Табы запрещены везде.** Перевод строки значим (конец логической строки), кроме позиции внутри незакрытых `(...)`, `[...]`, `{...}` — там переводы прозрачны. Бэкслэш-переноса нет. Пустые строки и строки только с комментарием прозрачны для отступов. `:` открывает блок. Алгоритм INDENT/DEDENT — docs/grammar.md.

**Ключевые слова (37, резервируются глобально):**

| Категория | Слова |
|---|---|
| Объявления | `пусть`, `функция`, `вернуть` |
| Управление | `если`, `иначе`, `пока`, `для`, `прервать`, `продолжить` |
| Логика | `и`, `или`, `не` |
| Литералы | `истина`, `ложь`, `пусто` |
| Декларатив | `источник`, `файл`, `метрика`, `где`, `агрегат`, `период`, `по_дате`, `процесс`, `шаг`, `исполнитель`, `срок`, `после`, `присвоить`, `вызвать`, `уведомить` |
| Триггеры | `когда`, `событие`, `значение`, `расписание`, `каждые`, `в`, `запустить` |

`значение` предопределено в теле `когда метрика …:`, `событие` — в `когда событие …:` (§6); оба зарезервированы глобально для контекстонезависимости лексера. `тип` — **ключевое слово** (`KW_TYPE`): атрибут источника-коннектора (`тип:`, §9) и контекстная лексема; в позиции выражения не начинает primary, поэтому `тип(…)` недостижим через парсер (§12). **Зарезервированные слова** (имена недопустимы, защита совместимости): `параллельно`, `модуль`, `импорт`, `экспорт`, `повторить`, `выбрать`, `пытаться`, `словить`, `бросить`, `асинхронно`, `ждать`.

**Операторы и разделители.** Арифметика `+ - * / // %`; сравнение `== != < <= > >=`; присваивание `=`; доступ к полю `.`; группировка `( ) [ ] { }`; разделители `,` `:`. Многосимвольные (`==`, `!=`, `<=`, `>=`, `//`) разбираются жадным максимальным совпадением. Приоритеты — §5; формат ошибок лексера — §13.

## §3 Грамматика

Нотация — W3C EBNF: `::=` определение, `|` альтернатива, `*` ноль+, `+` одно+, `?` опционально, `(...)` группировка, `"..."` литеральный токен; имя с заглавной буквы — нетерминал или класс токенов из §2. **Синтаксис однозначен; вложенные выражения разбираются по приоритетам §5.**

**Верхний уровень.** Файл скриптовый: смесь определений и операторов, исполняется сверху вниз. Определения регистрируются глобально и не выполняются в момент объявления; `Statement` исполняется немедленно.

```ebnf
Program        ::= TopLevelItem* EOF
TopLevelItem   ::= Statement | FunctionDecl | SourceDecl | MetricDecl | ProcessDecl | TriggerDecl
Statement      ::= LetStmt | AssignStmt | IfStmt | WhileStmt | ForStmt
                 | ReturnStmt | BreakStmt | ContinueStmt | StepAction | ExpressionStmt
LetStmt        ::= "пусть" Ident "=" Expression Newline
AssignStmt     ::= Ident "=" Expression Newline
ExpressionStmt ::= Expression Newline
IfStmt         ::= "если" Expression ":" Block ElseClause?
ElseClause     ::= "иначе" ":" Block | "иначе" "если" Expression ":" Block ElseClause?
WhileStmt      ::= "пока" Expression ":" Block
ForStmt        ::= "для" Ident "в" Expression ":" Block
ReturnStmt     ::= "вернуть" Expression? Newline
BreakStmt      ::= "прервать" Newline
ContinueStmt   ::= "продолжить" Newline
Block          ::= Newline Indent Statement Statement* Dedent
FunctionDecl   ::= "функция" Ident "(" ParamList? ")" ":" Block
ParamList      ::= Ident ("," Ident)* ","?
SourceDecl     ::= "источник" Ident ":" Newline Indent SourceAttr+ Dedent
SourceAttr     ::= "файл" ":" StringLiteral Newline
                 | "тип" ":" Ident Newline
                 | "поля" ":" Newline Indent FieldDef+ Dedent
FieldDef       ::= Ident ":" Ident Newline
MetricDecl     ::= "метрика" Ident ":" Newline Indent MetricAttr+ Dedent
MetricAttr     ::= ("источник" | "где" | "агрегат" | "по_дате") ":" Expression Newline
                 | "период" ":" PeriodValue Newline
PeriodValue    ::= Ident
                 | "последние" DurationLiteral
                 | ("прошлый" | "прошлая") Ident
ProcessDecl    ::= "процесс" Ident ("(" ParamList? ")")? ":" Newline Indent StepDecl+ Dedent
StepDecl       ::= "шаг" Ident StepAfter? ":" Newline Indent StepLine+ Dedent
StepAfter      ::= "после" Ident ("," Ident)*
StepLine       ::= StepAttr | Statement
StepAttr       ::= ("исполнитель" | "срок") ":" Expression Newline
StepAction     ::= AssignAction | CallAction | NotifyAction
AssignAction   ::= "присвоить" Ident "=" Expression Newline
CallAction     ::= "вызвать" Ident "(" ArgList? ")" Newline
NotifyAction   ::= "уведомить" Ident "(" ArgList? ")" Newline
TriggerDecl    ::= "когда" TriggerSpec ":" Block
TriggerSpec    ::= MetricTrigger | EventTrigger | ScheduleTrigger | DeadlineTrigger
MetricTrigger  ::= "метрика" Ident CompOp Expression
EventTrigger   ::= "событие" Ident
ScheduleTrigger::= "расписание" ("каждые" DurationLiteral | "в" StringLiteral)
DeadlineTrigger::= "задача" "просрочена" "в" Ident "." Ident
Expression     ::= LogicOr
LogicOr        ::= LogicAnd ("или" LogicAnd)*
LogicAnd       ::= LogicNot ("и" LogicNot)*
LogicNot       ::= "не" LogicNot | Comparison
Comparison     ::= Additive (CompOp Additive)?
CompOp         ::= "==" | "!=" | "<" | "<=" | ">" | ">="
Additive       ::= Multiplicative (("+" | "-") Multiplicative)*
Multiplicative ::= Unary (("*" | "/" | "//" | "%") Unary)*
Unary          ::= "-" Unary | Postfix
Postfix        ::= Primary PostfixOp*
PostfixOp      ::= "(" ArgList? ")" | "[" Expression "]" | "." Ident
ArgList        ::= Expression ("," Expression)* ","?
Primary        ::= IntLiteral | FloatLiteral | StringLiteral | BoolLiteral | NoneLiteral
                 | DurationLiteral | ListLiteral | RunProcessExpr | Ident | "(" Expression ")"
ListLiteral    ::= "[" (Expression ("," Expression)* ","?)? "]"
RunProcessExpr ::= "запустить" "процесс" Ident ("(" ArgList? ")")?
```

**Операторы.** `LetStmt` объявляет переменную, `AssignStmt` без `пусть` — переприсваивание объявленного имени (проверка семантикой); lvalue — только `Ident` (присваивание в поля/индексы недоступно). `вернуть` без выражения даёт `пусто`, валиден только в теле функции (§8). `прервать`/`продолжить` — только в цикле (§7). На строке — один statement, `;` нет, пустые блоки запрещены.

**Функции.** Только позиционные параметры, без значений по умолчанию и `*args`. Вложенные функции и замыкания не поддерживаются: `FunctionDecl` входит только в `TopLevelItem`. **Декларатив:** семантика источников — §9, метрик — §10; внутри `где`/`агрегат` неопределённые имена трактуются как поля текущей записи источника (§10); `ежедневно`/`еженедельно`/`ежемесячно`/`ежеквартально`/`ежегодно` — предопределённые идентификаторы типа `Период` (§4), не ключевые слова.

**Процессы и триггеры.** `StepAction` входит в `Statement`, поэтому действия допустимы внутри `если`/`пока`/`для` шага, но семантически валидны только в теле шага процесса (§11). Параметры процесса позиционны и становятся начальными переменными процесса (§11). Семантика триггеров и модель исполнения — §11, docs/execution-model.md.

**Выражения.** Цепочечные сравнения запрещены: `1 < x < 10` — ошибка парсера (пишите `1 < x и x < 10`). Литерал списка допускает висящую запятую и гетерогенность (`[1, "две", истина]`). `RunProcessExpr` — запуск процесса как выражение, возвращает строковый идентификатор инстанса (§11); скобки — часть самой `RunProcessExpr`, standalone оформляется как `ExpressionStmt`. Возведение в степень и тернарный оператор в v1 не поддерживаются. Полный EBNF декларатива, алгоритм INDENT/DEDENT, индекс нетерминалов — docs/grammar.md; AST и Go-типы — ARCHITECTURE.md.

## §4 Типы данных

**Общая модель.** Типы у значений, не у переменных; тип переменной = тип её текущего значения, переприсваивание может его изменить. Типизация **динамическая**, ошибки типов — **runtime**, без статического вывода и аннотаций. Каждая ошибка типа содержит строку, колонку, имена обоих типов и название операции (формат — §13).

```ladix
пусть x = 5      # Целое
x = "пять"       # теперь Строка — OK
пусть y = x + 1  # ошибка типа: '+' нельзя применить к Строка и Целое (строка 3)
```

**Список типов v1 (10):**

| Категория | Тип | Литерал | Примечание |
|---|---|---|---|
| Базовый | `Целое` | `42`, `-5` | int64 |
| Базовый | `Дробное` | `3.14`, `0.5` | float64 |
| Базовый | `Строка` | `"привет"` | UTF-8, неизменяемая |
| Базовый | `Булево` | `истина`, `ложь` | |
| Базовый | `Пусто` | `пусто` | синглтон типа `Пустота` |
| Временной | `Длительность` | `3дн`, `5мин` | пара (значение, единица) |
| Временной | `Период` | `ежедневно` … `ежегодно` | перечислимый, без операций |
| Временной | `Дата` | через `дата(...)`/`сегодня()` | год-месяц-день, без времени |
| Коллекция | `Список` | `[1, 2, 3]`, `[]` | ссылочный, изменяемый |
| Коллекция | `Запись` | нет литерала | открытая структура, доступ `.поле` |

Доменные сущности (`Задача`, `Процесс`, `Событие`, `Роль`) — через `Запись` и `Строка`.

**Целое и Дробное.** `Целое` — int64 (`-9_223_372_036_854_775_808 .. 9_223_372_036_854_775_807`). Переполнение В АРИФМЕТИКЕ — runtime-ошибка (§13.4 «переполнение целого числа»); ЦЕЛЫЙ ЛИТЕРАЛ вне диапазона — СТАТИЧЕСКАЯ ошибка ПАРСЕРА (§13, не лексическая). `Дробное` — float64 (магнитудой не переполняется: `±Inf` по IEEE-754). **Контраст путей не-конечного `Дробного` (фикс 024 D):** число из JSON-**payload** (`событие`, `--data`), выходящее за диапазон float64, декодируется **толерантно** в `Дробное{±Inf}` — деградация лучше сбоя доставки (`jsonval/decode.go:142`); строгие пути — CSV/JSON-**источники** (§9.5) и builtin'ы `дробное()`/`число()` (§8) — не-конечное (±Inf/NaN/hex-float) **отвергают** ошибкой (§13.4). Из ИСХОДНИКА языка ±Inf/NaN недостижимы (нет литерала; арифметика магнитудой не переполняется).

| Операция | Цел op Цел | Цел op Дроб | Дроб op Дроб |
|---|---|---|---|
| `+`, `-`, `*` | Целое | Дробное | Дробное |
| `/` | Дробное | Дробное | Дробное |
| `//` | Целое | ошибка типа | ошибка типа |
| `%` | Целое | ошибка типа | Дробное (`fmod`) |
| унарный `-` | Целое | — | Дробное |

`/` всегда даёт `Дробное`; `//` определено только для Целое//Целое. Сравнения между численными — с повышением Целого до Дробного (`1 == 1.0` → `истина`). **Деление на ноль (`/`, `//`, `%`) — runtime-ошибка** (текст — §13).

**Строка.** UTF-8, неизменяемая, регистр значим (`"А" != "а"`). `+` — конкатенация; `==`, `!=` — побайтно; `<`/`<=`/`>`/`>=` — лексикографически по code-point. `[i]` — индексация в **рунах**, возвращает строку из одного символа, отрицательных индексов нет; срезов `[i:j]` нет — функция `подстрока(s, i, j)`. `длина(s)` — число рун.

**Булево и условия.** Значения `истина`, `ложь`; операции `и`, `или`, `не` короткозамкнутые. Условия `если`/`иначе если`/`пока` **strict** — обязаны быть `Булево`, иначе runtime-ошибка (`если заказы:` — ошибка типа; `если длина(заказы) > 0:` — OK). Цикл `для x в E:` требует `E` типа `Список` (§7). Truthy-приведение прочих типов — только явным `булево(x)` (§8). Правила триггеров `когда` — §11.

**Пусто.** Единственное значение типа `Пустота`. Появляется из функций без `вернуть`/с голым `вернуть`, из отсутствующего поля Записи, из `null` JSON-источника. `пусто == пусто` → `истина`, `пусто == <иное>` → `ложь`; арифметика, `<`/`>` и использование в условиях — ошибка типа. `печать(пусто)` выводит `пусто`.

**Длительность.** Пара `(значение, единица)`, единица — `сек`/`мин`/`час`/`дн`/`нед`/`мес` (пара, а не секунды, т.к. `1мес` не сводится к фиксированному числу секунд).

| Выражение | Результат |
|---|---|
| `Длит ± Длит` (та же единица) | Длит той же единицы |
| `Длит ± Длит` (разные единицы) | runtime-ошибка |
| `Длит * Целое/Дробное` | Длит той же единицы (`7дн * 2 == 14дн`) |
| `Длит / Целое/Дробное` | Длит той же единицы; при нецелом результате значение → Дробное |
| `Длит == Длит` | истина только при совпадении единицы и значения (`1час != 60мин`) |
| `Длит < Длит` (та же единица) | по значению; разные единицы — runtime-ошибка |
| `Дата ± Длит` | Дата |
| `Дата - Дата` | Длительность в `дн` |

Приведение единиц — `в_секундах`/`в_минутах`/`в_часах`/`в_днях` (§8) **активированы фичей 008** (вместе с конструктором `длительность(значение, единица)` и `вчера()`/`завтра()`; канон — docs/datetime-builtins-model.md §DB-4); календарные (`мес`) — не приводятся без Даты-якоря (ОшибкаВыполнения). Таблица операторной арифметики выше — целевая семантика v1+; статус активации **операторной** арифметики по фичам — §12 (в 006 активны только `==`/`!=` и порядковые сравнения одной единицы, операторная арифметика до активации — ошибка типа, и в v1 **остаётся** deferred).

**Период.** Перечислимый: `ежедневно`, `еженедельно`, `ежемесячно`, `ежеквартально`, `ежегодно` — глобальные значения стдлиб (не ключевые слова; затенение именем переменной даёт предупреждение семантики, §6). Имена адвербиальные, чтобы не занимать `день`/`месяц`/`год`. Используется только в `метрика.период:` (§10). `==`, `!=` — между Периодами; `<`, `>`, арифметика — не определены.

**Дата.** Год-месяц-день, **без времени**. Литералов нет — создаётся `дата(год, месяц, день)`, `дата(строка)` (парсинг `"YYYY-MM-DD"` или `"...THH:MM:SS"`, время отбрасывается), `сегодня()`, `вчера()`, `завтра()`. `Дата ± Длит` → Дата (для `мес` — календарный сдвиг с end-of-month clamp); `Дата - Дата` → Длительность в `дн`; `Дата + Дата`, `Дата * X` — ошибка типа; `==` поэлементно, `<`/`>`/`<=`/`>=` хронологически. `строка(д)` → `"YYYY-MM-DD"`. Аксессоры компонент, границы периодов, календарные сдвиги отложены в v2 (§12). Реестр функций дат — §8 / docs/stdlib.md.

**Список.** Литерал `[выр, …]`, висящая запятая, пустой `[]`, гетерогенность. **Ссылочный** (`b = a` — общий список) и **изменяемый** (мутация через функции стдлиб; `s[i] = x` недоступно). `s[i]` — элемент (runtime-ошибка при `i < 0` или `i >= длина(s)`); `длина(s)` — число элементов; `s == t` поэлементно (разная длина → `ложь`); `s < t`, `s + t` не определены (используйте `соединить(s, t)`). Мутация во время активной итерации `для` над тем же списком — runtime-ошибка (§7); опт-ин на snapshot — `для x в копия(s):`. Сигнатуры — §8 / docs/stdlib.md.

**Запись.** Открытая структура с динамическим доступом к полям; литералов нет — пользователь читает, но не создаёт. Источники: записи JSON-источника в метрике, предопределённая `событие` в триггере, возвраты стдлиб. `r.поле` — доступ, **отсутствующее поле → `пусто`** (не ошибка); `r == s` — структурно; `r < s`, `r["поле"]`, итерация, `длина(r)` — в v1 нет.

**Равенство между типами.** `==`/`!=`: **разные типы → `ложь`, кроме пары Целое↔Дробное** (численно). В пределах типа: Строка — побайтно, Булево — по значению, Пусто — `истина` только с Пусто, Длительность — точно (единица+значение), Период — поименно, Дата — поэлементно, Список — поэлементно, Запись — структурно.

**Порядковые сравнения** `<`, `<=`, `>`, `>=` определены только для пар (всё прочее — runtime-ошибка типа): Целое↔Целое, Дробное↔Дробное, Целое↔Дробное (с промоушеном), Строка↔Строка (лексикографически), Дата↔Дата (хронологически), Длительность↔Длительность одной единицы.

**Приведения.** Неявных нет, кроме автопромоушена Целое→Дробное в численной арифметике и сравнениях (никаких `"x" + 1`, `5 + истина`). Явные — функции стдлиб `строка`, `целое`, `дробное`, `число`, `булево` (Python-truthiness только при явном вызове, не в условиях), `длительность`, `дата`. Интроспекция типа `тип(x)` зарезервирована для v1: имя `тип` — ключевое слово (`KW_TYPE`, §2), которое не начинает выражение, поэтому вызов из синтаксиса недоступен — парсер даёт ошибку `неожиданный элемент 'тип'` (зарегистрированная семантика — `тип(5) == "Целое"`, `тип(3.14) == "Дробное"`, `тип(сегодня()) == "Дата"` — это целевая семантика, активируется в v2; см. §12). Сигнатуры — §8 / docs/stdlib.md.

## §5 Выражения и операторы

Выражение состоит из литералов, идентификаторов, вызовов, индексаций, доступа к полю и операторов; грамматический каскад — §3, разбор однозначен.

**Приоритеты и ассоциативность** (от низшего к высшему):

| Уровень | Операторы | Ассоциативность |
|---|---|---|
| 1 | `или` | левая |
| 2 | `и` | левая |
| 3 | `не` | правая (префикс) |
| 4 | `==`, `!=`, `<`, `<=`, `>`, `>=` | не сцепляются |
| 5 | `+`, `-` (бинарные) | левая |
| 6 | `*`, `/`, `//`, `%` | левая |
| 7 | `-` (унарный) | правая (префикс) |
| 8 | постфикс `()`, `[]`, `.` | левая |

**Бинарные операторы лево-ассоциативны:** `a - b - c` ≡ `(a - b) - c`, `10 / 2 / 5` ≡ `(10 / 2) / 5`. Унарные `не`, `-` — префиксные, правоассоциативные. Скобки `(...)` переопределяют приоритет. Сравнения **не сцепляются** (`Comparison` допускает не более одного `CompOp`): `1 < x < 10` — ошибка парсера (§13), пишите `1 < x и x < 10`.

**Правила вычисления.** Операнды бинарного оператора вычисляются слева направо. Короткое замыкание: `или` не вычисляет правый операнд при левом `истина`, `и` — при левом `ложь`; оба операнда должны быть `Булево`. Аргументы вызова вычисляются слева направо до входа в тело. Типы проверяются динамически в момент вычисления; несовместимость — runtime-ошибка типа со строкой, колонкой, обоими типами и операцией (§13).

## §6 Переменные и области видимости

Опирается на §3 (`LetStmt`, `AssignStmt`, `FunctionDecl`, `StepDecl`, `TriggerDecl`) и §4 (динамическая типизация).

**Модель.** Лексический scope (имя разрешается по тексту, не по цепочке вызовов). Поиск изнутри наружу: локальный → объемлющие → глобальный → встроенные. **Функциональный scope** (Python-style): новый scope создают только функция, шаг процесса, тело триггера, выражения метрики и глобал; блоки `если`/`иначе`/`пока`/`для` своих областей **не создают** — `пусть` в их теле создаёт привязку в объемлющей области.

Виды scope: глобальная (top-level `пусть`/`функция`/`источник`/`метрика`/`процесс`/триггеры); тело функции (параметры + все `пусть`); тело шага (все `пусть`); тело триггера (предопределённые имена §6.5 + `пусть`); выражения `где`/`агрегат`/`по_дате` метрики (поля записи + `запись`, §10).

### 6.1 Глобальная область

Декларации (`функция`/`источник`/`метрика`/`процесс`/триггеры) регистрируются на первом проходе семантики, видны во всём файле независимо от порядка. Top-level `пусть` инициализируется сверху вниз — до своей строки имя не существует (`печать(порог)` до `пусть порог = 100` → `Ошибка: 'порог' не объявлено`). Метрика, прочитанная как имя, даёт скалярное значение (§10); `источник`/`функция`/`процесс` сами по себе не значения. Все глобальные имена — в одном пространстве: `функция выручка(…)` и `пусть выручка = …` одновременно невозможны. Тела триггеров исполняются при срабатывании: ссылка на top-level `пусть` работает, если к этому моменту строка уже исполнена, иначе runtime-ошибка `'x' не объявлено`. Рекомендуемый порядок: константы → источники → метрики → процессы → триггеры.

### 6.2 `пусть` против `=`, strict-объявление

`пусть x = E` создаёт **новую** привязку в текущей области; `x = E` модифицирует **существующую** (если `x` не найдено — `'x' не объявлено`). Повторный `пусть x` в той же области — ошибка `'x' уже объявлено в строке N` (блоки scope не создают, поэтому повтор внутри них в рамках одной функции/шага — тоже ошибка). Для переприсваивания — `x = …`, для затенения внешнего имени в подобласти — выделение в функцию. Параметр функции принадлежит её scope: `пусть` с именем параметра — ошибка `'x' уже объявлено как параметр функции в строке N`; переприсваивание параметра через `=` разрешено.

### 6.3 Циклы и условия

Переменная `для x в E:` создаётся в объемлющем scope; после цикла **видна** со значением последней итерации, на пустой коллекции не создаётся (обращение → `'x' не объявлено`). Привязка из ветки `если`/`иначе` принадлежит объемлющей области, поэтому «`пусть` в каждой ветке» **не работает** — два объявления одного имени:

```ladix
если статус == "оплачен":
    пусть скидка = 0.1
иначе:
    пусть скидка = 0           # Ошибка: 'скидка' уже объявлено в строке N-2
```

Идиома — объявить `пусть скидка = 0` до условия и менять через `=`, либо выделить ветвление в функцию с ранним `вернуть` (пример — `examples/функция.ladix`).

### 6.4 Переменные процесса

В теле шага: `пусть x = E` — локальная для шага, в Store не сохраняется; `присвоить x = E` — переменная процесса, персистится в Store, видна во всех шагах того же инстанса всё время жизни `ProcessInstance` (детали — `docs/execution-model.md`). Параметры процесса (`процесс P(п1, п2):`, §11) становятся начальными переменными процесса. Локальная `пусть x` в шаге **теняет** одноимённую процессную внутри тела шага (на выходе процессная не меняется). Голое `x = E`, достигшее слоя процесса, в v1 обновляет переменную процесса **без** персиста (диагностика `'x' — переменная процесса, используйте 'присвоить'` — v2); канонический канал мутации с персистом — только `присвоить` (docs/engine-model.md §EN-4/§EN-10). Параметров у шага в v1 нет.

### 6.5 Затенение встроенных и предопределённые имена триггеров

Затенение встроенной функции (`длина`/`сумма`/`печать`/…) или периода (`ежедневно`/…/`ежегодно`) через `пусть`/`функция`/параметр — разрешено, но семантика выдаёт предупреждение (формат — §13); затенение пользовательских глобалов — без предупреждения (формат предупреждения — §13).

Предопределённые имена в телах триггеров: `когда метрика m …:` → `значение` (тип метрики); `когда событие e:` → `событие` (`Запись`, доступ через `.` толерантный); `когда расписание …:` → нет (дата — через `сегодня()`). `событие`/`значение` — жёсткие ключевые слова (§2). `запись` — не ключевое слово, осмысленно только в `где`/`агрегат` (§10).

## §7 Управляющие конструкции

Семантика; синтаксис — §3, scope — §6. Группы: условные (`если`/`иначе если`/`иначе`), циклические (`пока`/`для` с `прервать`/`продолжить`), завершающие (`вернуть`, `запустить процесс`). Все — `Statement` (§3), кроме `запустить процесс` — это **выражение** (§5); без захвата результата — `ExpressionStmt`.

### 7.1 Условный оператор

Ветки проверяются по порядку, первая истинная исполняет `Block`, замыкающий `иначе:` — если ни одна не сработала. Условие **обязано** иметь тип `Булево` (strict, §4); иной тип — runtime-ошибка `условие должно быть Булево, получено <тип>` (заголовок `Ошибка в строке N, колонка M:`). Мягкое truthy — только через `булево(x)` (§8). `иначе если` — два слова; слипшаяся `иначеесли` — синтаксическая ошибка. Ветки scope не создают — «`пусть` в каждой ветке» даёт ошибку повторного объявления (§6.3).

### 7.2 Циклы `пока` и `для`

`пока`: условие (strict `Булево`) пересчитывается перед каждой итерацией, включая первую; бесконечный цикл — `пока истина:` + `прервать`. `для`: `Expression` после `в` обязан давать `Список` — **единственное** итерируемое в v1; иной тип — runtime-ошибка `'для' требует Список, получено <тип>`. Числовая итерация — через `диапазон(...)` (§8), напр. `для i в диапазон(10):` (0..9). Пустой список — тело не исполняется, переменная не создаётся; иначе элемент привязывается к `Ident` (тип может меняться, список гетерогенен), после выхода `Ident` хранит последний элемент (§6.3). Имя цикла должно быть свободно в области.

**Мутация коллекции во время итерации** над ней самой — runtime-ошибка `'добавить': коллекция изменяется во время активной итерации, начатой в строке M` (заголовок с колонкой). Единственный мутатор — `добавить`; `соединить`/`срез`/`копия` дают новый список. Идентичность ссылочная (включая вложенную итерацию того же списка); snapshot — `для x в копия(...)`.

### 7.3 `прервать`, `продолжить`, `вернуть`

`прервать` — выход из ближайшего охватывающего `пока`/`для`; `продолжить` — следующая итерация. «Ближайший» — по лексической вложенности. Меток циклов и `прервать <N>` нет — выход из вложенных циклов через выделение в функцию + ранний `вернуть`. Вне цикла — семантическая ошибка `'прервать' допустимо только внутри 'пока' или 'для'` (аналогично `продолжить`), заголовок `Ошибка в строке N, колонка M:`.

`вернуть E` — немедленный выход из функции; `вернуть`/конец тела — `пусто` (§4). Срабатывает сквозь любую вложенность. Допустим **только в теле функции** (не top-level, не шаг, не триггер, не выражение метрики); тип возврата не объявляется и может различаться между ветками. Вне функции — семантическая ошибка `'вернуть' допустимо только внутри функции` (в шаге текст уточняется: `…; в шаге процесса используйте 'присвоить'`).

### 7.4 Запуск процесса

**Выражение** (§5); без захвата — `ExpressionStmt`. Семантика проверяет, что `P` — объявленный процесс и арность совпадает. В runtime аргументы вычисляются слева направо; движок создаёт `ProcessInstance` (детали — `docs/execution-model.md`), связывает параметры процесса с аргументами как начальные переменные, персистирует инстанс, ставит первый шаг в очередь. Возвращает строковый идентификатор (`Строка`). **Запуск неблокирующий** — дожидаться завершения в v1 нельзя. Допустим везде, где допустимо выражение.

```ladix
пусть id = запустить процесс отчёт(сегодня())
когда метрика выручка < 5_000_000:
    запустить процесс разбор(значение)         # результат отбрасывается
```

Диагностики (semantic; exact-match — `docs/process-model.md §PM-6.C`): `P` — функция → `'P' — функция, не процесс`; `P` — метрика/источник → `'P' — не процесс`; `P` нигде не объявлен как процесс → `процесс 'P' не объявлен`; арность → `'P' принимает N аргументов, передано M` (формат как у функций, §8.3).

## §8 Функции

### 8.1 Объявление, вызов, рекурсия

Вызываемы две сущности, неотличимые в точке вызова (`Ident "(" ArgList? ")"`, §5): пользовательская функция (`функция имя(пар…): …`, §3) и встроенная (реализована движком). Обе — в пространстве функций; затенение встроенной — с предупреждением (§6.5). `источник`/`метрика`/`процесс` как функции не вызываемы.

- Только top-level, не вложенно. Параметры позиционные, без значений по умолчанию.
- Тело — собственный scope (параметры + локальные `пусть`, §6).
- Аргументы вычисляются слева направо до передачи; иммутабельные — «по значению», ссылочные (`Список`/`Запись`) — по ссылке (мутация видна вызывающему).
- `вернуть E` — выход со значением; `вернуть`/конец тела — `пусто` (§7.3).
- **Рекурсия** разрешена: имя функции видно из тела через глобальную область.

```ladix
функция факториал(n):
    если n <= 1:
        вернуть 1
    вернуть n * факториал(n - 1)

печать(факториал(5))     # 120
```

**Функции не первоклассны:** имя без `(` — не значение (нельзя присвоить, передать, вернуть, положить в список); замыканий нет. **Глубина рекурсии:** интерпретатор ведёт явный счётчик вызовов (не полагаясь на неперехватываемое переполнение стека Go) и при превышении бросает runtime-ошибку `превышена максимальная глубина вызовов (10000). Возможна бесконечная рекурсия.` (заголовок с колонкой). Лимит по умолчанию 10000, настраивается флагом `--max-depth` (README, раздел CLI). Арность пользовательских функций — на семантике, типы аргументов — в рантайме.

### 8.2 Стандартная библиотека

Полные сигнатуры и поведение — `docs/stdlib.md`. В v1 — **35 встроенных функций** (период-константы `ежедневно`/…/`ежегодно` — значения, не функции). Все затеняемы с предупреждением (§6.5). Единственный мутатор — `добавить`; прочие операции над списками дают новый список.

**Вывод** — `печать(…)`: строковые представления аргументов через пробел + перевод строки, единственный канал вывода.

**Преобразование типов** — `строка(x)` представление любого значения; `целое(x)`/`дробное(x)` приведение к `Целому`/`Дробному`; `число(x)` парсинг с автовыбором `Целое`/`Дробное`; `булево(x)` мягкое truthy (только явный вызов); `тип(x)` имя типа как `Строка` — **зарезервировано для v1** (имя `тип` — ключевое слово `KW_TYPE`, не начинает выражение, поэтому вызов из синтаксиса недоступен — парсер даёт `неожиданный элемент 'тип'`; §12).

**Строки** — `длина(s)` число рун (перегружена со списком); `подстрока(s, i, j)` подстрока из рун `[i, j)`.

**Числа / агрегаты** (над `Список`; в `метрика.агрегат:` — над спроецированным полем, §10) — `сумма(s)` сумма чисел (пустой → `0`); `количество(s)` число элементов; `среднее(s)` среднее (пустой → ошибка); `мин(s)`/`макс(s)` мин/макс по `<` (пустой → ошибка).

**Списки** — `добавить(s, x)` мутирует `s`; `соединить(s1, s2)` новый `s1`+`s2`; `срез(s, i, j)` новый из `[i, j)`; `содержит(s, x)`/`найти(s, x)` наличие / индекс первого `== x` (или `-1`); `копия(s)` поверхностная копия; `обратить(s)`/`сортировать(s)` новый в обратном/возрастающем порядке; `диапазон(stop)`/`диапазон(start, stop)` список целых.

**Даты и длительности** — `дата(год, месяц, день)`/`дата(s)`/`дата(пусто)→пусто` конструктор/парсинг/null-пропагация; `сегодня()`/`вчера()`/`завтра()` системная дата и сдвиги; `длительность(значение, единица)` конструктор; `в_секундах(d)`/`в_минутах(d)`/`в_часах(d)`/`в_днях(d)` перевод (для `мес` → ошибка, §4).

**Процессы** (сигнатуры здесь, семантика и статусы — §11, `docs/execution-model.md`) — `статус_процесса(id)` статус инстанса; `состояние_процесса(id)` переменные процесса как `Запись`; `задачи_пользователя(исполнитель)` список `Запись`-задач.

### 8.3 Диагностики вызова

| Случай | Уровень | Сообщение |
|---|---|---|
| Необъявленная функция `f()` | semantic | `функция 'f' не объявлена` |
| Неверная арность (пользовательская/встроенная фикс.) | semantic | `'имя' принимает N аргументов, передано M` |
| Неверная арность вариативной/перегруженной | runtime | `'имя': неверное число аргументов` |
| Несовместимый тип аргумента | runtime | стандартная ошибка типа (§13) |
| Имя функции как значение (без `(`) | semantic | `'имя' — функция, её нельзя использовать как значение в строке N` |
| Вызов не-функции | runtime | `'имя' — не функция (<тип>), вызов невозможен` |
| Превышение глубины рекурсии | runtime | `превышена максимальная глубина вызовов (10000)` |
| `среднее`/`мин`/`макс` на пустом списке | runtime | `<имя>: список пуст` |
| `срез`/`подстрока` вне диапазона | runtime | `<имя>: индексы вне диапазона` |
| Неизвестный id процесса | runtime | `процесс 'id' не найден` |
## §9 Источники данных

Источник — это **ввод данных** для Ladix: именованная, файловая, лениво загружаемая коллекция Записей. Интерактивного ввода со stdin в v1 нет (детали — §12); единственный канал входных данных — файловый источник, читаемый метриками.

### 9.1 Объявление

`источник Имя:` с блоком атрибутов (§3) регистрирует источник в глобальном пространстве на первом проходе семантического анализа (как `функция`/`метрика`/`процесс`, §6) и **не читает файл в момент объявления**. Атрибуты:

- **`файл:`** (обязателен) — строковый литерал с путём (разрешение пути — ниже).
- **`тип:`** (опционален) — формат файла: `json` (по умолчанию, если атрибут опущен), `csv`, `ndjson`. Значение — голый идентификатор; неизвестное значение → семантическая ошибка (§13).
- **`поля:`** (опционален для `json`, **обязателен** для `csv`/`ndjson`) — блок объявлений схемы записи: на каждой строке `имя: ТипПоля`, где `ТипПоля` ∈ `Целое`, `Дробное`, `Строка`, `Логическое`, `Дата`. Объявленные поля коэрсятся/валидируются при загрузке (§9.5); неизвестный тип поля или дубль имени → ошибка (§13).

Источник без `тип:`/`поля:` ведёт себя ровно как в v1 — JSON без объявленной схемы (schemaless). Блок расширяем дальше (`адрес:`/`разделитель:`/`кодировка:` — v2, §12) без поломки совместимости.

```ladix
источник продажи:
    файл: "data/sales.json"

источник заказы_csv:
    файл: "data/orders.csv"
    тип:  csv
    поля:
        дата_заказа:  Дата
        сумма_заказа: Дробное
        статус:       Строка
```

**Источник не первоклассен.** Имя источника — только цель `метрика.источник:`. Его нельзя присвоить, передать в функцию, проитерировать, измерить `длина(...)` или проиндексировать; иное использование — семантическая ошибка (§13). Доступ к данным — только через метрику.

**Разрешение пути.** Относительный путь — **от каталога `.ladix`-файла** (базовый каталог источников по умолчанию), не от cwd процесса; абсолютный — как есть. CLI-флаг `--source-base <dir>` переопределяет базу (приоритет над каталогом файла). Поэтому пример с `файл: "data/sales.json"` берёт файл рядом с программой (в витрине — `examples/data/sales.json`), и программу можно запускать из любого каталога по пути к ней. Сообщение «файл источника не найден» показывает итоговый абсолютный путь.

### 9.2 Формат файла

Формат задаётся атрибутом `тип:` (§9.1); по умолчанию — `json`.

- **`json`** (по умолчанию). Верхний уровень файла — **JSON-массив объектов**; каждый объект становится одной **Записью** (§4). Пример элемента: `{"клиент": "ООО Ромашка", "дата": "2026-04-12", "сумма": 154000, "статус": "оплачен"}`. Пустой массив `[]` валиден (источник из нуля записей, §9.5). Дубликаты ключей в объекте — побеждает последний (поведение `encoding/json`), без диагностики. Обёртка `{"записи": […]}` — не поддерживается.
- **`ndjson`** (newline-delimited JSON). Один JSON-объект на строку; пустые строки пропускаются. Не-объект на строке → ошибка данных (§9.6). Требует объявления `поля:` (§9.1).
- **`csv`**. Первая строка — заголовок (имена столбцов); разделитель — запятая. Каждая ячейка читается как `Строка` и затем коэрсится в объявленный тип поля (§9.5). Заголовок обязан содержать все объявленные `поля:`; отсутствующий столбец → ошибка данных (§9.6). Лишние столбцы игнорируются. Требует объявления `поля:` (§9.1). Настройка разделителя/кодировки (`разделитель:`/`кодировка:`) — v2 (§12).

Кодировка всех форматов — UTF-8.

### 9.3 Маппинг JSON → типы Ladix

Без объявленной схемы (`json`-источник без `поля:`) тип значения поля определяется **по факту JSON-значения** (динамическая типизация, §4); приведений при загрузке нет. Если объявлен блок `поля:` — объявленные поля коэрсятся/валидируются по схеме (§9.5).

| JSON | Тип Ladix | Примечание |
|---|---|---|
| `null` | `Пусто` | §4 |
| `true`/`false` | `Булево` | |
| строка | `Строка` | строки-даты **не** распознаются (§9.4) |
| число без `.`/`e`/`E` | `Целое` | вне диапазона int64 → ошибка загрузки (§9.6) |
| число с `.`/экспонентой | `Дробное` | `154000` → Целое; `154000.0`, `1.5e3` → Дробное |
| массив | `Список` | гетерогенный допускается (§4) |
| объект | `Запись` | вложенная (§4), доступ через `.` (§9.5) |

**Число — по форме токена, не по значению:** `100.0` — `Дробное`, наличие `.`/`e`/`E` решает. Это сохраняет различимость `тип()` (§4), целочисленное `//` и остаток `%` (§5) и совпадает с тем, как лексер различает целые и дробные литералы (§2).

### 9.4 Даты

JSON не имеет типа даты. **Без объявленной схемы** строка `"2026-04-12"` загружается как `Строка`; значение `Дата` получается **только** явным вызовом `дата(поле)` (§4, §8) — для НЕобъявленных полей авто-распознавание ISO-строк не делается (ложные срабатывания, неоднозначность формата).

**Поле, объявленное в `поля:` как `Дата`**, автоматически парсится из строки ISO `ГГГГ-ММ-ДД` в значение `Дата` при загрузке (для всех форматов — json/csv/ndjson); невалидная дата → ошибка данных (§9.6). По такому полю `период:`/`по_дате:` работают без явного `дата(...)`. Голые строки в незаявленных полях остаются `Строка`; в фильтрах по дате для них `дата(...)` пишется явно. Поле-ось времени для `период:` метрика задаёт явно — не угадывается (§10).

### 9.5 Запись, доступ к полям, схема источника

Каждая запись — `Запись` (§4): открытая структура с динамическим доступом. Поля доступны в выражениях `где`/`агрегат` метрики (§6) двумя формами — голое имя и `запись.поле`. Вложенный объект → `Запись`, вложенный массив → `Список`; доступ к вложенному полю — через `.` (голое имя разрешает только поля **верхнего** уровня).

**Множество полей источника (схема)** — объединение имён ключей **по всем записям** (а не по первой): опциональное поле, присутствующее хотя бы в одной записи, считается известным. Разрешение голого имени `x` в `где`/`агрегат`: известное поле, есть в записи → значение; известное поле, нет в записи → `пусто` (толерантно); не поле и не глобаль/встроенное → **ошибка** «возможна опечатка» (§13). Доступ через `запись.поле` — **полностью толерантный** (отсутствующее поле → `пусто`, без проверки по схеме). Strict-правило действует на уровне **схемы источника** (опечатка, которой нет ни в одной записи → ошибка), а не отдельной записи. Момент проверки — рантайм: для schemaless-источника схема известна только после загрузки. Несоответствие типа поля всплывает в момент операции — намеренно громко.

**Объявленная схема (`поля:`).** Если у источника задан блок `поля:` (§9.1), каждое объявленное поле в каждой записи коэрсится/валидируется при загрузке:

- **Отсутствует** объявленное поле в записи → ошибка данных (несёт имя источника, поле, номер записи N с 1).
- **Несовпадение типа** значения и объявленного типа → ошибка данных. Единственное разрешённое приведение — промоушен `Целое → Дробное`; обратного нет, прочие несовпадения — ошибка.
- **`Дата`-поле** парсится из строки ISO `ГГГГ-ММ-ДД` (§9.4); невалидная дата → ошибка данных.
- В формате `csv` каждая ячейка приходит как `Строка` и коэрсится в объявленный тип (`Целое`/`Дробное`/`Логическое`/`Дата`) с тем же набором ошибок.
- **Лишние** (необъявленные) поля записи — разрешены и игнорируются схемой (остаются доступны как обычно).

Тексты ошибок данных — §13.

### 9.6 Загрузка файла, кеш, ошибки

Файл читается **лениво**, при первом обращении метрики, и **кешируется на запуск** (`ladix run` или один тик `serve`): две метрики над одним источником не перечитывают файл. Live-reload файла в демоне — v2 (§12). Все ошибки загрузки — жёсткие runtime-ошибки в точке вычисления метрики, с номером строки и колонки объявления `источник`/`метрика` и путём к файлу (fail-loud, без молчаливого «пустого списка»). Полные тексты — §13. Битый JSON: позиция строка/колонка, если её даёт JSON-парсер; иначе — байтовое смещение с пометкой. **Нумерация записи `N` в сообщениях — с 1** (как пользовательская нумерация).

### 9.7 Пустой источник и ограничения

Источник из нуля записей: множество полей пусто, `где`/`агрегат` не вычисляются, метрика даёт «пустой» результат (§10). На пустом источнике без объявленной схемы опечатку в имени поля поймать нельзя (схема неизвестна) — осознанная цена ленивой schemaless-загрузки. Ограничения v1 (источник не первоклассен, кеш-на-запуск без live-reload, один источник на метрику) сведены в §12. Связь с Укладом (тот же синтаксис `источник Имя:` расширяется атрибутами в v2, не меняя фронтенд `где`/`агрегат`/`период`) — §12, путь отступления.

## §10 Метрики

`метрика Имя:` объявляет **именованный read-only скаляр-глобал, лениво вычисляемый над источником**. Регистрируется на первом проходе (как `источник`/`функция`/`процесс`, §6); значение вычисляется по требованию. Тип значения = тип результата выражения `агрегат` (обычно Целое/Дробное; `мин(...)`/`макс(...)` над полем дат → `Дата`).

```ladix
метрика выручка_месяца:
    источник: продажи
    где:      статус == "оплачен"
    агрегат:  сумма(сумма_заказа)
    период:   ежемесячно
    по_дате:  дата(дата_заказа)
```

### 10.1 Атрибуты

**`источник`** (обязателен) — ссылка на объявленный `источник` (Ident, не вычисляемое выражение); **`агрегат`** (обязателен) — агрегатное выражение, сводится к скаляру (§10.3); **`где`** — фильтр-предикат на записи, `Булево` (strict, §4); **`период`** — окно нарезки, требует `по_дате`; принимает одну из трёх форм (§10.4): адвербиальную константу (`ежемесячно`/…), скользящее окно `последние N <ед>`, либо «последний завершённый» `прошлый|прошлая <период>`; **`по_дате`** — ось времени на записи, `Дата` или `пусто` (§10.4). Каждый атрибут — не более одного раза, порядок произвольный. `период` без `по_дате` и `по_дате` без `период` — семантические ошибки (§13); `по_дате` обязателен тогда и только тогда, когда задан `период`.

### 10.2 Алгоритм вычисления

Чтение метрики `M` запускает конвейер (чистая функция от данных источника и `сегодня()`): (1) **загрузка источника** (лениво, кеш на запуск, §9; пустой источник короткозамыкается на «пустой» результат §10.5); (2) **окно периода** — при `период:` окно `[начало, конец]` относительно `сегодня()` по форме периода (§10.4: текущее календарное / скользящее `последние N <ед>` / последний завершённый), иначе все записи; (3) **фильтрация записей** в scope полей (§6, с амендментом §9.5): запись остаётся, если `по_дате` попадает в окно **и** `где` даёт `истина` (`по_дате` → `пусто` исключает запись; иной тип `по_дате`/не-`Булево` `где` → runtime-ошибка §13); (4) **агрегат** (§10.3).

### 10.3 Агрегат (модель проекции)

Выражение `агрегат:` — **общее скалярное выражение**, в котором агрегатные функции (`сумма`/`количество`/`среднее`/`мин`/`макс`, §8) — мост «записи → скаляр». Аргумент агрегатной функции — **выражение проекции**, вычисляемое на каждой выжившей записи (в scope полей), даёт список; функция сводит его к скаляру. Проекция **пропускает `пусто`-записи** (где спроецированное поле дало `пусто`). Вне аргументов агрегатных функций — обычная скалярная арифметика над их результатами, глобалями, константами, другими метриками. Голое поле вне агрегатной функции и вложенные агрегаты (`сумма(среднее(...))`) — семантические ошибки (§13).

Примеры: `сумма(сумма_заказа)` (простая сумма); `сумма(сумма_заказа) / количество(запись)` (средний чек, деривативная); `сумма(сумма_заказа * (1 - скидка))` (проекция-выражение внутри агрегата). `количество(запись)` — идиома «число отфильтрованных записей»: `запись` (вся текущая запись, §6) никогда не `пусто`, проекция ничего не отбрасывает.

### 10.4 Период и окна

Атрибут `период:` принимает одну из трёх форм. Все окна вычисляются относительно `D = сегодня()` (`eval.Clock`, фиксирована на запуск — детерминизм); метрика остаётся **скаляром** (окно меняет множество выживших записей, но не вводит временной ряд значений — §12).

**(1) Адвербиальная константа** — **полное** календарное окно, содержащее `D` («текущий, в процессе»), не усечённое по `D`:

| Период | Окно `[начало, конец]` (включительно) | Пример для D = 2026-05-31 |
|---|---|---|
| `ежедневно` | `[D, D]` | `[2026-05-31, 2026-05-31]` |
| `еженедельно` | ISO-неделя (пн–вс), содержащая `D` | `[2026-05-25, 2026-05-31]` |
| `ежемесячно` | календарный месяц | `[2026-05-01, 2026-05-31]` |
| `ежеквартально` | квартал (Q1 янв–мар … Q4 окт–дек) | `[2026-04-01, 2026-06-30]` |
| `ежегодно` | календарный год | `[2026-01-01, 2026-12-31]` |

Неделя — ISO-8601 (с понедельника).

**(2) Скользящее окно** — `период: последние N <ед>`, где `ед` ∈ `дн`, `нед`, `мес` (форма слитная, как литерал длительности: `последние 30дн`). Окно — полуинтервал `(D − N ед, D]`: последняя нижняя граница исключается, `D` включается. Единица `сек`/`мин`/`час` или `N ≤ 0` — семантическая ошибка (§13).

**(3) Последний завершённый период** — `период: прошлый <период>` (`прошлая` для женского рода): `прошлый день`, `прошлая неделя`, `прошлый месяц`, `прошлый квартал`, `прошлый год`. Это тот же календарный период, что у адвербиальной константы, но сдвинутый на один назад — последний полностью завершённый. Например, для `D = 2026-06-15` `прошлый месяц` → `[2026-05-01, 2026-05-31]`. Неизвестное слово периода — семантическая ошибка (§13).

Метрика над любой формой `период:` требует `по_дате:` (§10.1). Кастомные произвольные окна `[дата1, дата2]` и почасовые окна — v2 (§12).

**`по_дате`** вычисляется на каждой записи: `Дата` → проверка попадания в окно; `пусто` (поле даты отсутствует, §9.5) → запись исключается без ошибки (для этого `дата(пусто) → пусто`, §8); иной тип → runtime-ошибка (§13). Типичная форма — `по_дате: дата(поле)` (строки-даты из JSON остаются `Строка`, §9.4).

### 10.5 Пустой результат

Если выживших записей нет (пустой источник, окно без записей, `где` всё отсёк): результат **`0`**, если корневое `агрегат` — единичный `сумма(...)` или `количество(...)`; иначе **`пусто`** (единичные `среднее`/`мин`/`макс` и любые деривативные выражения — короткое замыкание до арифметики, чтобы не ловить `0/0`). Метрика — слой данных, пустота нормальна (дашборд показывает «—», а не падает). Это осознанно расходится с §8 (там `среднее([])`/`мин([])` → ошибка): то — функции общего назначения, пустое окно метрики — штатное состояние. Метрика-порог (`сумма`/`количество`) на пустом окне даёт `0`; для триггеров `значение` может оказаться `пусто` (§11).

### 10.6 Метрика как значение

Имя метрики — read-only глобал-скаляр: прочитанное как выражение где угодно (императив, тело функции, шаг процесса, тело триггера), оно даёт текущее скалярное значение. **Чтение запускает пересчёт** (кеша значения в v1 нет, сверх кеша источника на запуск). Детерминизм в рамках запуска: `сегодня()` фиксирована, источник кеширован → два чтения дают одно значение. Присваивание метрике запрещено; цикл зависимостей метрик → runtime-ошибка (§13).

Большой пример (продажи: метрика `выручка_месяца`, процесс `разбор_падения`, триггер) — **`examples/выручка.ladix`**. Ограничения v1 (метрика — только скаляр, не ряд; один источник на метрику; ось — только дата; пересчёт каждый раз) — §12.

## §11 Процессы и триггеры

**Выполнение программы** начинается с первого top-level statement; инструкции исполняются сверху вниз. Объявления (`функция`/`источник`/`метрика`/`процесс`/триггер) регистрируются на первом проходе и сами по себе не исполняются. Процессы запускаются явно (`запустить процесс`, §7) или из триггеров. Детальная модель исполнения (поля `ProcessInstance`/`Task`, контракт `Store`, момент персиста, планировщик) — **docs/execution-model.md**.

### 11.1 Сущности и статусы

**Процесс** (§3) — определение: имя, параметры, упорядоченный набор шагов; не исполняется в момент объявления. **Инстанс** — конкретный запуск с уникальным строковым id, статусом, переменными процесса. **Шаг** — единица работы: автоматический (без `исполнитель`) или человеческий (с `исполнитель` — точка ожидания). **Задача** (`Task`) создаётся при входе в человеческий шаг (исполнитель, дедлайн, ссылка на инстанс/шаг), завершается командой `ladix complete`. **Переменная процесса** живёт всё время жизни инстанса, персистируется на каждое изменение.

Статусы: `создан` (персистирован, первый шаг не начат — транзиентно) · `выполняется` (активный шаг исполняет тело, ожидания нет) · `ожидает` (шаг создал `Task`, инстанс заснул до `ladix complete`) · `выполнен` (все шаги готовы, терминальный успех) · `провален` (сбой `вызвать` или необработанная runtime-ошибка в теле/атрибутах шага, терминальный отказ) · `отменён` (зарезервирован для forward-compat, в v1 недостижим, §12).

Переходы: `запустить` → `создан` → `выполняется` → (шаг с `исполнитель`) `ожидает` ↔ (`ladix complete`) `выполняется` → `выполнен`; из `выполняется`/`ожидает` при сбое → `провален`. **Засыпание и пробуждение:** в статусе `ожидает` инстанс целиком персистирован, активных ресурсов (горутины/потока) не держит; «пробуждение» — внешняя команда `ladix complete` (сигнатура и гарды — §11.5), которая грузит инстанс, помечает шаг готовым и продвигает исполнение. Процесс переживает рестарт демона. Детали lifecycle/персиста — docs/execution-model.md.

### 11.2 Порядок шагов

Шаги исполняются **строго в порядке объявления** в исходнике; активен ровно один шаг (параллельности нет, §12). `после X` — **ограничение-валидатор, не переупорядочиватель**: семантический анализ проверяет, что каждое имя в `после` ссылается на шаг этого же процесса, объявленный **раньше**, и что граф ацикличен (нарушения — §13). Полноценная топологическая семантика `после` зарезервирована под параллельные шаги v2; программы v1 останутся валидными (порядок исходника — допустимая топосортировка).

### 11.3 Исполнение шага (тело-вперёд)

При активации шага: (1) вычисляются атрибуты `исполнитель`/`срок` (настройка задачи); (2) тело шага (`Statement`, включая действия и `если`/`пока`/`для`) исполняется **сверху вниз** — здесь все автоматические эффекты (`присвоить`, `вызвать`, `уведомить`, `печать`, `запустить процесс`); (3) развилка по `исполнитель`: нет → шаг сразу готов, продвижение к следующему (статус `выполняется`); есть → создаётся `Task`, статус → `ожидает`, инстанс персистируется и засыпает до `ladix complete`. Тело и `исполнитель` не взаимоисключающи: типичный паттерн — посчитать/уведомить, затем ждать человека.

```ladix
процесс эскалация(сумма_долга):
    шаг подготовить_и_ждать:
        исполнитель: "юрист"
        срок:        3дн
        присвоить долг = сумма_долга          # авто-эффект на входе
        уведомить юрист("долг к взысканию: " + строка(сумма_долга))
        # тело исполнено, создан Task, инстанс → ожидает
    шаг закрыть после подготовить_и_ждать:
        присвоить статус_дела = "закрыто"     # после ladix complete первого шага
```

### 11.4 Атрибуты, действия, провал

**`исполнитель`** (`Строка`) делает шаг точкой ожидания; в v1 — совещательная метка (реестра ролей/прав нет, завершить задачу по id может кто угодно, §12). **`срок`** (`Длительность`) — относительный дедлайн, фиксируемый абсолютно при создании `Task`, с **пассивной семантикой**: на истечении движок ничего не делает; «просрочено» вычисляется движком (Go-время против дедлайна) и выходит наружу как `просрочена: Булево`; эскалаций/авто-провала по дедлайну нет; `срок` без `исполнитель` — семантическая ошибка (§13).

Действия: **`присвоить Ident = E`** создаёт/обновляет переменную процесса (персист в `Store`, видна во всех последующих шагах — единственный канал данных между шагами); **`вызвать Ident(...)`** — внешний вызов: как **оператор** — fire-and-forget без захвата результата, как **выражение** — с захватом результата (`присвоить r = вызвать crm(x)`; узел `CallExternalExpr`, `ast/expr.go:80`; стаб возвращает `Пусто`); **`уведомить Ident(...)`** — сообщение исполнителю/роли (только оператор). **Реальные эффекты** `вызвать`/`уведомить`: дефолт — печать-стаб (`[вызов] цель(...)` / `[уведомление] цель: ...`, `engine/caller.go:30/41`); под CLI-флагом `--webhook <URL>` (или env `LADIX_WEBHOOK`) — HTTP POST plain-JSON `{"цель":target,"данные":[args]}` (`engine/caller.go:57`, `jsonval/encode.go:12`); невалидный URL → ошибка CLI `неверный URL вебхука '<URL>'` (`cmd/ladix/main.go:52`). Семантика сбоя `вызвать` определена под будущие системы (ошибка → инстанс `провален`); `уведомить` best-effort, сбоя нет. **Контекст действий:** `присвоить` допустимо только в теле шага процесса (включая `если`/`пока`/`для` шага); вне шага — семантическая ошибка (§13). `вызвать`/`уведомить` допустимы в теле шага **и** в теле любого триггера (метрика/событие/расписание/задача — allow-список `eval/analyze.go:608-629`); `присвоить` в теле триггера запрещён (тело-env read-only). **Провал:** инстанс → `провален` при сбое `вызвать`, любой необработанной runtime-ошибке в теле шага или при вычислении атрибутов `исполнитель`/`срок` (фаза (1) §11.3; docs/engine-model.md D-9/D-18) — в v1 нет `пытаться`/`словить`. Сообщение несёт строку и колонку (§13); инстанс персистируется как `провален`, исполнение останавливается; незавершённые задачи остаются «осиротевшими» (авто-отзыв — v2).

### 11.5 `ladix complete`

`ladix complete <file.ladix> <task-id> [--db путь] [--data '{...}']` — истина в исходнике, БД хранит только состояние: команда компилирует файл (лексика→синтаксис→семантика обязаны пройти чисто, иначе обычный барьер §13.3, код 1), грузит `Task` и инстанс, помечает шаг готовым, продвигает исполнение (следующий шаг по §11.3 — возможно, снова засыпает или процесс → `выполнен`), персистирует. **Гарды** перед продвижением: задача и инстанс существуют; инстанс в `ожидает` именно на шаге задачи; процесс инстанса и его текущий шаг найдены в файле (дрейф исходника против БД; граница v1 — исходник между запуском и `complete` не меняют). Нарушение гарда → ошибка CLI с кодом возврата 2, инстанс не тронут (тексты — docs/engine-model.md §EN-8). Исключение — **гард-догон**: повторный `complete` уже-завершённой задачи при инстансе, всё ещё ожидающем на том же шаге (хвост сбоя «задача закрыта, продвижение не успело»), идемпотентно до-продвигает инстанс и завершается успехом (код 0, с пометкой в выводе). Runtime-ошибка при продвижении → инстанс `провален`, диагностика по §13 в stderr, код 1 (как у `run`). **Payload задачи:** `--data '{...}'` пробрасывает JSON-объект как read-only эфемерную `Запись` под предопределённым именем `данные` (`engine/engine.go:26`), видимую **только в первом шаге догона** — после него payload гаснет (не персистируется в инстанс; `engine/engine.go:293`). Маппинг JSON→типы как у источников. Невалидный JSON → ошибка CLI `неверный JSON в --data: <деталь>` (`cmd/ladix/main.go:424`), Store не тронут. Пример человеко-в-цикле процесса (адаптация сотрудника: шаги с `исполнитель` и пробуждение через `ladix complete`) — `examples/онбординг.ladix`; пошаговый прогон через `Store` — docs/execution-model.md.

**Запуск и интроспекция инстанса (M2).** `ladix start <file.ladix> <процесс> [аргументы...] [--db путь]` запускает инстанс: аргументы из argv разбираются в типизированные литералы, проверяется арность и объявленность процесса (`cmd/ladix/start.go`). `ladix inspect <id> [--db путь]` печатает снимок инстанса (статус, текущий шаг, переменные) и историю задач, с пометкой `, эскалирована` для эскалированных (`cmd/ladix/inspect.go`). **Единая `--db`:** команды `start`/`inspect`/`complete`/`tasks`/`emit` по умолчанию используют файловый Store `ladix.db` (SQLite); `run`/`serve` по умолчанию — Memory (для `metric` — всегда Memory). Внимание: `serve` дефолтит Memory, поэтому демонстрация durable-сценариев требует явного `serve --db ladix.db`. Полный каталог подкоманд и кодов возврата — README, раздел CLI. CLI-ошибки разбора аргументов — §13.4.

### 11.6 Триггеры

Триггер (`когда ...`) — top-level-объявление, связывающее декларативную часть (метрики, события) с императивной (процессы): «при условии — запустить процесс». Грамматика — §3; механика планировщика (тик, состояние перехода, очередь событий, расписание, проверка дедлайнов) — docs/execution-model.md. Четыре формы:

```ladix
когда метрика просрочка > 5:
    запустить процесс разбор(значение)
когда событие заявка_создана:
    запустить процесс обработать(событие.клиент)
когда расписание каждые 1дн:
    запустить процесс ежедневный_отчёт()
когда задача просрочена в эскалация.подготовить_и_ждать:
    уведомить руководитель("дедлайн пропущен")
```

- **`когда метрика M CompOp E`** срабатывает **на переходе** результата сравнения из `ложь` в `истина` между двумя оценками (не на каждой истинной оценке). Первая оценка устанавливает базовую линию молча (**прайм без срабатывания**); база персистится, поэтому после рестарта демона прайма не повторяется. Невычислимое условие (`пусто`-окно §10.5 или не-`Булево`) трактуется как «не срабатывать» (тихо, не ошибка), **база замораживается** — мигание из-за легитимно пустых данных не порождает ложных переходов. В теле доступна `значение` — текущее значение метрики. **При срабатывании** метрика-триггер печатает человеко-`explain` (наблюдаемость DoD §2 «почему сработал триггер»; формат — канон `docs/reliability-model.md §C-5.3`, в SPEC не зеркалируется): в `run` без пометки ребра, в `serve` с пометкой `(ребро ложь→истина)`. Пример строки `run`: `триггер 'выручка_30д < 3000000' сработал: выручка_30д = 300000.0 (снимок) < 3000000 (порог) → истина` (снимок↔порог рендерятся `value.String`, оператор — `BinOp.String()`; всегда-вкл при срабатывании, на не-fire-тике тихо).
- **`когда событие E`** срабатывает на каждое поступившее событие `E` (состояния перехода нет). Источник событий в v1 — `ladix emit <E> [json]` через общий `Store`. В теле доступно `событие` — `Запись` из payload (маппинг JSON→типы как у источников, доступ толерантный).
- **`когда расписание каждые D`** / `в "ЧЧ:ММ"` — периодически / раз в сутки. Строка `в "…"` принимается фронтендом как обычный `StringLiteral` без проверки содержимого; формат `"ЧЧ:ММ"` (00:00–23:59) валидирует демон `serve` при исполнении расписания (фича 007b) — невалидный формат даёт семантическую ошибку §13.4 на стороне `serve`. Расписание/событие активны **только в `serve`**; в `run` — no-op с логом.
- **`когда задача просрочена в <Процесс>.<шаг>`** (узел `DeadlineTrigger`, `ast/trigger.go:70`) — эскалация дедлайна: тело срабатывает при просрочке задачи указанного шага. Под `serve` 4-я фаза тика проверяет дедлайны (`daemon/checkdeadlines.go`) и эскалирует **ровно один раз** на задачу (durable-флаг `Task.Escalated`, переживает рестарт демона). Под `run` — заглушка `задача триггер '<P>.<S>' требует serve (фича 007b)` (`eval/trigger_run.go:56`). Типичное тело — `уведомить руководитель(...)`.

Тело триггера — `Block`; допустимы `пусть`, встроенные функции, `если`/`пока`/`для`, `запустить процесс`, `вызвать`/`уведомить` (allow-список тела триггера, §11.4; `eval/analyze.go:608-629`), чтение метрик/глобалов. **Недопустим** `присвоить` (не в allow-списке + тело-env read-only → семантическая ошибка, §13): триггер не мутирует глобалы напрямую, а запускает процессы и шлёт уведомления/вызовы. Несколько триггеров на одну метрику/событие допустимо (независимое состояние перехода); порядок исполнения на одном тике — порядок объявления в исходнике. В `run` метрика-триггеры дают один `fire-if-true`-проход (база = `ложь`, истинное условие срабатывает один раз — демонстрируемость без демона).

## §12 Ограничения версии 1

Осознанно **не делаем** в v1 (снятие в v2+ не ломает синтаксис уже написанных программ — путь отступления краток ниже):

- **Выполнение/процессы:** параллельные шаги (`параллельно`); модули/`импорт`; статическая типизация; retry-policy при сбое `вызвать`; cron-выражения в `расписание` (только `каждые D` и `в "ЧЧ:ММ"`); отмена/приостановка/перезапуск инстанса (статус `отменён` зарезервирован, недостижим); `ждать <условие>`/таймерный гейт; обработка исключений в шаге (`пытаться`/`словить`); реестр ролей/прав и тип `Роль` (`исполнитель` — совещательная `Строка`); персист payload задачи в инстанс (`--data` виден только первому шагу догона, эфемерен — §11.5); отзыв осиротевших задач при `провален`.
  - *Реализовано в M2 (было отложено):* захват результата `вызвать` (теперь и выражение `CallExternalExpr`, §11.4); эскалация дедлайна (`когда задача просрочена в ...` под `serve`, durable, §11.6); реальные интеграции `вызвать`/`уведомить` (HTTP POST через `--webhook`/`LADIX_WEBHOOK`, иначе печать-стаб, §11.4); payload задачи `complete --data` (read-only эфемерная `Запись` `данные` — §11.5).
- **Выражения/типы:** возведение в степень; тернарный оператор (только блочный `если`/`иначе`); цепочечные сравнения (через `и`); один `Statement` на строку (нет `;`); литералы дат (только `дата(...)`/`сегодня()`); срезы строк (`подстрока`); прямая мутация списка `s[i] = x`; сравнение/конкатенация списков `<`/`>`/`+` (только `соединить`); литералы Записи (пользователь Запись только читает); итерация по полям Записи; hex/binary-нотация; неявные приведения (кроме промоушена Целое→Дробное); функции не первоклассны; затенение через `пусть` в той же области; точное значение `MinInt64` (`-9_223_372_036_854_775_808`) не выразимо целым литералом (лексер не сворачивает знак: `-X` это `MINUS · INT(X)`, а `9223372036854775808` = `MaxInt64 + 1`; диапазон-проверка парсера беззнаковая) — обойти вычислением; путь отступления к свёртке знака на литерале в парсере аддитивен; **порядок периодов** (`Период < Период`, `>` и т.п.) не определён — `Период` перечислим без порядка, активны только `==`/`!=` по имени (`value.Equal`; `Compare` → `ok=false` → чистая ОшибкаТипа `«'<оп>' нельзя применить к Период и Период»`), путь отступления к явному порядку перечисления аддитивен; **диапазон литерала `Длительность`** (`9999999999999999999дн`) проверяется **не** статически парсером, а в рантайме (ОшибкаВыполнения «литерал длительности вне диапазона типа Целое», `eval/expr.go`) — в отличие от целого литерала (статически, D2; на 309+ значащих цифрах `Дробное` ловится лексером как L-8), путь отступления к статической проверке в `buildDurationLit` аддитивен.
- **Управление:** `for-else`/`while-else`; слипшийся `иначеесли`; метки циклов / `прервать <N>`; `do-while` (`повторить` зарезервировано); итерация не-`Список` (числовые диапазоны — через `диапазон(...)`); парная итерация (`enumerate`/`zip`); распаковка (`пусть a, b = …`); мутация коллекции во время итерации над ней (через `копия(...)`); параметры процесса по умолчанию и именованные аргументы (только позиционные); третья форма `диапазон(start, stop, шаг)`.
- **Восстановление парсера — остаточные каскады (после вехи M-DX):** веха M-DX сняла каскад фантомных диагностик для ведущего ключевого слова (`если`/`пока`/`вернуть`/…) в позиции выражения на одной/смежной строке (напр. `пусть x = если` → одна диагностика, не 2–4) и перевела тексты лексики/синтаксиса в бизнес-тон с подсказками-опечатками (§13.4, канон `docs/diagnostics-model.md`). Осознанно остаётся отложенным (тот же приём подавления, аддитивно): (1) каскад на decl-attribute-trailing пути (`поля: если`, `период: последние если` → 2 диагностики, sync-lead-зависим) — отдельный путь `parseSourceDecl`/`parseMetricDecl`, бэклог «decl-line recovery»; (2) двойной фантом при сиротском отступе тела (`пусть x = если`⏎`    печать(1)` → 2) — характеризован как явный долг. Бесконечного цикла нет (backstop-продвижение гарантирует прогресс). Остаточные числа залочены характеризационными замками (`docs/diagnostics-model.md §MDX-5`).
- **Временное:** тип `ДатаВремя` и таймзоны; почасовые/поминутные окна метрик. Уточнение: «нет `ДатаВремя`» ≠ «движок не знает реального времени» — демон `serve` смотрит на Go-wall-clock **внутри** для `каждые D`/`в "ЧЧ:ММ"`, но наружу как значение Ladix реальное время не экспонируется. Часы предполагаются идущими **монотонно вперёд**: перевод системных часов назад через полночь после `в "ЧЧ:ММ"` может дать повторный fire на предыдущую дату (немонотонность wall-clock демоном не защищается — защита v2).
- **Источники/метрики:** форматы файла — `json`/`csv`/`ndjson` (обёртка `{"записи": […]}` — нет; БД/API/HTTP-коннекторы, атрибут `адрес:` — v2); для CSV нет настройки разделителя/кодировки (`разделитель:`/`кодировка:` — v2, фиксированы запятая и UTF-8); строки-даты в НЕобъявленных полях не распознаются автоматически (только поля, объявленные `Дата` в `поля:`); источник не первоклассен; чтение один раз с кешем на запуск (live-reload — нет); относительный путь источника резолвится от каталога `.ladix`-файла (file-relative; CLI-флаг `--source-base <dir>` переопределяет базу, абсолютный — как есть; фича 026); метрика — только скаляр, **не ряд** (временной ряд значений отложен); окна — адвербиальные константы, скользящие `последние N <ед>` (ед ∈ дн/нед/мес) и «последний завершённый» `прошлый <период>`; почасовые/поминутные окна и кастомные произвольные окна `[дата1, дата2]` — нет; один источник на метрику; ось времени — только дата; фиксированный набор агрегатов; пересчёт каждый раз.
- **Не-конечные дробные в источниках/метриках:** слой `jsonval` принимает `Дробное{±Inf}` (бесконечность) — такое значение утекает в агрегаты метрик без гарда конечности; `parseFiniteFloat` дополнительно принимает запись разрядов через `_` (`1_000`); **осознанно отложено в v3** (осознанный размен фичи 024, вне DoD), путь отступления — гард конечности при разборе JSON-числа в `jsonval` аддитивен (отклонять `±Inf` до агрегации).
- **Модель исполнения/триггеры:** синхронный CLI-драйвер без IPC (пробуждение — `ladix complete` над общим SQLite, не push из демона); персист на каждое `присвоить` (без батчинга); внешние эффекты тела шага (`вызвать`/`уведомить`) доставляются **exactly-once** через outbox-леджер идемпотентности (M3, `docs/reliability-model.md` §C-2b): ключ дедупа = инстанс + шаг + порядковый номер эффекта; повторная активация шага на рестарте видит доставленный ключ и пропускает дубль (остаточное окно «доставлено-но-не-помечено» = at-least-once — идемпотентность приёмника вне scope, §C-9); дедуп НЕ распространяется на `присвоить` (повторная активация может повторить мутации переменных процесса — `присвоить x = x + 1`, шаги пишутся идемпотентными по переменным) и НЕ на `запустить процесс` (повторная активация ре-спавнит дочерний инстанс); остаточная гонка двух одновременных `complete` одной задачи (двойное продвижение) не закрывается — последствия ограничены гардами `complete` (§11.5); инстанс, прерванный посреди шага (kill процесса ОС), остаётся залипшим в `выполняется` — рестарт-скан поднимает его при старте `serve` (фича 007); forward-only миграции схемы БД (`PRAGMA user_version`, база=1, миграция 1→2 = таблица `outbox`; M3 §C-2a) — **downgrade-граница не закрыта:** БД с будущей версией `user_version` (новее бинаря) открывается **молча**, без отказа и предупреждения; forward-only by design, защита от downgrade — v2 (`docs/reliability-model.md §C-9`, C2A-1); единые часы CLI во всех путях (`run`/`start`/`complete`/`tasks`/`metric` инъектируют один `engine.Clock`; M3 §C-4); триггеры реактивны только в `serve` (+ один `fire-if-true`-проход в `run`) — и то и другое появляется с фичей 007, движок 006 триггеры не исполняет; условие `когда метрика` — ровно **одно сравнение** `метрика Ident CompOp Выражение` (составное `X < Y и Z > W` или предикат по нескольким метрикам невыразимо; расширение аддитивно в v2); состояние перехода метрика/расписание-триггера в `Store`, durable-ключ выводится **из смысла условия** (контентный хеш канонизированного условия + порядковый номер внутри группы одинаковых условий), а не из позиции объявления — перестановка/вставка/удаление любого триггера (в т.ч. событие/дедлайн) больше **не сдвигает** durable-идентичность соседей, устранив тихую порчу edge-baseline (стабильные ключи триггеров реализованы фичей 027, §C-9 закрыт; ранее ключ был позиционный `trg-<N>`; событие/дедлайн-триггеры durable-ключа не имеют); источники событий — `ladix emit` (CLI) и опц. HTTP-приём `serve --listen` (трек B, after-v2, неразличимы ниже точки минта — `docs/inbound-events-model.md`); один `time.Ticker`, гранулярность = базовый интервал; арифметика Длительности и дат (`Длит ± Длит`, `Длит * X`, `Дата ± Длит`, `Дата - Дата` — §4) фичей 006 не активируется и до активации остаётся ошибкой типа — активны только `==`/`!=` и порядковые сравнения одной единицы (канон — docs/engine-model.md D-17/§EN-10; бэклог 007+/v2).
- **Отмена/тайм-аут внешних вызовов:** интерфейс `ExternalCaller` (`вызвать`/`уведомить`) не принимает `context.Context` — отмена и дедлайн вызова не протягиваются сквозь движок; зависший внешний эффект ограничен только жёстким тайм-аутом HTTP-клиента (`const webhookTimeout = 30 * time.Second`, `src/cmd/ladix/main.go`, источник истины — код), не идиоматичным `ctx`; **осознанно отложено в v3** (улучшение, не дефект — таймаут уже закрывает зависание), путь отступления — добавление `ctx context.Context` первым параметром методов `ExternalCaller` аддитивно (фронтенд и `Store`-контракт не меняются).
- **Интроспекция типа `тип(x)`:** зарезервирована для v1. Builtin `тип` зарегистрирован и реализован (целевая семантика — имя типа как `Строка`, §4/§8), но имя `тип` — ключевое слово `KW_TYPE` (§2; разрезервировано в 010-A1 как атрибут источника `тип:`, §9), которое не начинает primary, поэтому вызов `тип(...)` недостижим из синтаксиса: `печать(тип(5))` даёт парс-ошибку «неожиданный элемент 'тип'», а не `"Целое"`. Из 35 зарегистрированных builtins синтаксически достижимы 34; активация `тип(x)` — аддитивна, v2.

**Путь отступления (кратко).** Новые операторы/литералы/ключевые слова (`параллельно`/`модуль`/`ждать`/`словить` — зарезервированы в §2) и новые атрибуты блоков (`тип:`/`адрес:`/`поля:` источника, payload/эскалация задачи) — **аддитивны**: добавляются, не пересекаясь с текущим синтаксисом, программы v1 продолжают работать. Снятие schemaless, форматов источников, рядов метрик, серверной модели (демон-владелец БД + CLI-клиент по сети) — внутренние улучшения `Store`/движка или новые значения атрибутов; фронтенд (`где`/`агрегат`/`период`, грамматика `когда`) и `Store`-контракт не меняются. Полная трассировка решений → docs/STRUCTURE.md.

## §13 Ошибки и диагностика

§13 — единый источник истины по диагностике; на него ссылаются §2–§12. **Канонический формат — двухстрочный**, позиция обязательна во всех категориях:

```
Ошибка в строке N, колонка M:
<описание>
```

`N`, `M` — с 1. Предупреждения — тот же формат с заголовком `Предупреждение в строке N, колонка M:` (не прерывают компиляцию, не учитываются в счётчике). Под описанием допускается (рекомендуется для лексики/синтаксиса) печать исходной строки и каретки `^` под колонкой — улучшение UX, не часть контракта. Go-error-типы (пакет `internal/errors`, общая `Position{Line, Col}`, дружба с `errors.Is`/`errors.As`) — **ARCHITECTURE.md**; сентинелы Store `ErrInstanceNotFound`/`ErrTaskNotFound`/`ErrTaskAlreadyCompleted` — в `internal/store` (docs/engine-model.md §EN-2; `ErrTriggerStateNotFound` добавит фича 007). Наружу сентинелы не печатаются, транслируются в русские сообщения.

### 13.1 Категории (шесть пользовательских + предупреждение)

Каждая категория несёт строку **И** колонку; определяется слоем-источником и моментом обнаружения (репрезентативные тексты — §13.4):

- **Лексическая** (лексер) — символьный уровень: таб/неверный отступ, неизвестный символ, незакрытая строка, неверный escape/числовой литерал/суффикс длительности, зарезервированное слово как имя.
- **Синтаксическая** (парсер) — нарушение грамматики §3: неожиданный элемент, цепочечное сравнение, вложенная `функция`, незакрытый блок; целый литерал вне диапазона типа Целое (проверка при сборке литерала парсером — статическая, накапливается, §13.2).
- **Семантическая** (семантика) — статические правила имён/области/арности/контекста: необъявленная переменная, повторное объявление, неверная арность, `вернуть`/`прервать` не на месте, действие вне шага, нарушения атрибутов метрики/шага.
- **Типа** (интерпретатор) — динамическая проверка типа: несовместимые операнды, условие не `Булево`, `для` не над `Список`.
- **Выполнения** (интерпретатор/загрузчик) — деление на ноль, переполнение int64, индекс вне диапазона, лимит рекурсии, пустой агрегат, неизвестный id процесса, сбой загрузки источника.
- **Процесса** (движок) — зарезервирована, в v1 не порождается (D-14 — docs/engine-model.md): необработанная runtime-ошибка в теле/атрибутах шага сохраняет исходную категорию (Типа/Выполнения), инстанс при этом → `провален`; сбой `вызвать` → `провален` в v1 недостижим (стаб всегда успешен).
- *Предупреждение* (семантика) — допустимая, но подозрительная конструкция: затенение встроенной функции/предопределённого периода.

### 13.2 Накопление и fail-fast

**Panic-mode (сбор нескольких ошибок за прогон) — только лексер + парсер** (статическая фаза): обнаружив ошибку, парсер регистрирует её и синхронизируется до безопасной точки (`NEWLINE`/`DEDENT`/начало top-level-элемента), подавляя каскад фантомов; накопитель ограничен ≈20 ошибками. Накопленные блоки печатаются подряд, каждый — со своим заголовком «Ошибка в строке N, колонка M:»; **итоговой строки-сводки нет** — агрегатор выводит только блоки и НЕ печатает завершающую строку-счётчик с числом ошибок (зафиксировано тест-замком `src/internal/errors/aggregate_test.go`, проверяющим отсутствие такой сводки). **Семантические ошибки — fail-fast** (стоп на первой); накопление к семантике не применяется. **Runtime-ошибки не собираются** — первая останавливает выполнение.

### 13.3 Барьер CLI и коды возврата

Пайплайн каждой подкоманды обёрнут recover-барьером: **любая ошибка Ladix** форматируется по §13 в stderr и даёт ненулевой код (штатный путь, без паники); **непредвиденная Go-паника** (баг интерпретатора) перехватывается `recover()`, печатается дженерик `внутренняя ошибка интерпретатора` **без Go stack trace**. Штатные ошибки никогда не паникуют (лимит рекурсии, деление на ноль, overflow, индекс — проверяются явно). Коды: **0** — успех; **1** — ошибка программы Ladix (lex/parse/semantic/type/runtime/process) или внутренняя паника; **2** — ошибка использования CLI (плохие аргументы, файл не найден на уровне CLI, неизвестный/завершённый task-id `complete` — кроме гард-догона, §11.5). CLI-сообщения позиции в исходнике не имеют (README, раздел CLI). **CLI-ошибки M2 (код 2, префикс `ladix:`):** `start`/`inspect` — `процесс '<имя>' ожидает <N> аргументов, получено <M>` (арность, B5), `процесс '<имя>' не объявлен` (B5; проверка в CLI до движка, `cmd/ladix/start.go:146/150`), `не удалось разобрать аргумент '<argv>': целое вне диапазона типа Целое` (разбор литерала-аргумента, `start.go:177`), `инстанс '<id>' не найден` (B6, `cmd/ladix/inspect.go`); внешние эффекты — `неверный URL вебхука '<URL>'` (`cmd/ladix/main.go:52`), `неверный JSON в --data: <деталь>` (`cmd/ladix/main.go:424`). Новых SE-кодов M2 не вводит (счёт 14 цел — §13.4).

### 13.4 Сводная таблица ключевых диагностик
