# Задание: разработка собственного языка программирования

## Цель проекта

Вам нужно спроектировать и реализовать собственный небольшой язык программирования.

Результатом должен быть не просто набор синтаксических идей, а работающий язык, на котором можно писать и запускать программы. У языка должны быть описание, реализация, примеры программ и тесты.

Высоко оценивается не самый большой язык, а самый понятный, цельный, работающий и хорошо описанный язык.

Максимальная оценка за проект: **100 баллов**.

Дополнительно можно получить до **10 бонусных баллов**, но бонусы не заменяют базовую функциональность.

## 2. Лексика, синтаксис и грамматика — 15 баллов

Нужно описать и реализовать правила записи программ на вашем языке.

| Требование | Баллы |
|---|---:|
| Есть идентификаторы | 1 |
| Есть числовые литералы | 1 |
| Есть строковые или булевы литералы | 1 |
| Есть операторы и ключевые слова | 1 |
| Есть комментарии | 1 |
| Описаны правила токенизации: пробелы, переводы строк, неизвестные символы | 1 |
| Есть грамматика языка в BNF/EBNF или похожем формате | 4 |
| Синтаксис однозначный: понятно, как разбираются вложенные выражения и конструкции | 2 |
| Реализован парсер, который строит AST или другую внутреннюю структуру | 2 |
| Синтаксические ошибки обрабатываются без падения реализации | 1 |
| **Итого** | **15** |

Минимальный пример грамматики:

```ebnf
program     = statement* ;
statement   = var_decl | assignment | if_stmt | while_stmt | func_decl | return_stmt | expr_stmt ;
var_decl    = "let" IDENT "=" expression ";" ;
assignment  = IDENT "=" expression ";" ;
if_stmt     = "if" "(" expression ")" block ("else" block)? ;
while_stmt  = "while" "(" expression ")" block ;
func_decl   = "fn" IDENT "(" parameters? ")" block ;
return_stmt = "return" expression? ";" ;
block       = "{" statement* "}" ;
expression  = equality ;
```

Ваш язык может иметь другой синтаксис. Важно, чтобы грамматика соответствовала реализации.

### Что именно нужно реализовать

Лексер должен преобразовывать исходный текст программы в поток токенов. Токен - это отдельная значимая часть программы: число, имя переменной, оператор, скобка, ключевое слово.

Например, программа:

```text
let x = 10 + 20;
```

может быть превращена в такие токены:

```text
LET("let")
IDENT("x")
EQUAL("=")
NUMBER("10")
PLUS("+")
NUMBER("20")
SEMICOLON(";")
EOF
```

После лексера должен работать парсер. Парсер проверяет, что токены образуют корректную программу, и строит внутреннее представление программы, например AST.

Пример AST для выражения:

```text
2 + 3 * 4
```

может выглядеть так:

```text
BinaryExpression(
    operator="+",
    left=NumberLiteral(2),
    right=BinaryExpression(
        operator="*",
        left=NumberLiteral(3),
        right=NumberLiteral(4)
    )
)
```

Это важно, потому что выражение `2 + 3 * 4` должно вычисляться как `2 + (3 * 4)`, а не как `(2 + 3) * 4`.

### Как это выглядит в других языках

В JavaScript:

```javascript
let x = 10 + 20;
console.log(x);
```

В Python:

```python
x = 10 + 20
print(x)
```

В вашем языке может быть, например:

```text
let x = 10 + 20;
print(x);
```

Вы можете выбрать другой синтаксис, но должны явно описать его в `SPEC.md` и реализовать в парсере.

## 3. Семантика и модель выполнения — 20 баллов

Нужно описать и реализовать поведение программ: что именно происходит при запуске.

| Требование | Баллы |
|---|---:|
| Понятно, с чего начинается выполнение программы | 2 |
| Описан порядок выполнения инструкций | 2 |
| Есть модель значений: какие значения существуют во время выполнения | 2 |
| Есть правила вычисления выражений | 3 |
| Работают переменные: объявление, чтение, изменение значения | 3 |
| Есть окружения или другой механизм хранения переменных | 2 |
| Есть правила областей видимости | 3 |
| Есть обработка ошибок времени выполнения | 2 |
| Поведение языка описано в `SPEC.md`, а не только существует в коде | 1 |
| **Итого** | **20** |

Язык должен отвечать на вопросы:

- что такое программа;
- в каком порядке выполняются инструкции;
- что является значением;
- что происходит при присваивании;
- как ищется переменная;
- что происходит при ошибке.

### Что именно нужно реализовать

Недостаточно разобрать программу синтаксически. Нужно определить, что программа делает при запуске.

Например, для программы:

```text
let x = 1;
x = x + 2;
print(x);
```

ожидаемое поведение:

1. Создать переменную `x` со значением `1`.
2. Найти текущее значение `x`.
3. Прибавить `2`.
4. Записать новое значение `3` обратно в `x`.
5. Вывести `3`.

В реализации обычно появляется окружение, то есть структура данных, где хранятся переменные:

```text
environment = {
    "x": 3
}
```

Если в языке есть вложенные блоки, окружения могут быть вложенными:

```text
global:
  x = 10

block:
  y = 20
```

При обращении к переменной язык должен ясно определить, где ее искать: сначала в текущем блоке, затем во внешнем блоке, затем в глобальной области.

### Как это выглядит в других языках

В JavaScript переменная внутри блока может скрывать внешнюю:

```javascript
let x = 10;

if (true) {
  let x = 20;
  console.log(x); // 20
}

console.log(x); // 10
```

В Python область видимости блоков `if` устроена иначе:

```python
x = 10

if True:
    x = 20

print(x)  # 20
```

В вашем языке нужно явно выбрать и описать одно поведение. Оба варианта допустимы, если они реализованы последовательно.

### Что именно нужно реализовать

Нужно определить, какие значения могут существовать во время выполнения программы.

Минимальный набор:

```text

```

или:

```text
number
```

```text

string

```

Для каждого оператора нужно определить допустимые типы.

Пример правил:

```text

```

Например:


Возможные варианты:

1. Это ошибка типа.
2. Число автоматически превращается в строку.
3. Строка автоматически превращается в число, если это возможно.

Для учебного языка рекомендуется первый вариант: он проще, предсказуемее и легче проверяется.

## 5. Управляющие конструкции — 10 баллов

Нужно реализовать конструкции, которые управляют порядком выполнения программы.

| Требование | Баллы |
|---|---:|
| Есть условный оператор | 2 |
| Условный оператор поддерживает альтернативную ветку или описывает ее отсутствие | 1 |
| Есть цикл | 2 |
| Есть блоки кода | 2 |
| `break` и `continue` реализованы или явно описано, почему их нет | 1 |
| Управляющие конструкции корректно работают с областями видимости | 2 |
| **Итого** | **10** |

Минимальные конструкции:

```text
if condition {
    ...
} else {
    ...
}

while condition {
    ...
}
```

Синтаксис может быть другим.

### Что именно нужно реализовать

Условный оператор должен выбирать, какой блок выполнить.

Пример:

```text
let temperature = 20;

if (temperature > 0) {
    print("warm");
} else {
    print("cold");
}
```

Ожидаемое поведение: если условие истинно, выполняется первый блок; иначе выполняется блок `else`.

Цикл должен повторять блок, пока условие истинно.

Пример:

```text
let i = 0;

while (i < 3) {
    print(i);
    i = i + 1;
}
```

Ожидаемый вывод:

```text
0
1
2
```

Блоки кода должны определять группу инструкций. Вам нужно решить, создают ли блоки новую область видимости.

Пример вопроса, который должен быть описан в `SPEC.md`:

```text
if (true) {
    let x = 10;
}

print(x); // ошибка или 10?
```

### Как это выглядит в других языках

JavaScript с `let` создает блочную область видимости:

```javascript
if (true) {
  let x = 10;
}

console.log(x); // ReferenceError
```

Python не создает отдельную область видимости для `if`:

```python
if True:
    x = 10

print(x)  # 10
```

Оба варианта допустимы. Важно, чтобы ваш язык вел себя последовательно.

## 6. Функции и области видимости — 10 баллов

Нужно реализовать механизм объявления и вызова функций.

| Требование | Баллы |
|---|---:|
| Есть объявление функций | 2 |
| Есть параметры функций | 1 |
| Есть вызов функций с аргументами | 1 |
| Есть возвращаемое значение | 2 |
| Есть локальные переменные внутри функций | 1 |
| Функции корректно взаимодействуют с областями видимости | 1 |
| Работает рекурсия или в документации объяснено, почему она не поддерживается | 1 |
| Ошибки вызова функций обрабатываются понятно: неизвестная функция, неверное число аргументов | 1 |
| **Итого** | **10** |

Пример программы:

```text
fn add(a, b) {
    return a + b;
}

print(add(2, 3));
```

### Что именно нужно реализовать

Функция - это именованный блок кода, который можно вызвать несколько раз.

Минимальная функция должна уметь:

- принимать параметры;
- иметь локальные переменные;
- возвращать значение;
- вызываться из других частей программы.

Пример:

```text
fn square(x) {
    return x * x;
}

print(square(5));
```

Ожидаемый вывод:

```text
25
```

При вызове функции нужно создать новую область видимости для параметров и локальных переменных:

```text
fn test(a) {
    let b = 2;
    return a + b;
}
```

Во время вызова `test(10)` внутри функции должны быть доступны:

```text
a = 10
b = 2
```

После завершения функции локальная переменная `b` обычно исчезает.

Нужно также определить поведение при ошибках:

```text
add(1);        // неверное число аргументов
unknown(1, 2); // неизвестная функция
```

### Рекурсия

Если функция может вызывать саму себя, язык поддерживает рекурсию.

Пример:

```text
fn factorial(n) {
    if (n <= 1) {
        return 1;
    }

    return n * factorial(n - 1);
}

print(factorial(5));
```

Ожидаемый вывод:

```text
120
```

Рекурсию можно не поддерживать, но тогда это нужно явно написать в `SPEC.md` и объяснить причину.

### Как это выглядит в других языках

JavaScript:

```javascript
function add(a, b) {
  return a + b;
}

console.log(add(2, 3));
```

Python:

```python
def add(a, b):
    return a + b

print(add(2, 3))
```

Ваш синтаксис может быть другим, но должны быть понятны объявление, параметры, вызов и возврат значения.

## 7. Ошибки и диагностика — 10 баллов

### Что именно нужно реализовать

Обычный пользователь языка не должен видеть внутренние ошибки вашей реализации. Если программа на вашем языке написана неправильно, интерпретатор или компилятор должен показать понятную ошибку.

Нужно обрабатывать минимум четыре типа ошибок.

Синтаксическая ошибка:

```text
let x = ;
```

Возможное сообщение:

```text
Error at line 1, column 9:
Expected expression after '='.
```

Неизвестная переменная:

```text
print(total);
```

Возможное сообщение:

```text
Error at line 1, column 7:
Unknown variable 'total'.
```

Ошибка типа:

```text
print(1 + true);
```

Возможное сообщение:

```text
Error at line 1, column 9:
Operator '+' cannot be applied to number and boolean.
```

Ошибка времени выполнения:

```text
print(10 / 0);
```

Возможное сообщение:

```text
Error at line 1, column 10:
Division by zero.
```

Хорошая диагностика должна помогать исправить программу. Минимум - строка и описание ошибки. Лучше - строка, колонка и фрагмент кода.

### Как это выглядит в других языках

Python показывает тип ошибки, строку и фрагмент программы:

```python
print(unknown_name)
```

Примерный результат:

```text
NameError: name 'unknown_name' is not defined
```

JavaScript:

```javascript
console.log(unknownName);
```

Примерный результат:

```text
ReferenceError: unknownName is not defined
```

В вашем языке сообщения могут быть проще, но они должны быть предназначены для пользователя языка, а не для автора интерпретатора.

Рекомендуемая структура:

```text

```

Структура может быть другой, если она логична и описана в `README.md`.

### Что именно нужно реализовать

Проект должен принимать файл с программой на вашем языке и выполнять или компилировать его.

Пример ожидаемого запуска:

```bash
your-language examples/hello.lang
```

или:

```bash
python src/main.py examples/hello.lang
```

или:

```bash
npm start examples/hello.lang
```

Главное, чтобы команда была описана в `README.md` и реально работала.

Типичный путь выполнения интерпретатора:

```text
source code
  -> lexer
  -> tokens
  -> parser
  -> AST
  -> interpreter
  -> output
```

Типичный путь выполнения компилятора:

```text
source code
  -> lexer
  -> tokens
  -> parser
  -> AST
  -> code generator
  -> target code / bytecode
  -> run target code / bytecode
```

Для учебного проекта проще всего делать интерпретатор.

### Минимальные компоненты реализации

Лексер:

```text
input:  "let x = 1;"
output: [LET, IDENT(x), EQUAL, NUMBER(1), SEMICOLON, EOF]
```

Парсер:

```text
input:  [LET, IDENT(x), EQUAL, NUMBER(1), SEMICOLON, EOF]
output: VarDeclaration(name="x", value=NumberLiteral(1))
```

Интерпретатор:

```text
input:  VarDeclaration(name="x", value=NumberLiteral(1))
effect: creates variable x with value 1
```

Обработка ошибок:

```text
input:  "let x = ;"
output: user-friendly syntax error
```

### Что можно не делать

Не нужно реализовывать промышленный язык программирования. Необязательны:

- оптимизации;
- сложный сборщик мусора;
- полноценная стандартная библиотека;
- IDE;
- отладчик;
- компиляция в машинный код.

Эти возможности могут быть бонусами, но базовая оценка зависит от того, насколько хорошо работает ядро языка.
