# Требования к продукту Ladix

## Цель продукта

Ladix — это работающий язык программирования: на нём можно писать и запускать программы. У языка есть описание, реализация, примеры программ и тесты.

Ценность языка — в его понятности, цельности, надёжности работы и качестве описания, а не в объёме возможностей.

## Охват требований

## 1. Концепция языка и область применения

Раздел определяет, какой это язык, зачем он нужен и какие идеи лежат в его основе.

Требования:

- У языка есть название и краткое описание.
- Описана область применения языка.
- Объяснены ключевые идеи языка.
- Синтаксис и возможности языка соответствуют заявленной идее.
- Язык выглядит цельным, а не случайным набором возможностей.
- Есть 1-2 коротких примера типичных программ.

Пример удачной концепции: язык для обучения алгоритмам, язык для сценариев, минималистичный функциональный язык, язык для работы с таблицами, предметно-ориентированный русскоязычный язык.

Неудачный вариант: "как Python, только немного другой", без объяснения отличий и целей.

### Что именно описано

В начале `README.md` и `SPEC.md` коротко объяснена идея языка. Это не рекламный текст, а техническое описание: для каких задач язык подходит, какие конструкции в нём главные и почему он устроен именно так.

Пример описания:

```text
MiniCalc - компактный язык для простых вычислений и алгоритмов.
В языке есть переменные, числа, условия, циклы и функции.
Синтаксис похож на JavaScript, но без объектов, классов и асинхронности.
Главная цель языка - быть простым для чтения и реализации.
```

Также приведены 1-2 коротких примера программ, чтобы сразу был понятен стиль языка.

Пример:

```text
let radius = 10;
let area = 3.14 * radius * radius;
print(area);
```

### Как это выглядит в других языках

Python часто выбирают для читаемости:

```python
radius = 10
area = 3.14 * radius * radius
print(area)
```

JavaScript часто выбирают как пример C-подобного синтаксиса:

```javascript
let radius = 10;
let area = 3.14 * radius * radius;
console.log(area);
```

Ladix не обязан быть похож на Python или JavaScript. Но стиль языка выбран осознанно: скобки или отступы, явные точки с запятой или перевод строки, английские или русские ключевые слова, строгая или свободная типизация.

## 2. Лексика, синтаксис и грамматика

Раздел описывает и реализует правила записи программ на языке.

Требования:

- Есть идентификаторы.
- Есть числовые литералы.
- Есть строковые или булевы литералы.
- Есть операторы и ключевые слова.
- Есть комментарии.
- Описаны правила токенизации: пробелы, переводы строк, неизвестные символы.
- Есть грамматика языка в BNF/EBNF или похожем формате.
- Синтаксис однозначный: понятно, как разбираются вложенные выражения и конструкции.
- Реализован парсер, который строит AST или другую внутреннюю структуру.
- Синтаксические ошибки обрабатываются без падения реализации.

Минимальный пример грамматики:

```ebnf
program     = statement* ;
statement   = var_decl | assignment | if_stmt | while_stmt | func_decl | return_stmt | expr_stmt ;
var_decl    = "let" IDENT "=" expression ";" ;
assignment  = IDENT "=" expression ";" ;
if_stmt     = "if" "(" expression ")" block ("else" block)? ;
while_stmt  = "while" "(" expression ")" block ;
func_decl   = "fn" IDENT "(" parameters? ")" block ;
return_stmt = "return" expression? ";" ;
block       = "{" statement* "}" ;
expression  = equality ;
```

Синтаксис языка может быть другим. Важно, чтобы грамматика соответствовала реализации.

### Что именно реализовано

Лексер преобразует исходный текст программы в поток токенов. Токен - это отдельная значимая часть программы: число, имя переменной, оператор, скобка, ключевое слово.

Например, программа:

```text
let x = 10 + 20;
```

может быть превращена в такие токены:

```text
LET("let")
IDENT("x")
EQUAL("=")
NUMBER("10")
PLUS("+")
NUMBER("20")
SEMICOLON(";")
EOF
```

После лексера работает парсер. Парсер проверяет, что токены образуют корректную программу, и строит внутреннее представление программы, например AST.

Пример AST для выражения:

```text
2 + 3 * 4
```

может выглядеть так:

```text
BinaryExpression(
    operator="+",
    left=NumberLiteral(2),
    right=BinaryExpression(
        operator="*",
        left=NumberLiteral(3),
        right=NumberLiteral(4)
    )
)
```

Это важно, потому что выражение `2 + 3 * 4` должно вычисляться как `2 + (3 * 4)`, а не как `(2 + 3) * 4`.

### Как это выглядит в других языках

В JavaScript:

```javascript
let x = 10 + 20;
console.log(x);
```

В Python:

```python
x = 10 + 20
print(x)
```

В Ladix это может выглядеть, например, так:

```text
let x = 10 + 20;
print(x);
```

Синтаксис может быть другим, но он явно описан в `SPEC.md` и реализован в парсере.

## 3. Семантика и модель выполнения

Раздел описывает и реализует поведение программ: что именно происходит при запуске.

Требования:

- Понятно, с чего начинается выполнение программы.
- Описан порядок выполнения инструкций.
- Есть модель значений: какие значения существуют во время выполнения.
- Есть правила вычисления выражений.
- Работают переменные: объявление, чтение, изменение значения.
- Есть окружения или другой механизм хранения переменных.
- Есть правила областей видимости.
- Есть обработка ошибок времени выполнения.
- Поведение языка описано в `SPEC.md`, а не только существует в коде.

Язык отвечает на вопросы:

- что такое программа;
- в каком порядке выполняются инструкции;
- что является значением;
- что происходит при присваивании;
- как ищется переменная;
- что происходит при ошибке.

### Что именно реализовано

Недостаточно разобрать программу синтаксически. Определено, что программа делает при запуске.

Например, для программы:

```text
let x = 1;
x = x + 2;
print(x);
```

ожидаемое поведение:

1. Создать переменную `x` со значением `1`.
2. Найти текущее значение `x`.
3. Прибавить `2`.
4. Записать новое значение `3` обратно в `x`.
5. Вывести `3`.

В реализации обычно появляется окружение, то есть структура данных, где хранятся переменные:

```text
environment = {
    "x": 3
}
```

Если в языке есть вложенные блоки, окружения могут быть вложенными:

```text
global:
  x = 10

block:
  y = 20
```

При обращении к переменной язык ясно определяет, где её искать: сначала в текущем блоке, затем во внешнем блоке, затем в глобальной области.

### Как это выглядит в других языках

В JavaScript переменная внутри блока может скрывать внешнюю:

```javascript
let x = 10;

if (true) {
  let x = 20;
  console.log(x); // 20
}

console.log(x); // 10
```

В Python область видимости блоков `if` устроена иначе:

```python
x = 10

if True:
    x = 20

print(x)  # 20
```

В Ladix одно поведение выбрано и описано явно. Оба варианта допустимы, если они реализованы последовательно.

## 4. Система типов и значения

Раздел определяет, какие типы данных есть в языке и какие операции с ними допустимы.

Требования:

- Есть минимум два базовых типа данных.
- Поддерживаются числа.
- Поддерживаются строки или булевы значения.
- Описано, является ли типизация статической или динамической.
- Описаны правила операций над типами.
- Ошибки типов обнаруживаются и показываются пользователю.
- Поведение типов описано в `SPEC.md`.

Примеры вопросов, на которые отвечает спецификация:

```text
1 + 2        // можно?
1 + "abc"    // можно?
"abc" * 3    // можно?
if 10 { }    // число считается true или это ошибка?
```

### Что именно реализовано

Определено, какие значения могут существовать во время выполнения программы.

Минимальный набор:

```text
number
boolean
```

или:

```text
number
string
```

Лучше поддержать все три:

```text
number
string
boolean
```

Для каждого оператора определены допустимые типы.

Пример правил:

```text
number + number -> number
string + string -> string
number < number -> boolean
boolean and boolean -> boolean
```

Также определено, что происходит при ошибке типа.

Например:

```text
print(1 + "hello");
```

Возможные варианты:

1. Это ошибка типа.
2. Число автоматически превращается в строку.
3. Строка автоматически превращается в число, если это возможно.

В Ladix выбран первый вариант: он проще, предсказуемее и легче проверяется.

### Как это выглядит в других языках

JavaScript делает много неявных преобразований:

```javascript
console.log(1 + "2"); // "12"
console.log("5" - 2); // 3
```

Python чаще выдает ошибку:

```python
print(1 + "2")
# TypeError
```

В Ladix поведение выбрано и описано в `SPEC.md`.

## 5. Управляющие конструкции

Раздел реализует конструкции, которые управляют порядком выполнения программы.

Требования:

- Есть условный оператор.
- Условный оператор поддерживает альтернативную ветку или описывает её отсутствие.
- Есть цикл.
- Есть блоки кода.
- `break` и `continue` реализованы или явно описано, почему их нет.
- Управляющие конструкции корректно работают с областями видимости.

Минимальные конструкции:

```text
if condition {
    ...
} else {
    ...
}

while condition {
    ...
}
```

Синтаксис может быть другим.

### Что именно реализовано

Условный оператор выбирает, какой блок выполнить.

Пример:

```text
let temperature = 20;

if (temperature > 0) {
    print("warm");
} else {
    print("cold");
}
```

Ожидаемое поведение: если условие истинно, выполняется первый блок; иначе выполняется блок `else`.

Цикл должен повторять блок, пока условие истинно.

Пример:

```text
let i = 0;

while (i < 3) {
    print(i);
    i = i + 1;
}
```

Ожидаемый вывод:

```text
0
1
2
```

Блоки кода определяют группу инструкций. Решено, создают ли блоки новую область видимости.

Пример вопроса, который описан в `SPEC.md`:

```text
if (true) {
    let x = 10;
}

print(x); // ошибка или 10?
```

### Как это выглядит в других языках

JavaScript с `let` создает блочную область видимости:

```javascript
if (true) {
  let x = 10;
}

console.log(x); // ReferenceError
```

Python не создает отдельную область видимости для `if`:

```python
if True:
    x = 10

print(x)  # 10
```

Оба варианта допустимы. Важно, чтобы язык вёл себя последовательно.

## 6. Функции и области видимости

Раздел реализует механизм объявления и вызова функций.

Требования:

- Есть объявление функций.
- Есть параметры функций.
- Есть вызов функций с аргументами.
- Есть возвращаемое значение.
- Есть локальные переменные внутри функций.
- Функции корректно взаимодействуют с областями видимости.
- Работает рекурсия или в документации объяснено, почему она не поддерживается.
- Ошибки вызова функций обрабатываются понятно: неизвестная функция, неверное число аргументов.

Пример программы:

```text
fn add(a, b) {
    return a + b;
}

print(add(2, 3));
```

### Что именно реализовано

Функция - это именованный блок кода, который можно вызвать несколько раз.

Минимальная функция умеет:

- принимать параметры;
- иметь локальные переменные;
- возвращать значение;
- вызываться из других частей программы.

Пример:

```text
fn square(x) {
    return x * x;
}

print(square(5));
```

Ожидаемый вывод:

```text
25
```

При вызове функции создаётся новая область видимости для параметров и локальных переменных:

```text
fn test(a) {
    let b = 2;
    return a + b;
}
```

Во время вызова `test(10)` внутри функции доступны:

```text
a = 10
b = 2
```

После завершения функции локальная переменная `b` обычно исчезает.

Также определено поведение при ошибках:

```text
add(1);        // неверное число аргументов
unknown(1, 2); // неизвестная функция
```

### Рекурсия

Если функция может вызывать саму себя, язык поддерживает рекурсию.

Пример:

```text
fn factorial(n) {
    if (n <= 1) {
        return 1;
    }

    return n * factorial(n - 1);
}

print(factorial(5));
```

Ожидаемый вывод:

```text
120
```

Рекурсию можно не поддерживать, но тогда это явно указано в `SPEC.md` с объяснением причины.

### Как это выглядит в других языках

JavaScript:

```javascript
function add(a, b) {
  return a + b;
}

console.log(add(2, 3));
```

Python:

```python
def add(a, b):
    return a + b

print(add(2, 3))
```

Синтаксис может быть другим, но объявление, параметры, вызов и возврат значения понятны.

## 7. Ошибки и диагностика

Раздел обеспечивает, чтобы пользователь языка понимал, что пошло не так.

Требования:

- Ошибки содержат номер строки.
- Желательно содержат позицию в строке или фрагмент исходного кода.
- Синтаксические ошибки понятны пользователю.
- Ошибки типов понятны пользователю.
- Ошибки неизвестных переменных понятны пользователю.
- Ошибки времени выполнения понятны пользователю.
- Интерпретатор/компилятор не падает внутренним stack trace для обычных ошибок пользователя.

Пример хорошей ошибки:

```text
Error at line 4:
Unknown variable 'countt'
```

Пример плохой ошибки:

```text
NullPointerException
```

### Что именно реализовано

Обычный пользователь языка не видит внутренние ошибки реализации. Если программа на языке написана неправильно, интерпретатор или компилятор показывает понятную ошибку.

Обрабатывается минимум четыре типа ошибок.

Синтаксическая ошибка:

```text
let x = ;
```

Возможное сообщение:

```text
Error at line 1, column 9:
Expected expression after '='.
```

Неизвестная переменная:

```text
print(total);
```

Возможное сообщение:

```text
Error at line 1, column 7:
Unknown variable 'total'.
```

Ошибка типа:

```text
print(1 + true);
```

Возможное сообщение:

```text
Error at line 1, column 9:
Operator '+' cannot be applied to number and boolean.
```

Ошибка времени выполнения:

```text
print(10 / 0);
```

Возможное сообщение:

```text
Error at line 1, column 10:
Division by zero.
```

Хорошая диагностика должна помогать исправить программу. Минимум - строка и описание ошибки. Лучше - строка, колонка и фрагмент кода.

### Как это выглядит в других языках

Python показывает тип ошибки, строку и фрагмент программы:

```python
print(unknown_name)
```

Примерный результат:

```text
NameError: name 'unknown_name' is not defined
```

JavaScript:

```javascript
console.log(unknownName);
```

Примерный результат:

```text
ReferenceError: unknownName is not defined
```

В Ladix сообщения могут быть проще, но они предназначены для пользователя языка, а не для автора интерпретатора.

## 8. Реализация интерпретатора или компилятора

Раздел реализует язык как работающую программу.

Требования:

- Есть лексер.
- Есть парсер.
- Есть AST или другая внутренняя структура программы.
- Есть интерпретатор, компилятор или транслятор.
- Код структурирован, читаем и разделён на логические части.
- Проект можно запустить по инструкции из `README.md`.

Рекомендуемая структура:

```text
src/
  lexer
  parser
  ast
  interpreter или compiler
  runtime
  errors
```

Структура может быть другой, если она логична и описана в `README.md`.

### Что именно реализовано

Проект принимает файл с программой на языке и выполняет или компилирует его.

Пример ожидаемого запуска:

```bash
your-language examples/hello.lang
```

или:

```bash
python src/main.py examples/hello.lang
```

или:

```bash
npm start examples/hello.lang
```

Команда описана в `README.md` и реально работает.

Типичный путь выполнения интерпретатора:

```text
source code
  -> lexer
  -> tokens
  -> parser
  -> AST
  -> interpreter
  -> output
```

Типичный путь выполнения компилятора:

```text
source code
  -> lexer
  -> tokens
  -> parser
  -> AST
  -> code generator
  -> target code / bytecode
  -> run target code / bytecode
```

Ladix реализован как интерпретатор.

### Минимальные компоненты реализации

Лексер:

```text
input:  "let x = 1;"
output: [LET, IDENT(x), EQUAL, NUMBER(1), SEMICOLON, EOF]
```

Парсер:

```text
input:  [LET, IDENT(x), EQUAL, NUMBER(1), SEMICOLON, EOF]
output: VarDeclaration(name="x", value=NumberLiteral(1))
```

Интерпретатор:

```text
input:  VarDeclaration(name="x", value=NumberLiteral(1))
effect: creates variable x with value 1
```

Обработка ошибок:

```text
input:  "let x = ;"
output: user-friendly syntax error
```

### Границы версии

Версия 1 не ставит целью промышленный язык программирования. Вне скоупа:

- оптимизации;
- сложный сборщик мусора;
- полноценная стандартная библиотека;
- IDE;
- отладчик;
- компиляция в машинный код.

Эти возможности относятся к дальнейшему развитию; основа продукта — надёжно работающее ядро языка.
