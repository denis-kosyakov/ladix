# Ladix — заметки для агентов

**Ladix** — декларативно-императивный DSL для системы управления бизнесом «Уклад»: метрики и KPI, бизнес-процессы с человеком-в-цикле и триггеры, связывающие их. Это не язык общего назначения. Полное описание идеи и контракт CLI — в [README.md](README.md); язык — в [SPEC.md](SPEC.md).

> Этот файл — onboarding для AI-агентов и контрибьюторов, работающих в репозитории. Он описывает фактическое состояние, раскладку и команды, а **не** ставит задачу «реализовать язык» (язык уже отгружен).

## Статус

Версия **v2 финализирована** и принята. Реализованы: ядро языка (v1), аналитика (M1: коннекторы источников + оконные метрики), диагностика авторинга (M-DX), автоматизация (M2: внешний запуск/inspect/payload/эскалация/HTTP-вебхуки), надёжность (M3: outbox exactly-once, миграции схемы, единые часы CLI, объяснение срабатывания триггеров). Дальнейшее развитие — аддитивно, не ломая синтаксис пользователя.

## Раскладка

```text
.
├── README.md          # концепция + полный контракт CLI (основной справочник)
├── SPEC.md            # спецификация языка (лексика, грамматика, типы, семантика, ошибки)
├── CHECKLIST.md       # функциональный чек-лист (закрыт «внутри» Ladix)
├── TASK.md            # исходное ТЗ
├── ARCHITECTURE.md    # модули реализации, их ответственность и зависимости
├── docs/              # модель-доки (eval/engine/trigger/source/window/automation/reliability…) + grammar/stdlib/quickstart
├── examples/          # программы на .ladix (ядро языка + бизнес-витрины + ошибочные) + MANIFEST.md
├── specs/             # SpecKit-артефакты по фичам (001–029): spec/plan/tasks
├── tests/             # честная заглушка-отсылка (тесты живут рядом с кодом)
├── go.mod  go.sum     # Go-модуль github.com/denis-kosyakov/ladix — В КОРНЕ репозитория
├── ladix.go  ir/      # ПУБЛИЧНАЯ поверхность библиотеки: фасад Compile/CompileFile + контракт IR
├── cmd/ladix/         # CLI (reference-implementation)
└── internal/          # ВНУТРЕННИЕ пакеты: {lexer,parser,ast,value,errors,eval,engine,store,daemon,jsonval}
```

Go-модуль лежит **в корне репозитория** — все команды сборки/тестов выполняются **из корня**
(`go get github.com/denis-kosyakov/ladix` работает; фича 029). Публичная поверхность —
РОВНО два пакета: корневой `ladix` (фасад) и `ir` (версионируемый контракт вывода); всё
остальное под `internal/` и частью semver-контракта НЕ является.

## Команды

```sh
# сборка статического бинарника в корень репозитория (без CGO)
go build -o ladix ./cmd/ladix

# тесты и статический анализ
go test ./...
go vet ./...

# запуск программы (из корня — там бинарник и examples/, на которые ссылаются примеры)
./ladix run examples/hello.ladix
```

Подкоманды CLI: `run`, `metric`, `start`, `complete`, `tasks`, `serve`, `emit`, `inspect`. Полный контракт флагов и кодов возврата — в README.md.

## Конвенции

- **Реализация — Go**, идиоматичный: `gofmt`, `errors.Is`/`errors.As`, явные error-типы с позицией, без глобального состояния и беспричинных паник. Без CGO (чистый Go, `modernc.org/sqlite`).
- **Парсер** — ручной recursive descent.
- **Продуктовая документация — русская** (README/SPEC/CHECKLIST/examples/docs); английский — только в Go-коде и комментариях.
- **Spec-driven**: спецификация (SPEC.md + `docs/*-model.md`) — источник истины; код — производное. Изменения проходят через SpecKit-артефакты в `specs/NNN/` (см. `.specify/`).
- Расширение файлов программ — `.ladix`.
