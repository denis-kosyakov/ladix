## §SM-0. Граница фичи 004

**Входит в 004:**

1. **Парсер декларатива (только `источник`/`метрика`).** Снятие запрета на `KW_SOURCE`/`KW_METRIC`,
   новые AST-узлы `SourceDecl`/`MetricDecl`, разбор блоков атрибутов.
2. **Семантический проход** по `источник`/`метрика`: регистрация, валидация атрибутов.
3. **Конструируемые типы:** `Дата` (порядок `Compare`), `Период` (5 предопределённых значений),
   `Запись` (порождается загрузчиком источника; механизм в `value/` уже готов).
4. **Встроенные функции:** `дата(...)`, `сегодня()` (минимум для оси времени). Активируются из
   списка deferred (`builtins.go`).
5. **Инъекция времени (`Clock`)** — детерминизм метрик с `период:`.
6. **Движок метрики:** ленивая загрузка источника (JSON→`Запись`), конвейер
   `окно→фильтр→агрегат` (§10.2), пустой результат (§10.5).
7. **CLI `ladix metric <файл> <имя>`.**
8. **Реестр ошибок нового слоя** (§SM-9) + golden-приёмка на фикс-дате (§SM-10).

**НЕ входит (отложено, остаётся отвергаемым/deferred):**

- `процесс`/`шаг`/`когда` — `KW_PROCESS`/`KW_WHEN`/`KW_VALUE` **по-прежнему** в
  `isUnexpectedTopLevel` → `ОшибкаРазбора «неожиданный токен '<kw>'»`. Поэтому
  `examples/выручка.ladix` (содержит `процесс` + `когда`) в 004 **ещё не парсится целиком** —
  как и обещано в `examples/MANIFEST.md` (исполняема с 006 + триггерами). Golden 004 берёт
  метрику из **метрик-онли** фикстуры (§SM-10), не из `выручка.ladix`.
- Пакеты `internal/engine`, `internal/store` (жизненный цикл процессов) — 005/006.
- Встроенные `длительность`, `в_секундах…в_днях`, `вчера`, `завтра` — остаются deferred;
  **арифметика `Дата ± Длительность`, `Дата − Дата`** в 004 **не нужна** (нет конструктора
  `Длительность`) и **не реализуется** — окна считаются календарной арифметикой над полями
  `Дата` напрямую (§SM-8).
- Авто-распознавание дат-строк, NDJSON/CSV, live-reload, таймзоны — v2 (`SPEC §12`).

## §SM-1. Разрешённые открытые вопросы (решения архитектора)

Эти развилки аудит пометил как «исполнитель додумает». Решены здесь — **обязательны к исполнению**.

| # | Вопрос | Решение |
|---|---|---|
| **D-1** | `метрика.источник:` — `Ident` или `Expression`? | **`Ident`-only, синтаксически.** Парсер в позиции `источник:` читает ровно один `IDENT` (`parseSourceRef`), не общее выражение. Это **синтаксис**, не семантика (имя не резолвится в парсере) → guardrail 7 не нарушен. Прочие атрибуты (`где`/`агрегат`/`период`/`по_дате`) — `Expression`. |
| **D-2** | Атрибуты — отдельные AST-узлы или поля? | **Типизированные поля** на `SourceDecl`/`MetricDecl` (nullable-указатели для опциональных) **плюс** позиция ключевого слова каждого присутствующего атрибута (для точной диагностики). См. §SM-2. |
| **D-3** | Где ловится дубликат/неизвестный атрибут? | **В парсере (структурно).** Набор имён атрибутов фиксирован грамматикой (`MetricAttr ::= (источник\|где\|агрегат\|период\|по_дате)`), поэтому неизвестное имя и повтор — `ОшибкаРазбора` (§SM-9.A). Это структура блока, не разрешение имён → guardrail 7 соблюдён. |
| **D-4** | Где ловится связка `период`↔`по_дате` и обязательность `источник`/`агрегат`? | **Семпроход** (стадия 3, §SM-4). Кросс-атрибутные и обязательность — `СемантическаяОшибка`. |
| **D-5** | Поля записи как идентификаторы. | **Eval-time.** `где`/`агрегат`/`по_дате` парсятся как обычные `Expression`; неопределённое имя трактуется как поле текущей записи **на исполнении** (после загрузки источника, когда известна схема §9.5). Парсер/семпроход их не резолвят. |
| **D-6** | Голое поле вне агрегата / вложенный агрегат. | **Eval-time** (§10.3), не парсер. Парсер принимает любой `Expression` в `агрегат:`; нарушение проекции ловит движок метрики при вычислении (§SM-8, §SM-9.C). |
| **D-7** | Детерминизм `сегодня()`. | **`Clock`-инъекция** (§SM-7). Интерпретатор/движок получает `Clock`; прямой `time.Now()` в `eval`/движке запрещён. В тестах — фикс-дата `2026-05-31`. |
| **D-8** | Имя метрики как значение (§10.6). | **Eval-time, через `Ident`.** Отдельного узла `MetricRef` нет: при вычислении `Ident`, не найденного среди переменных/функций/встроенных, движок проверяет реестр метрик и, найдя, **запускает пересчёт** (§SM-8). Цикл → ошибка (§SM-9.B-цикл). |
| **D-9** | `период:` — где вычисляется? | **Один раз, в глобальной области** (не per-record): `период:` даёт значение `Период` (обычно предопределённый идент `ежемесячно`). `где`/`по_дате`/проекции агрегата — per-record в scope полей. См. контексты §SM-8. |

## §SM-2. AST-контракт (пакет `internal/ast`)

Конвенции — как `specs/002-parser-ast/data-model.md`: встраиваемая `declBase{base{Position}}`,
`Pos()` = ведущий ключевой токен, имена типов английские, конструктор `NewXxxDecl(pos, …)`.
Оба узла реализуют маркеры `declNode()`/`topLevelItem()` (как `FunctionDecl`) → пополняют union
`Decl` (в scope B была одна `FunctionDecl`; теперь `FunctionDecl | SourceDecl | MetricDecl`).

### Узлы

| Узел | Поля | `Pos()` |
|---|---|---|
| `SourceDecl` | `Name Ident; File StringLit; FilePos Position` (атрибут `файл:`; `File` — строковый литерал пути, не `Expression`) | токен `источник` |
| `MetricDecl` | `Name Ident; Source Ident; Where Expression?; Aggregate Expression; Period Expression?; ByDate Expression?; Attrs MetricAttrPos` | токен `метрика` |
| `MetricAttrPos` | `SourcePos, WherePos, AggregatePos, PeriodPos, ByDatePos Position` (позиция ключевого слова каждого **присутствующего** атрибута; нулевая для отсутствующего) | — (вспомогательная, не `Node`) |

**Нотация:** `Expression?` — nullable (Go: указатель `Expression` или сам интерфейс с `nil`;
выбрать единообразно с тем, как 002 хранит `IfStmt.Else *ElseClause`). `Source Ident` —
**не** `Expression` (D-1). `Aggregate` — обязателен (не-nil после успешного парса). `Where`,
`Period`, `ByDate` — nil, если атрибут отсутствует.

**Конструкторы:**

```
func NewSourceDecl(pos Position, name Ident, file StringLit, filePos Position) *SourceDecl
func NewMetricDecl(pos Position, name Ident, source Ident,
                   where Expression, aggregate Expression,
                   period Expression, byDate Expression,
                   attrs MetricAttrPos) *MetricDecl
```

**Почему позиции атрибутов в отдельной структуре, а не узлы-атрибуты:** диагностика «дубликат
`где`» / «`период` без `по_дате`» должна указывать на строку конкретного атрибута, а не на
начало блока; при этом плодить узлы-обёртки `MetricAttr{name, value, pos}` избыточно — типизированные
поля проще для обхода в семпроходе и движке (D-2).

> **Граница 002.** `ProcessDecl`/`StepDecl`/`TriggerDecl` в 004 **не вводятся** — их ведущие
> токены остаются отвергаемыми парсером (§SM-3). Когда дойдёт до 005+, их AST добавится тем же
> способом; здесь они умышленно отсутствуют.

## §SM-3. Переход парсера (стадия 2)

**Что меняется в `isUnexpectedTopLevel` (`parser/parse_stmt.go`):** убрать из множества
отвергаемых **`KW_SOURCE` и `KW_METRIC`**. Остаются отвергаемыми (без изменений):
`KW_PROCESS`, `KW_WHEN`, `KW_VALUE`, `LBRACE`, `RBRACE`.

**Новые ветви в `parseTopLevelItem`:** при `KW_SOURCE` → `parseSourceDecl`, при `KW_METRIC` →
`parseMetricDecl`. Декларации допустимы **только на верхнем уровне** (как `функция`); внутри
блоков/функций ведущий `источник`/`метрика` — `ОшибкаРазбора` (та же, что для `функция` внутри
тела — переиспользовать существующую диагностику «вложенная декларация», если есть, иначе
SE-UNEXPECTED).

**`parseSourceDecl`:** `источник IDENT ':' NEWLINE INDENT SourceAttr+ DEDENT`. Единственный
допустимый атрибут — `файл: STRING NEWLINE`. Пустой блок (нет ни одного атрибута) → структурная
ошибка (как пустой блок в 002, переиспользовать). Атрибут не `файл` → §SM-9.A «неизвестный
атрибут». Повтор `файл` → §SM-9.A «дубликат».

**`parseMetricDecl`:** `метрика IDENT ':' NEWLINE INDENT MetricAttr+ DEDENT`. Каждый
`MetricAttr` — `attrName ':' value NEWLINE`, где:
- `attrName ∈ {источник, где, агрегат, период, по_дате}`; иное имя → §SM-9.A «неизвестный атрибут»;
- для `источник:` → `parseSourceRef` (ровно один `IDENT`; иной токен → `ОшибкаРазбора`
  «ожидается имя источника», §SM-9.A) — D-1;
- для прочих → `parseExpression` (полное выражение, приоритеты как в 002);
- повтор любого имени → §SM-9.A «дубликат атрибута».

Парсер заполняет позиции в `MetricAttrPos` по факту встреченных атрибутов. **Обязательность
(`источник`/`агрегат`) и связку `период↔по_дате` парсер НЕ проверяет** — это семпроход (D-4).

**Регрессы 002 (обновить):**
- `parser/examples_test.go::TestDeclarativeExamplesUnexpected` — кейс `выручка.ladix` сейчас
  ждёт `«неожиданный токен 'источник'»`. После 004 `источник`/`метрика` парсятся, но
  `выручка.ladix` **всё равно** падает позже — на `процесс`. Обновить ожидание кейса
  `выручка.ladix` на `«неожиданный токен 'процесс'»`; кейс `онбординг.ladix` (ведущий
  `процесс`) — без изменений.
- Добавить позитивные parse-тесты: метрик-онли фикстура (§SM-10) парсится с нулём ошибок.

## §SM-4. Семантический проход (стадия 3) — расширение `Analyze`

`Analyze(prog) error` (fail-fast, `eval-model.md §9`). Дополнения:

**Шаг 1 (регистрация) — добавить:** top-level `SourceDecl` → реестр источников; `MetricDecl` →
реестр метрик. Повтор имени **в общем глобальном пространстве** (источник/метрика/функция делят
его, как и в §6) → `«'<имя>' уже объявлено в строке N»` (переиспользовать существующий текст
для функций, обобщив; либо отдельные тексты — см. §SM-9.A). Имя источника/метрики не должно
сталкиваться со **встроенной функцией** или **предопределённым периодом** → §SM-9.A
«имя '<имя>' зарезервировано …» (ревью №1, C1-1). Проверка — здесь, на Шаге 1: после успешной
регистрации декларации сверять её имя с `i.builtins` (активные + deferred) и `value`-реестром
5 периодов; столкновение → `СемантическаяОшибка` в позиции ведущего токена `источник`/`метрика`.
Пользовательских функций (`функция`) это **не** касается — для них затенение встроенного остаётся
предупреждением (`SPEC §6.5`); жёсткий запрет только для не-первоклассных `источник`/`метрика`.

**Новый шаг 1b (валидация деклараций), статически разрешимое:**
- `SourceDecl`: атрибут `файл` присутствует (гарантирован парсером — `SourceAttr+` непуст и
  единственный вид — `файл`; формально проверять не требуется, но обязательность зафиксировать).
- `MetricDecl`: `источник` и `агрегат` присутствуют (иначе §SM-9.A); `период` присутствует
  **тогда и только тогда**, когда присутствует `по_дате` (иначе §SM-9.A pairing);
- `MetricDecl.Source`: имя ссылается на **зарегистрированный источник**; не найдено → §SM-9.A
  «источник не объявлен»; найдено, но это метрика/функция/переменная → §SM-9.A «не источник».

**Что НЕ делает семпроход (оставлено движку/рантайму, flow/data-зависимо):** разрешение полей
записи (схема известна после загрузки, §9.5), типы `где`/`по_дате`/проекций, голое поле вне
агрегата, вложенный агрегат, цикл зависимостей метрик. Всё это — §SM-8 (eval-time).

> **Источник не первоклассен (§9.1).** Если имя источника встречается как **выражение-значение**
> (в императиве, теле функции, аргументе) — это ловит eval (`Ident` резолвится в источник):
> §SM-9.B «источник нельзя использовать как значение». Аналогично функции (`eval-model §8.3`:
> `'имя' — функция, её нельзя использовать как значение`).

## §SM-5. Конструируемые типы

Go-представления уже заданы (`value/deferred.go`, `value/record.go`); `Equal`/`String(repr)`
реализованы (`value/equal.go`, `value/repr.go`). Единственная правка `repr` в 004 — **R1**:
`value/repr.go::formatFloat` чинит формат `Дробного` для бизнес-диапазона `|f| ∈ [1e-4, 1e16)`
(фиксированная запись вместо `'g'`), сохраняя инвариант `2175 → 2175.0` и фиксируя канонические
кейсы `1000000.0 → 1000000.0` и `1000000.5 → 1000000.5` (см. `eval-model §7`). 004 добавляет
**только** недостающее:

| Тип | Что добавить в 004 | Что НЕ трогаем |
|---|---|---|
| `Дата{Year,Month,Day}` | **`Compare`** (порядок): лексикографически по `(Year, Month, Day)`. Нужен для проверки окна `начало ≤ d ≤ конец` (§SM-8). Конструируется встроенной `дата()` и движком окон. | `repr` (ISO `YYYY-MM-DD`) — готов. Арифметика с `Длительность` — **не в 004**. |
| `Период{Name}` | **5 предопределённых значений** регистрируются в глобальной области интерпретатора при инициализации: `ежедневно`, `еженедельно`, `ежемесячно`, `ежеквартально`, `ежегодно` (read-only иденты, не ключевые слова; `grammar §6`). `Equal` по `Name` — готов; `Compare` — **не определён** (периоды не упорядочены; `Compare` возвращает `ok=false`). | `repr` (= `Name`) — готов. |
| `Запись{keys,fields}` | Порождается **загрузчиком источника** (§SM-8) через `value.NewRecord(keys, fields)`. Конструктор/`Get`/`Keys`/`repr` — готовы. Доступ к отсутствующему полю → `None` (готов). | Всё готово; нужен лишь вызывающий код (движок). |
| `Длительность` | **Ничего** (нет конструктора в 004; остаётся смоделированным). | — |

`Compare` для `Дата` встроить в существующую `value.Compare()` рядом с `Целое`/`Дробное`/`Строка`
(сравнения `<`, `<=`, `>`, `>=`, `==`, `!=` над двумя `Дата`). Сравнение `Дата` с не-`Дата` —
несравнимы (как сейчас для несовместимых типов): даёт `ОшибкаТипа` через существующий путь
`evalOrder`.

## §SM-6. Встроенные функции 004

Активировать из `deferredNames` (`builtins.go`) **ровно две** функции; остальные 7 дата/время и
3 процессных — остаются deferred.

### `сегодня() → Дата`

- Арность 0. Лишние аргументы → `«'сегодня' принимает 0 аргументов, передано M»` (форма §8.3).
- Возвращает текущую дату из **`Clock`** (§SM-7), **не** `time.Now()` напрямую. В пределах
  запуска фиксирована (§10.6, README run-заметки).

### `дата(...) → Дата | Пусто` (перегруженная)

| Форма | Поведение |
|---|---|
| `дата(s: Строка)` | разобрать `s` как `YYYY-MM-DD` (ISO-8601 date). Успех → `Дата{Y,M,D}`. Невалидно (формат/несуществующая дата) → §SM-9.C «не является датой». |
| `дата(п: Пусто)` | → `Пусто`. Это ключ к §10.4: запись без поля даты даёт `по_дате: дата(поле) → Пусто` → запись вне окна, **без ошибки**. |
| `дата(г: Целое, м: Целое, д: Целое)` | собрать дату; невалидный календарь (`м∉1..12`, `д` вне числа дней месяца) → §SM-9.C «некорректные год/месяц/день». |

- Иная арность (2, ≥4) или 1 аргумент не `Строка`/`Пусто` / 3 аргумента не `Целое` →
  `«'дата': неверное число аргументов»` (арность) либо §SM-9.C «ожидается …» (тип). Используем
  существующий механизм `overloaded` (как у текущих перегруженных встроенных).
- Разбор `YYYY-MM-DD`: ровно 10 символов, `\d{4}-\d{2}-\d{2}`, валидный календарь (учесть високосный
  год для февраля). Время/таймзона/`T…` — **не** в v1 (`SPEC §12`); строка с `T` → невалидна.

> **`stdlib.md` синк (выполнено T032).** Раздел «Дата и длительность» описывает `дата/сегодня`
> как **доступные** (правда для них двоих после 004). Описания `длительность/в_*/вчера/завтра`
> помечены **«v2 (deferred)»**. Тексты ошибок `дата` приведены к §SM-9.C дословно.

## §SM-7. Инъекция времени (`Clock`)

**Проблема (блокер детерминизма).** Метрика с `период:` считается относительно `сегодня()`;
прямой `time.Now()` сделал бы golden недетерминированным (май ≠ июнь).

**Контракт.**

```go
// пакет eval (или общий internal/clock)
type Clock interface{ Now() Дата }   // или Now() time.Time → усечь до Y/M/D
```

- Интерпретатор и движок метрики получают `Clock` при конструировании
  (`NewInterpreter(..., clock Clock)` / поле движка). `сегодня()` и вычисление окна периода
  читают **только** его.
- **Прод:** `SystemClock{}` → `time.Now()` в локальной зоне сервера, усечённая до даты (таймзоны —
  v2, `SPEC §12`; для v1 «сегодня» = календарная дата `time.Now()` в `time.Local`).
- **Тесты:** `FixedClock{Дата{2026,5,31}}`. Все golden-тесты метрик (§SM-10) инъектируют эту дату.
- `ladix run`/`ladix metric` в проде строят `SystemClock`; `сегодня()` фиксируется один раз на
  запуск (снять `Now()` в начале и переиспользовать, либо кешировать в интерпретаторе) — §10.6.

Запрет: ни один путь `eval`/движка не вызывает `time.Now()` напрямую — только через `Clock`
(аналогично тому, как вывод идёт только через инъектированный `out`, а не `os.Stdout`).

## §SM-8. Движок метрики (конвейер вычисления)

Реализует `SPEC §10.2` дословно. Чтение метрики `M` (из CLI `metric`, из императива по имени —
D-8, или из триггера в будущем) запускает конвейер. **Чистая функция** от данных источника и
`Clock.Now()`.

### Контексты вычисления атрибутов (D-9 — критично, было дырой)

| Атрибут | Когда вычисляется | В какой области | Ожидаемый тип |
|---|---|---|---|
| `источник` | не вычисляется | — (имя источника, D-1) | — |
| `период` | **один раз**, до записей | глобальная (предопр. периоды/глобали) | `Период` (иначе §SM-9.B) |
| `по_дате` | **на каждой записи** | scope полей (§6+§9.5) | `Дата` или `Пусто` (иначе §SM-9.C) |
| `где` | **на каждой записи** | scope полей | `Булево` (иначе §SM-9.C) |
| `агрегат` | один раз; аргументы агрегатных функций — проекции **на каждой записи** | агрегат-узлы: scope полей; вне их: глобаль/константы/др. метрики | скаляр |

### Шаги (§10.2)

1. **Загрузка источника** (§SM-8.1). Пустой источник (0 записей) → короткое замыкание на пустой
   результат (шаг 5, §10.5).
2. **Окно периода.** Если `период:` задан → вычислить `Период` (глобально); по нему и `D = Clock.Now()`
   построить `[начало, конец]` (включительно) календарной арифметикой (§SM-8.2). Если `период:`
   нет → окна нет (все записи проходят шаг фильтра по дате тривиально).
3. **Фильтрация записей** (в порядке записей источника). Для каждой записи в scope полей:
   1. если `период:` задан: вычислить `по_дате` → `d`. `d = Пусто` → **исключить** запись
      (без проверки `где`, без ошибки). `d` не `Дата` → §SM-9.C. Иначе оставить, если
      `начало ≤ d ≤ конец` (через `Дата.Compare`), иначе исключить.
   2. вычислить `где` (если задан) → должно быть `Булево` (иначе §SM-9.C); `ложь` → исключить.
      `где` отсутствует → считается `истина`.
4. **Агрегат** (§10.3). Вычислить выражение `агрегат`. Каждая агрегатная функция
   (`сумма/количество/среднее/мин/макс`) берёт **проекцию** — своё выражение-аргумент,
   вычисленное на каждой **выжившей** записи в scope полей, дающее список; проекция **пропускает
   записи, где она дала `Пусто`** (§10.3). Агрегаты уже реализованы — переиспользовать.
   - Голое поле (резолвится в поле) **вне** агрегатной функции → §SM-9.C.
   - Вложенный агрегат (`сумма(среднее(...))`) → §SM-9.C.
5. **Пустой результат** (§10.5). Если выживших записей нет: результат `Целое 0`, если корневой
   `агрегат` — единичный `сумма(...)`/`количество(...)`; иначе `Пусто` (единичные
   `среднее`/`мин`/`макс` и любые деривативные выражения). **Внимание:** в контексте метрики
   пустая проекция **не** даёт ошибку `«<имя>: список пуст»` (§8.3) — это правило §10.5
   перекрывает поведение функций общего назначения.

   > **Реализация (ревью №1, D4-1) — критично.** Решение принимается по **корню** AST-выражения
   > `агрегат:` **ДО** его вычисления, а **не** по отдельным агрегатам внутри. Если выживших нет:
   > проверить корневой узел `m.Aggregate` — это **единичный** `CallExpr` к `сумма`/`количество`?
   > Да → `Целое 0`. Нет (единичный `среднее`/`мин`/`макс` **ИЛИ** любое составное выражение, напр.
   > `сумма(сумма_заказа) / количество(запись)` — средний чек, §10.3) → вернуть `Пусто` **коротким
   > замыканием**, не спускаясь в арифметику. Иначе per-leaf замыкание `сумма`/`количество` → `0`
   > даёт `сумма(x)/количество(запись)` = `0/0` (ошибка «деление на ноль») и `сумма(x)+1` = `Целое 1`
   > вместо `Пусто` — ровно то, что §10.5 обещает не допускать («короткое замыкание до арифметики,
   > чтобы не ловить `0/0`»).

### §SM-8.1. Загрузчик источника

- **Путь:** `SourceDecl.File` относительно **cwd** процесса (§9.1), абсолютный — как есть.
- **Лень + кеш на запуск** (§9.6): файл читается при первом обращении любой метрики к источнику,
  результат кешируется до конца запуска (`run`/`metric`/один тик `serve`).
- **Разбор:** верхний уровень — JSON-массив объектов (§9.2). Не массив → §SM-9.B. Элемент не
  объект → §SM-9.B (с номером записи, **с 1**). Битый JSON → §SM-9.B (позиция/смещение от
  JSON-парсера).
- **Маппинг JSON→`Value`** (§9.3): `null→Пусто`, `bool→Булево`, строка→`Строка` (даты НЕ
  распознаются), число без `.`/`e`/`E`→`Целое` (вне int64 → §SM-9.B), число с `.`/экспонентой→
  `Дробное`, массив→`Список`, объект→`Запись` (рекурсивно). Различение целое/дробное — **по форме
  токена JSON** (нужен `json.Decoder` с `UseNumber()`, затем разбор `json.Number`: наличие
  `.`/`e`/`E` → `Дробное`, иначе `Целое`).
- **Запись:** `value.NewRecord(keys, fields)`. Порядок ключей в `repr` не нагружает метрики
  (записи не печатаются); сохранять текстовый порядок через потоковый разбор не обязательно для
  004 — допустим любой устойчивый порядок.
- **Схема (§9.5):** объединение ключей по **всем** записям. В сообщении «неизвестное поле»
  список известных полей — **отсортированный по возрастанию** (детерминизм golden). Разрешение голого имени `x` в
  `где`/`агрегат`/`по_дате`: глобаль/функция/встроенное → как обычно; иначе известное поле схемы →
  значение записи (нет в данной записи → `Пусто`); иначе → §SM-9.C «неизвестное поле». Доступ
  `запись.поле` — толерантный (нет поля → `Пусто`, без проверки схемы). На **пустом** источнике
  схема пуста → опечатку поля поймать нельзя (§9.7) — осознанная цена.

### §SM-8.2. Календарные окна (§10.4, дословно, `D = Clock.Now()`)

Окно — **полный** календарный период, содержащий `D` (не усечён по `D`):

| `Период` | `[начало, конец]` (включительно) |
|---|---|
| `ежедневно` | `[D, D]` |
| `еженедельно` | ISO-8601 неделя пн–вс, содержащая `D` |
| `ежемесячно` | `[Дата(Y,M,1), Дата(Y,M,послед_день_месяца)]` |
| `ежеквартально` | квартал по `M`: Q1 `[1.янв,31.мар]`, Q2 `[1.апр,30.июн]`, Q3 `[1.июл,30.сен]`, Q4 `[1.окт,31.дек]` |
| `ежегодно` | `[Дата(Y,1,1), Дата(Y,12,31)]` |

- Послед. день месяца — с учётом високосного года (фев = 29 в високосный). Високосный по
  григорианскому правилу.
- ISO-неделя: понедельник — первый день. `начало = D − (ISO_номер_дня_недели(D) − 1)` дней,
  `конец = начало + 6` дней. Реализация: через `time.Time.Weekday()` Go (Mon=1…Sun=7 по ISO;
  Go `Weekday` Sun=0 — преобразовать) либо `time.Time.ISOWeek` + смещения. Окно может пересекать
  границу месяца — это нормально.
- Граница **включительна** с обеих сторон: запись с `по_дате = начало` или `= конец` — внутри.

> **Реализация дат-арифметики окон.** Считать границы можно через `time.Date(...)` (UTC) и обратно
> в `Дата{Y,M,D}` — это служебная Go-арифметика, не язык Ladix; `Длительность` Ladix тут ни при
> чём. Главное — результат-границы суть `Дата`, сравниваемые `Дата.Compare`.

## §SM-9. Реестр сообщений нового слоя (полезная нагрузка, дословно)

Соглашения §8.3: payload **без** завершающей точки; одинарные кавычки `'…'` — для
**идентификаторов/ключевых слов/имён атрибутов**; гильемы `«…»` — для **дословного строкового
значения** (формат/путь/значение даты); `<тип> ∈ {Целое,Дробное,Строка,Булево,Пусто,Длительность,
Период,Дата,Список,Запись}`; `N` нумеруется **с 1**. Позиция = строка/колонка, указанные в скобках.

### §SM-9.A. Семантика/структура деклараций (`ОшибкаРазбора` — парсер; `СемантическаяОшибка` — семпроход)

```
неизвестный атрибут '<имя>'                       // парсер, поз. имени атрибута
атрибут '<имя>' уже задан                         // парсер, поз. повторного атрибута
ожидается имя источника                           // парсер, источник: не IDENT (D-1)
'<имя>' уже объявлено в строке N                  // семпроход, повтор источник/метрика/функция
метрика '<имя>': отсутствует обязательный атрибут 'источник'   // семпроход, поз. метрика
метрика '<имя>': отсутствует обязательный атрибут 'агрегат'    // семпроход, поз. метрика
метрика '<имя>': 'период' требует 'по_дате'       // семпроход, поз. период
метрика '<имя>': 'по_дате' без 'период' не имеет смысла        // семпроход, поз. по_дате
метрика '<имя>': источник '<ист>' не объявлен     // семпроход, поз. источник:
метрика '<имя>': '<ист>' — не источник            // семпроход, поз. источник: (имя занято функцией/метрикой)
имя '<имя>' зарезервировано встроенной функцией    // семпроход, поз. источник/метрика (C1-1)
имя '<имя>' зарезервировано предопределённым периодом  // семпроход, поз. источник/метрика (C1-1)
```

### §SM-9.B. Загрузка источника и имя-как-значение (`ОшибкаВыполнения`, поз. объявления `источник`/`метрика` или `Ident`)

```
источник '<имя>': файл «<путь>» не найден
источник '<имя>': не удалось прочитать файл «<путь>»
источник '<имя>': ожидался JSON-массив объектов в «<путь>»
источник '<имя>': запись N не является объектом
источник '<имя>': некорректный JSON в «<путь>» (<деталь>)
источник '<имя>': запись N, поле '<поле>': целое число вне диапазона
'<имя>' — источник, его нельзя использовать как значение     // Ident резолвится в источник
'период' должно давать Период, получено <тип>                // период: не Период
цикл зависимостей метрик: <имя> → … → <имя>                  // D-8, чтение метрики по кругу
```

### §SM-9.C. Вычисление метрики и конструкторы дат (`ОшибкаВыполнения`/`ОшибкаТипа`, поз. подвыражения)

```
неизвестное поле '<имя>' (известные: <поле1>, <поле2>, …)    // голое имя ∉ схема/глобаль/функция
'по_дате' должно давать Дата или Пусто, получено <тип>
'где' должно давать Булево, получено <тип>
поле '<имя>' использовано вне агрегатной функции             // §10.3 голое поле
вложенный агрегат недопустим                                 // §10.3 сумма(среднее(...))
дата: «<значение>» не является датой                         // дата(Строка), формат ≠ YYYY-MM-DD
дата: некорректные год/месяц/день                            // дата(Целое,Целое,Целое)
дата: ожидается Строка или Пусто, получено <тип>             // дата(x), 1 арг неверного типа
```

### §SM-9.D. CLI `metric` (см. §SM-11)

```
неизвестная метрика '<имя>'                       // СемантическаяОшибка, exit 1
'<имя>' — не метрика                              // имя — переменная/функция/источник, exit 1
```

> **Расширение `eval-model.md §8.3`.** Перенести §SM-9.B/§SM-9.C-строки про конструкторы дат
> (`дата: …`) в реестр §8.3 (это слой `eval`), а декларативные (§SM-9.A) и движковые
> (источник/метрика) держать здесь — они принадлежат новому слою. Где удобно импл-чату —

## §SM-10. Golden-приёмка (фикс-дата `2026-05-31`, источник `data/sales.json`)

`data/sales.json` (3 записи, все май 2026): `[1 200 000 оплачен 05-03; 800 000 оплачен 05-17;
500 000 отменён 05-20]`. `FixedClock = 2026-05-31`.

**Метрик-онли фикстура** (для parse-теста и CLI-демо; БЕЗ `процесс`/`когда`, поэтому парсится в
004 целиком). Импл-чат кладёт её как тест-фикстуру (например `src/internal/eval/testdata/` или
`tests/`), НЕ в `examples/` (вывод дата-зависим):

```ladix
источник продажи:
    файл: "data/sales.json"

метрика выручка_месяца:
    источник: продажи
    где:      статус == "оплачен"
    агрегат:  сумма(сумма_заказа)
    период:   ежемесячно
    по_дате:  дата(дата_заказа)
```

**Таблица ожидаемых значений** (та же фикстура, варьируем один атрибут; все при `D=2026-05-31`):

| Метрика (вариант) | Окно | Выжило | Результат (тип, `строка()`) |
|---|---|---|---|
| `сумма(сумма_заказа)`, `где оплачен`, `ежемесячно` | `[05-01,05-31]` | 2 | `Целое 2000000` → `2000000` |
| то же, `ежеквартально` | `[04-01,06-30]` | 2 | `2000000` |
| то же, `ежегодно` | `[01-01,12-31]` | 2 | `2000000` |
| то же, `еженедельно` | `[05-25,05-31]` | 0 | `Целое 0` (пустое окно, §10.5) |
| то же, `ежедневно` | `[05-31,05-31]` | 0 | `Целое 0` |
| `сумма(сумма_заказа)`, `где оплачен`, **без периода** | все | 2 | `2000000` |
| `сумма(сумма_заказа)`, **без `где`**, `ежемесячно` | месяц | 3 | `2500000` |
| `количество(запись)`, `где оплачен`, `ежемесячно` | месяц | 2 | `Целое 2` |
| `среднее(сумма_заказа)`, `где оплачен`, `ежемесячно` | месяц | 2 | `Дробное 1000000.0` → `1000000.0` |
| `мин(сумма_заказа)`, `где оплачен`, `ежемесячно` | месяц | 2 | `Целое 800000` |
| `макс(сумма_заказа)`, `где оплачен`, `ежемесячно` | месяц | 2 | `Целое 1200000` |
| `среднее(сумма_заказа)`, `где оплачен`, `ежедневно` | `[05-31,05-31]` | 0 | `Пусто` → `пусто` (§10.5) |
| `сумма(сумма_заказа) / количество(запись)` (средний чек, деривативная), `где оплачен`, `ежедневно` | `[05-31,05-31]` | 0 | `Пусто` → `пусто` (§10.5, D4-1: НЕ `0/0`) |
| `сумма(сумма_заказа) + 1` (деривативная), `где оплачен`, `ежедневно` | `[05-31,05-31]` | 0 | `Пусто` → `пусто` (§10.5, D4-1: НЕ `Целое 1`) |

**Краевые parse/eval-кейсы для тестов ошибок (exact-match §SM-9):**
- `период: ежемесячно` без `по_дате:` → `«метрика '…': 'период' требует 'по_дате'»`.
- `источник: несуществующий` → `«метрика '…': источник 'несуществующий' не объявлен»`.
- метрика над источником с битым путём `файл: "нет.json"` → `«источник '…': файл «нет.json» не найден»`
  (поз. объявления источника).
- `где: статус` (поле `статус` — `Строка`, не `Булево`) → `«'где' должно давать Булево, получено Строка»`.
- `агрегат: сумма_заказа` (голое поле) → `«поле 'сумма_заказа' использовано вне агрегатной функции»`.
- `где: статус_опечатка == "x"` → `«неизвестное поле 'статус_опечатка' (известные: дата_заказа, клиент, статус, сумма_заказа)»` (поля отсортированы).
- `дата("2026-13-40")` → `«дата: «2026-13-40» не является датой»`.

## §SM-11. CLI `ladix metric <файл> <имя>`

Контракт уже описан в `README` (раздел `ladix metric`); здесь — точки реализации.

- **Диспетчер** (`cmd/ladix/main.go`): сейчас распознаётся только `run`. Ввести ветвление по
  `args[0]`: `run` (как есть), `metric`; прочие подкоманды (`serve`/`complete`/`tasks`/`emit`) —
  пока `«подкоманда '<x>' не поддерживается»`, exit 2 (или оставить как есть, если уже так).
- **Синтаксис:** `ladix metric путь.ladix имя_метрики [--max-depth N]`. Нет двух позиционных →
  ошибка использования, exit **2**.
- **Конвейер:** лексер → парсер → `Analyze` → вычислить указанную метрику → напечатать
  `value.String(результат)` в **stdout** + перевод строки. `Store` — `MemoryStore` безусловно
  (метрика не трогает инстансы), без `--db`.
- **Коды/ошибки:** неизвестная метрика / имя-не-метрика → §SM-9.D, exit **1**. Ошибки
  загрузки/вычисления → §SM-9.B/C в stderr, exit **1**. Recover-барьер — как у `run`
  (`eval-model §10.2`): штатные ошибки Ladix → код 1; Go-паника → «внутренняя ошибка
  интерпретатора» без стектрейса → код 1; ошибка использования → код 2.
- **`сегодня()`** в `metric` — `SystemClock` (прод), фиксируется на вызов.
