> **Назначение:** зафиксировать факты живого кода и предрешённые/финализируемые развилки A2 так, чтобы

## §MW-0 Граница фичи 011 (что A2 делает и не делает)

**Делает.** Снимает ограничения §12 SPEC для метрик (окна):
1. Скользящее окно `период: последние N <ед>` (`ед` ∈ `дн`/`нед`/`мес`) — окно `(сегодня − N ед, сегодня]` от `eval.Clock`.
2. «Последний завершённый период» `период: прошлый|прошлая <день|неделя|месяц|квартал|год>` — тот же календарный период, сдвинутый на −1.

**НЕ делает (вне A2, §MW-12):**
- **Метрика-как-РЯД (временной ряд значений) — ОТЛОЖЕНА (A2-1).** Меняет Value-модель и сравнение в триггере; не нужна золотому сценарию. Метрика остаётся **скаляром по окну**. Зафиксировано здесь и в спеке.
- Почасовые окна (`сек`/`мин`/`час`) — бессмысленны для оси-даты (A2-2).
- Мультиисточник на метрику, доп. агрегаты, ось не-дата, `ДатаВремя`/таймзоны — вне M1.

**Несущее свойство (инварианты хартии §5):** A2 — расширение фронтенда (парсер `период:`) + вычислителя окна (`window.go`/`value.Период`). `Store`/`ProcessRuntime`/экспорт `eval`/**условие триггера** не трогаются. Все программы v1 валидны (5 календарных периодов работают как раньше). Окно считается от `eval.Clock` (`i.now()`, заморожен на запуск), НЕ от `time.Now()` — детерминизм.

## §MW-2 Факты механизма периода (живой код — точки интеграции)

- **Лексер:** период-имена (`ежедневно`…`ежегодно`) — **НЕ ключевые слова**, лексятся как `IDENT` (`scan_ident.go:33`). `последние`/`прошлый`/`прошлая`/`день`/`неделя`/`месяц`/`квартал`/`год` — тоже `IDENT`. Литерал длительности `30дн` — **один токен `DURATION`** с `DurationValue{Amount string, Unit string}` (`scan_number.go`); единицы `сек/мин/час/дн/нед/мес` (`keywords.go durationUnits`). **Лексер НЕ трогается.**
- **Предрегистрация:** `value.PeriodNames` (`value/periods.go`) — 5 имён; `NewInterpreter` (`interpreter.go:77-79`) заводит каждое в global как read-only `value.Период{Name}`. Так `период: ежемесячно` (IDENT) резолвится `evalIdent`→`env.Lookup`→`value.Период`.
- **Парсер:** `parseMetricDecl` (`parse_decl.go:181-239`), ветка `período:` (строка ~226) сейчас зовёт **generic `parseExpression()`**. `последние 30дн` = `[IDENT("последние"), DURATION("30дн")]` — два соседних primary, generic parseExpression вернёт ОДИН узел (`Ident`) и оставит DURATION → парс-ошибка. **Нужен спец-парс ветки `период:`** (§MW-4).
- **value:** `Период{Name string}` (`deferred.go:27`). **Расширяется** (§MW-D-VALUE).
- **Окно:** `periodWindow(p value.Период, d value.Дата) (начало, конец value.Дата, ok bool)` (`window.go:17-52`) — switch на `p.Name`, INCLUSIVE `[начало,конец]`. Помощники `dateToTime`/`timeToDate`/`lastDayOfMonth`. **Расширяется** (§MW-D-WINDOW).
- **Вычисление метрики:** `evalMetric` (`metric_engine.go:45-60`): период вычисляется ОДИН раз глобально (`evalExpr(i.global, m.Period)`, recordCtx=nil), тип-чек `pv.(value.Период)` (:54), затем `periodWindow(per, i.now())` (:59). `i.now()` — заморожен (`interpreter.go:155-161`) от инжектированного `Clock`.
- **Фильтр записей:** `recordSurvives` (`metric_engine.go:108-153`): при `hasPeriod` — `по_дате` per-record→`value.Дата`; `Compare(d, winStart)<0` → reject, `Compare(d, winEnd)>0` → reject → **INCLUSIVE [winStart,winEnd]**. **НЕ трогается** (§MW-D-WINDOW делает окно инклюзивно-эквивалентным).
- **Валидация период↔по_дате:** `analyze.go:164-172` — «период требует по_дате» (presence `Attrs.PeriodPos.Line!=0`), «по_дате без период запрещён». Покрывает A2-4 автоматически.
- **Триггер:** `trigger_run.go:64` `evalMetricByName` — скаляр, без изменений (A2-7).
- **Golden:** `metric_engine_test.go:24` `FixedClock{2026,5,31}`; `период:ежемесячно`+`по_дате` на май-2026 → `[2026-05-01, 2026-05-31]`.

## §MW-3 value.Период — расширение (§MW-D-VALUE; конституция VII)

Расширяем `value.Период` **аддитивно** (пакет `value` остаётся листовым — без новых импортов; `Период` буквально моделирует период):

```go
type Период struct {
    Name   string  // "ежедневно".."ежегодно" (календарный) | "последние" (скользящий)
    Amount int64   // скользящий: N; иначе 0
    Unit   string  // скользящий: "дн"/"нед"/"мес"; иначе ""
    Offset int     // «последний завершённый»: -1 к календарному Name; иначе 0
}
```

- 5 календарных констант (`PeriodNames`) → `{Name:X, Amount:0, Unit:"", Offset:0}` (нулевые поля — обр. совместимость, регистрация в `interpreter.go:77-79` не меняется).
- `последние N <ед>` → `{Name:"последние", Amount:N, Unit:ед, Offset:0}`.
- `прошлый <noun>` → `{Name:<базовый адверб>, Amount:0, Unit:"", Offset:-1}`.
- **§MW-D-VALUE-EQ (верифицировано — точечные правки `value`).** Затрагиваются ровно 3 файла пакета `value`:
  - `deferred.go:27` — расширить структуру (выше).
  - `equal.go:71-73` — `case Период` сравнивает только `Name`; обновить на ВСЕ поля: `ok && x.Name==y.Name && x.Amount==y.Amount && x.Unit==y.Unit && x.Offset==y.Offset`.
  - `repr.go:49` — `case Период` печатает `x.Name`; обновить: `Name=="последние"`→`fmt.Sprintf("последние %d%s", Amount, Unit)`; `Offset!=0`→`"прошлый "+nounFromAdverb(Name)`; иначе `Name` (v1).
  - **`store/codec.go:92` НЕ трогать (обосновано).** Кодирует `Период` только по `Name`. Скользящие/завершённые `Период` **недостижимы как first-class значения**: парсер спец-парсит `последние`/`прошлый` ТОЛЬКО в ветке `период:` (§MW-4); в общем выражении (`присвоить x = последние 30дн`) `последние` — обычный IDENT (undefined→ошибка), DURATION остаётся → не порождает скользящий Период. Персистятся лишь 5 календарных адвербов (read-only глобалы) с нулевыми `Amount/Unit/Offset` → `Name`-only кодек round-trip корректен. Контракт Store и сериализация не меняются (инвариант §5). (Если будущая фича сделает Период first-class — кодек тогда.)
  - `window_test.go:42` строит `Период{Name:c.period}` keyed → нулевые новые поля, существующие тесты не ломаются.

## §MW-4 Парсер `период:` — спец-парс (§MW-D-PARSE; конституция II/IV/VI)

В `parseMetricDecl` ветку `case "период":` заменить `period = p.parseExpression()` на `period = p.parsePeriodValue()`:

```
parsePeriodValue():
  tok := peek()
  if tok.Kind==IDENT && tok.Lexeme=="последние":
     advance; durTok := expect(DURATION, "длительность окна, например 30дн")
     → ast.WindowPeriodLit{Amount: durTok.Value.Amount, Unit: durTok.Value.Unit, Pos}
  if tok.Kind==IDENT && (tok.Lexeme=="прошлый" || tok.Lexeme=="прошлая"):
     advance; nounTok := expect(IDENT, "период: день/неделя/месяц/квартал/год")
     → ast.LastCompletedPeriodLit{Noun: nounTok.Lexeme, Pos}   // маппинг noun→адверб в семантике/eval
  else:
     → parseExpression()   // адверб-константа (ежемесячно…) — путь v1 БЕЗ изменений
```

- **§MW-D-PARSE-1 (`последние` остаётся IDENT).** Матч по `attrTok.Lexeme == "последние"` в контексте `период:` (как A1 матчит `тип`/`поля`). НЕ keyword (v1-программа может звать переменную `последние`; контекстный матч безопасен). Аналогично `прошлый`/`прошлая`/nouns — IDENT.
- **§MW-D-PARSE-2 (контигуальная форма).** `последние 30дн` — `30дн` обязан быть `DURATION` (контигуально). `последние 30 дн` (пробел) = `последние` `INT(30)` `IDENT(дн)` → `expect(DURATION)` найдёт INT → парс-ошибка «ожидался период вида N<ед>, например 30дн». Документировать; DoD-срез использует `30дн`.
- **§MW-D-PARSE-3 (AST-узлы, листовые).** Новые узлы-выражения в `ast/` (несут локальную `ast.Position`, не импортируют `errors`):
  - `WindowPeriodLit{Amount string, Unit string, Pos}` (Amount — строка из `DurationValue`, парсится в int в семантике/eval).
  - `LastCompletedPeriodLit{Noun string, Pos}` (Noun ∈ {день,неделя,месяц,квартал,год}).
  Оба — Expression; eval → `value.Период` (§MW-5).
- **§MW-D-PARSE-4.** `parseExpression`-путь для адверб-констант не меняется → `período: ежемесячно` валиден как раньше.

## §MW-5 Семантика + eval новых форм (§MW-D-SEM; конституция VIII/IX)

**Eval (`expr.go`/`metric_engine.go`):**
- `WindowPeriodLit` → `value.Период{Name:"последние", Amount:atoi(lit.Amount), Unit:lit.Unit, Offset:0}`.
- `LastCompletedPeriodLit` → `value.Период{Name: nounToAdverb(lit.Noun), Amount:0, Unit:"", Offset:-1}`, где `nounToAdverb`: день→ежедневно, неделя→еженедельно, месяц→ежемесячно, квартал→ежеквартально, год→ежегодно.

**Семантические проверки (`analyze.go`, статические где возможно; иначе eval — но предпочесть Analyze):**
- **§MW-SEM-1 (единицы окна, A2-2).** `WindowPeriodLit.Unit ∈ {дн,нед,мес}` — иначе `semErr` (позиция period attr): `метрика '<имя>': единица '<ед>' недопустима для окна (допустимо: дн, нед, мес)`.
- **§MW-SEM-2 (положительность N).** `Amount ≥ 1` — иначе `semErr`: `метрика '<имя>': размер окна должен быть положительным`.
- **§MW-SEM-3 (noun завершённого).** `LastCompletedPeriodLit.Noun ∈ {день,неделя,месяц,квартал,год}` — иначе `semErr`: `метрика '<имя>': неизвестный период '<noun>' (допустимо: день, неделя, месяц, квартал, год)`. (Если eval не достигает — проверка статическая в Analyze, обход AST метрик.)
- **§MW-SEM-4 (по_дате, A2-4).** Покрыто существующей «период требует по_дате» (`analyze.go:167`) — последние/прошлый суть период. **Новой проверки НЕ добавлять**; добавить лишь golden, что `последние 30дн` без `по_дате` даёт существующее сообщение.

> Семантика статическая: обход `m.Period` AST в Analyze (различить `WindowPeriodLit`/`LastCompletedPeriodLit`/`Ident`). Тексты — дословный канон (конституция VIII), вносятся в §MW-9.

## §MW-6 Вычисление окна — `periodWindow` (§MW-D-WINDOW; конституция V — детерминизм)

`periodWindow(p value.Период, d value.Дата)` — `d = i.now()` (заморожен). Расширить switch:

**§MW-D-WINDOW-SLIDE (`p.Name == "последние"`):** скользящее окно `(d − N ед, d]`, возвращается ИНКЛЮЗИВНО-эквивалентно (чтобы переиспользовать инклюзивный `recordSurvives` БЕЗ его изменения):
- `конец = d` (инклюзивно).
- `нижняя_искл = d − N ед`: `дн`→`AddDate(0,0,-N)`; `нед`→`AddDate(0,0,-7*N)`; `мес`→`AddDate(0,-N,0)`.
- `начало = нижняя_искл.AddDate(0,0,+1)` (инклюзивная нижняя граница ≡ полуинтервал `(нижняя_искл, d]`).
- Через `dateToTime`/`timeToDate` (UTC-полночь, как существующие случаи).

**§MW-D-WINDOW-COMPLETED (`p.Offset != 0`, календарный `Name`) — ИСПРАВЛЕНО после self-check.**
> **Дефект исходного подхода (поймал self-check Ф8):** сдвиг сырой даты `d.AddDate(0,Offset,0)` на day-31 ПЕРЕПОЛНЯЕТСЯ вперёд (`2026-05-31.AddDate(0,-1,0)` = `2026-05-01`, т.к. апрель 30 дней → 31 апр → 1 мая = **ВСЁ ЕЩЁ МАЙ**). Тогда `прошлый месяц` на 31-м числе давал **ТЕКУЩИЙ месяц вместо предыдущего** — сломанная семантика «прошлый» (квартал/год иммунны: ≤3-дн спилл остаётся в прошлом периоде).
>
> **Правильный подход — «шаг назад от начала текущего периода»:** вычислить окно ТЕКУЩЕГО периода `[начало_тек, конец_тек]` базовым `periodWindow({Name, Offset:0}, d)`; затем `якорь = начало_тек − 1 день` (через `dateToTime/AddDate(0,0,-1)/timeToDate`) — гарантированно попадает в ПРЕДЫДУЩИЙ период для ЛЮБОГО `Name` (день/неделя/месяц/квартал/год) БЕЗ переполнения дня; вернуть `periodWindow({Name, Offset:0}, якорь)`. Для `|Offset|>1` (в A2 не порождается) — цикл `|Offset|` шагов. Псевдокод:
> ```
> if p.Offset != 0 {
>     base := value.Период{Name: p.Name}
>     anchor := d
>     for i := 0; i < -p.Offset; i++ {
>         start, _, ok := periodWindow(base, anchor); if !ok { return false }
>         anchor = timeToDate(dateToTime(start).AddDate(0,0,-1))  // в предыдущий период
>     }
>     return periodWindow(base, anchor)
> }
> ```

**§MW-D-WINDOW-EDGE (арифметика месяцев — переоценено).** После §MW-D-WINDOW-COMPLETED-фикса **`прошлый месяц/квартал/год/неделя/день` КОРРЕКТНЫ на всех датах** (включая концы месяца) — выбирают строго предыдущий полный календарный период. Остаётся ОДИН принятый edge: **скользящее `последние N мес`** использует `d.AddDate(0,-N,0)` для нижней границы, и на day>28 Go-нормализация даёт слегка смещённую границу (напр. `последние 1мес` на `2026-05-31` → нижняя_искл `2026-05-01`, окно `[2026-05-02, 2026-05-31]`). Для СКОЛЬЗЯЩЕГО окна это лишь вариация РАЗМЕРА (не выбор неверного периода) — **принято и документировано**; golden-кейс конца месяца пиннит фактическое значение честно. Смягчение «снап на последний день» — backlog. **Огромный `N`** (`последние 100000мес`) даёт далёкую/отрицательную нижнюю границу — безвредно (все записи проходят нижнюю границу, окно = «всё до сегодня»), без паники; **принято без верхней границы** (вырожденное, но валидное окно).

**Детерминизм:** всё от `d = i.now()` (заморожен), через `eval.Clock`. НИКОГДА `time.Now()` (конституция V; §MW-SEM golden на `FixedClock`).

## §MW-8 Реестр сообщений A2 (канон; расширение §SM-9.A/C)

Конвенция §SM-9: без точки в конце; `'…'` идентификаторы; `«…»`/прямой текст значений; позиция = period attr (`Attrs.PeriodPos`) или decl. Дословный канон (конституция VIII).

**§MW-8.A — Семантика/парсер:**
```
метрика '<имя>': единица '<ед>' недопустима для окна (допустимо: дн, нед, мес)
метрика '<имя>': размер окна должен быть положительным
метрика '<имя>': размер окна слишком велик
метрика '<имя>': неизвестный период '<noun>' (допустимо: день, неделя, месяц, квартал, год)
```
> «размер окна слишком велик» — для `N`, переполняющего `int64` при `strconv.ParseInt` (отделено от «должен быть положительным», т.к. значение положительно, лишь вне диапазона; self-check Ф8).
Парс-ошибки формы — `ожидался период вида N<ед>, например 30дн` / `ожидался период: день/неделя/месяц/квартал/год` (через `expect`).

## §MW-9 Golden-приёмка и тест-замки (конституция VI; расширение §SM-10)

Детерминизм — `FixedClock` (инъекция), НЕ пиннинг `сегодня()`. Паттерн `metric_engine_test.go`/`goldenMetric` + расширить под `период: последние N <ед>` и `прошлый <noun>`. Витрина — `examples/*.ladix` + golden CLI (через harness с фикс-Clock для дата-зависимых, как §SC-10).

**Обязательные замки A2:**
1. **§MW-D-WINDOW-SLIDE golden-таблица (A2-3).** `FixedClock{2026,6,15}`, `последние 30дн`/`последние 2нед`/`последние 1мес` — точная МЕМБЕРШИП записей у границ окна (запись ровно на `начало`/`конец`/`начало−1`/`конец+1`). Полуинтервал `(d−N, d]` пиннится таблицей: запись на `d` — включена; на `нижняя_искл` (= d−N) — ИСКЛЮЧЕНА; на `d−N+1` — включена.
2. **Эквивалентность единиц.** `последние 7дн` ≡ `последние 1нед` (одинаковая мембершип) — golden.
3. **Завершённый период (A2-6).** `FixedClock{2026,6,15}`, `прошлый месяц` → окно `[2026-05-01, 2026-05-31]`; `прошлая неделя`/`прошлый квартал`/`прошлый год`/`прошлый день` — каждый golden.
4. **Месяц-конец edge (§MW-D-WINDOW-EDGE).** `FixedClock{2026,5,31}`, `последние 1мес` и `прошлый месяц` — зафиксировать НОРМАЛИЗОВАННЫЙ результат Go (честный golden, не «красивый»).
5. **A2-2 негатив.** `последние 5час` → `единица 'час' недопустима для окна …`; `последние 0дн` → `размер окна должен быть положительным`; `прошлый век` → `неизвестный период 'век' …`. Каждый exit 1, §13-канон.
6. **A2-4 негатив.** `последние 30дн` без `по_дате` → существующее «период требует по_дате».
7. **A2-7 триггер.** `когда метрика <оконная> < N` срабатывает на скаляр окна (golden на фикс-Clock) — БЕЗ изменения триггер-кода (замок на регресс границы eval↔движок).
8. **Обр. совместимость.** 5 календарных периодов (`выручка.ladix`/`метрики.ladix`) — БЕЗ изменения поведения; `period:ежемесячно` golden зелёный.
9. **DoD-срез M1.** `выручка_30д` = `последние 30дн` + `по_дате: дата(...)`/`Дата`-поле на CSV-источнике (A1) → корректный скаляр на фикс-Clock (зелёный в `run` и через harness).
10. **Мутпробы (Ф8):** инверсия границы (полуинтервал→замкнутый / N→N±1 / Offset 0↔−1 / unit-guard снять) ломает соответствующий golden.
