# Модель активации дата/время builtins (фича 008)

> **Якорь фичи 008.** Источник истины для активации 7 отложенных дата/время
> встроенных функций. Импл-чат реализует строго по этому документу; любое
> расхождение или вопрос исполнителя = пробел якоря, закрывается ЗДЕСЬ до
> следующей задачи, а не додумыванием.
>
> Канон-ссылки: типы — SPEC §4; стдлиб-реестр — `docs/stdlib.md` + `docs/eval-model.md §6`;
> тексты ошибок — `docs/eval-model.md §8.3` (слой eval); зеркало активных дат `сегодня`/`дата`
> — `docs/source-metric-model.md §SM-6`; инъекция времени — `Clock` (§SM-7).

## §DB-0. Скоуп и решения владельца

Активируются 7 функций из `deferredNames` (`src/internal/eval/builtins.go:49`):
`вчера`, `завтра`, `длительность`, `в_секундах`, `в_минутах`, `в_часах`, `в_днях`.
После активации `deferredNames` пуст — реестр становится **35 активных + 0 deferred = 35**.

Решения kickoff-аудита (приняты владельцем):

- **D-A = A.** Активируются РОВНО 7 builtins на **внутреннем Go date-math**. Операторная
  арифметика `Дата±Длит`, `Дата−Дата`, `Длит±Длит`, `Длит*X` (SPEC §4 / §12:548) **ОСТАЁТСЯ
  deferred (v2)**: `eval/arith.go` и `value.Compare` НЕ трогаются. Граница: пользователь может
  **сконструировать** `Длительность` (через `длительность(...)` или литерал `5мин`),
  **сравнить** её (`==`/`!=`, порядок одной единицы — активно с 006) и **перевести** в число
  (конвертеры), но НЕ может складывать/вычитать/умножать даты и длительности оператором — это
  по-прежнему ошибка типа до v2. Появление конструктора `длительность()` без операторной
  арифметики — осознанная асимметрия, не дыра.
- **D-B.** Конвертеры `в_*` при неделимости — **усечение целочисленным делением Go** (к нулю;
  зеркало поведения `целое()`).
- **D-C.** Пользовательское строковое значение в текстах ошибок — **гильемы «…»** (конвенция
  §SM-9, живой паттерн `builtins_date.go:32` «дата: «<значение>» не является датой»).
- **D-D.** Инвариант-комментарий `builtins.go:54` переформулировать в «РОВНО 35 активных,
  0 deferred = 35».
- **D-E.** Новый `.ladix`-демо **не добавляем** (учебный CHECKLIST не требует; golden-прогон
  `cmd/ladix` не инжектит `Clock`, абсолютные даты поплыли бы).
- **D-F = A.** Type-mismatch аргументов — **префиксированные exact-match строки** (зеркало
  `дата:`-конвенции), вносятся в §8.3.

## §DB-1. Сигнатуры и арность (финал)

| Функция | Арность | Возврат | Класс |
|---|---|---|---|
| `вчера()` | 0 | `Дата` | `ArityFixed N=0` |
| `завтра()` | 0 | `Дата` | `ArityFixed N=0` |
| `длительность(значение, единица)` | 2 | `Длительность` | `ArityFixed N=2` |
| `в_секундах(d)` | 1 | `Целое` | `ArityFixed N=1` |
| `в_минутах(d)` | 1 | `Целое` | `ArityFixed N=1` |
| `в_часах(d)` | 1 | `Целое` | `ArityFixed N=1` |
| `в_днях(d)` | 1 | `Целое` | `ArityFixed N=1` |

Все — `ArityFixed` (НЕ `Overloaded`): нарушение арности ловится семпроходом (`checkCall`) и
защитно в рантайме (`callBuiltin`), текст `'<имя>' принимает N аргументов, передано M` (§8.3,
существующая форма). Регистрация — в блоке `builtins.go:88-90` (рядом с активными `сегодня`/`дата`):
`add(fixed("вчера", 0, builtinVchera))`, `add(fixed("длительность", 2, builtinDlitelnost))`,
`add(fixed("в_секундах", 1, builtinVSekundah))` и т.д. Реализация Fn — новый файл
`src/internal/eval/builtins_duration.go` в стиле `builtins_date.go` (`вчера`/`завтра` допустимо
положить в `builtins_date.go`; имя `builtins_duration.go` намеренно парно уже существующему
тесту `duration_builtins_test.go` — порядок слов инвертирован, это ок). Сигнатура Fn — общая:
`func(i *Interpreter, args []value.Value, pos ast.Position) (value.Value, error)`.

## §DB-2. `вчера()` / `завтра()` — Clock + Go date-shift

`вчера()` = `сегодня() − 1 календарный день`; `завтра()` = `сегодня() + 1 день`. Реализуются
**без операторной арифметики Ladix**, через готовые хелперы `eval/window.go`:

- `вчера`: `timeToDate(dateToTime(i.now()).AddDate(0, 0, -1))`
- `завтра`: `timeToDate(dateToTime(i.now()).AddDate(0, 0, +1))`

`dateToTime(d)` (`window.go:57`) даёт полночь UTC; `AddDate(0,0,±1)` — корректный календарный
переход (граница месяца/года, високос); `timeToDate(t)` (`window.go:62`) — обратно в `value.Дата`.
Время берётся **только** через `i.now()` (`interpreter.go:155`, кеш `i.today` от `Clock`),
**никогда** `time.Now()` напрямую. Этим автоматически сохраняется инвариант serve-демона:
`ResetRunState()` (`interpreter.go:124`) обнуляет `i.today`, следующий тик переснимает дату —
`вчера`/`завтра` наследуют корректность без отдельного кода. Собственных ошибок нет (только
арность).

**Golden-приёмка** (`FixedClock{Дата{2026,5,31}}`, зеркало §SM-10): `сегодня()`=2026-05-31,
`вчера()`=2026-05-30, `завтра()`=2026-06-01 (переход через границу месяца проверяет `AddDate`).

## §DB-3. `длительность(значение, единица)` → `Длительность`

Единственный конструктор `Длительность` из значений (литерал `5мин` — отдельный путь
`evalDurationLit`, `expr.go`). Возвращает `value.Длительность{Amount: значение, Unit: единица}`
**без нормализации единиц** (D-17: `1час ≠ 60мин`, хранится как есть).

Валидация (по порядку):

1. `значение` обязан `Целое`, `единица` обязана `Строка`. Иначе → **ОшибкаТипа** (§8.3):
   `длительность: ожидается Целое и Строка, получено <тип> и <тип>` (показываются ОБА
   полученных типа, даже если неверен один; `<тип>` = `TypeName`). `Дробное` для `значение`
   (включая `1.0`) — ошибка типа (промоушена `Дробное→Целое` нет).
2. `единица` ∈ {`сек`,`мин`,`час`,`дн`,`нед`,`мес`} (канон `lexer/keywords.go:38`). Иначе →
   **ОшибкаВыполнения** (§8.3): `длительность: неизвестная единица «<единица>»` (гильемы —
   единица есть пользовательское строковое значение).

`значение` — **любое** `Целое`, включая 0 и отрицательное: `длительность(0,"нед")` =
`Длительность{0,"нед"}`, `длительность(-3,"дн")` = `Длительность{-3,"дн"}`. Конструктор **НЕ**
дублирует литерал-валидацию «ноль недель» — та живёт в семпроходе расписания
(`когда расписание каждые 0нед` → SCHED-1, иной слой, `analyze_time_test.go:84`); сырое значение
Длительности нуль/знак допускает (иначе вводим ошибку без мотива). Эквивалентность с литералом:
`длительность(5,"мин") == 5мин` (`value.Equal` по `{Amount,Unit}`).

Позиция всех ошибок = `pos` (`CallExpr.Pos()`).

## §DB-4. Конвертеры `в_секундах`/`в_минутах`/`в_часах`/`в_днях`(d) → `Целое`

Перевод `Длительность` в число выбранной единицы. Аргумент `d` обязан `Длительность`, иначе →
**ОшибкаТипа** (§8.3): `<имя>: ожидается Длительность, получено <тип>`.

**Таблица множителей единица→секунды.** Числа согласованы с `engine/deadline.go:10-26` (который
хранит их как `time.Duration`: `24*time.Hour`, `168*time.Hour` — литералов `86400`/`604800` в коде
нет, это деривация ×3600), но саму int64-карту секунд impl заводит локально в `builtins_duration.go`.
**ВНИМАНИЕ:** `deadline.go:23` обрабатывает `мес` календарным `AddDate(0,n,0)` — это **НЕ копировать**
для конвертеров: по п.1 ниже `мес` даёт ошибку, а не приведение. Конвертеры НЕ вызывают `AddDuration`.

| единица | секунд | вывод |
|---|---|---|
| `сек` | 1 | |
| `мин` | 60 | |
| `час` | 3600 | |
| `дн` | 86400 | 24·3600 |
| `нед` | 604800 | 168·3600 = 7·86400 |
| `мес` | — | **не приводится** (календарная единица, без даты-якоря) |

Алгоритм (единый для всех 4 функций):

1. Если `d.Unit == "мес"` → **ОшибкаВыполнения** (§8.3): `<имя>: месяцы не приводятся без
   даты-якоря` (`<имя>` = имя вызванной функции).
2. `totalSec, overflow := mulInt64(d.Amount, секунд[d.Unit])`; при `overflow` →
   **ОшибкаВыполнения** `переполнение целого числа` (существующий хелпер `arith.go:259`,
   существующий текст — новой строки реестра не нужно).
3. Результат (`value.Целое`):
   - `в_секундах` → `totalSec`
   - `в_минутах` → `totalSec / 60`
   - `в_часах` → `totalSec / 3600`
   - `в_днях` → `totalSec / 86400`

   Деление — целочисленное Go (усечение к нулю, D-B): `в_минутах(длительность(90,"сек"))`=1.
   Отрицательные допустимы и усекаются к нулю (`-90сек` → `в_минутах` = -1).

Позиция всех ошибок = `pos` (`CallExpr.Pos()`).

## §DB-7. Golden-матрица приёмки (минимум)

**Позитив** (`FixedClock{2026,5,31}` для дат):
- `вчера()` → Дата `2026-05-30`; `завтра()` → `2026-06-01`; `тип(вчера())` → `"Дата"`.
- Конструктор: `длительность(5,"мин")` → Длительность; `длительность(5,"мин") == 5мин` → истина;
  `длительность(0,"нед")`, `длительность(-3,"дн")` → конструируются без ошибки.
- Конвертеры (матрица 5 валидных единиц × 4 функции): `в_секундах` — сек→×1, мин→×60, час→×3600,
  дн→×86400, нед→×604800; `в_минутах`/`в_часах`/`в_днях` аналогично с усечением. Тождества:
  `в_днях(длительность(1,"нед"))`=7; `в_часах(длительность(1,"дн"))`=24;
  `в_секундах(длительность(2,"мин"))`=120. Усечение: `в_минутах(длительность(90,"сек"))`=1;
  `в_часах(длительность(90,"мин"))`=1; `в_днях(длительность(40,"час"))`=1.

**Негатив** (exact-match по §DB-5):
- `длительность(5,"XYZ")` → `длительность: неизвестная единица «XYZ»`;
  `длительность(1.5,"час")` / `длительность("5","мин")` →
  `длительность: ожидается Целое и Строка, получено …`; `длительность(5)` → арность.
- `в_секундах(длительность(1,"мес"))` (и аналогично для всех 4) →
  `<имя>: месяцы не приводятся без даты-якоря`; `в_секундах(5)` →
  `в_секундах: ожидается Длительность, получено Целое`; `в_секундах()` → арность.

## §DB-9. Вне скоупа 008 (v2; путь отступления аддитивен)

Операторная арифметика `Дата±Длит`/`Дата−Дата`/`Длит±Длит`/`Длит*X` (§12:548 остаётся в силе);
нормализация единиц Длительности (`1час≠60мин`, D-17); конверсия `мес` через дату-якорь;
аксессоры компонент `Дата` / границы периодов / календарные сдвиги (SPEC §4); тип `ДатаВремя`,
таймзоны, почасовые/поминутные окна; именованные/перегруженные формы конструктора. Снятие
любого — **аддитивно** (новая функция/оператор/значение атрибута), фронтенд (грамматика,
`value`-типы) и существующие программы v1 не ломаются.
