> видимости, §7 управляющие, §8 функции/стдлиб, §13 ошибки). Источник истины по **архитектуре**

> исполняет, какими структурами Go представляет значения и области видимости, как считает
> выражения, исполняет statements, вызывает функции, сообщает ошибки и где проходит граница
> фичи 003. Симметричен `docs/execution-model.md` (модель движка процессов), который описывает
> отложенный engine-трек.

## §1. Граница фичи 003 и инварианты

### §1.1. Что входит (scope)

Фича 003 реализует **чистое императивное ядро** подмножества B — tree-walking интерпретатор в
пакете `internal/eval/`, который обходит AST от парсера (002) и:

- вычисляет выражения с приоритетами (дерево уже построено парсером — eval только считает);
- исполняет statements: `пусть`, присваивание, выражение-оператор, `если/иначе если/иначе`,
  `пока`, `для … в …`, `прервать`, `продолжить`, `вернуть`;
- ведёт области видимости (функциональный scope, см. §2);
- вызывает пользовательские функции с рекурсией и явным счётчиком глубины;
- предоставляет **35 активных** встроенных функций (24 чистые, включая конструктор `дата(…)`; `сегодня()` зависит от `Clock`; `статус_процесса`/`состояние_процесса`/`задачи_пользователя` — от `runtime`/`Store`; 7 дата/время-функций активированы в 008; см. §6);
- печатает (`печать`) — единственный штатный канал вывода;
- сообщает рантайм- и семантические ошибки с позицией (строка + колонка), без Go stack trace.

**Типы значений, конструируемые в 003 (6):** `Целое`, `Дробное`, `Строка`, `Булево`, `Пусто`,
`Список`. Тип `Запись` смоделирован полностью (чтение полей, равенство, печать с сохранением
порядка), но в чистом 003 **не порождается** — у него нет литерала, а все его источники
(доменные функции) отложены; см. §1.2 и §2.1.

### §1.2. Что НЕ входит (deferred)

Следующее **парсится** (узлы строятся в 002), но в 003 **не исполняется** — при встрече eval
даёт семантическую ошибку `«конструкция <X> не поддерживается в этой версии»` с позицией узла
(не тихий no-op):

| Отложено | Узлы / конструкции | Трек |
|---|---|---|
| Процессный слой | `RunProcessExpr` (`запустить процесс`), `AssignAction`/`CallAction`/`NotifyAction` (`присвоить`/`вызвать`/`уведомить`) | engine 004+ |
| Декларатив | `источник`, `метрика`, `процесс`, `триггер` | engine 004+ |
| Дата-подсистема | литерал `Длительность` (`3дн`), конструкторы `Дата` (`дата()`/`сегодня()`/…), арифметика `Дата`/`Длительность`, типы-значения `Дата`/`Длительность`/`Период` | стдлиб 004+ |
| Доменная стдлиб | `статус_процесса`, `состояние_процесса`, `задачи_пользователя` (Store) + 9 функций дата/время | engine/стдлиб 004+ |

> Таблица — снимок на момент 003. К фиче 006 активированы `дата`/`сегодня` (004) и три
> процессных builtins (006); в 008 активированы 7 дата/время-функций
> (`вчера`/`завтра`/`длительность`/`в_*`). Актуальный реестр — 35 активных + 0 deferred (§6,
> `src/internal/eval/builtins.go`).

Примеры `выручка.ladix`, `онбординг.ladix` — **не** в обязательном прогоне 003 (тестируются
отдельным треком движка). Обязательный прогон 003 (`ladix run`): `hello`, `арифметика`,
`условие`, `цикл`, `функция`, `факториал` (stdout == golden, код 0) + `ошибка.ladix` (деление
`100/0` → двухстрочный stderr, код 1).

### §1.3. Инварианты, которые eval не нарушает

1. **Числа раздельны:** `Целое`=int64, `Дробное`=float64. `/` всегда → `Дробное`; `//` только
   `Цел○Цел` → `Целое`; `%` — `Цел%Цел` → `Целое` или `Дроб%Дроб` → `Дробное` (fmod), смешанное →
   `ОшибкаТипа`; смешение Цел/Дроб в `+ - *` → промоушен в `Дробное`. Переполнение int64 в `+ - *` —
   **явная** проверка → `ОшибкаВыполнения «переполнение целого числа»` (не wrap-around).
2. **Деление на ноль** для `/`, `//`, `%` при нулевом правом операнде →
   `ОшибкаВыполнения «деление на ноль»` на позиции **оператора**.
3. **Условия strict-Булево** (`если/иначе если/пока`); не-Булево →
   `ОшибкаТипа «условие должно быть Булево, получено <тип>»`. `для x в E` требует `E: Список`.
4. **`и`/`или` короткозамкнуты**, оба операнда обязаны быть `Булево` (не возвращают значение
   операнда как Python).
5. **Функциональный scope** (Python-style): блоки `если/иначе/пока/для` своей области НЕ
   создают (§2.2).
6. **`Список`/`Запись` ссылочные**; `Запись` открытая (нет поля → `пусто`, не ошибка); lvalue
   присваивания — только `Ident`.
7. **Функции не первоклассны** — ровно 10 типов Value, функция значением не является (§2.3, §5).
8. **Ошибки:** двухстрочный формат `«Ошибка в строке N, колонка M:»` + текст; `Pos`
   бинарных/унарных = токен **оператора**; колонки в **рунах**; тексты **дословно** (§8); eval
   **fail-fast** (накопитель только в лексере/парсере).
9. **Без panic в штатных путях** — пользовательские ошибки возвращаются как `error`;
   recover-барьер только на границе CLI.
10. **Сообщения по-русски**, имена типов канонические (`Целое`/`Дробное`, не «Число»).

## §2. Модель значений и области видимости

### §2.1. Пакет `value` — носители рантайм-значений

Листовой пакет `internal/value/` (зависит только от стандартной библиотеки Go). Значение —
интерфейс с единственным обязательным методом:

```go
// Value — рантайм-значение Ladix. Реализуется ровно 10 конкретными типами.
type Value interface {
	TypeName() string // каноническое имя: "Целое", "Дробное", … (для сообщений об ошибках; и для builtin тип(), зарезервированного для v1 — см. ниже)
}
```

> **Go-идиома.** Интерфейс с одним методом + конкретные структуры — это «sum type»
> (размеченное объединение) на Go. Eval различает варианты через `switch v := val.(type)`
> (type switch). Метод `TypeName()` держит имя типа в одном месте, чтобы сообщения об ошибках и
> builtin `тип(x)` не расходились. В v1 наружу через `TypeName()` ходят только сообщения об
> ошибках: сама `тип(x)` **зарезервирована** — имя `тип` отнесено к reserved-словам лексера
> (`internal/lexer/keywords.go`), поэтому `печать(тип(5))` даёт лексическую ошибку, а не
> `"Целое"`. Регистрация/реализация builtin сохранены; активация (снятие имени из reserved) — v2.

Конкретные типы (Go-представление):

```go
type Целое struct{ V int64 }
type Дробное struct{ V float64 }
type Строка struct{ V string }   // UTF-8; индексация и длина — в рунах
type Булево struct{ V bool }
type Пусто struct{}              // синглтон, см. ниже

// Ссылочные (изменяемость и алиасинг видны через указатель / map):
type Список struct{ Elems *[]Value }   // мутатор «добавить» меняет *Elems; алиас делит хранилище

// Запись — ОТКРЫТАЯ структура с сохранением порядка полей (порядок важен для печати).
type Запись struct {
	keys   []string         // порядок появления полей
	fields map[string]Value // быстрый доступ по имени
}
func (r Запись) Get(name string) Value // отсутствующее поле → Пусто (открытая запись)
func (r Запись) Keys() []string        // итерация для строка()/печать() в порядке вставки

// Определены в пакете, но в 003 НЕ конструируются (deferred, §1.2):
type Дата struct{ … }
type Длительность struct{ … }
type Период struct{ … }
```

Замечания:

- **`Пусто` — синглтон.** Один разделяемый экземпляр `var None = Пусто{}`; «пустота»
  проверяется по типу. Функция без `вернуть` и `вернуть` без выражения дают именно его.
- **Ссылочная семантика.** `Список` несёт `*[]Value`; `Запись` — `map` (в Go map уже
  ссылочный). Поэтому `пусть b = a` над списком делит хранилище: мутация `добавить(a, x)` видна
  в `b`. Это требование SPEC §4, закреплённое структурой, а не деталь реализации.
- **`Запись` с порядком полей.** Хранение `keys []string` + `fields map` даёт и
  предсказуемую печать `{поле: значение, …}` в порядке появления, и доступ за O(1). Открытость:
  `Get` на отсутствующем поле возвращает `Пусто`, не ошибку.
- **Все 10 структур существуют сразу** — стабильная поверхность под границу `eval↔store`
  (`store` оперирует `Value`, не зная про eval). Но в 003 ни один путь кода не конструирует
  `Дата`/`Длительность`/`Период`/`Запись`: их «ворота» (литерал `3дн`, конструктор `дата()`,
  доменные функции) закрыты deferred-ошибкой (§1.2). Когда engine-трек откроет эти ворота,
  чтение/печать/равенство уже будут работать.

### §2.2. `Environment` — цепочка областей видимости

```go
// Environment — одна область видимости переменных. Цепочка через parent даёт лексический поиск.
type Environment struct {
	vars   map[string]value.Value
	parent *Environment // nil у глобальной области
}

func NewEnvironment(parent *Environment) *Environment
func (e *Environment) Define(name string, v value.Value) error   // пусть: новая привязка в ЭТОЙ области
func (e *Environment) Assign(name string, v value.Value) error   // =: ищет вверх по цепочке существующую
func (e *Environment) Lookup(name string) (value.Value, bool)    // чтение: вверх по цепочке
```

**Правила (функциональный scope, SPEC §6):**

- Новую область в 003 создают **только**: (1) глобальная область программы, (2) кадр вызова
  функции. Блоки `если/иначе/пока/для` **своей области не создают** — их тело исполняется в том
  же `Environment`, что и охватывающий код.
- **`пусть x = E`** → `Define` в **текущей** области. Повтор `Define` того же имени в той же
  области → семантическая ошибка `«'x' уже объявлено в строке N»` (ловится семпроходом §9 —
  внутри функции/глобала это статически разрешимо, т.к. блоки не вкладывают области).
- **`x = E`** → `Assign`: поиск существующей привязки вверх по цепочке; не найдено →
  `«'x' не объявлено»`.
- **Лексический parent кадра функции — ГЛОБАЛЬНАЯ область, не кадр вызывающего.** Функции
  только top-level и не замыкания, поэтому цепочка вызова: `кадр-функции → global`. Рекурсия
  добавляет независимые кадры, каждый с `parent = global` (лексическая, а не динамическая
  видимость).
- **Следствие для блоков:** `пусть` внутри ветки `если` или тела цикла кладёт переменную в кадр
  функции (или в global на верхнем уровне). Поэтому `пусть категория` в обеих ветках
  `если/иначе` → «уже объявлено»; а `категория = …` в ветках мутирует внешнюю переменную
  (контракт `условие.ladix`). Переменная цикла `для x` создаётся в охватывающей области и видна
  после цикла со значением последней итерации; на пустом списке не создаётся.

> **Go-идиома.** `parent *Environment` — связный список «изнутри наружу». `Lookup`/`Assign`
> поднимаются по цепочке, пока не найдут имя или не упрутся в `nil`. `map[string]value.Value` —
> изменяемое хранилище кадра; кадр создаётся явно и передаётся параметром (без глобального
> состояния, конституция §V).

### §2.3. Два пространства имён: переменные и функции

Чтобы удержать «ровно 10 типов Value» и «функции не первоклассны», имена резолвятся в **двух
раздельных пространствах**:

| Пространство | Где живёт | Содержимое |
|---|---|---|
| **Переменные** | `Environment` (цепочка кадров) | `пусть`-привязки, параметры функций, переменные цикла |
| **Функции** | таблица `funcs` (не `Value`) | пользовательские `FunctionDecl` (наполняется семпроходом) + реестр встроенных (35 активных, 0 deferred) |

- Функция **не является** `Value`: её нельзя присвоить/передать/вернуть/положить в список. Это
  обеспечено физически — таблица функций отделена от `Environment`, функция не может оказаться
  значением переменной.
- **Имя в позиции значения** (`Ident` не под вызовом): резолв в `Environment`. Промах, но имя
  есть в таблице функций → `«'имя' — функция, её нельзя использовать как значение»`. Иначе →
  `«'x' не объявлено»` (рантайм, т.к. видимость зависит от порядка top-level `пусть`, §9).
- **Имя в позиции вызова** (`CallExpr.Callee`): порядок и затенение — §5.2.

## §3. Семантика выражений

Точка входа: `evalExpr(env *Environment, e ast.Expression) (value.Value, error)` — type switch по
конкретным узлам. Операнды бинарных операторов и аргументы вычисляются **слева направо**.
Дерево приоритетов уже построено парсером — eval не переразбирает приоритеты, только считает.

### §3.1. Литералы и идентификатор

| Узел | Результат |
|---|---|
| `IntLit` | `value.Целое{V}` (диапазон уже проверен парсером, D2) |
| `FloatLit` | `value.Дробное{V}` |
| `StringLit` | `value.Строка{V}` (уже развёрнутая строка) |
| `BoolLit` | `value.Булево{V}` |
| `NoneLit` | `value.None` (синглтон `Пусто`) |
| `ListLit` | новый `value.Список` — элементы вычислены слева направо в свежий `*[]Value` |
| `DurationLit` | **deferred-ошибка** `«конструкция <X> не поддерживается в этой версии»` (exact-match-канон — §8.3; ловится семпроходом §9) |
| `Ident` (значение) | `env.Lookup` → значение; промах → §2.3 (функция-как-значение / не объявлено) |

### §3.2. Унарные операции

| `Op` | Допустимый операнд | Результат | Иначе |
|---|---|---|---|
| `OpNeg` (`-`) | `Целое`/`Дробное` | арифметическое отрицание (для `Целое` — с проверкой переполнения, единообразно; `-MinInt64` недостижим, т.к. `MinInt64` невыразим) | `ОшибкаТипа «унарный '-' нельзя применить к <тип>»` |
| `OpNot` (`не`) | `Булево` | логическое отрицание | `ОшибкаТипа «'не' нельзя применить к <тип>»` |

Позиция ошибки = токен оператора (`UnaryExpr.Pos()`).

### §3.3. Бинарные операции

**Сначала** — короткое замыкание для `OpOr`/`OpAnd` (правый операнд вычисляется не всегда):

- `или`: вычислить левый (обязан `Булево`); `истина` → результат `истина` **без** вычисления
  правого; иначе вычислить правый (обязан `Булево`) → он и есть результат.
- `и`: вычислить левый (обязан `Булево`); `ложь` → `ложь` **без** правого; иначе правый.
- Любой операнд не `Булево` → `ОшибкаТипа «'<оп>' требует Булево, получено <тип>»`.

Остальные операторы — вычислить оба операнда слева направо, затем диспетчеризовать:

**Арифметика** (`+ - * / // %`):

| Случай | Правило |
|---|---|
| `Цел ○ Цел`, `○ ∈ {+ - *}` | → `Целое` с **явной** проверкой переполнения int64 → `«переполнение целого числа»` |
| участвует `Дробное` (`+ - *`) | промоушен → `Дробное` (float не переполняется) |
| `/` (любые числовые) | **всегда** `Дробное` |
| `//` | только `Цел // Цел` → `Целое`; иначе `ОшибкаТипа` |
| `%` | `Цел % Цел` → `Целое`; `Дроб % Дроб` → `Дробное` (fmod); смешанное → `ОшибкаТипа` |
| правый операнд `/`,`//`,`%` равен нулю | `ОшибкаВыполнения «деление на ноль»` |
| `Строка + Строка` | конкатенация → `Строка` |
| прочие комбинации `+` | `ОшибкаТипа «'+' нельзя применить к <тип> и <тип>»` |

> Списки **не** складываются `+` и не сравниваются `<` — для соединения `соединить(s1, s2)`.

**Сравнение** (`== != < <= > >=`):

- `==`/`!=`: значения любых типов. Разные типы → `ложь` (для `==`), **кроме** пары
  `Целое`↔`Дробное` (численно: `1 == 1.0` → `истина`). В пределах типа: `Строка` — по
  код-поинтам, `Булево` — по значению, `Пусто` — равно только `Пусто`, `Список` — поэлементно
  (разная длина → `ложь`), `Запись` — структурно (совпадение множества полей и значений).
- `< <= > >=`: только взаимно-упорядочиваемые — `Цел↔Цел`, `Дроб↔Дроб`, `Цел↔Дроб` (промоушен),
  `Строка↔Строка` (лексикографически по код-поинтам), `Дата↔Дата`,
  `Длительность↔Длительность` **одной единицы** (D-17: по значению; разные единицы → `ОшибкаТипа`).
  Прочее → `ОшибкаТипа «'<оп>' нельзя применить к <тип> и <тип>»`.

Позиция любой ошибки бинарного оператора = токен оператора (`BinaryExpr.Pos()`).

### §3.4. Постфиксные: вызов, индексация, поле

- **`CallExpr`** — см. §5.
- **`IndexExpr`** (`target[index]`):
  - `target: Список` → элемент по индексу. `index` обязан `Целое`; вне `[0, длина)` (включая
    отрицательные) → `ОшибкаВыполнения «индекс N вне диапазона (длина L)»`.
  - `target: Строка` → строка из одной руны (индексация в рунах, те же границы).
  - иной `target` → `ОшибкаТипа «значение типа <тип> не индексируется»`.
  - `index` не `Целое` → `ОшибкаТипа «индекс должен быть Целое, получено <тип>»`.
  - Позиция = `IndexExpr.Pos()` (начало `target`).
- **`FieldExpr`** (`target.field`):
  - `target: Запись` → `Get(field)` (отсутствующее поле → `Пусто`).
  - иной `target` → `ОшибкаТипа «значение типа <тип> не имеет полей»`. (В чистом 003 `Запись`
    не конструируется, поэтому на практике `FieldExpr` всегда упирается в эту ошибку; механизм
    чтения готов к моменту, когда доменные функции начнут порождать записи.)
  - Позиция = `FieldExpr.Pos()` (начало `target`).
- **`RunProcessExpr`** → deferred-ошибка (§9).

## §4. Statements и механизм управляющих сигналов

### §4.1. Сигнальный механизм (control-flow без panic)

`вернуть`/`прервать`/`продолжить` — нелокальный выход. Реализуем **явным возвращаемым
сигналом**, не `panic/recover` (конституция §III «без panic в штатных путях»):

```go
type SignalKind int
const (
	SigNormal   SignalKind = iota // обычное завершение, исполнение продолжается
	SigBreak                      // прервать
	SigContinue                   // продолжить
	SigReturn                     // вернуть (несёт значение)
)
type Signal struct {
	Kind  SignalKind
	Value value.Value // значимо только при SigReturn
}

func evalStmt(env *Environment, s ast.Statement) (Signal, error)
func evalBlock(env *Environment, b *ast.Block) (Signal, error)
```

> **Go-идиома.** Два независимых канала: `error` — рантайм-ошибки (всегда прерывают немедленно,
> всплывают до CLI); `Signal` — штатный поток управления. `evalBlock` после каждого
> `evalStmt`: при `err != nil` — сразу наверх; при `sig.Kind != SigNormal` — прекращает блок и
> возвращает сигнал. Цикл «ловит» `SigBreak`/`SigContinue`; вызов функции «ловит» `SigReturn`.
> Так раскрутка стека идиоматична и видна в сигнатурах, а не спрятана в `recover`.

```go
func evalBlock(env, b):
	for _, st := range b.Stmts:
		sig, err := evalStmt(env, st)
		if err != nil:        return Signal{}, err
		if sig.Kind != SigNormal: return sig, nil   // break/continue/return — наверх
	return Signal{SigNormal}, nil
```

### §4.2. Таблица statements

| Узел | Семантика | Сигнал |
|---|---|---|
| `LetStmt` | `env.Define(Name, evalExpr(Value))` | `SigNormal` |
| `AssignStmt` | `env.Assign(Name, evalExpr(Value))` (не объявлено → ошибка) | `SigNormal` |
| `ExpressionStmt` | `evalExpr(Expr)`, результат отбрасывается (`печать(…)`, `добавить(…)`) | `SigNormal` |
| `IfStmt` | вычислить `Cond` (strict `Булево`); первая истинная ветвь → `evalBlock`; иначе обойти цепочку `ElseClause` (`IsFinal()` различает финальный `иначе` и `иначе если`) | сигнал из выбранного блока |
| `WhileStmt` | перед каждой итерацией вычислять `Cond` (strict `Булево`); тело — `evalBlock` | см. §4.3 |
| `ForStmt` | вычислить `Iterable` (обязан `Список`, иначе `«'для' требует Список, получено <тип>»`); по элементам | см. §4.3 |
| `BreakStmt` | — | `SigBreak` |
| `ContinueStmt` | — | `SigContinue` |
| `ReturnStmt` | `Value` или `Пусто` (если `nil`) | `SigReturn{value}` |
| `FunctionDecl` (top-level) | **не исполняется** как statement: зарегистрирована семпроходом в `Funcs` (§9). Eval её пропускает | `SigNormal` |
| `AssignAction`/`CallAction`/`NotifyAction` | deferred-ошибка (§9) | — |

### §4.3. Циклы и обработка сигналов

```go
// пока:
for {
	c := evalExpr(env, Cond); требовать Булево
	if !c.V { break }
	sig, err := evalBlock(env, Body)
	if err != nil { return ..., err }
	switch sig.Kind {
	case SigBreak:    goto done          // выход из цикла, сигнал ПОГЛОЩЁН
	case SigContinue: continue            // следующая итерация, сигнал ПОГЛОЩЁН
	case SigReturn:   return sig, nil      // пробрасываем наверх (до вызова функции)
	}
}
done: return Signal{SigNormal}, nil
```

`для x в E`:

- `E` обязан `Список`; элементы перебираются по индексу.
- Переменная `x` привязывается в **охватывающей** области: `Define` при первом элементе (если
  имени там ещё нет), затем `Assign` на каждой итерации. На пустом списке `x` не создаётся.
  После цикла `x` видна со значением последней итерации.
- **Мутация во время итерации.** Перед перебором список помечается «итерируется»; единственный
  мутатор `добавить` на помеченном списке → `ОшибкаВыполнения «список изменён во время
  итерации»`. Снимок — через `для x в копия(s)`.
- `SigBreak`/`SigContinue` обрабатываются как у `пока` (поглощаются); `SigReturn` — наверх.

### §4.4. Порядок исполнения программы

`Program.Items` исполняются по порядку до EOF. **Стадия 3 (семпроход, §9)** проходит первой:
регистрирует все top-level `FunctionDecl` в `Funcs` (поэтому forward-вызов функции, объявленной
ниже, разрешён) и проверяет статику. **Стадия 4 (исполнение)** идёт сверху вниз: top-level
`пусть` инициализируются в порядке появления (ссылка на top-level переменную до её строки →
рантайм `«не объявлено»`, §9).

## §5. Функции, вызовы, рекурсия

### §5.1. Структура интерпретатора

```go
type Interpreter struct {
	global   *Environment      // глобальная область (top-level пусть)
	funcs    map[string]*ast.FunctionDecl // пользовательские функции (из семпрохода)
	builtins map[string]Builtin           // 35 активных, 0 deferred
	maxDepth int               // из флага --max-depth, по умолчанию 10000
	depth    int               // текущая глубина пользовательских вызовов
	out      io.Writer         // канал печать(); инжектируется (тест перехватывает)
}
```

> Состояние передаётся явно (конституция §V): `out` инжектируется (в тестах — `bytes.Buffer`),
> лимит глубины — поле, а не глобал.

### §5.2. Резолв вызова `CallExpr`

`Callee` практически всегда `Ident` (имя). Порядок резолва имени `f` (SPEC §6: переменные →
функции → встроенные):

1. **`env.Lookup(f)`** — если найдена переменная: в v1 значение никогда не функция → если за ней
   стоит `(` → `ОшибкаВыполнения «'f' — не функция (<тип>), вызов невозможен»`. (Так
   обрабатывается затенение: `пусть длина = 5` затем `длина(2)` → переменная найдена,
   не функция.)
2. иначе **`funcs[f]`** — пользовательская функция → вызов (§5.3).
3. иначе **`builtins[f]`** — встроенная: активная → вызов; deferred-заглушка →
   `«функция 'f' не поддерживается в этой версии»` (§9).
4. иначе → `«функция 'f' не объявлена»` (статически ловится семпроходом для прямого `Ident`, §9).

Если `Callee` — не `Ident` (в v1 не порождает функций; например `(5)(3)`, `[1][0](2)`) →
вычислить и получить значение → `ОшибкаВыполнения «значение — не функция (<тип>), вызов
невозможен»` (канон §8.3, строка для не-`Ident` callee). Лексема `— не функция (<тип>), вызов
невозможен` та же, что у `Ident`-ветки; субъект — `значение` (а не `'имя'`), т.к. имени у
произвольного выражения нет. Позиция всех ошибок вызова = `CallExpr.Pos()` (= `Callee.Pos()`).

### §5.3. Вызов пользовательской функции

1. Вычислить аргументы слева направо в `[]value.Value`.
2. **Арность** (фиксированная) проверена семпроходом: число аргументов ≠ числу параметров →
   `«'имя' принимает N аргументов, передано M»` (семантическая).
3. `i.depth++`; если `i.depth > i.maxDepth` →
   `ОшибкаВыполнения «превышена максимальная глубина вызовов (10000). Возможна бесконечная
   рекурсия.»` (число в тексте = фактический лимит). `defer i.depth--`.
4. Новый кадр `frame := NewEnvironment(i.global)`; для каждого параметра `frame.Define(param,
   arg)` (позиционно). Ссылочные аргументы (`Список`/`Запись`) передаются как есть — мутация
   видна вызывающему; неизменяемые — семантика «по значению».
5. `sig, err := evalBlock(frame, body)`. Результат: `SigReturn` → его значение; `SigNormal`
   (дошли до конца тела) → `value.None`. `SigBreak`/`SigContinue` сюда дойти не могут — их
   легальность (только в цикле) проверена семпроходом.

Рекурсия работает: имя функции резолвится через `funcs` (шаг 2), независимо от кадра. Счётчик
глубины — защита от убегающей рекурсии вместо неперехватываемого переполнения Go-стека.

## §6. Стандартная библиотека (35 активных функций)

Плоские глобальные имена (без модулей в языке). В Go-реализации сгруппированы по категориям
(`builtins_io.go`, `builtins_convert.go`, `builtins_agg.go`, `builtins_list.go`,
`builtins_str.go`), регистрируются в `Interpreter.builtins`. Сигнатура реализации:

```go
type Builtin struct {
	Name    string
	Arity   ArityKind // Fixed(n) → проверка на семпроходе; Variadic/Overloaded → в рантайме
	Fn      func(args []value.Value, pos ast.Position) (value.Value, error)
}
```

Все встроенные **затеняемы** объявлением `пусть` того же имени — с предупреждением-диагностикой
(не ошибка; SPEC §6). Полные сигнатуры и поведение — `docs/stdlib.md`; здесь — состав 003 и
точки отказа.

| Категория | Функции (арность) | Ключевые рантайм-ошибки |
|---|---|---|
| **Вывод** | `печать(…)` *(вариативная)* | — |
| **Преобразование** | `строка(x)`, `целое(x)`, `дробное(x)`, `число(x)`, `булево(x)`, `тип(x)` *(фикс. 1; `тип` зарезервирован лексером — недостижим из синтаксиса, v2)* | парсинг `целое("3.14")`/мусор → ошибка типа |
| **Агрегаты** | `сумма(s)`, `количество(s)`, `среднее(s)`, `мин(s)`, `макс(s)` *(фикс. 1)* | `среднее/мин/макс` на пустом списке → `«<имя>: список пуст»`; нечисловой/несравнимый элемент → ошибка типа |
| **Списки** | `длина(s)` *(перегр. тип)*, `добавить(s,x)`, `соединить(s1,s2)`, `срез(s,i,j)`, `содержит(s,x)`, `найти(s,x)`, `копия(s)`, `обратить(s)`, `сортировать(s)` *(фикс.)*, `диапазон(stop)` / `диапазон(start,stop)` *(перегр. арность 1\|2 → рантайм)* | `срез` вне `[0..длина]` → `«срез: индексы вне диапазона»`; `добавить` при активной итерации → `«список изменён во время итерации»`; `сортировать` несравнимых → ошибка типа |
| **Строки** | `длина(s)` *(перегр. со списком)*, `подстрока(s,i,j)` *(фикс. 3)* | `подстрока` вне `[0..длина]` → `«подстрока: индексы вне диапазона»` |
| **Дата/время** *(004)* | `сегодня()` *(фикс. 0, через `Clock`)*, `дата(г,м,д)` / `дата("ГГГГ-ММ-ДД")` *(перегр. 3\|1)* | невалидные компоненты / неразбираемая строка → ошибка выполнения (точные тексты — `docs/source-metric-model.md §SM-9`) |
| **Дата/время** *(008)* | `вчера()` / `завтра()` *(фикс. 0, через `Clock`)* — `сегодня()∓1` календарный день (Go `AddDate`, без операторной арифметики) | только арность |
| **Длительность** *(008)* | `длительность(значение, единица)` *(фикс. 2)* → `Длительность{значение, единица}` без нормализации; `значение`: `Целое`, `единица` ∈ {`сек`,`мин`,`час`,`дн`,`нед`,`мес`} | `значение`/`единица` неверного типа → ошибка типа; неизвестная единица → ошибка выполнения (тексты — §8.3) |
| **Конвертеры** *(008)* | `в_секундах(d)`, `в_минутах(d)`, `в_часах(d)`, `в_днях(d)` *(фикс. 1)* → `Целое` через карту множителей (сек 1, мин 60, час 3600, дн 86400, нед 604800); деление целочисленное (усечение к нулю) | `d` не `Длительность` → ошибка типа; `d.Unit == "мес"` → ошибка выполнения (мес не приводится без даты-якоря); переполнение `Целое` (тексты — §8.3) |
| **Процессные** *(006)* | `статус_процесса(id)`, `состояние_процесса(id)`, `задачи_пользователя(исп.)` *(фикс. 1, через `i.runtime`/`Store`)* | неизвестный id / сбой `Store` → ошибка выполнения (точные тексты — `docs/engine-model.md §EN-8`) |

- **`печать`** — строковые представления (§7) через один пробел + перевод строки; `печать()` →
  пустая строка; возвращает `Пусто`. Пишет в `Interpreter.out`.
- **`добавить`** — единственный мутатор: меняет `*s.Elems` на месте, возвращает `Пусто`.
- Все прочие операции над списками (`соединить/срез/копия/обратить/сортировать`) возвращают
  **новый** список.
- **Типы аргументов** не проверяются на семпроходе (динамика): несовместимый тип всплывает в
  рантайме первой же операцией с позицией вызова (`CallExpr.Pos()`).
- **Deferred-функций больше нет.** В 008 активированы последние 7 (`вчера`/`завтра`/`длительность`/
  `в_секундах`/`в_минутах`/`в_часах`/`в_днях`); реестр — 35 активных, 0 deferred. (`дата`/`сегодня`
  активированы в 004, три процессных — в 006; см. §6 и `builtins.go`.) Механизм deferred-заглушек
  (`Builtin.Deferred`) оставлен инертным backstop'ом.

## §7. Строковое представление значений и печать

`строка(x)` и `печать` используют единое представление (канон — `docs/stdlib.md`
«Строковое представление значений», согласован с SPEC §4):

| Тип | Представление | Пример |
|---|---|---|
| `Целое` | десятичная запись | `42`, `-5` |
| `Дробное` | см. политику ниже | `3.14`, `1.0`, `2175.0`, `1000000.0` |
| `Строка` | сам текст, без кавычек | `привет` |
| `Булево` | `истина` / `ложь` | `истина` |
| `Пусто` | `пусто` | `пусто` |
| `Список` | `[` элементы через `, ` (рекурсивно через `строка`) `]` | `[1, две, истина]` |
| `Запись` | `{` `поле: значение` через `, `, **в порядке полей** `}` | `{номер: 7, сумма: 1000}` |

Строки внутри `Список`/`Запись` печатаются **без** кавычек (как на верхнем уровне).

**Политика форматирования `Дробное` (закрывает пробел SPEC):**

```
строка(Дробное v):
	если math.IsInf(v, 0) или math.IsNaN(v)     // спец-значения (только из переполнения float) — R1.1
		вернуть strconv.FormatFloat(v, 'g', -1, 64)   // "+Inf"/"-Inf"/"NaN" как есть, БЕЗ ".0"
	verb := 'g'
	если 1e-4 ≤ |v| < 1e16                      // бизнес-диапазон → фиксированная запись (R1)
		verb := 'f'                              // иначе 'g' сократил бы 1000000.0 до "1e+06"
	s := strconv.FormatFloat(v, verb, -1, 64)   // кратчайшая обратимая запись
	если s не содержит '.', 'e', 'E'            // т.е. выглядит целым ("2175", "1000000", "5")
		s += ".0"                                // принудительная дробная часть → "2175.0", "1000000.0"
	вернуть s
```

- Кратчайшее (`-1`) представление однозначно восстановимо в тот же `float64`. Для бизнес-диапазона
  `|f| ∈ [1e-4, 1e16)` берётся **фиксированная** запись (`'f'`), чтобы целочисленное Дробное
  печаталось как `1000000.0`, а не `1e+06`; вне диапазона — научная нотация как у Go (`1e20` → `1e+20`).
- Принудительная `.0` гарантирует, что `Дробное` всегда визуально отличимо от `Целое`
  (`2175.0`, не `2175`) — этого требуют golden-примеры (`функция.ladix` → `2175.0`).
- Особые значения (достижимы только переполнением float, т.к. деление на ноль — ошибка):
  `+Inf`/`-Inf`/`NaN` отсекаются **отдельной первой веткой** (`math.IsInf`/`math.IsNaN`) и
  печатаются как их даёт `strconv` (`+Inf`, `-Inf`, `NaN`) — **без** принудительной `.0` (иначе
  `NaN` стал бы `NaN.0`: проверка «выглядит целым» по набору букв не ловит заглавное `N`, R1.1).
  В golden-примерах не встречаются.

## §8. Ошибки рантайма

### §8.1. Категории и формат

Типизированные ошибки в `internal/errors`, каждая несёт `Line, Col int` и `Msg string`,
реализует `error`, дружелюбна к `errors.Is/As`. Релевантные eval:

- **`СемантическаяОшибка`** (стадия 3): повтор объявления, арность, контекст
  `вернуть`/`прервать`/`продолжить`, необъявленная функция, deferred-конструкции.
- **`ОшибкаТипа`** (стадия 4): несовместимые операнды, условие не `Булево`, `для` не над
  `Список`, индекс/поле неверного типа.
- **`ОшибкаВыполнения`** (стадия 4): деление на ноль, переполнение int64, индекс вне диапазона,
  лимит рекурсии, рантайм-ошибки стдлиб (пустой агрегат, индексы среза).

Все — **fail-fast**: первая ошибка останавливает исполнение (накопителя в eval нет). Формат
вывода (CLI, §10):

```
Ошибка в строке N, колонка M:
<полезная нагрузка>
```

`N, M` — с 1, `M` — в рунах. Опциональная строка-источник с кареткой `^` под колонкой — UX,
не контракт.

### §8.2. Привязка позиции к узлу

| Ошибка | Узел → позиция |
|---|---|
| деление на ноль, переполнение, тип/сравнение бинарных | `BinaryExpr` → токен **оператора** |
| тип унарного (`-`/`не`) | `UnaryExpr` → токен оператора |
| условие не `Булево` | выражение условия → `Cond.Pos()` |
| `для` не над `Список` | `ForStmt` → `Iterable.Pos()` |
| индекс вне диапазона / индекс не `Целое` / не индексируется | `IndexExpr.Pos()` (начало `target`) |
| нет полей у значения | `FieldExpr.Pos()` (начало `target`) |
| необъявленная переменная / функция-как-значение | `Ident.Pos()` |
| арность / не функция / глубина рекурсии / рантайм-ошибки стдлиб / deferred-вызов | `CallExpr.Pos()` (= `Callee.Pos()`) |
| deferred-узлы (`RunProcessExpr`, `*Action`, `DurationLit`) | `node.Pos()` |

Контрольный golden: `ошибка.ladix` строка 5 `печать(всего / делитель)` → деление на ноль на
позиции токена `/` → **строка 5, колонка 14**.

## §9. Семантический проход (стадия 3)

`Analyze(prog *ast.Program) error` — лёгкий проход по AST **до** исполнения, **fail-fast**
(возвращает первую ошибку или `nil`; накопителя нет). Делает только то, что разрешимо
статически; flow-зависимое оставляет рантайму.

**Шаг 1 — регистрация деклараций.**
- Все top-level `FunctionDecl` → `funcs` (forward-вызовы разрешены). Повтор имени функции →
  `«функция 'f' уже объявлена в строке N»`.
- top-level `источник/метрика/процесс/триггер` в подмножестве B **до семпрохода не доходят**:
  парсер 002 не строит для них AST-узлов и отвергает раньше — на **стадии 2** как
  `ОшибкаРазбора «неожиданный токен '<kw>'»` (`источник продажи` → «неожиданный токен
  'источник'»). Граница соблюдена (программа отвергается, тихого no-op нет), но через парсер,
  а не deferred-семпроход. Deferred-ошибку `«конструкция … не поддерживается в этой версии»`
  семпроход выдаёт только для узлов, которые парсер **реально строит** — reserved-узлы и
  `DurationLit` (см. Шаг 2). Перенос отсечения декларатива в стадию 3 потребовал бы расширения
  грамматики/AST 002 (вне scope v1).

**Шаг 2 — обход тел функций и top-level statements.** Для каждой области (кадр функции / global;
блоки область не открывают):
- собрать множество имён `пусть` этой области; **повтор `пусть x`** в той же области (в т.ч. в
  разных ветках `если`, в `для x` при уже объявленном `x`) → `«'x' уже объявлено в строке N»`;
- **`вернуть`** вне тела функции (на top-level) → `«'вернуть' допустимо только внутри функции»`;
- **`прервать`/`продолжить`** вне `пока`/`для` → `«'прервать' допустимо только внутри 'пока'
  или 'для'»` (аналогично `продолжить`);
- **`CallExpr` с `Ident`-callee `f`**: пусть `V` — множество имён-переменных области (`пусть` +
  параметры). Если `f ∈ V` → **в рантайм** (переменная; функция-ли — решит §5.2). Иначе если
  `f` — пользовательская/активная встроенная → ок; если deferred-встроенная → deferred-ошибка;
  если ничего из этого → `«функция 'f' не объявлена»`. Для разрешённого вызова фикс. арности —
  проверить число аргументов → `«'имя' принимает N аргументов, передано M»`;
- **reserved-узлы** (`AssignAction/CallAction/NotifyAction`, `RunProcessExpr`) и
  **`DurationLit`** в любом месте → deferred-ошибка.

**Что НЕ делает семпроход (оставлено рантайму, flow-зависимо):**
- declaredness **переменной** в позиции значения — зависит от порядка top-level `пусть`
  (`печать(порог)` до `пусть порог = 100` → рантайм `«не объявлено»`);
- любые проверки **типов** (динамическая типизация);
- арность вариативных/перегруженных встроенных (`печать/диапазон/длина`).

## §10. CLI, recover-барьер и приёмка

### §10.1. `ladix run <файл>`

Конвейер: **лексер** → **парсер** (синтаксические ошибки — накопленные, печать и выход) →
**`Analyze`** (семпроход; первая ошибка → печать и выход) → **исполнение** (`Interpreter.Run`).
Флаг `--max-depth N` (по умолчанию 10000) задаёт лимит глубины рекурсии.

### §10.2. Recover-барьер и коды возврата

Граница CLI-подкоманды обёрнута `defer recover()`:

- штатные ошибки Ladix (`ОшибкаТипа`/`ОшибкаВыполнения`/`СемантическаяОшибка`/…) форматируются
  по §8 в **stderr** → код **1**;
- непредвиденная Go-паника (инвариант «не должно случиться») → дженерик
  `«внутренняя ошибка интерпретатора»` в stderr, **без** Go stack trace → код **1**;
- ошибка использования CLI (нет файла, неверный флаг) → код **2**;
- успех → код **0**.

Штатные ошибки (деление на ноль, переполнение, индекс, лимит рекурсии) проверяются **явно** и
**никогда** не доходят до паники.

### §10.3. Приёмка фичи 003

**Golden-прогон `ladix run`:**

| Программа | Ожидание |
|---|---|
| `hello` | stdout `Привет, Уклад!`, код 0 |
| `арифметика` | stdout `14 20` / `3 2` / `3.4` / `25` / `истина` / `истина`, код 0 |
| `условие` | stdout `категория: средний` / `чётная сумма`, код 0 |
| `цикл` | stdout `сумма чётных: 30` / `дорогие: [250, 400]` / `первая степень двойки > 16: 32`, код 0 |
| `функция` | stdout `2175.0` / `0`, код 0 |
| `факториал` | stdout `120` / `1`, код 0 |
| `ошибка` | stderr `Ошибка в строке 5, колонка 14:` / `деление на ноль`, код 1 |

**Табличные тесты (по слоям, `testing`):** выражения (приоритеты `2+3*4`→14, промоушен,
короткое замыкание, индексация, сравнения), переменные/области (функциональный scope: `пусть` в

диапазона). Печать перехватывается через инжектированный `out` (`bytes.Buffer`).

**Гейты:** `go build` без ошибок, `go vet ./...` чисто, `gofmt` без диффа, `-race` без гонок,
тесты на все слои зелёные.
