# Модель диагностик Ladix — якорь M-DX (фича 012-mdx-diagnostics)

> **Статус:** канон формулировок диагностик для вехи M-DX. Код берёт тексты scope A
> **дословно отсюда** (конституция, Принцип VIII «тексты — дословно из docs»). Перенос
> канона в большой `SPEC §13.4` — зона архитектора на шве (FR-013), в ветке `012-*` НЕ
> делается. Этот документ — единый источник истины для §MDX-разделов до синка SPEC.

## §MDX-0. Назначение и границы

M-DX поднимает качество диагностик для бизнес-автора `.ladix`. Два среза:
- **DX1** — подавление фантомного каскада парсера (поведение; `contracts/parser-recovery.md`).
- **DX2** — бизнес-понятные формулировки + полнота каталога + подсказки + витрина (этот документ).

**Двухстрочный канон (НЕ меняется):** `Ошибка в строке N, колонка M:`⏎`<текст>`. Позиция
(строка+колонка, с 1, в рунах) обязательна у 100% диагностик. Коды (`L-*`/`SE-*`) —
ВНУТРЕННИЕ, наружу не выводятся.

## §MDX-1. Scope A — переформулируемые тексты (бизнес-формулировки)

Де-жаргонизация: убрать внутренние термины «токен»/«литерал». Минимальные точечные замены
(всё прочее в L-*/SE-* сохранено дословно — минимальный дифф):

| Код | Было | Стало | Источник |
|-----|------|-------|----------|
| SE-UNEXPECTED | `неожиданный токен '%s'` | `неожиданный элемент '%s'` | `parser/errors.go` msgUnexpected |
| SE-INT-RANGE | `целочисленный литерал вне диапазона типа Целое '%s'` | `целое число '%s' вне диапазона типа Целое` | `parser/errors.go` msgIntRange |
| L-5 | `незакрытый строковый литерал` | `незакрытая строка в кавычках` | `lexer/messages.go` msgUnterminatedStr |
| L-6 | `незакрытый строковый литерал (перевод строки внутри строки запрещён)` | `незакрытая строка в кавычках (перевод строки внутри строки запрещён)` | `lexer/messages.go` msgNewlineInStr |
| L-8 | `неверный числовой литерал '%s'` | `неверная запись числа '%s'` | `lexer/messages.go` msgBadNumber |

**Сохранены дословно (рассмотрены, НЕ класс «токен/литерал»):** L-7 «неизвестная
escape-последовательность '%s'» и L-9 «… неизвестный суффикс длительности. Допустимые: …» —
устоявшиеся техтермины с контекстом (L-9 уже перечисляет допустимые единицы). Псевдо-лексемы
виртуальных токенов наружу — уже русифицированы: `конец строки`/`увеличение отступа`/`конец
блока`/`конец файла` (используются в текстах SE-UNEXPECTED/SE-EXPECTED как читаемые имена).

## §MDX-4. Подсказки «возможно, вы имели в виду…»

Дешёвый детерминированный модуль (`parser/suggest.go`, Левенштейн). **Скоуп вехи — парсер-side по
ограниченным словарям, которыми владеет парсер:** валидные атрибуты деклараций источник/метрика
(к SE-UNKNOWN-ATTR). Формат суффикса: `; возможно, вы имели в виду '<кандидат>'?`. Порог — малое
расстояние; при равенстве выбор стабилен (порядок словаря). Прецедент текста — `SPEC.md:641`.

**ОТЛОЖЕНО (явный долг, не сужено молча):** подсказки **по объявленным ИМЕНАМ** (переменные/
функции) требуют symbol-table из `eval` (analyze-проход), а `eval` в этой вехе заморожен (FR-021).
Кандидат на отдельную фичу, когда бэкенд разморозится.

## §MDX-5. Мутпроба M1 (§7.6 хартии) — зафиксированный результат

Прогон same-line sync-lead в M1-конструкциях (числа — живой прогон бинаря на ветке, минимал):
- **Процесс, не-шаг (sync-lead `если`):** каскад 2 → исправлен до **1** (`parse_decl.go`, тот же
  consume-before-error; контроль: не-sync-lead `123` и так давал 1). Sync-lead-специфично → DX1.
- **Field-block (`поля: если`) и metric-window (`период: последние если`):** минимал = **2**, в
  широком файле (bleed от смежной строки тела/блока) = **3** (НЕ 5/3 — прежняя запись была ошибочна).
  Каскад **sync-lead-ЗАВИСИМ**, а НЕ «одинаков для любого токена»: ведущее `если` рождает фантомный
  re-dispatch (+1 «неожиданный элемент 'конец строки'»), тогда как не-sync-lead `123`/`+` его НЕ
  дают (ровно **1**). Это ТОТ ЖЕ sync-lead фантомный класс, что лечит DX1, но на
  **decl-attribute-trailing** пути (`parseSourceDecl`/`parseMetricDecl`), который DX1 НЕ трогал
  (залоченный scope DX1 = sync-lead в позиции **выражения**). Пре-существующее поведение (на `master`
  идентично); **отложено** в будущую фичу «decl-line recovery» (бэклог B). Характеризационный замок
  `TestDeclAttributeTrailingSyncLeadCascade_DeferredDebt` (`recover_test.go`) лочит 2/2/1, чтобы
  отложенный долг не дрейфовал молча. Не «закрыто тихо».
- **NB по истории:** commit-message коммита `981bb6a` содержит устаревшее (теперь опровергнутое
  живым прогоном) описание этого каскада — числа 5/3 и «одинаков для любого токена». Авторитетная
  запись — настоящий §MDX-5; коммит не переписываем, `--no-ff` мерж сохранит его как исторический
  артефакт.

## §MDX-6. Согласование Принципа VIII (для архитектора на шве)

v1-эровый канон VIII требует «тексты дословно из SPEC §13, переформулировать запрещено». Хартия v2
§1 поднимает бизнес-понятную диагностику в продуктовую ценность (гейт `v2-charter.md:143`). Scope A
переформулирован; новый канон размещён ЗДЕСЬ (VIII допускает «дословно из docs»), код берёт дословно
отсюда. **Действие архитектора на шве:** перенести §MDX-1 в `SPEC §13.4`; обновить таблицу §13
каталога; при желании — MINOR-уточнение Принципа VIII для v2 (эволюция scope-A канона через docs).
Транзиторное расхождение `SPEC §13.4` ↔ код на время ветки — известный отложенный синк (FR-013).
