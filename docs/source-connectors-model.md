## §SC-0 Граница фичи 010 (что A1 делает и не делает)

**Делает.** Снимает три ограничения §12 SPEC для источников:
1. Атрибут `тип:` источника — значения `json` (как v1), `csv`, `ndjson`.
2. Блок схемы `поля:` — объявление типизированных полей записи (`Целое`/`Дробное`/`Строка`/`Логическое`/`Дата`).
3. Распознавание дат: поле, объявленное `Дата`, парсится из строки ISO `ГГГГ-ММ-ДД` в `value.Дата`.

**НЕ делает (вне A1, §SC-12):** окна метрик (`последние N <ед>` — это A2/011), БД/API/HTTP-коннекторы, `адрес:`/`разделитель:`/`кодировка:`, live-reload, базовый каталог-конфиг, мультиисточник на метрику, операторную арифметику дат. Фронтенд `где`/`агрегат`/`период`/`по_дате` и контракт `Store` **не трогаются**. Движок/`ProcessRuntime`/условие триггера — **не трогаются**.

**Несущее свойство (инвариант 3 хартии §5):** изменения — чистый фронтенд + загрузчик. Лексер/парсер/AST/семантика расширяются аддитивно; **все программы v1 остаются валидными** (источник без `тип:`/`поля:` ведёт себя ровно как v1 — JSON schemaless).

## §SC-2 AST-контракт (расширение §SM-2)

`SourceDecl` (`ast/decl.go:21`) сегодня несёт только `Name`/`File`/`FilePos`. Расширяем **аддитивно**:

```go
type SourceDecl struct {
    declBase
    Name    Ident
    File    StringLit
    FilePos Position
    Type    Ident       // НОВОЕ: значение тип: (json|csv|ndjson); zero-value Name=="" → json (A1-2)
    TypePos Position     // НОВОЕ: позиция атрибута тип: (presence: Line!=0)
    Fields  []FieldDef   // НОВОЕ: объявленная схема поля:; nil/пусто → schemaless (A1-3)
    FieldsPos Position    // НОВОЕ: позиция атрибута поля: (presence: Line!=0)
}
```

Новый листовой узел AST (в `ast/decl.go`, рядом с `SourceDecl`):

```go
// FieldDef — одно объявление поля в блоке поля: (имя: ТипПоля)
type FieldDef struct {
    Name     Ident     // имя поля (произвольный идентификатор)
    TypeName Ident     // имя типа (Целое|Дробное|Строка|Логическое|Дата) — резолвится семантически
    Pos      Position  // позиция строки объявления поля
}
```

- **§SC-D-1 (presence-конвенция).** Наличие `тип:`/`поля:` отслеживается `Pos.Line != 0` (как `MetricAttrPos`), а не nil. Это совместимо с конструктором `NewSourceDecl`, который для v1-формы получает `Type`/`Fields` нулевыми.
- **§SC-D-2 (листовость).** `FieldDef` несёт локальную `ast.Position`, не импортирует `errors` (конституция IV/VII). `ast` остаётся листовым.
- **§SC-D-3 (конструктор).** `NewSourceDecl` сохраняет текущую сигнатуру для совместимости вызовов; `Type`/`Fields` заполняются парсером сеттер-присваиванием (`sd.Type = …`), как `MetricDecl.Attrs`. (Альтернатива — расширить сигнатуру; выбрана сеттер-форма, чтобы не трогать иные вызовы конструктора.)

## §SC-3 Переход лексера (расширение §SM-2; конституция II/VI)

- **§SC-D-RESERVE (ключевая развилка лексера — ИСПРАВЛЕНО после верификации).** Слово `тип` сегодня в `reservedWords` (`lexer/keywords.go:29`) → даёт L-11 lex-ошибку и **не порождает токен**. **Ловушка (верификация):** builtin с именем `тип` ЗАРЕГИСТРИРОВАН (`builtins.go:75 add(fixed("тип",1,builtinTip))`); единственное, что держит `тип(x)` недостижимым, — лексер-резерв. Если просто разрезервировать `тип` в `IDENT`, то `тип(5)` распарсится как вызов builtin `тип` → **СЛУЧАЙНО активирует `тип(x)`**, что хартия §3/§9 запрещает («вне v2»).
  - **Решение:** `тип` делается **ключевым словом `KW_TYPE`** (новый `TokenType`), а НЕ обычным `IDENT`. Убирается из `reservedWords`, добавляется `"тип": KW_TYPE` в `keywords` (`keywords.go`). Парсер `parseSourceDecl` матчит атрибут по `attrTok.Lexeme == "тип"` (как уже делает для `"файл"` = `KW_FILE`; матч по сырой лексеме, не по типу токена).
  - **Последствие для `тип(x)`.** После A1 `тип(5)` = `KW_TYPE` `(` `5` `)`. В выражении `KW_TYPE` **не начинает выражение** (`parsePrimary` его отвергает) → **парс-ошибка** → `тип(x)` ПО-ПРЕЖНЕМУ недостижим, `builtinTip` остаётся dormant, **достижимость 34 builtin'ов сохраняется**. Меняется только КАТЕГОРИЯ диагностики (lex→parse), не факт блокировки. Обновляются: 009-тест `TestDocsAlignmentA4TipReserved` (см. §SC-10 #7) и комментарии `builtins.go:57-59`/`builtins_test.go:63` (механизм: keyword, не reserved).
  - **`поля` ОБЯЗАН остаться `IDENT`** (НЕ keyword): сегодня `поля` — обычный идентификатор, и v1-программа МОЖЕТ использовать `поля` как имя переменной; превращение в keyword сломало бы такую программу (нарушение инварианта обр. совместимости). Парсер матчит `поля:`-атрибут по `attrTok.Lexeme == "поля"` (работает для `IDENT`). Асимметрия с `тип` принципиальна: `тип` уже был зарезервирован (ни одна валидная v1-программа его не использует как идентификатор) → keyword-изация безопасна и НЕОБХОДИМА (блокирует `тип(x)`); `поля` ничем не зарезервирован → keyword-изация ОПАСНА.
  - Тип-аннотации `Целое`/`Дробное`/`Строка`/`Логическое`/`Дата` — **остаются `IDENT`**, резолвятся семантически (§SC-4). `json`/`csv`/`ndjson` — **`IDENT`** (голое значение `тип: csv`), резолвятся семантически.
- **§SC-D-LEX-MIN.** Изменения лексера A1: (1) удалить `"тип"` из `reservedWords` (счётчик-комментарий 12→11); (2) добавить `KW_TYPE` в `TokenType` и `"тип": KW_TYPE` в `keywords` (комментарий keyword-счётчика +1). `KW_TYPE` НЕ добавляется в `startsExpression`/`parsePrimary`. Никаких новых единиц/литералов. (Конституция I — минимальная поверхность; II — ручной парсер.)

## §SC-4 Переход парсера (расширение §SM-3; конституция II/IV/VI)

`parseSourceDecl` (`parse_decl.go:41`) — цикл атрибутов сегодня жёстко допускает только `файл`. Расширяем:

- **§SC-D-PARSE-1.** Цикл атрибутов перевести на `switch attrTok.Lexeme` с валидатором `sourceAttrName(lexeme) ∈ {файл, тип, поля}` (зеркало `metricAttrName`, `parse_decl.go:95`). Неизвестный атрибут → `msgUnknownAttr(lexeme)` (как сейчас). Дубликат атрибута → `msgDuplicateAttr` через `seen map` (паттерн из `parseMetricDecl`).
- **§SC-D-PARSE-2 (`тип:`).** `тип` `:` `IDENT(json|csv|ndjson)` `NEWLINE`. Значение читается как `Ident` (голый идентификатор), сохраняется в `sd.Type`, `sd.TypePos` = позиция атрибута. **Валидация множества значений — семантическая** (§SC-4-sem), не парсерная (парсер принимает любой `IDENT`, чтобы дать чистую доменную диагностику в Analyze, а не «ожидался json»).
- **§SC-D-PARSE-3 (`поля:` — вложенный блок).** `поля` `:` `NEWLINE` `INDENT` { `IDENT(имя)` `:` `IDENT(тип)` `NEWLINE` }+ `DEDENT`. Открытие блока — `openAttrBlock()` (`parse_decl.go:372`, уже эмитит и проверяет INDENT). Внутренний цикл — `for !p.check(DEDENT) && !p.check(EOF)`, собственный `seen map` на имена полей (дубль поля → `msgDuplicateAttr`/доменная), **восстановление через `continue`** (стиль `parseStepDecl`, чтобы собрать несколько `FieldDef`, а не падать на первой). Пустой `поля:` (INDENT сразу DEDENT) → `msgEmptyBlock`. Каждая строка → `FieldDef{Name, TypeName, Pos}`.
  - **Trap (из рекона):** внешний цикл `parseSourceDecl` потребляет одну строку-атрибут за итерацию с `NEWLINE`; для `поля:` после двоеточия вызывается `openAttrBlock()` рекурсивно ВНУТРИ итерации, затем внутренний цикл, затем `expect(DEDENT)`.
  - **Trap (восстановление внешнего цикла):** внешний цикл источника сегодня делает `break` на первом плохом атрибуте. Это сохраняется (источник — короткий блок); многострочное восстановление нужно только во ВНУТреннем `поля:`-цикле.

- **§SC-4-sem — Семантический проход (расширение §SM-4; конституция IX).** В `Analyze` (после регистрации источников) добавить проверки источника:
  1. **Значение `тип:`** ∈ {`json`,`csv`,`ndjson`} — иначе `semErr` (§SC-9 «неизвестный тип источника»). Позиция = `TypePos`.
  2. **`поля:` обязательно для csv/ndjson** (A1-3): если `Type ∈ {csv,ndjson}` и `Fields` пуст → `semErr` (§SC-9 «тип … требует объявления полей»). Позиция = `TypePos` (или decl).
  3. **Тип каждого поля** `FieldDef.TypeName.Name` ∈ {`Целое`,`Дробное`,`Строка`,`Логическое`,`Дата`} — иначе `semErr` (§SC-9 «неизвестный тип поля»). Позиция = `FieldDef.Pos`.
  4. **Дубликаты имён полей** — пойманы парсером (§SC-D-PARSE-3); семантика не дублирует.
  - Все четыре — статические (без чтения файла), на этапе Analyze, как существующие проверки 004 (цикл метрик, неизвестный источник).

## §SC-5 Конструируемые/аннотируемые типы (расширение §SM-5)

Множество аннотаций `поля:` и их отображение в `value`-типы:

| Аннотация в `поля:` | Значение `value` | Печать `TypeName()` |
|---|---|---|
| `Целое` | `value.Целое{V int64}` | `Целое` |
| `Дробное` | `value.Дробное{V float64}` | `Дробное` |
| `Строка` | `value.Строка{V string}` | `Строка` |
| `Логическое` | `value.Булево{V bool}` | `Булево` |
| `Дата` | `value.Дата{Year,Month,Day}` | `Дата` |

- **§SC-D-BOOL.** Аннотация `Логическое` отображается в значение `Булево` (исторический тип-имя значения). В диагностиках несовпадения «ожидался» печатается **аннотация** (`Логическое`), «получено» — фактический `TypeName()` значения. A1 принимает **ровно эти пять** имён (хартия/хендофф A1-4); прочее — `semErr` «неизвестный тип поля».
- **§SC-D-DATE.** `value.Дата` строится строгим `parseISODate(s)` (`eval/builtins_date.go:61`, 10-байт `ГГГГ-ММ-ДД`, валидация календаря/високосного). Тот же парсер, что у builtin `дата(...)` — единый канон формата.

## §SC-6 Загрузчик и коэрсия (расширение §SM-8.1; конституция I/III/V)

`loadSource` (`source_loader.go:24`) — диспетчер по `decl.Type`:

```
name := decl.Name.Name; if cache hit → return
path := decl.File.Value
switch decl.Type.Name {            // "" → json (A1-2)
case "", "json":   recs = loadJSON(decl, path)   // текущий путь lines 42-78
case "csv":        recs = loadCSV(decl, path)     // НОВОЕ
case "ndjson":     recs = loadNDJSON(decl, path)  // НОВОЕ
}
if len(decl.Fields) > 0 { recs = applySchema(decl, recs) }  // §SC-D-COERCE
i.recordCache[name] = recs
```

- **§SC-D-CSV.** `loadCSV` использует `encoding/csv` (stdlib — **0 новых зависимостей**, конституция I; это формат данных, не парсер языка → конституция II не нарушена; аналог `encoding/json` для JSON-источника). 1-я строка — заголовок (имена столбцов). UTF-8, разделитель `,`. Сопоставление столбцов с `поля:`:
  - Заголовок ОБЯЗАН содержать все объявленные поля; отсутствует столбец → load-ошибка `…в заголовке CSV … отсутствует поле '<поле>'` (позиция decl).
  - Лишние столбцы — игнорируются (A1-6).
  - Каждая ячейка — `Строка`; затем коэрсия в объявленный тип (`поля:` обязательно для csv, §SC-4-sem).
- **§SC-D-NDJSON.** `loadNDJSON` читает построчно; пустые строки пропускаются (A1-9); каждая непустая — независимый JSON-объект через `decodeValue`-логику (переиспользование JSON-декодера на один объект). Не-объект на строке → load-ошибка «запись N не является объектом». `поля:` обязательно (§SC-4-sem) → applySchema валидирует/коэрсит.
- **§SC-D-CACHE.** Новые загрузчики ТОЖЕ пишут `i.recordCache[name]` (кеш по имени, per-run). Путь — `os.Open(path)` от CWD (§12, НЕ менять).

**§SC-D-COERCE — матрица коэрсии/валидации `applySchema(decl, recs)`** (применяется при `len(decl.Fields) > 0`):

Для каждой записи N (с 1) и каждого объявленного `FieldDef{name, T}`:
1. **Отсутствие** (A1-5): поля `name` нет в записи → `runtimeErr` «отсутствует объявленное поле». (Записи с лишними полями — ок, A1-6.)
2. **Коэрсия значения `v` в тип `T`:**

| `T` \ источник | CSV (всё `Строка`) | JSON/NDJSON (типизировано) |
|---|---|---|
| `Строка` | оставить как есть | требуется `Строка`; иначе A1-10 |
| `Целое` | `strconv` строки→int; ошибка→A1-10 | `Целое` ок; `Дробное`→A1-10 (демоушена нет) |
| `Дробное` | `strconv` строки→float; ошибка→A1-10 | `Дробное` ок; `Целое`→промоушен в `Дробное` (A1-10) |
| `Логическое` | `истина`/`ложь`→`Булево`; иначе A1-10 | `Булево` ок; иначе A1-10 |
| `Дата` | `parseISODate`; ошибка→A1-7 | `Строка`→`parseISODate` (A1-7); иначе A1-10 |

   - **§SC-D-COERCE-INT.** Целое из CSV — без `.`/`e`/`E`; со знаком десятичной точки → ошибка (а не молчаливое Дробное), чтобы CSV-Целое было ровно Целое (инвариант формы числа, §9.3 SPEC).
   - **§SC-D-COERCE-FLOAT.** Дробное из CSV принимает и `1200000` и `1200000.5` (обе → `Дробное`).
   - **§SC-D-COERCE-PROMO.** Единственный кросс-тип промоушен — `Целое→Дробное` (A1-10), как в `arith.go:233`. Прочее несовпадение — `runtimeErr` (A1-10).
3. **Запись с коэрснутыми значениями** заменяет исходную (порядок ключей сохраняется; лишние поля остаются).

- **§SC-D-RECORD (механизм, верифицировано).** `value.Запись` (`record.go`) имеет приватные `keys`/`fields`, публичные `Keys() []string`, `Get(name) Value`, `NewRecord(keys, fields)` — **Set-метода НЕТ, `fields` неэкспортируем**. `applySchema` НЕ мутирует на месте, а **пересобирает**: `keys := r.Keys()`; `newFields := {}`; для каждого `k` в `keys`: `newFields[k] = r.Get(k)` (сохранить лишние поля как есть); затем для каждого `FieldDef{name,T}`: **присутствие = членство `name` в `keys`** (отличает «отсутствует» A1-5 от «есть, но `Пусто`/null» — последнее → несовпадение типа A1-10); коэрснуть `r.Get(name)`, записать в `newFields[name]`; вернуть `NewRecord(keys, newFields)`. **Пакет `value` НЕ трогается** (остаётся листовым, конституция VII).
  - **Edge (null/пустая ячейка):** объявленное поле со значением `Пусто` (JSON null) или пустой CSV-ячейкой (`""`) — НЕ «отсутствует» (ключ есть), а несовпадение/непарс: `Пусто`→A1-10 «ожидался <Тип>, получено Пусто»; `""`→A1-7/A1-10 непарс. Строгий контракт схемы M1 (смягчение — M-DX). Зафиксировать golden-кейсом.

- **§SC-D-EMPTY.** Источник из нуля записей со схемой — `applySchema` ничего не валидирует (нечего); метрика даёт пустой результат (§SM-10 `emptyWindowResult`). Совместимо с §9.7 SPEC.

## §SC-9 Реестр сообщений A1 (канон; расширение §SM-9)

Конвенция §SM-9: **без точки в конце**; `'…'` — идентификаторы/имена атрибутов/полей; `«…»` — строковые литералы (пути, значения, форматы); `<тип>` — из закрытого множества; **N с 1**; позиция = токен `источник` (load/coerce) либо `TypePos`/`FieldDef.Pos` (семантика). **§SC-9.A — Семантика (Analyze), `СемантическаяОшибка`:**
```
источник '<имя>': неизвестный тип источника '<знач>' (допустимо: json, csv, ndjson)
источник '<имя>': тип '<csv|ndjson>' требует объявления полей (поля:)
источник '<имя>': неизвестный тип поля '<знач>' (допустимо: Целое, Дробное, Строка, Логическое, Дата)
```
(Парсерные `неизвестный атрибут '<имя>'` / `атрибут '<имя>' уже задан` / `поле '<имя>' уже объявлено` — переиспользуют §SM-9.A `msgUnknownAttr`/`msgDuplicateAttr`.)

**§SC-9.B — Загрузка/коэрсия (рантайм), `ОшибкаВыполнения`, позиция = decl:**
```
источник '<имя>': запись N: отсутствует объявленное поле '<поле>'
источник '<имя>': запись N, поле '<поле>': ожидался <Тип>, получено <тип>
источник '<имя>': запись N, поле '<поле>': «<знач>» не является датой (ожидался формат ГГГГ-ММ-ДД)
источник '<имя>': запись N, поле '<поле>': «<знач>» не является целым
источник '<имя>': запись N, поле '<поле>': «<знач>» не является дробным
источник '<имя>': запись N, поле '<поле>': «<знач>» не является логическим (ожидалось истина/ложь)
источник '<имя>': в заголовке CSV «<путь>» отсутствует поле '<поле>'
источник '<имя>': некорректный CSV в «<путь>» (<деталь>)
источник '<имя>': запись N: некорректный JSON (<деталь>)
```
(`<Тип>` в «ожидался» — аннотация `поля:` (`Логическое`, не `Булево`); `<тип>` в «получено» — `TypeName()` значения. Существующие JSON-сообщения §SM-9.B — без изменений.)
