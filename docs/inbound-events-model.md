# Модель входящих событий (HTTP-приём) — `docs/inbound-events-model.md`

> Канон трека B «Входящие события». Активирует то, что v1 отложил как «Design Y» (HTTP-эндпоинт приёма
> событий, `docs/execution-model.md` EM-17.10, SPEC §12). Якорь для импл-чата: разделы §IE-0..§IE-8.
> Парность с исходящими эффектами: M2/M3 сделали надёжными **исходящие** эффекты (`вызвать`/`уведомить`
> через `--webhook`); этот трек добавляет **входящую** сторону — приём событий по сети.
>
> Статус: анкор верифицирован роем против живого кода (38 утверждений подтверждены; координаты file:line
> сверены; адверсариальный страх «гонка `NextEventID`» опровергнут — `SQLiteStore` транзакционен и
> `MaxOpenConns=1`).

## §IE-0. Разрез скоупа и границы

README §99 склеил **три ортогональные** фичи в одном буллете. Решающий факт разреза: событие-триггеры
матчатся по **имени** (`src/internal/daemon/events.go:32` → `eventTriggers(e.Name)`) и **не имеют строки
`trigger_state`** (`src/internal/store/types.go:63`; дубль-канон `docs/trigger-model.md:1493-1495`) —
значит латентный баг «хрупких ключей `trg-<N>`» физически **не на пути входящих событий**. Поэтому режем:

**ВХОДИТ в трек B (эта итерация):**
- HTTP-эндпоинт приёма событий внутри демона `serve` — «`emit` по сети»: новый продюсер в уже
  существующую durable-очередь `events`.

**ВЫНЕСЕНО НАРУЖУ (отдельные фичи/бэклог, НЕ в этом доке):**
- **Стабильные ключи триггеров** (хеш-подпись вместо порядкового `trg-<N>`) — самостоятельный малый
  durability-фикс; касается только метрика/расписание-триггеров, ортогонален сети.
- **Хеш-версионирование определений** (дрейф процесса под живым инстансом) — `reliability` «сценарий не
  требует»; минимум — снять хеш + лог, полный пиннинг = v2.
- **Дедуп входящих по `Idempotency-Key`** (новая таблица + миграция) — аддитивно поверх тонкого приёма
  (см. D-IE-5; если ретраи клиента станут болью).
- **Push-пробуждение** (досрочный тик при приёме, без ожидания `--interval`) — отдельное согласование.
- **Машинно-читаемый `--json`-ответ / audit-журнал** — часть C3, не трек B.

## §IE-1. Продуктовая модель приёма

Внешняя система Уклада (или любой источник) шлёт HTTP POST → демон кладёт событие в durable-очередь →
на ближайшем тике `drainEvents` матчит триггеры `когда событие E { … }` и исполняет их тела. До этого
трека единственный продюсер событий — CLI `ladix emit <имя> [json]` (`src/cmd/ladix/emit.go`); сеть
закрыта. Трек B добавляет сетевого продюсера, **не меняя** ни фронтенд (`когда событие`, грамматику), ни
контракт очереди в `Store`, ни `drainEvents`. Входящее по HTTP и входящее по `emit` событие
**неразличимы** ниже точки минта (одинаковая `store.Event`, одинаковый путь обработки).

## §IE-2. HTTP-контракт приёма

**(D-IE-4 = F4-A.)** Эндпоинт:

```
POST /events/{имя}
Тело: сырой JSON-payload как есть (или пусто)
```

- **`{имя}`** — последний сегмент пути, URL-декодируется (имена событий — Unicode-идентификаторы, включая
  кириллицу: `/events/падение_выручки`; клиент percent-кодирует, сервер декодирует). → `Event.Name`.
  **Матч строго байтовый, без Unicode-нормализации** (`events.go:71` `Event.Name == name`; `emit.go:44`
  сырой аргумент). Следствие-граница: клиент **обязан** слать имя в той же нормализации, что в исходнике
  `.ladix` (на практике NFC). NFD-сегмент даст другие байты → событие уйдёт в ветку «без триггеров»
  (`events.go:33-36`), молча `processed`. Серверная NFC-нормализация **отложена** осознанно: тянет
  `golang.org/x/text`, а проект stdlib-only (`src/go.mod` = единственная прямая зависимость
  `modernc.org/sqlite`). TODO-FACT: подтвердить, что лексер не нормализует идентификаторы (тогда
  байт-матч корректен).
- **Тело** — читается как сырая строка → `Event.PayloadJSON` **как есть, без парсинга на приёме**.
- **Толерантность к битому JSON (несущий инвариант, FR-IE-7):** невалидный JSON в теле **НЕ роняет
  приём** — событие ставится в очередь с сырым телом; валидацию делает `drainEvents`/`PayloadToRecord`
  (пустая `Запись` + лог, `src/internal/daemon/events.go:42`). 400 за «битый JSON» **не возвращаем**.
- **Лимит размера тела** — вне scope v1 (защита — обратный прокси, §IE-6). Реализация МОЖЕТ применить
  `http.MaxBytesReader` со щедрым дефолтом (превышение → `413`); это backlog, не блокер.

**Коды ответа:**

| Код | Когда | Тело (RU, golden) |
|---|---|---|
| `202 Accepted` | событие поставлено в очередь | `событие e-NNNNNN '<имя>' принято\n` |
| `400 Bad Request` | пустое имя (`POST /events/` без сегмента) | `ladix: пустое имя события\n` |
| `401 Unauthorized` | задан `--token`, заголовок не совпал/отсутствует | `ladix: неверный токен\n` |
| `405 Method Not Allowed` | метод не POST | `ladix: метод не поддерживается, только POST\n` |
| `500 Internal Server Error` | сбой `Store` при enqueue | `ladix: сбой хранилища\n` |

`202` (а не `200`) — честно отражает асинхронность: приняли в очередь, тело исполнится на тике (§IE-4).
`202` возвращается **только после успешного `EnqueueEvent`** (at-least-once, FR-IE-6). Ack-текст HTTP
(«принято») **намеренно отличается** от ack `emit` («поставлено в очередь», `emit.go:82`) — см. D-IE-8.

## §IE-3. CLI-модель

**(D-IE-2 = F2-A, D-IE-7 durability.)** Расширяем `serve` (НЕ новая подкоманда, НЕ `--webhook` — он занят
исходящим драйвером):

```
ladix serve [--db путь] [--interval D] [--max-depth N] [--webhook URL]
            [--listen host:port] [--token СЕКРЕТ] <файл>
```

- **`--listen host:port`** — opt-in. **Без флага `serve` работает РОВНО как сейчас** (нулевой регресс,
  FR-IE-1). Парсинг — зеркало `--interval` (`serve.go:82`, формы `--listen v` и `--listen=v`).
- **Требование `--db` (D-IE-7, FR-IE-4):** проверка `--listen` без `--db` ставится **ПЕРЕД** открытием
  сокета → ошибка CLI, exit 2: `ladix: --listen требует --db\n`. Без `--db` `serve` поднимает эфемерный
  `MemoryStore` (`serve.go:155`) — сетевой приёмник ответил бы `202` на событие, которое исчезнет при
  рестарте, нарушив обещанный at-least-once. Durability-граница — инвариант приёмки, не деталь.
- **`--token СЕКРЕТ`** (§IE-6) — опционально; env-двойник `LADIX_LISTEN_TOKEN`.
- **Bind синхронно и ВНЕ guard:** сокет открывается через `net.Listen("tcp", host:port)` **рядом с
  открытием SQLite** (`serve.go:146-153`), **вне** recover-guard — симметрично сбою открытия Store: ошибка
  (порт занят/нет прав) → прямой exit 2, детерминированно: `ladix: не удалось открыть сокет
  '<host:port>': <err>\n`. (Если открывать внутри guard, паника/ошибка дала бы exit 1 «внутренняя ошибка
  интерпретатора», `main.go:584-592` — это неверная категория для сбоя окружения.) Уже открытый
  `net.Listener` передаётся в `srv.Serve(ln)` (§IE-5).
- **Дефолт-граница loopback:** если `host` не loopback (`127.0.0.1`/`::1`/`localhost`) И `--token` не задан
  → стартовое предупреждение в stderr (не блокируем): `ladix: ВНИМАНИЕ: --listen на не-loopback адресе
  без --token — эндпоинт запускает процессы без аутентификации`.

## §IE-4. Модель исполнения — listener только enqueue

**(D-IE-3 = F3-A.)** Несущий инвариант: **Engine и Interpreter НЕ потокобезопасны** (Engine несёт
изменяемый стек `active`, `engine.go:43`; Interpreter — run-state `recordCache`/`today`); сериализация
держится ИСКЛЮЧИТЕЛЬНО на `d.mu` и инварианте «движок зовётся из одной горутины»
(`docs/execution-model.md` EM-17.7, строки 377/508/647: «один процесс ОС, всё синхронно в одной
горутине» / «один тик — последовательный проход» / «один поток исполнения движка»). HTTP-listener —
**вторая горутина**, поэтому:

1. **Хендлер касается ТОЛЬКО `Store`**, никогда — Engine/Interpreter. Делает ровно: проверка метода/auth →
   декод имени → чтение тела → **минт события общим хелпером** → ответ.
2. **Минт через общий хелпер (D-IE-8, рефактор):** вынести из `emitEvent` (`emit.go:58-85`) тонкий
   `enqueueEvent(st store.Store, name, payload string, clock engine.Clock) (id string, err error)`:
   `NextEventID` → `Event{ID, Name, PayloadJSON, CreatedAt: clock.Now(), Processed:false}` → `EnqueueEvent`.
   Его зовут **И** `emit.go` (после открытия своего Store), **И** HTTP-хендлер (на Store демона).
   **Ack-печать в хелпер НЕ входит** — хелпер возвращает `(id, error)`; `emit` печатает «поставлено в
   очередь» (без изменений), хендлер печатает «принято». Один путь минта → одинаковая семантика
   `ID`/`CreatedAt`; тексты ack различны намеренно (не выравнивать — сломает golden).
3. **`CreatedAt` минтится `engine.Clock` демона (D-IE-9), НЕ временем клиента и НЕ голым `time.Now()`** —
   иначе теряется детерминизм тестов (`FixedClock`). **FIFO-порядок** при этом гарантирует не `CreatedAt`,
   а **монотонный `NextEventID`**: `SQLiteStore` сериализует `CreatedAt` как `time.RFC3339` без долей
   секунды (`sqlite.go:677`) и сортирует `ORDER BY created_at ASC, id ASC` (`sqlite.go:685`) — события
   одной секунды получают идентичный `created_at`, и порядок держится **исключительно на `id ASC`**
   (счётчик `NextEventID`). `CreatedAt` — грубый внешний порядок; не закладываться на суб-секундное время.
4. **Тело исполняется асинхронно** обычным `drainEvents` на следующем тике под `d.mu` (`tick.go:13`) —
   ноль изменений в контракте обработки. Цена — задержка до `--interval` (дефолт 1m); push-пробуждение
   отложено (§IE-0).
5. **Конкурентный доступ к `Store` безопасен (подтверждённый факт, не TODO):** `SQLiteStore` ставит
   `db.SetMaxOpenConns(1)` (`sqlite.go:138`) — единственный коннект сериализует `EnqueueEvent` (хендлер)
   ∥ `ListUnprocessedEvents`/`MarkEventProcessed` (тик). `SQLiteStore` **не несёт in-memory счётчиков**
   (единственное поле `db *sql.DB`, `sqlite.go:18-20`); `NextEventID` транзакционен поверх таблицы
   `counters` (`sqlite.go:416-434`) — гонки на минте ID нет. `--db` обязателен (§IE-3) → Store всегда
   SQLite, не Memory.

## §IE-5. Жизненный цикл и graceful shutdown

`daemon.Run(ctx)` блокирующий (`daemon.go:71`); HTTP-сервер должен жить конкурентно и завершаться вместе
с демоном по тому же `ctx` (`signal.NotifyContext(SIGINT/SIGTERM)`, `serve.go:164`). Требуемый контракт
(stdlib-only — `WaitGroup` + `srv.Shutdown`, **без `errgroup`**: `go.mod` не несёт `golang.org/x/sync`;
симметрия с `ticker`+`defer Stop` в `daemon.go:73`):

1. **Старт:** `net.Listen` синхронно ВНЕ guard (bind-ошибка → exit 2, §IE-3); `srv.Serve(ln)` в горутине
   под `WaitGroup`.
2. **КРИТИЧНЫЙ инвариант порядка (FR-IE-6):** `srv.Shutdown(shutdownCtx)` и join сервер-горутины
   (`wg.Wait()`) **ОБЯЗАНЫ завершиться СТРОГО ДО `Store.Close()`**. Сейчас `Store` закрывается
   `defer sq.Close()` (`serve.go:152`); если сервер ещё сливает in-flight POST, его `EnqueueEvent`
   попадёт в закрытый коннект → потеря события, нарушение at-least-once. Механизм: координацию завершения
   (`srv.Shutdown` + `wg.Wait`) зарегистрировать как `defer` **внутри** guard-замыкания (позже по
   исполнению, чем `defer sq.Close()` на `serve.go:152`, который вне/раньше guard) → по LIFO раскрутке
   shutdown отрабатывает **до** `Close`. Порядок: перестать принимать → дослить in-flight → join → выйти.
3. `daemon.Run(ctx)` возвращается на `ctx.Done()` между тиками (как сейчас). События, принятые перед
   остановкой, остаются в durable-очереди и дренятся при следующем старте `serve` (at-least-once целостен).
4. **Нет утечки горутин (FR-IE-8) — это БАРЬЕР «не сломать», не новый тест.** Существующие замки уже гоняют
   прод-путь `buildServeDaemon`+`d.Run` и проверяют `NumGoroutine()`: `daemon_test.go:44-45` (after>before
   → fail), `serve_golden_test.go:365/370` (`waitGoroutines` требует `NumGoroutine() <= before`). Оба — БЕЗ
   `--listen`. Требование: (а) **без `--listen` сервер не стартует совсем** (нулевой регресс — эти замки
   остаются зелёными нетронутыми); (б) с `--listen` сервер-горутина join-ится (`wg.Wait()`) ДО возврата из
   serve-пути.

## §IE-6. Безопасность

**(D-IE-6 = F6-B.)** Эндпоинт **запускает бизнес-процессы по сети** (`когда событие E { запустить
процесс … }`) — открыть его без защиты нельзя.

- **`--token СЕКРЕТ` / env `LADIX_LISTEN_TOKEN`** — опционально, **по умолчанию ВЫКЛ** (обратная
  совместимость и локальная разработка). Если задан: хендлер сверяет заголовок `X-Ladix-Token` с секретом
  (constant-time сравнение `crypto/subtle`); несовпадение/отсутствие → `401` (§IE-2). Точное имя заголовка
  — TODO-FACT.
- **Дефолт-привязка loopback** + стартовое предупреждение при не-loopback без токена (§IE-3).
- **Граница v1 (задокументировать честно):** сильная аутентификация (HMAC-подпись тела, mTLS) **вне
  scope** — «внешняя аутентификация — задача обратного прокси». Путь отступления к HMAC **аддитивен**
  (новый опциональный режим проверки, синтаксис/Store не трогаются).

## §IE-7. Инварианты и тест-замки

Замки (httptest, симметрично исходящему `--webhook`: `webhook_cli_test.go`):

- **FR-IE-1 (регресс):** `serve` БЕЗ `--listen` — байт-идентичен текущему; сервер не стартует, сокет не
  открывается. Существующие `serve_golden`/m2/`daemon_test` NumGoroutine-замки остаются зелёными.
- **FR-IE-2 (изоляция движка):** хендлер не импортирует/не зовёт Engine/Interpreter — только `Store`+
  `engine.Clock`. Замок: статический (сигнатура хендлера принимает `store.Store`+`engine.Clock`, не `*Engine`).
- **FR-IE-3 (неразличимость):** golden «`POST /events/{имя}` `{json}` → `202 e-id` → тик `drainEvents` →
  тело триггера сработало с теми же значениями, что у `emit <имя> {json}`». **Имя в замке — кириллическое,
  с явным percent-кодированием** (ловит регресс URL-декода/нормализации, §IE-2).
- **FR-IE-4 (durability-граница):** `--listen` без `--db` → exit 2, текст замком; проверка ПЕРЕД `net.Listen`.
- **FR-IE-5 (bind-ошибка):** занятый порт → exit 2, текст замком (через занятый `net.Listen` в тесте).
- **FR-IE-6 (at-least-once + порядок shutdown):** `202` только после `EnqueueEvent`; сбой Store → `500`,
  событие НЕ теряется молча; `srv.Shutdown`+join завершаются ДО `Store.Close` (in-flight POST не пишет в
  закрытый коннект). Замок: мок-Store с ошибкой enqueue → `500`.
- **FR-IE-7 (толерантность payload):** `POST` с битым JSON-телом → `202` (НЕ 400); на тике — пустая
  `Запись` + лог, тело исполняется. Замок кусается, если приём начнёт валидировать JSON.
- **FR-IE-8 (нет утечки горутин, SC-007):** после `ctx`-cancel (SIGINT) сервер-горутина завершена и
  join-нута; опираемся на СУЩЕСТВУЮЩИЕ `daemon_test.go:44-45`/`serve_golden_test.go:365/370` как на барьер.
- **FR-IE-9 (auth):** с `--token` несовпадение/отсутствие → `401`; совпадение → `202`. Без `--token` любой
  POST → `202`.
- **FR-IE-10 (метод/имя):** `GET /events/x` → `405`; `POST /events/` (пустое имя) → `400`.
