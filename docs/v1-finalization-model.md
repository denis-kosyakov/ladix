# Модель финализации v1 (приёмка против рубрики §1–§9)

> **Якорь финализации v1.** Источник истины для приёмочного конвейера v1 Ladix:
> закрытие подтверждённых разрывов «док↔реальность», «чеклист↔факт» и
> «витрина↔скоуп» БЕЗ добавления новой языковой функциональности. Импл-чат
> работает строго по этому документу; любое расхождение или вопрос исполнителя =
> пробел якоря, закрывается ЗДЕСЬ до следующей задачи, а не додумыванием.
>
> Канон-ссылки: воспроизводимость и CLI — `README.md`; чеклист — `CHECKLIST.md`;
> витрина — `examples/` + `examples/MANIFEST.md`; стдлиб/тип — `docs/stdlib.md` +
> `docs/eval-model.md`; формат ошибок — SPEC §13 + `src/internal/errors/`;
> детерминизм примеров — `Clock` (`docs/source-metric-model.md §SM-7`/§SM-10) +
> golden-дисциплина `cmd/ladix/trigger_golden_test.go`.

## §VF-0. Состояние и цель

**Гейты на входе (HEAD `348ee64`, ветка `master`, up-to-date с origin).** Все
зелёные ИЗ `src/` (там лежит `src/go.mod`):

- `go build ./...` → PASS (exit 0).
- `go vet ./...` → PASS (exit 0).
- `go test ./... -count=1` → PASS, **10/10 пакетов `ok`**, ноль «no test files»:
  `cmd/ladix`, `internal/ast`, `internal/daemon`, `internal/engine`,
  `internal/errors`, `internal/eval`, `internal/lexer`, `internal/parser`,
  `internal/store`, `internal/value`.
- Рабочее дерево **грязное** (не блокер финализации, но фон): ` M .gitignore`
  (unstaged) + `?? src/ladix` (нетрекаемый собранный бинарник ~11 МБ). Перед
  финальной приёмкой дерево привести в чистое (бинарник игнорировать/удалить).

**Вывод.** Ядро языка реализовано и протестировано: 49 из 50 пунктов-чекбоксов
`CHECKLIST.md` фактически подтверждаются кодом/тестами. Это **конвейер
финализации, а не достройки фич** — ни один §VF ниже не вводит новую языковую
функциональность. Все разрывы — это (а) рассинхроны документации с фактическим
поведением, (б) непроставленный чеклист, (в) неполнота витрины примеров против
скоупа, (г) недостающие пользовательские доки. Один пункт — `тип(x)` (§VF-3) —
дефект-двойник: расхождение док↔реальность, у которого есть и кодовая причина
(коллизия лексера), но его починка остаётся **доковой** (выровнять доки под
зарезервированный статус), а не активацией функции.

**Граница скоупа (6 пунктов IN).**

1. Воспроизводимость из чистого клона: README дословно даёт успешную
   сборку/запуск/тесты.
2. `CHECKLIST.md` — честная простановка `[x]` с доказательством файл:строка.
3. Витрина примеров: событие/расписание-триггеры, мультиисточник/мультиметрика,
   полный жизненный цикл процесса, доп.классы ошибок, детерминизм пинить.
4. Пользовательский `docs/quickstart.md` «первая метрика и первый процесс за
   5 минут».
5. Выравнивание доков (README/SPEC/ARCHITECTURE) под фактическое поведение.
6. Финальная приёмка против рубрики §1–§9.

**OUT (НЕ финализация, см. последний раздел):** бонусы
(REPL/массивы/словари/статич.типизация/модули/компиляция/отладчик); v2-границы
(parallel-шаги, полные `вызвать`/`уведомить`, cron, `--json`, `ladix start`,
период «последние N дней», HTTP-приём событий); правки `TASK.md`/конституции;
любая новая языковая функциональность.

## §VF-1. Воспроизводимость README из чистого клона (скоуп 1)

**Разрыв.** `src/go.mod` лежит в `src/`, но README даёт команды без `cd src` и
с bare-командой `ladix`. Из чистого клона дословные инструкции README **не дают
ни сборки, ни прогона тестов, ни запуска**. Группа подтверждённых разрывов
(G3·G9·G11·G15·G16·G19·G26·G27·G28·G29·G30·G32):

- **Сборка из корня падает.** `README.md:20` (`go build -o ladix ./cmd/ladix`),
  `README.md:27-31` (кросс-компиляция той же формы) → из корня
  `go: cannot find main module, but found .git/config` (exit 1). Работает только
  `cd src && go build ./cmd/ladix`. (G3·G9·G15·G26·G28)
- **Тесты из корня падают.** `README.md:62` (`go test ./...`) → из корня
  `pattern ./...: directory prefix . does not contain main module` /
  `FAIL ./... [setup failed]`. Работает `cd src && go test ./...`. (G11·G19·G27)
- **Bare `ladix` не на PATH.** `README.md:39-41,229,283,320`
  (`ladix run examples/hello.ladix`, `serve`, `emit`) → `command not found:
  ladix` (exit 127). Работает `./src/ladix run examples/hello.ladix` → `Привет,
  Уклад!`. (G29)
- **Каталог сборки ≠ каталог запуска.** `README.md:23` обещает бинарник «в
  текущем каталоге», `README.md:37` велит запускать «из корня репозитория» (там
  `data/`, `data/sales.json`, `examples/`). Собрать можно только из `src/` →
  бинарник появляется в `src/ladix`, а запускать примеры с источниками надо из
  корня. README переход между каталогами не объясняет (ни `go install`/`GOBIN`,
  ни `cp`/`mv`, ни PATH). (G16·G30)
- **`src/README.md` — заглушка.** `src/README.md:1-3` («# Переехало / →
  AGENTS.md»): пользователь, оказавшийся в единственном рабочем каталоге `src/`,
  там инструкций сборки/запуска/тестов не находит. (G32)

**Что делаем.** Выровнять README под фактическое расположение `go.mod` (в `src/`),
БЕЗ переноса `go.mod` (см. «Предрешённые развилки»):

- В §Установка и §Запуск тестов всем командам предпослать `cd src` (build, vet,
  test, кросс-компиляция). После сборки указать, что бинарник появляется в
  `src/ladix`.
- Дать пользователю один из явных мостов между каталогами: либо «соберите в корень»
  (`cd src && go build -o ../ladix ./cmd/ladix`, затем `./ladix run
  examples/...` из корня), либо «положите на PATH» (`go install ./cmd/ladix`).
  Выбрать ОДИН канонический путь и провести его сквозь все примеры запуска
  (`run`/`serve`/`emit`/`metric`).
- Команды запуска примеров (`ladix run examples/...`) привести к выбранному пути
  (`./ladix run ...` из корня), чтобы `data/sales.json`/`examples/` были на месте.
- Опционально (см. «Предрешённые развилки»): добавить корневой `Makefile`
  (`build`/`test`/`vet` делают `cd src && go ...`; запуск бинарника из корня ради
  `data/`) — тогда README ссылается на `make build`/`make test` и churn минимален.
- `src/README.md`: либо краткий блок dev-команд из `src/`, либо явная отсылка «все
  команды разработчика — в корневом README, выполнять из этого каталога».

**Критерий приёмки (проверяемый).** Из свежего клона на чистой машине
последовательность команд README **дословно** даёт: (1) собранный бинарник;
(2) `./ladix run examples/hello.ladix` → `Привет, Уклад!` exit 0; (3) `go test`
(или `make test`) → 10/10 пакетов `ok`. Регрессия-замок: smoke-скрипт/CI-шаг,
прогоняющий ровно блоки README из корня, exit 0 на каждом. Никаких ручных
`cd src`, не упомянутых в README.

**Детерминизм.** Smoke не зависит от `сегодня()`: `hello.ladix` чисто
детерминирован (golden `Привет, Уклад!`); прогоны build/test детерминированы по
своей природе. Если smoke трогает `выручка.ladix` — пинить только exit 0
(вывод дата-зависим, см. §VF-6), а не stdout.

## §VF-3. `тип(x)` — выровнять доки под зарезервированный статус (скоуп 5)

**Разрыв (дефект-двойник).** `тип(x)` документирован как активная стдлиб-функция
интроспекции типа, но в рантайме недостижим:

- Доки заявляют активность: `SPEC.md:220`/`SPEC.md:343`
  (`тип(5)=="Целое"`, `тип(3.14)=="Дробное"`, `тип(сегодня())=="Дата"`);
  `docs/stdlib.md:51` (`тип(x: Любой) → Строка` — без пометки недоступности, в
  отличие от явных «**Доступна.**» у `длительность`/`в_*`);
  `docs/eval-model.md:101` (`TypeName()` держит имя «чтобы встроенная `тип(x)` не
  расходилась»). (G6)
- Реализация есть, но мертва: `src/internal/eval/builtins.go:67`
  (`add(fixed("тип", 1, builtinTip))`) + реализация
  `src/internal/eval/builtins_convert.go:17` (`func builtinTip`); инвариант
  `builtins.go:53` «РОВНО 35 активных». Но `src/internal/lexer/keywords.go:31`
  (`"тип": true`) резервирует идентификатор как ключевое слово → токен никогда не
  доходит до парсера как вызов. `тип(5)` падает: «тип — зарезервированное слово,
  появится в будущих версиях Ladix». По факту достижимо 34, не 35; `тип` нет и в
  §12-списке отложенного → читатель не получает сигнала. (G7)

**Что делаем (доковый путь, без активации функции).** Финализация **выравнивает
доки под фактический зарезервированный статус**, а не активирует `тип` (активация
= новая функциональность = OUT):

- `docs/stdlib.md:51`: пометить `тип(x)` как **зарезервировано/недоступно в v1**
  (зеркало стиля «**Доступна.**» — явная анти-пометка), чтобы строка не вводила в
  заблуждение.
- `SPEC.md:220`/`:343`: заменить примеры «активной» интроспекции на пометку
  «зарезервировано до v2»; добавить `тип` в §12-список отложенного, чтобы сигнал
  был согласован.
- `docs/eval-model.md:101`: коммент про `TypeName()` оставить, но снять
  подразумевание, что `тип(x)` уже работает (привязать к будущей активации).
- Инвариант `builtins.go:53` «РОВНО 35 активных» сделать честным относительно
  достижимости: либо коммент-сноска «`тип` зарегистрирован, но недостижим из-за
  резерва лексера (v1) — достижимо 34», либо снять `тип` из активной регистрации
  под коммент-заглушку (по аналогии с дормантным `deferredBuiltin`). **По
  умолчанию — коммент-сноска** (минимум churn, регистрацию/реализацию не
  удаляем — это путь будущей активации).

**Критерий приёмки.** Grep по `stdlib.md`/`SPEC.md`/`eval-model.md` не находит
утверждений, что `тип(x)` доступна в v1; каждое место либо помечено
«зарезервировано», либо `тип` есть в §12-списке отложенного. Инвариант-коммент в
`builtins.go` честен относительно достижимости. Регрессия: прогон `печать(тип(5))`
по-прежнему даёт reserved-word ошибку (поведение НЕ меняем) — это и есть
зафиксированная истина; при наличии теста на эту ошибку он остаётся зелёным.

**Детерминизм.** Правки текстовые; reserved-word ошибка детерминирована и не
зависит от даты.

## §VF-5. Витрина примеров против скоупа §3 (скоуп 3)

**Разрыв.** `examples/` неполна против скоупа: нет демо событие/расписание-триггеров,
мультиисточника/мультиметрики, полного жизненного цикла процесса, доп.классов
ошибок. Группа (G24·G33·G34·G35·G37·G38):

- **Событие-триггер отсутствует.** Форма `когда событие Ident:` есть только как
  тест-фикстура `src/cmd/ladix/testdata/event.ladix:4`, не в `examples/`. (G33·G24)
- **Расписание-триггер отсутствует.** Обе под-формы (`каждые Nдн` и `в "HH:MM"`)
  только в `src/cmd/ladix/testdata/schedule.ladix:1,4`. (G34·G24)
- **Мультиисточник/мультиметрика отсутствует.** `examples/выручка.ladix:2,7` — ровно
  1 источник (`продажи`) + 1 метрика (`выручка_месяца`); других объявлений в
  `examples/` нет. (G35)
- **Доп.классы ошибок отсутствуют.** Единственный негатив `examples/ошибка.ladix:1-5`
  — runtime деление-на-ноль. Нет примера синтаксической ошибки (parse-error), нет
  примера тип/семантической ошибки, нет примера **ошибки процесса** (запуск
  несуществующего процесса / неверная арность процесса / runtime внутри шага). (G37·G38·G24)
- **Полный жизненный цикл процесса** (`run --db`→`tasks`→`complete`→пробуждение) как
  примера-витрины нет (есть unit-тесты движка + CLI-цепочка сценария Б, но не как
  демо). (G24)

**Что делаем.** Добавить недостающие демо в `examples/` и зарегистрировать каждое в
`examples/MANIFEST.md` (формат: файл / назначение / golden-stdout). Парсер/семантика
для этих форм уже есть — **новой функциональности не вводим**, только витрина:

- `событие.ladix` — `когда событие <Ident>: запустить процесс ...` (из формы
  `testdata/event.ladix`).
- `расписание.ladix` — `когда расписание каждые Nдн` и/или `в "HH:MM"` (из
  `testdata/schedule.ladix`).
- мультиисточник/мультиметрика — отдельный демо с ≥2 `источник` и ≥2 `метрика` в
  одном файле.
- доп.ошибки — три файла-негатива: синтаксис, тип/семантика, ошибка процесса
  (каждый с зафиксированным stderr + код возврата 1, как `ошибка.ladix`).
- жизненный цикл процесса — демо/сценарий, прогоняющий `run --db`→`tasks`→`complete`
  до пробуждения (детерминированный Store/`--db` во временной директории).

**Критерий приёмки.** Каждый новый демо: (1) зарегистрирован в `MANIFEST.md` с
golden-stdout (или, где вывод дата-зависим, — с пинингом exit и каналом
детерминированного run-golden); (2) покрыт замком в `cmd/ladix` (например, в
`main_test.go`/`trigger_golden_test.go` — байт-точный stdout либо exit+маркеры);
(3) для негативов — точный stderr (двухстрочный формат строка/колонка) + код 1.
Регрессия: `parser/examples_test.go` (компиляция всех `examples/*.ladix`) и
golden-замки зелёные. Скоуп §3 закрыт: событие+расписание+мультиисточник+цикл+3
класса ошибок присутствуют как файлы.

**Детерминизм.** Демо НЕ зависят от `сегодня()`: триггерные/процессные демо с
golden строить через инъекцию `Clock` (`FixedClock`, зеркало §SM-10) и/или
встроенно во временной директории (`t.TempDir()` + `os.WriteFile`, паттерн
`trigger_golden_test.go`, §TR-9 D-25); `--db` — во временной директории, id
детерминированы (`p-000001`/`t-000001`), маска только `<время>`. Где окно/дата
неизбежны (метрика `ежемесячно`) — пинить exit, а не stdout (см. §VF-6).

## §VF-6. Детерминизм `выручка.ladix` (скоуп 3)

**Разрыв.** `examples/выручка.ladix` дата-зависим: метрика `выручка_месяца` имеет
период `ежемесячно` (`выручка.ladix:13`), окно берётся от `сегодня()`/часов
планировщика по полю `по_дате` (`выручка.ladix:11`), поэтому истинность условия
триггера и состав stdout зависят от системной даты. Из-за этого по `выручка.ladix`
**намеренно нет строгой golden-фикстуры**: `src/cmd/ladix/main_test.go:134-139`
(коммент «окно зависит от сегодня() … тест НЕ пинит полный stdout») пинит только
exit 0 и отсутствие маркеров диагностик; `examples/MANIFEST.md:90-95` фиксирует
отсутствие строгой stdout-фикстуры. Скоуп §3 требует «детерминизм пинить (фикс
данные/Clock, не зависеть от сегодня())» — у `выручка.ladix` этого нет. (G39)

**Что делаем.** Дать детерминированный канал для метрика-триггерного сценария БЕЗ
ломки самого `выручка.ladix` (он остаётся живой бизнес-демо):

- Закрепить/расширить детерминированный run-golden в
  `src/cmd/ladix/trigger_golden_test.go`: программа метрика-триггера строится
  встроенно (`t.TempDir()` + `os.WriteFile`) с **фиксированным `Clock`/датой** и
  фиксированными данными источника, stdout пинится байт-точно (включая истинность
  условия и состав вывода). Это снимает дата-зависимость из приёмки, не трогая
  `выручка.ladix`.
- `examples/выручка.ladix` оставить дата-зависимым демо (его роль —
  parse-clean + run-demo живой метрики), но в `MANIFEST.md` явно указать: строгой
  stdout-фикстуры нет ПО ПРИЧИНЕ дата-зависимости, детерминизм сценария закрыт
  отдельным run-golden с фикс-Clock.

**Критерий приёмки.** Существует тест, который для метрика-триггерного сценария
пинит **байт-точный stdout** при фиксированных `Clock`+данных (зелёный
независимо от текущей даты — прогон в любой день одинаков). `MANIFEST.md`
честно объясняет, почему на самом `выручка.ladix` строгой фикстуры нет и где
живёт детерминированный замок.

**Детерминизм.** Это и есть суть раздела: `Clock` инъектируется (`FixedClock`),
данные источника фиксированы во временной директории, окно метрики
детерминировано → ноль зависимости от `сегодня()`.

## §VF-7. Пользовательский docs/quickstart.md (скоуп 4)

**Разрыв.** Отсутствует пользовательский `docs/quickstart.md` «первая метрика и

**Детерминизм.** Все шаги quickstart детерминированы: `hello` — golden; метрика —
через `metric`/фикс-данные или с пометкой «вывод зависит от даты» (пинить exit, не
stdout, см. §VF-6); процесс — `--db` во временной директории, id

## Предрешённые развилки

- **`go.mod` НЕ переносить в корень.** Перенос — churn по всему дереву импортов и
  истории; вместо этого воспроизводимость обеспечивается README-инструкциями «из
  `src/`» (§VF-1) + опционально корневой `Makefile` (цели `build`/`test`/`vet`
  делают `cd src && go ...`; запуск бинарника — из корня ради `data/`).
- **`go.work` НЕ годится.** При `go.work` команда `go ... ./...` перечисляет пакеты
  под текущим cwd; из корня (где нет Go-пакетов) это даёт 0 пакетов, а не
  обход `src/`. Воспроизводимость через `go.work` иллюзорна — не использовать.
- **`CHECKLIST.md` — только `[x]` с доказательством, текст пунктов НЕ менять.**
  Рубрика — внешний generic-шаблон; редактирование её формулировок (включая
  `.lang→.ladix` в `:54`) — правка рубрики, вне скоупа. Разрешено только проставить
  `[x]` и приложить доказательство/сноску.
- **`TASK.md` НЕ редактировать.** Вне скоупа финализации.
- **Язык доков — русский.** Английский только в Go-коде; все новые/правленые доки
  (README/quickstart/MANIFEST/model) — по-русски.
- **Детерминизм примеров обязателен.** Любое новое демо с golden-проверкой — на
  фикс-`Clock`/фикс-данных или встроенно во временной директории; пиннинг по
  `сегодня()` запрещён.

## Вне скоупа (НЕ делать)

**Бонусы** (не финализировать, не упоминать как разрыв):
REPL · массивы · словари · статическая типизация · модули · компиляция в байткод/нативно ·
отладчик.

**v2-границы** (явно отложены):
parallel-шаги процессов · полные интеграции `вызвать`/`уведомить` (внешние эффекты) ·
cron-планирование · `--json`-вывод · команда `ladix start` · период «последние N дней» ·
HTTP-приём событий · **операторная арифметика дат/длительностей** (`Дата±Длит`, `Дата−Дата`,
`Длит±Длит`, `Длит*X` — остаётся deferred v2, §DB-9) · **активация `тип(x)`** как достижимого
builtin (в финализации только доковое выравнивание под зарезервированный статус, §VF-3).

**Процедурное** (вне скоупа правок): редактирование `TASK.md` / конституции · перенос
`go.mod` в корень · любая новая языковая функциональность.
