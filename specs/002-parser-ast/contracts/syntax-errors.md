# Contract: Каталог синтаксических ошибок + множество синхро-токенов

**Feature**: 002-parser-ast | **Источники**: SPEC §13 (§13.1/§13.2/§13.4), docs/grammar.md §3/§4/§9/§10,
spec.md US5/FR-022..FR-026

Категория **Синтаксическая** (`SPEC §13.1`). Тексты идут под каноническим двухстрочным заголовком
(`SPEC §13`):

```
Ошибка в строке N, колонка M:
<описание>
```

`<описание>` — это `ParseError.Msg` (без заголовка). `N`/`M` — 1-based, колонка в **рунах**. Три текста
воспроизводятся **ДОСЛОВНО** из `SPEC §13.4` (конституция VIII, FR-024); четыре — сформулированы по
стилю §13.4 и зафиксированы этим контрактом (бриф явно поручил, конституция IX). Переформулировать
ЗАПРЕЩЕНО.

## Правила подстановки (для текстов с `'…'`)

| Код | `<X>` / `<лексема>` подставляется |
|---|---|
| SE-INT-RANGE | реальная лексема числа целиком (`'99999999999999999999999999999999'`) |
| SE-EXPECTED | `<X>` — ожидаемая лексема/символ (`':'`, `')'`, `']'`, `'='`, `'в'`, имя после `.`); `<лексема>` — реальный токен или псевдо-лексема виртуального (см. ниже) |
| SE-UNEXPECTED | реальный ведущий токен или псевдо-лексема виртуального |

**Псевдо-лексемы виртуальных токенов** (у них пустая лексема — отображаются описательно, без кавычек как
имя или в кавычках как ожидаемое): `NEWLINE` → `конец строки`, `INDENT` → `увеличение отступа`,
`DEDENT` → `конец блока`, `EOF` → `конец файла`. Пример: незакрытый `печать(1, 2` на `EOF` →
`ожидалось ')', получено 'конец файла'`.

## Семантические замечания

- **SE-EXPECTED** покрывает все «отсутствует обязательный токен»: нет `:` после условия/заголовка
  (`если x` → `ожидалось ':', получено '<лексема>'`); незакрытая скобка на `EOF` (`ожидалось ')',
  получено 'конец файла'`); нет `в` в `для`; нет имени после `.`; нет `NEWLINE`-завершения statement
  (например `иначеесли C:` слитно → `ожидалось 'конец строки', получено '<лексема>'`).
- **SE-UNEXPECTED** — ведущий токен не начинает ни один допустимый элемент/выражение: отложенные
  декларации `источник`/`метрика`/`процесс`/`когда` и `значение` на верхнем уровне; `{`/`}` (грамматика
  v1 фигурных скобок не использует); прочий неожиданный старт.
- **SE-ASSIGN-TARGET** — разбор «expr, затем `=`»: если слева не `*ast.Ident` (`x.f = …`, `x[i] = …`,
  `5 = …`) → ошибка (D-R11). Объявленность переменной НЕ проверяется (eval-later).
- **SE-INT-RANGE** — статическая накапливаемая (§13.2), при сборке `IntLit` (`strconv.ParseInt`); узел
  всё равно создаётся, чтобы разбор продолжился. Знак не сворачивается → `MinInt64` даёт эту ошибку.
- **SE-NESTED-FN** — это **синтаксис** (grammar §4: `FunctionDecl` не входит в `Statement`), не семантика.
- **SE-CHAIN** — после `Additive CompOp Additive`, если снова `CompOp` → ошибка (не более одного `CompOp`).
- **SE-EMPTY-BLOCK** — при пустом блоке лексер `INDENT` НЕ эмитит, поэтому позиция берётся с реально
  присутствующего токена на месте ожидаемого `INDENT` (первый токен недо-отступленного тела: `DEDENT`,
  ведущий токен внешнего оператора или `EOF`) — фиксированная точка для воспроизводимого golden (SC-003).

## Множество синхро-токенов panic-mode (явный список — FR-026, D-R8)

Обнаружив ошибку, парсер регистрирует её в `ErrorList`, затем отбрасывает токены до ближайшего токена из
набора и возобновляет разбор; до точки синхронизации регистрация НОВЫХ ошибок подавлена (без фантомов).

| Группа | Токены | При синхронизации |
|---|---|---|
| Структурные | `NEWLINE`, `DEDENT`, `EOF` | `NEWLINE`/`DEDENT` **потребляются**; на `EOF` разбор завершается |
| Ведущие ключевые слова statements | `пусть`, `если`, `пока`, `для`, `вернуть`, `прервать`, `продолжить` | НЕ потребляются (разбор начинается с них) |
| Декларация scope B | `функция` | НЕ потребляется |
| Зарезервированные step-action | `присвоить`, `вызвать`, `уведомить` | НЕ потребляются |
| Отложенные top-level декларации | `источник`, `метрика`, `процесс`, `когда` | НЕ потребляются (сами дают SE-UNEXPECTED) |

> Имена видов токенов (`KW_LET`/`KW_IF`/…) — деталь реализации лексера; контракт фиксирует только лексемы
> (см. `specs/001-lexer-tokens/contracts/token-stream.md`).

## Канон позиционирования и накопления

- Все позиции — в **рунах** (на кириллическом префиксе колонка = рунный индекс; SC-003).
- Накопитель — общий `errors.ErrorList`, бюджет ≈20 (общий с лексером, §13.2, FR-025). Парсер НЕ печатает
  сводку «Найдено K ошибок.» — это слой-потребитель (CLI).
- В выводе нет Go stack trace (конституция III; FR-025): синтаксические ошибки — накапливаемые значения,
  паника в штатных путях запрещена.

## Каноны, которые парсер НЕ порождает (границы)

- Лексические тексты (табы, незакрытая строка, неизвестный суффикс, …) — **лексер** (фича 001).
- Семантические (`'x' не объявлено`, `'вернуть' допустимо только внутри функции`, `действие '<имя>'
  допустимо только в шаге процесса`, дубли/арность) — **eval** (фича 003).
- Ошибки типа/выполнения (деление на ноль, переполнение арифметики, индекс вне диапазона) — **eval**.
- Предупреждения («Предупреждение в строке N, колонка M:») — парсер не порождает.
