# Quickstart: Парсер + AST Ladix (002-parser-ast)

**Feature**: 002-parser-ast | **Plan**: [plan.md](./plan.md)

Как разработчику начать реализацию и проверять парсер. На этом шаге создаются пакеты `internal/ast` и
`internal/parser`, плюс один файл `internal/errors/parserror.go`. Корень модуля — `src/`. Лексер
(`internal/lexer`) и остальной `internal/errors` НЕ меняются.

## 0. Каркас (Фаза 0)

```bash
cd src
# пакеты создаются по мере фаз:
#   src/internal/ast/{position,node,op,literal,expr,stmt,decl,step,block}.go (+ _test.go)
#   src/internal/parser/{parser,parse_expr,parse_stmt,parse_decl,literals,pos,recover,errors}.go (+ _test.go)
#   src/internal/errors/parserror.go (+ parserror_test.go)   # ЕДИНСТВЕННОЕ дополнение к errors
```

Граф зависимостей (без циклов): `parser → ast`, `parser → errors`, `parser → lexer`; **`ast` ничего не
импортирует из проекта** (листовой — несёт свою `Position`, D1).

## 1. Цикл tests-first (конституция VI, FR-028)

Для КАЖДОГО правила грамматики подмножества B и КАЖДОГО из 7 кодов синтаксических ошибок — табличный/
golden тест **до/вместе** с кодом:

```bash
cd src
go test ./internal/errors/...      # формат ParseError (двухстрочный), errors.As, складывание в ErrorList
go test ./internal/ast/...         # конструкторы узлов, Pos(), String() операторов
go test ./internal/parser/...      # таблицы «вход → AST» + golden «вход → строка/колонка/текст»
go test ./...                      # всё вместе (вкл. лексер 001 — не должен сломаться)
```

Табличный тест AST сверяет дерево с эталоном (тип узла, поля, `Pos()`); golden-тест ошибок сверяет
`(Pos, Msg)` через двухстрочное представление. Источники эталонов:
- узлы, приоритеты, конвенция `Pos()` → [contracts/ast.md](./contracts/ast.md) §C-2/§C-4;
- тексты ошибок (дословно) и синхро-набор → [contracts/syntax-errors.md](./contracts/syntax-errors.md).

## 2. Гейты качества (конституция I, FR-027, SC-007)

```bash
cd src
gofmt -l .            # пусто = отформатировано
go vet ./...          # без замечаний
go build ./...        # собирается чисто
```

Все три ОБЯЗАНЫ быть чистыми до завершения каждой задачи.

## 3. Чек-лист приёмки по фазам (по приоритетам US)

- **P1 (US1+US2, MVP)** — выражения и каркас:
  - [x] `2 + 3 * 4` → `BinaryExpr(+, 2, BinaryExpr(*, 3, 4))`; `a - b - c` → `((a-b)-c)` (SC-002)
  - [x] `печать("…")` → `ExpressionStmt(CallExpr(Ident(печать), …))`; отдельного print-узла нет
  - [x] `examples/{hello,арифметика}.ladix` → `Program` без синтаксических ошибок; завершение на `EOF` (SC-001/SC-006)
  - [x] литерал на 30 девяток → SE-INT-RANGE; `x.f = 5` → SE-ASSIGN-TARGET; `1 < x < 10` → SE-CHAIN (SC-003)
- **P2a (US3)** — условия/циклы/блоки:
  - [x] `если/иначе если/иначе`, `пока`, `для` → корректные `Block`/`ElseClause`; вложенные блоки (SC-001)
  - [x] пустой блок → SE-EMPTY-BLOCK; `иначеесли` слитно → SE-EXPECTED; `examples/{условие,цикл}.ladix` parse-clean
- **P2b (US4)** — функции:
  - [x] `examples/{функция,факториал}.ladix` → `FunctionDecl` без ошибок; рекурсия — обычный `CallExpr` (SC-001)
  - [x] вложенная `функция` → SE-NESTED-FN дословно (SC-003)
  - [x] `StepAction`/`RunProcessExpr` парсятся (зарезервированы), семантика НЕ проверяется
- **P2c (US5, финализация)** — диагностика+восстановление:
  - [x] все 7 кодов воспроизводятся ДОСЛОВНО, позиции в рунах, по одному golden-кейсу (SC-003)
  - [x] ≥2 ошибки на разных строках → несколько диагностик без фантомов; накопитель ≤ ≈20; без stack trace (SC-005)
  - [x] `источник`/`метрика`/`процесс`/`когда`/`значение`/`{` на верхнем уровне → SE-UNEXPECTED

## 4. Границы (НЕ делать на этом шаге)

- НЕ eval/исполнение, НЕ резолв имён/типов, НЕ вычисление выражений (фича 003).
- НЕ декларации `источник`/`метрика`/`процесс`/`триггер` (вне scope B → SE-UNEXPECTED на верхнем уровне).
- НЕ семантика: контекст `вернуть`/`прервать`/`продолжить`/`присвоить`, дубли, арность, типы.
- НЕ диапазон `DurationLit`; НЕ свёртка знака целого литерала; НЕ материализовать `GroupExpr`.
- НЕ менять лексер; `errors` — только новый файл `parserror.go` (агрегат `ErrorList` без правок).
