**Feature**: 003-interpreter-eval | **Date**: 2026-06-05 | **Plan**: [plan.md](./plan.md)

Открытых `[NEEDS CLARIFICATION]` нет: спека детальна, а поведение полностью зафиксировано единственным связывающим источником `docs/eval-model.md §1–§10` (+ `docs/stdlib.md` для встроенных) и решениями D1–D9 брифа. ## D-R1. Модель значений в листовом `internal/value` (вариант A) (ARCHITECTURE §2.1)

- **Decision**: ввести **отдельный листовой** пакет `internal/value` с интерфейсом `Value{ TypeName() string }` и 10 конкретными типами; `internal/eval` импортирует `value`, а не определяет значения у себя.
- **Rationale**: будущий `internal/store` обязан оперировать `value.Value` (контракт ARCHITECTURE §6). Если бы `Value` жил в `eval`, то `store` импортировал бы `eval` → цикл `eval → store → eval`. Вынесение `value` в листовой пакет (зависит только от stdlib) разрывает цикл и даёт нейтральную поверхность `eval↔store` (ARCHITECTURE §2.1, вариант A — принят). Сохраняет конституцию VII (листовые `value`/`errors`/`ast`).
- **Alternatives considered**:
  - `Value` внутри `eval` (вариант B) — **отвергнут**: делает `eval` «толстым» хабом и втягивает интерпретатор в зависимости хранилища, порождает цикл с будущим `store`.
  - Дженерик-`any` без интерфейса — **отвергнут**: теряется `TypeName()` для `тип(x)`/сообщений и дисциплина type switch.
- **Статус**: Guardrail 1, Guardrail 2. Восьмой пакет — осознанное доопределение (Complexity Tracking, не нарушение).

## D-R2. Числа раздельны; правила `//` и `%` (§3.3, D2)

- **Decision**: `Целое`=int64, `Дробное`=float64. `+ - *`: `Цел○Цел`→`Целое` с явной проверкой переполнения int64, участвует `Дробное`→промоушен. `/` — **всегда** `Дробное`. `//` — только `Цел//Цел`→`Целое`, иначе `ОшибкаТипа`. `%` — `Цел%Цел`→`Целое` **или** `Дроб%Дроб`→`Дробное` (через `math.Mod`/fmod), смешанное `Цел/Дроб`→`ОшибкаТипа`. Деление на ноль для `/ // %` → `«деление на ноль»` на позиции оператора.
- **Rationale**: дословно §3.3 / §1.3.1 / FR-011 (исправлено в точке ревью №1: `%` допускает `Дроб%Дроб`, в отличие от `//`). Явная проверка переполнения — конституция III (без молчаливого wrap-around). `math.Mod` даёт C-семантику остатка для float.
- **Alternatives considered**:
  - `%` только над `Целое` (как `//`) — **отвергнут**: противоречит FR-011/§3.3 (исправлено владельцем).
  - wrap-around переполнения int64 — **отвергнут**: конституция III требует явную ошибку `«переполнение целого числа»`.
- **Статус**: Guardrail 5. РЕШЁН (источник §3.3).

## D-R3. Control-flow через `Signal`, два канала, не `panic` (D4, конституция III)

- **Decision**: `вернуть`/`прервать`/`продолжить` — явный возвращаемый `Signal{Kind SignalKind; Value value.Value}`, `SignalKind ∈ {SigNormal,SigBreak,SigContinue,SigReturn}`. Сигнатуры `evalStmt(env,s) (Signal,error)`, `evalBlock(env,b) (Signal,error)`. Два независимых канала: `error` (рантайм-ошибки, всплывают немедленно) и `Signal` (штатный поток).
- **Rationale**: конституция III запрещает panic в штатных путях; идиоматичная раскрутка видна в сигнатурах, а не спрятана в `recover`. `recover` остаётся только барьером на границе CLI (D-R14). Цикл поглощает `SigBreak`/`SigContinue`, пробрасывает `SigReturn`; вызов функции ловит `SigReturn`.
- **Alternatives considered**:
  - `panic/recover` для `вернуть` (как делают некоторые tree-walkers) — **отвергнут**: нарушает конституцию III, скрывает поток, мешает `-race`-чистоте.
  - Совмещённый возврат `(Value, error)` с особым sentinel для break — **отвергнут**: смешивает штатный поток с ошибками, ломает fail-fast семантику `error`.
- **Статус**: Guardrail 8.

## D-R4. Функциональный scope; блоки область не открывают; кадр `parent=global` (D3)

- **Decision**: `Environment{vars map[string]value.Value; parent *Environment}` с `Define`/`Assign`/`Lookup`. Новую область создают ТОЛЬКО глобал и кадр вызова функции; блоки `если/иначе/пока/для` исполняются в той же области. Кадр функции — `NewEnvironment(global)` (лексический parent = глобал, не вызывающий).
- **Rationale**: Python-style функциональный scope (SPEC §6, §1.3.5). Следствия проверяемы golden-кейсами: `пусть категория` в обеих ветках `если/иначе`→«уже объявлено»; `категория=…` в ветке мутирует внешнюю (контракт `условие.ladix`). `parent=global` даёт лексическую, не динамическую видимость; рекурсия = независимые кадры.
- **Alternatives considered**:
  - Блочный scope (как C/Go) — **отвергнут**: противоречит SPEC §6 и поведению golden-примеров.
  - `parent = кадр вызывающего` (динамическая видимость) — **отвергнут**: §1.3, функции top-level не замыкания.
- **Статус**: Guardrail 3.

## D-R5. Два пространства имён; функция — не `Value` (D8)

- **Decision**: имена резолвятся в двух раздельных пространствах — переменные в `Environment`, функции в таблице `funcs` (пользовательские) + `builtins`. Функция физически не `Value` (не присвоить/передать/вернуть/положить в список). Имя в позиции значения, найденное только в таблице функций → `«'имя' — функция, её нельзя использовать как значение»`.
- **Rationale**: SPEC §2.3/§6; ровно 10 типов `Value` (§1.3.7), функция среди них отсутствует. Разделение пространств — единственный способ дать понятную ошибку «функция как значение» вместо тихого промаха.
- **Alternatives considered**:
  - Первоклассные функции (функция как `Value`) — **отвергнут**: вне scope v1, ломает закрытый список из 10 типов.
- **Статус**: Guardrail 3, Guardrail 10.

## D-R6. Семпроход `Analyze` — fail-fast; граница «статика vs рантайм» (FR-034/035)

- **Decision**: `Analyze(prog *ast.Program) error` — лёгкий fail-fast обход (первая ошибка или `nil`, накопителя нет). **Шаг 1**: регистрация top-level `FunctionDecl`→`funcs` (forward-вызовы разрешены), повтор имени→ошибка, top-level декларатив→deferred. **Шаг 2** (по областям, блоки область не открывают): повтор `пусть`, контекст `вернуть`/`прервать`/`продолжить`, резолв `CallExpr`-`Ident` + проверка **фиксированной** арности, reserved-узлы→deferred. **НЕ** проверяет: declaredness переменной в позиции значения (flow-зависимо), типы (динамика), арность вариативных/перегруженных (`печать`/`диапазон`/`длина`).
- **Rationale**: накопитель — только в лексере/парсере (ARCHITECTURE §3, конституция III); семантика и исполнение fail-fast. Граница «что статически / что в рантайме» дословно из §9: declaredness переменной зависит от порядка top-level `пусть`, поэтому оставлена рантайму (`печать(b)` до `пусть b` → рантайм `«'b' не объявлено»`).
- **Alternatives considered**:
  - Накопитель ошибок в семпроходе (как panic-mode парсера) — **отвергнут**: §9/FR-031, eval-слой fail-fast; накопитель — артефакт статической фазы.
  - Полная проверка типов на семпроходе — **отвергнут**: язык динамически типизирован, типы всплывают в рантайме с позицией `CallExpr.Pos()`.
- **Статус**: Guardrail 15.

## D-R7. Три типа ошибок в `internal/errors` по образцу `LexError`/`ParseError` (FR-031)

- **Decision**: добавить три листовых типа — `СемантическаяОшибка` (стадия 3), `ОшибкаТипа` и `ОшибкаВыполнения` (стадия 4), каждый в своём файле, с полями `Pos Position` + `Msg string`, **без** конструктора (композитный литерал), с методом-**значением** `Error() string`, печатающим тот же двухстрочный заголовок `Ошибка в строке N, колонка M:\n<Msg>`. Дружат с `errors.As`; сентинелы/`Unwrap` не требуются.
- **Rationale**: единый дом-паттерн «1 тип = 1 файл = {Pos,Msg} + метод-значение `Error()`» (наблюдаемо в `lexerror.go`/`parserror.go`). Листовость `errors` сохраняется: типы НЕ импортируют `ast`/`value` — `<тип>` подставляется вызывающим eval через `value.TypeName()`, позиция — из `ast.Pos()`. Метод-значение (а не на `*T`) важен для `errors.As` по значению.
- **Alternatives considered**:
  - Один общий тип `EvalError` с полем-категорией — **отвергнут**: ломает дом-паттерн и `errors.As` по конкретному типу, мешает различать стадию 3 vs 4.
  - Вынести формат в общий helper — **отвергнут**: дублирование строки формата между типами осознанное (контракт стабильности), как в 001/002.
- **Статус**: Guardrail 14.

## D-R8. Привязка позиции к узлу AST (§8.2, FR-032)

- **Decision**: позиция ошибки берётся из `Pos()` узла по таблице §8.2: деление на ноль / переполнение / тип бинарного → `BinaryExpr.Pos()` (токен **оператора**); тип унарного → `UnaryExpr.Pos()`; условие не-`Булево` → `Cond.Pos()`; `для` не над `Список` → `Iterable.Pos()`; индекс / не индексируется → `IndexExpr.Pos()`; нет полей → `FieldExpr.Pos()`; необъявленная переменная / функция-как-значение → `Ident.Pos()`; арность / не функция / глубина / рантайм-стдлиб / deferred-вызов → `CallExpr.Pos()`; deferred-узлы → `node.Pos()`.
- **Rationale**: контракт AST 002 (D4) уже кладёт `Pos()` бинарных/унарных на токен оператора, `CallExpr.Pos()=Callee.Pos()`, `Index/Field.Pos()=Target.Pos()` — eval просто читает. Контрольный golden `ошибка.ladix` стр.5 `печать(всего / делитель)` → строка 5, колонка 14 (токен `/`).
- **Alternatives considered**:
  - Позиция на начале всего выражения — **отвергнут**: §8.2 требует токен оператора для арифметики/сравнений (точная локализация, конституция IV).
- **Статус**: Guardrail 14, контрольный SC-002.

## D-R9. Тексты сообщений — ДОСЛОВНО из реестра §8.3 (D1, FR-033)

- **Decision**: полезная нагрузка воспроизводится байт-в-байт из `docs/eval-model.md §8.3` — **без** завершающей точки, **кроме** многофразовых (текст лимита рекурсии `«превышена максимальная глубина вызовов (10000). Возможна бесконечная рекурсия.»`). Плейсхолдеры: `<тип>` ∈ {`Целое`,`Дробное`,`Строка`,`Булево`,`Пусто`,`Длительность`,`Период`,`Дата`,`Список`,`Запись`}, `<оп>`, `'имя'`/`'x'`/`'f'`, `N`/`M`/`L`. Тире — длинное «—».
- **Rationale**: D1 — при любом расхождении `§13.4 ↔ §8.3` побеждает §8.3; `§13.4` в 003 не используется и не синхронизируется. exact-match тексты переводятся в тесты «как есть» (конституция VIII).
- **Alternatives considered**:
  - Брать тексты из SPEC §13.4 — **отвергнут**: §13.4 рассогласован по пунктуации, не источник exact-match (D1).
- **Статус**: Guardrail 14. См. [contracts/runtime-errors.md](./contracts/runtime-errors.md).

## D-R10. Единое строковое представление `строка(x)`/`печать` (§7, FR-030)

- **Decision**: одно представление для `строка(x)` и `печать`: `Целое`→десятичная; `Дробное`→`strconv.FormatFloat(v,'g',-1,64)` с **принудительной** `.0`, если результат «выглядит целым» (не содержит `.`/`e`/`E`/`n`/`i`); `Строка`→текст без кавычек; `Булево`→`истина`/`ложь`; `Пусто`→`пусто`; `Список`→`[`элементы через `, ` рекурсивно`]`; `Запись`→`{поле: значение, …}` в порядке полей. Строки **внутри** `Список`/`Запись` — тоже без кавычек.
- **Rationale**: §7 / FR-030. Принудительная `.0` гарантирует визуальное отличие `Дробное` от `Целое` и требуется golden `функция.ladix` (`2175.0`, не `2175`). Кратчайшая обратимая запись — отсутствие потери точности.
- **Alternatives considered**:
  - `%v`/`%g` без принудительной `.0` — **отвергнут**: `2175.0` напечатался бы как `2175`, ломая golden и различимость типов.
  - Строки в кавычках внутри списков — **отвергнут**: §7 печатает без кавычек на всех уровнях.
- **Статус**: Guardrail 13. См. [contracts/values.md](./contracts/values.md).

## D-R11. Стдлиб — закрытый список 23 активных + 12 deferred; классы арности (D6, FR-025/027/029)

- **Decision**: РОВНО **23** активных встроенных + **12** deferred-заглушек (= 35), закрытый список (расширять/сокращать ЗАПРЕЩЕНО). Классы арности: фиксированная (нарушение → семпроход `«'имя' принимает N аргументов, передано M»`); вариативная (`печать`) и перегруженная по арности (`диапазон` 1|2) — проверка в рантайме `«'имя': неверное число аргументов»`; перегруженная по типу (`длина`: `Строка`|`Список`) — одна функция, счёт ×1. `печать` — единственный канал вывода; `добавить` — единственный мутатор (меняет `*s.Elems`), прочие списочные возвращают новый список. Все встроенные затеняемы `пусть` (с предупреждением, не ошибка).
- **Rationale**: §6 / `docs/stdlib.md`. Разделение арности на статическую (фикс.) и рантайм (вариативные/перегруженные) дословно FR-035: семпроход не знает арность `печать`/`диапазон`/`длина`.
- **Alternatives considered**:
  - Проверять арность `диапазон`/`печать` на семпроходе — **отвергнут**: FR-035, их арность динамична.
  - `соединить` как мутатор — **отвергнут**: единственный мутатор — `добавить` (FR-027).
- **Статус**: Guardrail 12. См. [contracts/builtins.md](./contracts/builtins.md).

## D-R12. `булево(x)` — единственная точка truthy; strict-`Булево` в условиях (D6, FR-028)

- **Decision**: мягкий truthy (`0`/`0.0`/`""`/`[]`/`пусто`/`ложь`→`ложь`, прочее→`истина`) существует ТОЛЬКО внутри встроенной `булево(x)` при явном вызове. В `если/иначе если/пока` truthiness НЕ применяется — strict-`Булево`, не-`Булево`→`«условие должно быть Булево, получено <тип>»`.
- **Rationale**: §1.3.3/§1.3.4/FR-028 — единственная точка мягкого приведения локализует «магию» в явный вызов и держит условия предсказуемыми.
- **Alternatives considered**:
  - Python-truthiness в условиях — **отвергнут**: спека требует strict-`Булево`.
- **Статус**: Guardrail 7.

## D-R13. `для x в E` — `Define`-если-нет + защита от мутации (FR-019, §4.3)

- **Decision**: `E` обязан `Список`; `x` привязывается в **охватывающей** области — `Define` при первом элементе **только если имени там ещё нет**, затем `Assign` на каждой итерации; на пустом списке `x` не создаётся; после цикла `x` видна со значением последней итерации. На время цикла список помечается «итерируется»; `добавить` на помеченном → `ОшибкаВыполнения «список изменён во время итерации»` (снимок — через `для x в копия(s)`).
- **Rationale**: оговорка «если имени ещё нет» (восстановлена в точке ревью №1) предотвращает ложное «'x' уже объявлено» при повторном входе (`для` внутри `пока`, два `для x` подряд в одной области), §4.3. Защита от мутации — детерминизм итерации.
- **Alternatives considered**:
  - Безусловный `Define` при первом элементе — **отвергнут**: §4.3, ломается повторный вход в цикл.
  - Снимок списка автоматически — **отвергнут**: §4.3, снимок явный через `копия`, иначе мутация — ошибка.
- **Статус**: Guardrail 9.

## D-R14. Лимит глубины 10000, `--max-depth`, recover-барьер, коды 0/1/2 (D9)

- **Decision**: `Interpreter.maxDepth` (поле из флага `--max-depth N`, по умолчанию **10000**), `depth` инкрементируется на пользовательском вызове (`defer depth--`); `depth > maxDepth` → `ОшибкаВыполнения «превышена максимальная глубина вызовов (10000). Возможна бесконечная рекурсия.»` (число = фактический лимит). Граница CLI-подкоманды — `defer recover()`: штатные ошибки→stderr §8/код 1; Go-паника→`«внутренняя ошибка интерпретатора»` без stack trace/код 1; ошибка использования CLI→код 2; успех→код 0.
- **Rationale**: D9/§10.2 — явный счётчик вместо неперехватываемого переполнения Go-стека; recover ловит только «не должно случиться» (конституция III). Число в тексте = фактический лимит (`--max-depth` меняет и поведение, и текст).
- **Alternatives considered**:
  - Полагаться на переполнение Go-стека — **отвергнут**: даёт неперехватываемую панику и Go stack trace (нарушает SC-008).
- **Статус**: Guardrail 11, Guardrail 17.

## D-R15. Deferred-граница — явная ошибка, не тихий no-op (D7, FR-036)

- **Decision**: конструкции, которые парсятся в 002, но в 003 не исполняются, дают явную ошибку на позиции узла: reserved-узлы (`RunProcessExpr`, `AssignAction`/`CallAction`/`NotifyAction`), `DurationLit` (`3дн`), декларатив (top-level `источник`/`метрика`/`процесс`/`триггер`) → `«конструкция ... не поддерживается в этой версии»`; 12 deferred-встроенных → `«функция '<имя>' не поддерживается в этой версии»`; period-константы (`ежедневно`…`ежегодно`) в 003 не предопределены → рантайм `«'<имя>' не объявлено»`. Deferred-конструкции ловятся **семпроходом** (стадия 3) там, где разрешимо статически.
- **Rationale**: §1.2/§9/FR-036 — отличить «не реализовано» от «опечатка/не объявлено». Узлы декларатива (`источник`/…) в текущем AST 002 как типы отсутствуют — ловятся как top-level конструкции при их появлении; реально присутствующий процессный узел — `RunProcessExpr` + `*Action`-семейство.
- **Alternatives considered**:
  - Тихо игнорировать deferred-узлы — **отвергнут**: FR-036 требует явную ошибку (не no-op).
  - Предопределить period-константы — **отвергнут**: D7/A4, тип `Период` deferred, предзаполнение — задача декларатив/engine-трека.
- **Статус**: Guardrail 16.

## D-R16. `Запись` смоделирована полностью, но в 003 не конструируется (D5)

- **Decision**: `Запись` реализуется в `internal/value` полностью (открытая, с сохранением порядка полей: `keys []string` + `fields map`; `Get`→`Пусто` на отсутствующем; `Keys`; равенство; печать §7), но ни один путь кода 003 её не порождает (литерала нет, источники — доменные функции deferred). `FieldExpr` в чистом 003 всегда упирается в `«значение типа <тип> не имеет полей»`. Тестов на успешную непустую `Запись` не требуется.
- **Rationale**: `Запись` — стабильная поверхность `eval↔store` (ARCHITECTURE §7.7): внешний мир (источники/движок/store) втекает в язык как читаемое значение. Полная модель сейчас фиксирует контракт чтения/равенства/печати как стабильную поверхность под будущий store, без активации ворот (D5/§2.1).
- **Alternatives considered**:
  - Отложить и сам тип `Запись` — **отвергнут**: тогда поверхность `eval↔store` нестабильна, и `FieldExpr` пришлось бы спецкейсить иначе.
  - Ввести литерал `Запись` в 003 — **отвергнут**: вне scope, AST 002 не содержит `RecordLit`.
- **Статус**: Guardrail 2.

## Решения по текстам ошибок eval

- **Канон — §8.3.** Все полезные нагрузки берутся ДОСЛОВНО из `docs/eval-model.md §8.3` (D-R9). Полный каталог с кодами и позиционной привязкой — в [contracts/runtime-errors.md](./contracts/runtime-errors.md).

- **Категории по стадии**: `СемантическаяОшибка` — стадия 3 (повтор объявления, фикс. арность, контекст `вернуть`/`прервать`/`продолжить`, необъявленная функция, deferred-конструкции/встроенные); `ОшибкаТипа` — стадия 4 (несовместимые операнды, условие не-`Булево`, `для` не над `Список`, индекс/поле, ошибки преобразования стдлиб); `ОшибкаВыполнения` — стадия 4 (деление на ноль, переполнение, индекс вне диапазона, лимит рекурсии, рантайм-стдлиб, функция-как-значение/не-функция, period-имя «не объявлено»).
- **Псевдо-плейсхолдеры** подставляются вызывающим eval: `<тип>` через `value.TypeName()`, `<оп>` — строковое имя оператора (`ast.BinOp.String()`/`UnOp.String()`), `N`/`M`/`L` — числа.
