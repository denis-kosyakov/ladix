# Feature Specification: Интерпретатор Ladix (tree-walking eval, чистое императивное ядро B)

**Feature Branch**: `003-interpreter-eval`

**Created**: 2026-06-05

**Status**: Draft

**Input**: User description: «Реализовать третий слой компилятора Ladix: интерпретатор (tree-walking eval) чистого императивного ядра подмножества B. Он потребляет AST от парсера (фича 002) как стабильный вход и исполняет программу: вычисляет выражения с уже построенными приоритетами; выполняет statements (`пусть`, присваивание, выражение-оператор, `если/иначе если/иначе`, `пока`, `для … в …`, `прервать`, `продолжить`, `вернуть`); ведёт области видимости; вызывает пользовательские функции с рекурсией; печатает (`печать`) и сообщает рантайм- и семантические ошибки с позицией (строка + колонка) по-русски. НЕ декларатив и НЕ движок процессов — это будущие фичи.»

**Источники истины**: `docs/eval-model.md` §1–§10 — **единственный связывающий** источник поведения, семантики и текстов (§8.3 — реестр дословных сообщений для exact-match; §10.3 — golden-приёмка). `SPEC.md` §4 (типы), §5 (выражения), §6 (области видимости), §7 (управляющие), §8 (функции/стдлиб) — фон; §13 / §13.4 — репрезентативные тексты, рассогласованы по пунктуации, **НЕ** источник exact-match. `docs/stdlib.md` — реестр встроенных. `specs/002-parser-ast/spec.md` + `data-model.md` — AST-контракт (стабильный вход). `ARCHITECTURE.md` §3 (стадии), §4 (AST), §5 (значения).

**Приоритет текстов ошибок**: при ЛЮБОМ расхождении §13.4 ↔ §8.3 (точка в конце, плейсхолдеры vs конкретные типы) побеждает `docs/eval-model.md §8.3`. §13.4 в рамках 003 не используется и не синхронизируется (см. D1).

## User Scenarios & Testing *(mandatory)*

«Пользователи» интерпретатора — два класса: **(A) автор программы на Ladix**, который видит результат исполнения (вывод `печать`) и позиционные рантайм-/семантические диагностики при ошибках; и **(B) учебный грейдер**, который проверяет golden-вывод обязательных примеров и закрытие учебного чеклиста (`CHECKLIST.md`). Сценарии описывают наблюдаемое поведение для обоих, без деталей реализации.

Срез историй (по брифу): **P1** = выражения с приоритетами + переменные/печать (минимально исполняемое ядро); **P2** = управляющие конструкции и циклы; **P3** = функции/рекурсия и стандартная библиотека; ошибки/семантический проход — **сквозной слой** (US5, пронизывает все P1–P3).

### User Story 1 — Выражения вычисляются с приоритетами и раздельной арифметикой (Priority: P1)

Автор пишет любое выражение Ladix; интерпретатор считает его по дереву, уже построенному парсером (приоритеты не переразбираются — только вычисляются), слева направо. Раздельны `Целое`(int64) и `Дробное`(float64): `/` всегда даёт `Дробное`; `//` — только над `Целое`; `%` — над `Целое` либо `Дробное` (fmod при `Дроб%Дроб`), смешение Цел/Дроб в `%` → ошибка типа; смешение `Цел`/`Дроб` промоутится в `Дробное`; переполнение int64 в `+ - *` — явная ошибка. Сравнения, логические `и`/`или` (короткозамкнутые, оба операнда `Булево`), унарные `не`/`-`, индексация списка/строки в рунах.

**Why this priority**: выражения — ядро, на котором стоят все statements (условия, присваивания, аргументы, возвраты, печать). Без корректного вычисления дерева не исполнить ни один следующий слой. Это самостоятельный MVP: посчитать `арифметика.ladix`.

**Independent Test**: подать таблицу выражений, сверить значение и тип результата; контрольные инварианты `2 + 3 * 4` → `Целое 14`; `7 / 2` → `Дробное 3.5`; `2 < 3 и 3 < 4` → `Булево истина`; короткое замыкание не вычисляет правый операнд `или`/`и`.

**Acceptance Scenarios**:

1. **Given** `2 + 3 * 4`, **When** вычисление, **Then** `Целое 14` (умножение глубже сложения, дерево от парсера).
2. **Given** `7 / 2` и `6 / 2`, **When** вычисление, **Then** оба `Дробное` (`3.5` и `3.0`) — `/` всегда `Дробное`; а `7 // 2` → `Целое 3`, `7 % 2` → `Целое 1` (`//` — только `Цел○Цел`; `%` — также `Дроб%Дроб` → fmod).
3. **Given** `2 + 3.0`, **When** вычисление, **Then** промоушен в `Дробное 5.0`; **And** `9223372036854775807 + 1` → `ОшибкаВыполнения «переполнение целого числа»` на позиции `+`.
4. **Given** `ложь и (1 / 0 == 0)` и `истина или (1 / 0 == 0)`, **When** вычисление, **Then** результат `ложь`/`истина` без вычисления правого операнда (короткое замыкание; деления на ноль НЕ происходит).
5. **Given** `1 == 1.0`, `"а" < "б"`, `[1, 2] == [1, 2]`, **When** вычисление, **Then** `истина`, `истина`, `истина` (численное равенство `Цел↔Дроб`; строки по код-поинтам; списки поэлементно).
6. **Given** `[10, 20, 30][1]` и `"привет"[0]`, **When** вычисление, **Then** `Целое 20` и `Строка "п"` (индексация в рунах); **And** `[1, 2][5]` → `ОшибкаВыполнения «индекс 5 вне диапазона (длина 2)»`.
7. **Given** `не истина` и `-5`, **When** вычисление, **Then** `Булево ложь` и `Целое -5`; **And** `не 1` → `ОшибкаТипа «'не' нельзя применить к Целое»`.

### User Story 2 — Переменные, области видимости, присваивание, печать (Priority: P1)

Автор объявляет переменные (`пусть`), присваивает (`=`), печатает (`печать(...)`); интерпретатор ведёт **функциональные** области видимости (Python-style): новую область создают только глобал и кадр вызова функции, блоки `если/иначе/пока/для` своей области НЕ открывают. `печать` — единственный штатный канал вывода. Программа исполняется сверху вниз: top-level `пусть` инициализируются в порядке появления.

**Why this priority**: переменные с областями, присваивание и печать вместе с US1 дают минимально исполняемое ядро — прогнать `hello.ladix` и `арифметика.ladix` с эталонным stdout. Без них выражения некуда положить и нечем показать.

**Independent Test**: исполнить программу из `пусть`/`=`/`печать(...)`, перехватить вывод через инжектированный `out` (`bytes.Buffer`), сверить с эталоном; проверить функциональный scope: `пусть` одного имени в обеих ветках `если` → «уже объявлено»; `=` в ветке мутирует внешнюю переменную.

**Acceptance Scenarios**:

1. **Given** `печать("Привет, Уклад!")`, **When** исполнение, **Then** stdout `Привет, Уклад!` + перевод строки; результат `печать` — `Пусто`, отбрасывается.
2. **Given** `пусть a = 2` затем `печать(a)`, **When** исполнение, **Then** stdout `2`; повторное `пусть a = 3` в той же области → `СемантическаяОшибка «'a' уже объявлено в строке N»` (ловится семпроходом, §9).
3. **Given** `печать(b)` до объявления `пусть b = 1`, **When** исполнение, **Then** `ОшибкаВыполнения «'b' не объявлено»` (declaredness переменной flow-зависима, оставлена рантайму).
4. **Given** `если истина:` с телом `категория = "x"` (где `категория` объявлена выше), **When** исполнение, **Then** мутируется внешняя `категория` (блок области не открывает); а `пусть категория` в обеих ветках `если/иначе` → «уже объявлено».
5. **Given** `печать(1, "две", истина)`, **When** исполнение, **Then** stdout `1 две истина` (через один пробел, строки без кавычек, + перевод строки).

### User Story 3 — Управляющие конструкции и циклы (Priority: P2)

Автор пишет `если/иначе если/иначе`, `пока`, `для … в …` с `прервать`/`продолжить`; интерпретатор вычисляет условия как **strict-`Булево`** (без truthiness), исполняет тела блоков в текущей области, обрабатывает управляющие сигналы штатно (без panic). Переменная `для x` создаётся в охватывающей области и видна после цикла; мутация списка во время итерации — ошибка.

**Why this priority**: управляющие конструкции расширяют ядро до `условие.ladix` и `цикл.ladix`. Зависят от US1 (условия — выражения) и US2 (тело — statements в той же области), поэтому P2.

**Independent Test**: исполнить вложенные `если/пока/для`, сверить вывод; проверить, что `прервать`/`продолжить` поглощаются циклом, а `вернуть` пробрасывается наверх; `для`-переменная видна после цикла со значением последней итерации; условие не-`Булево` → ошибка типа.

**Acceptance Scenarios**:

1. **Given** `если сумма > 100: ... иначе если сумма > 50: ... иначе: ...`, **When** исполнение, **Then** исполняется первая истинная ветвь; цепочка `ElseClause` обходится по `IsFinal()`.
2. **Given** условие `если 1:` (не `Булево`), **When** исполнение, **Then** `ОшибкаТипа «условие должно быть Булево, получено Целое»` на позиции выражения условия.
3. **Given** `пока i < 5:` с телом, увеличивающим `i`, **When** исполнение, **Then** цикл завершается; `прервать` выходит из цикла (сигнал поглощён), `продолжить` переходит к следующей итерации.
4. **Given** `для x в [10, 20, 30]:` с телом, **When** исполнение, **Then** перебор по элементам; после цикла `x` == `30` (видна со значением последней итерации); на `[]` переменная `x` не создаётся.
5. **Given** `для y в [1]:` где тело вызывает `добавить(тот_же_список, 2)`, **When** исполнение, **Then** `ОшибкаВыполнения «список изменён во время итерации»` (снимок — через `для y в копия(s)`).
6. **Given** `для z в 5:` (не `Список`), **When** исполнение, **Then** `ОшибкаТипа «'для' требует Список, получено Целое»` на позиции `Iterable`.

### User Story 4 — Функции, рекурсия, стандартная библиотека (Priority: P3)

Автор объявляет top-level функции с позиционными параметрами и телом-блоком, вызывает их (в т.ч. рекурсивно и forward — объявленные ниже по тексту), пользуется **23 чистыми** встроенными функциями. Кадр вызова имеет `parent = ГЛОБАЛЬНАЯ область` (лексическая, не динамическая видимость); рекурсия добавляет независимые кадры; убегающая рекурсия упирается в понятную ошибку глубины, а не в падение Go-стека. Функции **не первоклассны** — не значение.

**Why this priority**: функции и стдлиб замыкают учебный чеклист (`функция.ladix`, `факториал.ladix`). Зависят от US1–US3, поэтому P3. (Исключение: `печать` как канал вывода введена раньше — в US2.)

**Independent Test**: исполнить `функция.ladix`/`факториал.ladix`, сверить stdout; `факториал(5)` → `120`; голый `вернуть` → `Пусто`; глубокая рекурсия без базового случая → ошибка глубины (с `--max-depth` лимит конфигурируем); вызов с неверной арностью → семантическая ошибка; каждую из 23 встроенных проверить таблично; 12 deferred-заглушек → «не поддерживается».

**Acceptance Scenarios**:

1. **Given** `функция факториал(n): если n <= 1: вернуть 1 ... вернуть n * факториал(n - 1)`, **When** `печать(факториал(5))`, **Then** stdout `120`; рекурсия резолвится через таблицу функций, кадры независимы (`parent = global`).
2. **Given** функция без `вернуть` (или голый `вернуть`), **When** вызов в выражении, **Then** результат `Пусто`.
3. **Given** функция, вызывающая себя без базового случая, **When** исполнение с лимитом по умолчанию, **Then** `ОшибкаВыполнения «превышена максимальная глубина вызовов (10000). Возможна бесконечная рекурсия.»` (число = фактический лимит; `--max-depth N` меняет его и текст).
4. **Given** `функция f(a, b):` вызвана как `f(1)`, **When** семпроход/исполнение, **Then** `СемантическаяОшибка «'f' принимает 2 аргументов, передано 1»`.
5. **Given** `сумма([1, 2, 3])`, `длина("привет")`, `диапазон(1, 4)`, `булево(0)`, `тип(3.0)`, **When** вычисление, **Then** `6`, `6`, `[1, 2, 3]`, `ложь`, `"Дробное"` — поведение из `docs/stdlib.md`; `булево(x)` — единственная точка мягкого truthy (0/0.0/пустая строка/пустой список/пусто/ложь → ложь), действует только при явном вызове.
6. **Given** вызов `сегодня()` или `запустить процесс P`, **When** семпроход, **Then** соответственно `СемантическаяОшибка «функция 'сегодня' не поддерживается в этой версии»` и `СемантическаяОшибка «конструкция ... не поддерживается в этой версии»` (отличаются от «не объявлена»).

### User Story 5 — Рантайм-/семантические ошибки с позицией и deferred-граница (Priority: P1, пронизывающая)

Автор допускает ошибку (типов, деление на ноль, переполнение, неизвестная переменная, выход за границу, глубина рекурсии) или использует ещё не реализованную конструкцию; интерпретатор сообщает её **fail-fast**, в двухстрочном формате `Ошибка в строке N, колонка M:` + дословный текст из §8.3, с позицией в рунах, **без** Go stack trace. Семантический проход (стадия 3) ловит статически разрешимое до исполнения. Recover-барьер на границе CLI гарантирует понятный вывод и коды возврата.

**Why this priority**: понятные позиционные ошибки без stack trace — ключевая ценность языка и часть обязательной golden-приёмки (`ошибка.ladix` → код 1). Пронизывает US1–US4 (каждая порождает свои ошибки), но самостоятельно тестируется набором ошибочных входов — поэтому пронизывающая P1.

**Independent Test**: по одному входу на каждое сообщение §8.3; сверить категорию, позицию (строка и колонка в рунах) и дословный текст; `ошибка.ladix` → stderr `Ошибка в строке 5, колонка 14:` / `деление на ноль`, код 1; обычная пользовательская ошибка НЕ даёт Go stack trace.

**Acceptance Scenarios**:

1. **Given** `печать(всего / делитель)` на строке 5 при `делитель == 0` (`ошибка.ladix`), **When** исполнение, **Then** stderr `Ошибка в строке 5, колонка 14:` + `деление на ноль`, код 1 (позиция — токен `/`).
2. **Given** `"а" + 1`, **When** вычисление, **Then** `ОшибкаТипа «'+' нельзя применить к Строка и Целое»` на позиции `+`.
3. **Given** обращение к необъявленной переменной `x`, **When** исполнение, **Then** `«'x' не объявлено»`; а имя функции в позиции значения → `«'имя' — функция, её нельзя использовать как значение»`.
4. **Given** `вернуть` на верхнем уровне или `прервать` вне цикла, **When** семпроход, **Then** `«'вернуть' допустимо только внутри функции»` / `«'прервать' допустимо только внутри 'пока' или 'для'»`.
5. **Given** литерал `3дн`, узел `запустить процесс`, декларация `источник ...`, **When** семпроход, **Then** `«конструкция ... не поддерживается в этой версии»` на позиции узла (не тихий no-op).
6. **Given** имя периода `ежедневно` в позиции значения, **When** исполнение, **Then** `ОшибкаВыполнения «'ежедневно' не объявлено»` (тип `Период` deferred; константы в 003 НЕ предопределены).
7. **Given** искусственная Go-паника на границе CLI, **When** recover-барьер, **Then** stderr `внутренняя ошибка интерпретатора` без Go stack trace, код 1.

### Edge Cases

- **`/` всегда `Дробное`**: `6 / 3` → `Дробное 3.0` (печатается `3.0`, не `3`), даже когда делится нацело; `//` над не-`Цел` → `ОшибкаТипа`; `%` над смешанными Цел/Дроб → `ОшибкаТипа` (но `Дроб%Дроб` → `Дробное` (fmod)).
- **Деление на ноль** для `/`, `//`, `%` при нулевом правом операнде → `«деление на ноль»` на позиции **оператора**; благодаря явной проверке никогда не доходит до Go-паники.
- **Переполнение int64** в `+ - *` (вкл. унарный `-`) → явная проверка → `«переполнение целого числа»` (не wrap-around). `-MinInt64` недостижим (литерал `MinInt64` невыразим, D2 фичи 002).
- **`Запись` не конструируется в 003**: единственные источники — доменные функции (deferred), литерала нет. Поэтому `target.поле` всегда упирается в `ОшибкаТипа «значение типа <тип> не имеет полей»` — это **граница**, не баг; тестов на успешное чтение/печать/равенство непустой `Записи` НЕ требуется (механизм чтения готов как стабильная поверхность `eval↔store`, §2.1).
- **Ссылочные списки**: `пусть b = a` над списком делит хранилище; `добавить(a, x)` видно в `b` (требование SPEC §4, закреплённое структурой `*[]Value`).
- **Короткое замыкание не возвращает операнд**: `и`/`или` дают строго `Булево`, не значение операнда (в отличие от Python); оба операнда обязаны быть `Булево`.
- **Голый `вернуть` / функция без `вернуть`** → `value.None` (синглтон `Пусто`).
- **`для x` на пустом списке**: переменная не создаётся; после непустого цикла `x` видна со значением последней итерации.
- **Затенение встроенных**: `пусть длина = 5` затем `длина(2)` → переменная найдена, не функция → `«'длина' — не функция (Целое), вызов невозможен»`; объявление-затенение допустимо (с диагностикой-предупреждением, не ошибка).
- **`печать()` без аргументов** → пустая строка + перевод строки; возвращает `Пусто`.
- **Особые `Дробное`** (`+Inf`/`-Inf`/`NaN`) достижимы только переполнением float; печатаются как их даёт `strconv`; в учебных golden-примерах не встречаются.
- **Примеры `выручка.ladix`/`онбординг.ladix`** — НЕ в обязательном golden-прогоне 003 (нет строгой golden-stdout; отдельный трек движка, §1.2, `examples/MANIFEST.md`).

## Requirements *(mandatory)*

### Functional Requirements — модель значений и областей видимости

- **FR-001**: ОБЯЗАН быть листовой пакет `internal/value/` (зависит только от стандартной библиотеки Go) с интерфейсом `Value` (единственный метод `TypeName() string` — каноническое имя типа для `тип(x)` и сообщений). РОВНО **10** конкретных типов; в 003 **конструируются 6**: `Целое`(int64), `Дробное`(float64), `Строка`(UTF-8, индексация/длина в рунах), `Булево`, `Пусто`, `Список`. Имена типов канонические (`Целое`/`Дробное`, не «Число»).
- **FR-002**: `Запись` ОБЯЗАНА быть смоделирована полностью как открытая структура с сохранением порядка полей (`keys []string` + `fields map`, `Get`→`Пусто` на отсутствующем поле, `Keys`, равенство, печать), но в чистом 003 **НЕ конструироваться** (нет литерала, источники — доменные функции deferred). `Дата`/`Длительность`/`Период` определены в пакете, но в 003 **НЕ конструируются** (deferred-ворота закрыты, §1.2). Ни один путь кода 003 не порождает `Запись`/`Дата`/`Длительность`/`Период`.
- **FR-003**: `Пусто` ОБЯЗАН быть синглтоном (`var None = Пусто{}`); `Список` несёт `*[]Value` (ссылочная семантика и алиасинг); `Запись` — `map` (ссылочный). Функция без `вернуть` и голый `вернуть` дают именно `None`. Lvalue присваивания — только `Ident`.
- **FR-004**: ОБЯЗАН быть тип `Environment{vars map[string]value.Value; parent *Environment}` с `Define` (новая привязка в ЭТОЙ области; повтор → ловится семпроходом), `Assign` (поиск существующей вверх по цепочке; не найдено → «не объявлено»), `Lookup` (чтение вверх по цепочке). **Функциональный scope**: новую область создают ТОЛЬКО (1) глобал и (2) кадр вызова функции; блоки `если/иначе/пока/для` своей области НЕ создают (тело — в кадре функции / global).
- **FR-005**: Кадр вызова функции ОБЯЗАН иметь `parent = ГЛОБАЛЬНАЯ область` (не кадр вызывающего): функции top-level и не замыкания → лексическая, а не динамическая видимость. Рекурсия добавляет независимые кадры, каждый с `parent = global`.
- **FR-006**: Имена ОБЯЗАНЫ резолвиться в **двух раздельных пространствах**: переменные — в `Environment`; функции — в таблице `funcs` (пользовательские) + реестре `builtins` (23 активных + 12 deferred-заглушек). Функция **не является** `Value` (не первоклассна — нельзя присвоить/передать/вернуть/положить в список). Имя в позиции значения, найденное только в таблице функций → `«'имя' — функция, её нельзя использовать как значение»`.

### Functional Requirements — выражения

- **FR-007**: `evalExpr(env, e)` ОБЯЗАН быть type switch по конкретным узлам AST; операнды бинарных и аргументы вычисляются **слева направо**; дерево приоритетов от парсера НЕ переразбирается (только вычисляется). Литералы: `IntLit`→`Целое`, `FloatLit`→`Дробное`, `StringLit`→`Строка`, `BoolLit`→`Булево`, `NoneLit`→`None`, `ListLit`→новый `Список` (элементы слева направо в свежий `*[]Value`).
- **FR-008**: `Ident` в позиции значения ОБЯЗАН резолвиться через `env.Lookup`; промах → §2.3: имя есть в таблице функций → «функция, её нельзя использовать как значение»; иначе → `«'x' не объявлено»` (рантайм — declaredness flow-зависима).
- **FR-009**: Унарные ОБЯЗАНЫ: `OpNeg`(`-`) над `Целое`/`Дробное` (для `Целое` — с проверкой переполнения), иначе `«унарный '-' нельзя применить к <тип>»`; `OpNot`(`не`) над `Булево`, иначе `«'не' нельзя применить к <тип>»`. Позиция = токен оператора (`UnaryExpr.Pos()`).
- **FR-010**: `или`/`и` ОБЯЗАНЫ быть **короткозамкнуты**: левый операнд (обязан `Булево`); для `или` `истина`→`истина` без правого; для `и` `ложь`→`ложь` без правого; иначе — правый (обязан `Булево`). Результат строго `Булево` (НЕ возврат операнда). Любой операнд не `Булево` → `«'<оп>' требует Булево, получено <тип>»`.
- **FR-011**: Арифметика ОБЯЗАНА: `Цел○Цел` (`+ - *`)→`Целое` с **явной** проверкой переполнения int64 (`«переполнение целого числа»`); участвует `Дробное`→промоушен в `Дробное`; `/` (любые числовые)→**всегда** `Дробное`; `//` только `Цел//Цел`→`Целое`, иначе `ОшибкаТипа`; `%` — `Цел%Цел`→`Целое`, `Дроб%Дроб`→`Дробное`(fmod), смешанное→`ОшибкаТипа`; правый операнд `/`/`//`/`%` равен нулю→`«деление на ноль»`; `Строка+Строка`→конкатенация; прочие `+`→`«'+' нельзя применить к <тип> и <тип>»`. Списки `+` НЕ складываются (для соединения — `соединить`).
- **FR-012**: Сравнения ОБЯЗАНЫ: `==`/`!=` над любыми типами (разные типы→`ложь`, **кроме** `Целое↔Дробное` численно; `Строка` по код-поинтам; `Булево` по значению; `Пусто` равно только `Пусто`; `Список` поэлементно, разная длина→`ложь`; `Запись` структурно). `< <= > >=` — только взаимно-упорядочиваемые (`Цел↔Цел`, `Дроб↔Дроб`, `Цел↔Дроб` промоушен, `Строка↔Строка` лексикографически по код-поинтам), прочее→`«'<оп>' нельзя применить к <тип> и <тип>»`. Позиция = токен оператора (`BinaryExpr.Pos()`).
- **FR-013**: `IndexExpr` (`target[index]`) ОБЯЗАН: `Список`→элемент, `Строка`→руна (индексация в рунах); `index` обязан `Целое`, иначе `«индекс должен быть Целое, получено <тип>»`; вне `[0, длина)` (вкл. отрицательные)→`«индекс N вне диапазона (длина L)»`; иной `target`→`«значение типа <тип> не индексируется»`. Позиция = `IndexExpr.Pos()` (начало `target`).
- **FR-014**: `FieldExpr` (`target.field`) ОБЯЗАН: `Запись`→`Get(field)` (отсутствующее поле→`Пусто`); иной `target`→`«значение типа <тип> не имеет полей»` (в чистом 003 всегда упирается в неё — граница, не баг, D5). Позиция = `FieldExpr.Pos()` (начало `target`).

### Functional Requirements — statements и управляющие сигналы

- **FR-015**: Управляющий поток `вернуть`/`прервать`/`продолжить` ОБЯЗАН реализовываться **явным возвращаемым сигналом** (`SignalKind` ∈ {`SigNormal`,`SigBreak`,`SigContinue`,`SigReturn`}; `SigReturn` несёт `Value`), НЕ через `panic/recover`. Два независимых канала: `error` (рантайм-ошибки, всплывают немедленно до CLI) и `Signal` (штатный поток). `evalBlock` после каждого statement: `err != nil`→наверх; `sig.Kind != SigNormal`→прекратить блок и вернуть сигнал.
- **FR-016**: ОБЯЗАНЫ исполняться: `LetStmt`→`Define`; `AssignStmt`→`Assign` (не объявлено→ошибка); `ExpressionStmt`→`evalExpr`, результат отбрасывается (`печать(…)`, `добавить(…)`). `FunctionDecl` как statement НЕ исполняется (зарегистрирована семпроходом, eval её пропускает → `SigNormal`).
- **FR-017**: `IfStmt` ОБЯЗАН вычислять `Cond` как **strict-`Булево`** (не-`Булево`→`«условие должно быть Булево, получено <тип>»` на позиции `Cond`); первая истинная ветвь→`evalBlock`; иначе обход цепочки `ElseClause` (`IsFinal()` различает финальный `иначе` и `иначе если`). Truthiness в условиях НЕ применяется.
- **FR-018**: `WhileStmt` ОБЯЗАН перед каждой итерацией вычислять `Cond` (strict-`Булево`); тело — `evalBlock`; `SigBreak`→выход (поглощён), `SigContinue`→следующая итерация (поглощён), `SigReturn`→наверх.
- **FR-019**: `ForStmt` (`для x в E`) ОБЯЗАН: `E` обязан `Список` (иначе `«'для' требует Список, получено <тип>»` на позиции `Iterable`); переменная `x` привязывается в **охватывающей** области (`Define` при первом элементе, **если имени в области ещё нет**, затем `Assign`); на пустом списке `x` не создаётся; после цикла `x` видна со значением последней итерации. Мутация помеченного «итерируется» списка через `добавить`→`«список изменён во время итерации»`. Сигналы как у `пока`.
- **FR-020**: `BreakStmt`→`SigBreak`, `ContinueStmt`→`SigContinue`, `ReturnStmt`→`SigReturn{Value или None если nil}`. Легальность контекста (`вернуть` только в функции; `прервать`/`продолжить` только в цикле) ОБЯЗАНА проверяться семпроходом (§9), а не рантаймом.

### Functional Requirements — функции, вызовы, рекурсия

- **FR-021**: ОБЯЗАН быть тип `Interpreter{global *Environment; funcs map[string]*ast.FunctionDecl; builtins map[string]Builtin; maxDepth int; depth int; out io.Writer}`. Состояние передаётся явно (без глобалов): `out` инжектируется (тест — `bytes.Buffer`); `maxDepth` — поле из флага `--max-depth` (по умолчанию **10000**); `depth` — текущая глубина пользовательских вызовов.
- **FR-022**: Резолв `CallExpr` с `Ident`-callee `f` ОБЯЗАН идти по порядку (SPEC §6: переменные→функции→встроенные): (1) `env.Lookup(f)` — если переменная (в v1 никогда не функция) и за ней `(` → `«'f' — не функция (<тип>), вызов невозможен»`; (2) `funcs[f]` → вызов пользовательской; (3) `builtins[f]` — активная→вызов, deferred-заглушка→`«функция 'f' не поддерживается в этой версии»`; (4) иначе→`«функция 'f' не объявлена»` (статически — семпроход). Не-`Ident` callee→вычислить→`«… — не функция (<тип>)»`. Позиция всех ошибок вызова = `CallExpr.Pos()` (=`Callee.Pos()`).
- **FR-023**: Вызов пользовательской функции ОБЯЗАН: (1) вычислить аргументы слева направо; (2) арность (фикс.) проверена семпроходом (≠→`«'имя' принимает N аргументов, передано M»`); (3) `depth++`, при `depth > maxDepth`→`«превышена максимальная глубина вызовов (10000). Возможна бесконечная рекурсия.»` (число = фактический лимит), `defer depth--`; (4) `frame := NewEnvironment(global)`, позиционно `frame.Define(param, arg)` (ссылочные аргументы — как есть, мутация видна вызывающему); (5) `evalBlock(frame, body)`: `SigReturn`→его значение, `SigNormal`→`None`. `SigBreak`/`SigContinue` сюда не доходят (легальность — семпроход).
- **FR-024**: Рекурсия ОБЯЗАНА работать (имя резолвится через `funcs` независимо от кадра); счётчик глубины — защита от убегающей рекурсии вместо неперехватываемого переполнения Go-стека.

### Functional Requirements — стандартная библиотека

- **FR-025**: ОБЯЗАНЫ быть зарегистрированы **РОВНО 23** активных чистых встроенных (закрытый, исчерпывающий список §6 — расширять/сокращать ЗАПРЕЩЕНО): `печать`; `строка`, `целое`, `дробное`, `число`, `булево`, `тип`; `сумма`, `количество`, `среднее`, `мин`, `макс`; `длина`, `добавить`, `соединить`, `срез`, `содержит`, `найти`, `копия`, `обратить`, `сортировать`, `диапазон`; `подстрока`. `длина` — одна перегруженная функция (список и строка), в счёте 23 учитывается **один раз**. Поведение и сигнатуры — `docs/stdlib.md`. Все встроенные **затеняемы** объявлением `пусть` того же имени (с диагностикой-предупреждением, не ошибка).
- **FR-026**: `печать` ОБЯЗАНА быть единственным штатным каналом вывода: строковые представления (§7) через один пробел + перевод строки; `печать()`→пустая строка + перевод; возвращает `Пусто`; пишет в инжектированный `Interpreter.out`. Ключевые рантайм-ошибки стдлиб: `среднее/мин/макс` на пустом списке→`«<имя>: список пуст»`; `срез`/`подстрока` вне `[0..длина]`→`«<имя>: индексы вне диапазона»`; неверное число аргументов вариативной/перегруженной (`печать`/`диапазон`/`длина`)→`«'имя': неверное число аргументов»` (рантайм, позиция `CallExpr.Pos()`; источник — docs/stdlib.md); `добавить` при активной итерации→`«список изменён во время итерации»`.
- **FR-027**: `добавить` ОБЯЗАН быть **единственным мутатором** (меняет `*s.Elems` на месте, возвращает `Пусто`); прочие операции над списками (`соединить`/`срез`/`копия`/`обратить`/`сортировать`) возвращают **новый** список. Типы аргументов НЕ проверяются на семпроходе (динамика) — несовместимый тип всплывает рантаймом первой операцией с позицией `CallExpr.Pos()`.
- **FR-028**: `булево(x)` ОБЯЗАНА быть **ЕДИНСТВЕННОЙ** точкой мягкого truthy (`0`/`0.0`/пустая строка/пустой список/`пусто`/`ложь` → `ложь`), действующей ТОЛЬКО при явном вызове. В условиях `если`/`пока`/`иначе если` truthiness НЕ применяется (strict-`Булево`, FR-017/FR-018).
- **FR-029**: ОБЯЗАНЫ быть зарегистрированы **РОВНО 12** deferred-заглушек (вызов→`«функция '<имя>' не поддерживается в этой версии»`, отличается от «не объявлена»): 9 дата/время (`дата`, `сегодня`, `вчера`, `завтра`, `длительность`, `в_секундах`, `в_минутах`, `в_часах`, `в_днях`) + 3 процессные (`статус_процесса`, `состояние_процесса`, `задачи_пользователя`). Ни одна НЕ реализуется в 003, даже если выглядит детерминированным конструктором. Полное множество встроенных = 23 + 12 = **35** (SPEC §8); «35» НЕ означает 35 активных.
- **FR-030**: `строка(x)` и `печать` ОБЯЗАНЫ использовать единое строковое представление (§7): `Целое`→десятичная; `Дробное`→кратчайшая обратимая запись (`strconv.FormatFloat(v,'g',-1,64)`) с **принудительной** `.0` если выглядит целым (`2175.0`, не `2175`); `Строка`→текст без кавычек; `Булево`→`истина`/`ложь`; `Пусто`→`пусто`; `Список`→`[`элементы через `, ``]`; `Запись`→`{поле: значение, …}` в порядке полей. Строки внутри `Список`/`Запись` — без кавычек.

### Functional Requirements — ошибки и привязка позиции

- **FR-031**: Рантайм-ошибки ОБЯЗАНЫ быть типизированными в `internal/errors`, нести `Line, Col int` + `Msg`, реализовывать `error`, дружить с `errors.Is/As`. Категории: `СемантическаяОшибка` (стадия 3), `ОшибкаТипа` (стадия 4), `ОшибкаВыполнения` (стадия 4). Все — **fail-fast** (накопителя в eval нет; накопитель — только лексер/парсер). Формат вывода — двухстрочный: `Ошибка в строке N, колонка M:` + перевод строки + полезная нагрузка; `N, M` с 1, `M` — в **рунах**.
- **FR-032**: Привязка позиции к узлу ОБЯЗАНА быть (§8.2): деление на ноль / переполнение / тип-сравнение бинарных → `BinaryExpr` (токен **оператора**); тип унарного → `UnaryExpr` (оператор); условие не-`Булево` → `Cond.Pos()`; `для` не над `Список` → `Iterable.Pos()`; индекс/не индексируется → `IndexExpr.Pos()`; нет полей → `FieldExpr.Pos()`; необъявленная переменная / функция-как-значение → `Ident.Pos()`; арность / не функция / глубина / рантайм-стдлиб / deferred-вызов → `CallExpr.Pos()`; deferred-узлы (`RunProcessExpr`/`*Action`/`DurationLit`) → `node.Pos()`. Контрольный golden: `ошибка.ladix` строка 5 `печать(всего / делитель)` → **строка 5, колонка 14** (токен `/`).
- **FR-033**: Полезная нагрузка сообщений ОБЯЗАНА воспроизводиться **ДОСЛОВНО** из реестра §8.3 (см. раздел «Реестр сообщений» ниже) — без завершающей точки, **кроме** многофразовых (рекурсия). При любом расхождении §13.4 ↔ §8.3 побеждает §8.3 (D1). `<тип>` ∈ {`Целое`,`Дробное`,`Строка`,`Булево`,`Пусто`,`Длительность`,`Период`,`Дата`,`Список`,`Запись`}.

### Functional Requirements — семантический проход (стадия 3)

- **FR-034**: `Analyze(prog *ast.Program) error` ОБЯЗАН быть лёгким проходом по AST **до** исполнения, **fail-fast** (первая ошибка или `nil`; накопителя нет). **Шаг 1**: все top-level `FunctionDecl`→`funcs` (forward-вызовы разрешены), повтор имени→`«функция 'f' уже объявлена в строке N»`; top-level `источник/метрика/процесс/триггер`→deferred-ошибка. **Шаг 2** (по областям; блоки область не открывают): повтор `пусть x` в той же области (в т.ч. в разных ветках `если`, `для x` при объявленном `x`)→`«'x' уже объявлено в строке N»`; `вернуть` вне функции→`«'вернуть' допустимо только внутри функции»`; `прервать`/`продолжить` вне `пока`/`для`→соответствующий текст; `CallExpr` с `Ident`-callee — резолв (переменная→в рантайм; пользовательская/активная встроенная→ок + проверка фикс. арности; deferred-встроенная→deferred; иначе→`«функция 'f' не объявлена»`); reserved-узлы (`*Action`, `RunProcessExpr`) и `DurationLit`→deferred-ошибка.
- **FR-035**: Семпроход НЕ ОБЯЗАН делать (оставлено рантайму, flow-зависимо): declaredness **переменной** в позиции значения (зависит от порядка top-level `пусть`); любые проверки **типов** (динамическая типизация); арность вариативных/перегруженных встроенных (`печать`/`диапазон`/`длина`).

### Functional Requirements — CLI, recover-барьер, deferred-граница

- **FR-036**: Конструкции, которые парсятся в 002, но в 003 не исполняются, ОБЯЗАНЫ давать семантическую ошибку с позицией узла (не тихий no-op): процессный слой (`RunProcessExpr`, `AssignAction`/`CallAction`/`NotifyAction`), декларатив (`источник`/`метрика`/`процесс`/`триггер`), дата-подсистема (литерал `DurationLit` `3дн`, конструкторы дат, арифметика дат) → `«конструкция ... не поддерживается в этой версии»`. period-константы `ежедневно`/`еженедельно`/`ежемесячно`/`ежеквартально`/`ежегодно` в 003 НЕ предопределены и НЕ резолвятся: имя в позиции значения → рантайм `«'<имя>' не объявлено»` (тип `Период` deferred).
- **FR-037**: ОБЯЗАН быть CLI `ladix run <файл>` с конвейером: **лексер**→**парсер** (синтаксические ошибки — накопленные, печать и выход)→**`Analyze`** (семпроход; первая ошибка→печать и выход)→**исполнение** (`Interpreter.Run`). Флаг `--max-depth N` (по умолчанию 10000) задаёт лимит глубины рекурсии.
- **FR-038**: Граница CLI-подкоманды ОБЯЗАНА быть обёрнута `defer recover()`: штатные ошибки Ladix→формат §8 в **stderr**, код **1**; непредвиденная Go-паника→дженерик `внутренняя ошибка интерпретатора` в stderr **без** Go stack trace, код **1**; ошибка использования CLI (нет файла, неверный флаг)→код **2**; успех→код **0**. Штатные ошибки (деление на ноль, переполнение, индекс, лимит рекурсии) проверяются явно и НИКОГДА не доходят до паники.

### Quality / Constitution Gates

- **FR-039**: Код ОБЯЗАН проходить `go build ./...` и `go vet ./...` без замечаний и быть отформатирован `gofmt` без диффа (конституция I).
- **FR-040**: Интерпретатор разрабатывается **tests-first**: табличные тесты на eval по слоям (значения, выражения, statements, scope, функции/рекурсия, стдлиб, ошибки) + golden-прогон всех обязательных примеров — часть каждой задачи; `go test -race` зелёный (конституция VI). Печать перехватывается через инжектированный `out` (`bytes.Buffer`).

### Out of Scope (границы)

- **НЕ** менять грамматику, приоритеты, AST — приходят готовыми от 002 (стабильный вход).
- **НЕ** реализовывать декларатив (`источник`/`метрика`/`процесс`/`триггер`), движок процессов, таймеры/планировщик, персистентность SQLite, режим `serve` — будущие фичи (engine 004+).
- **НЕ** конструировать `Запись`/`Дата`/`Длительность`/`Период` (типы смоделированы/определены, но ворота закрыты deferred); тестов на успешную непустую `Запись` НЕ требовать.
- **НЕ** реализовывать 12 deferred-встроенных (дата/время + процессные) — только заглушки «не поддерживается».
- **НЕ** предопределять period-константы (`ежедневно`…`ежегодно`).
- `examples/выручка.ladix`, `examples/онбординг.ladix` **НЕ** входят в обязательный golden-прогон 003.

### Key Entities

- **`value.Value` и 10 типов**: интерфейс с `TypeName()`; 6 конструируемых в 003 (`Целое`/`Дробное`/`Строка`/`Булево`/`Пусто`/`Список`), `Запись` смоделирована но не порождается, `Дата`/`Длительность`/`Период` deferred.
- **`Environment`**: область видимости (`vars` + `parent`); цепочка даёт лексический поиск; `Define`/`Assign`/`Lookup`.
- **`Signal`/`SignalKind`**: штатный поток управления (`Normal`/`Break`/`Continue`/`Return`) без panic.
- **`Interpreter`**: состояние исполнения (`global`, `funcs`, `builtins`, `maxDepth`, `depth`, `out`).
- **`Builtin`**: запись встроенной (`Name`, `Arity`, `Fn`); 23 активных + 12 deferred-заглушек.
- **Категории ошибок**: `СемантическаяОшибка` (стадия 3), `ОшибкаТипа`/`ОшибкаВыполнения` (стадия 4); двухстрочный формат, позиция в рунах.
- **`Analyze`**: семантический проход (стадия 3) — fail-fast, статически разрешимое.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Golden-прогон `ladix run` по 6 обязательным примерам (`hello`, `арифметика`, `условие`, `цикл`, `функция`, `факториал`) даёт эталонный stdout (байт-в-байт по таблице выше / §10.3) и код **0**.
- **SC-002**: `ошибка.ladix` (`100/0` на строке 5) даёт stderr ровно `Ошибка в строке 5, колонка 14:` + `деление на ноль` (двухстрочно, позиция = токен `/`) и код **1** — не зависание и не падение.
- **SC-003**: Каждое сообщение реестра §8.3 (деление на ноль, переполнение, глубина рекурсии, ошибка типов, неизвестная переменная, индекс вне диапазона, арность, не функция, функция-как-значение, «не поддерживается») воспроизводится **ДОСЛОВНО** в двухстрочном формате с корректной позицией `(строка, колонка)` 1-based в рунах — по проверенному golden-кейсу на сообщение.
- **SC-004**: Инварианты выражений подтверждены табличными тестами: приоритеты `2 + 3 * 4`→`14`; `/`→`Дробное` (`7/2`=`3.5`); промоушен `Цел+Дроб`→`Дробное`; короткое замыкание `или`/`и` не вычисляет правый операнд; сравнения (`1==1.0`→истина, списки поэлементно); индексация в рунах.
- **SC-005**: Функциональный scope подтверждён: `пусть` одного имени в обеих ветках `если/иначе`→`«уже объявлено»`; `=` в ветке мутирует внешнюю переменную; переменная `для x` видна после цикла со значением последней итерации; кадр функции имеет `parent = global` (рекурсия независима).
- **SC-006**: Функции/рекурсия подтверждены: `факториал(5)`→`120`; голый `вернуть`→`пусто`; убегающая рекурсия→`«превышена максимальная глубина вызовов (10000)...»` (с `--max-depth` лимит и текст меняются); неверная арность→семантическая ошибка.
- **SC-007**: Стдлиб подтверждена: 23 активных встроенных дают поведение `docs/stdlib.md`; `булево(x)` — единственная точка truthy; 12 deferred-заглушек→`«функция '<имя>' не поддерживается в этой версии»`; deferred-узлы (`RunProcessExpr`/`*Action`/`DurationLit`/декларатив)→`«конструкция ... не поддерживается в этой версии»`; period-имена→`«не объявлено»`.
- **SC-008**: Обычная пользовательская ошибка (любого слоя) НЕ даёт Go stack trace; recover-барьер ловит непредвиденную панику→`внутренняя ошибка интерпретатора`; коды возврата `0` (успех) / `1` (ошибка Ladix или паника) / `2` (использование CLI).
- **SC-009**: Гейты зелёные: `go build ./...` и `go vet ./...` без замечаний, `gofmt` без диффа, `go test -race` без гонок; табличные тесты на все слои (значения, выражения, statements, scope, функции/рекурсия, стдлиб, ошибки) + golden-прогон проходят.

## Assumptions

- **A1 — Вход стабилен**: интерпретатор опирается на AST-контракт фичи 002 (`specs/002-parser-ast/spec.md` + `data-model.md`): узлы подмножества B построены, каждый несёт `ast.Position{Line, Col}` (1-based, в рунах) по конвенции `Pos()` (оператор для `BinaryExpr`/`UnaryExpr`, `Callee` для `CallExpr`, `Target` для `IndexExpr`/`FieldExpr`). Грамматика/приоритеты/AST в 003 НЕ меняются.
- **A2 — Имена и язык**: публичные Go-имена английские и идиоматичные (`Interpreter`, `Environment`, `Value`, `Signal`, `Builtin`); тексты пользовательских сообщений — русские, имена типов канонические (`Целое`/`Дробное`). Листовой `internal/value/` пакета `errors` не импортирует.
- **A3 — Deferred-ворота закрыты**: `Запись`/`Дата`/`Длительность`/`Период` смоделированы/определены как стабильная поверхность `eval↔store`, но в 003 ни один путь кода их не конструирует; их источники (литерал `3дн`, конструкторы дат, доменные функции) дают deferred-ошибку. `FieldExpr` в чистом 003 всегда упирается в «не имеет полей» — ожидаемо.
- **A4 — period-константы не предопределены**: `ежедневно`…`ежегодно` в 003 — обычные `Ident`, резолвятся как переменные → «не объявлено» (тип `Период` deferred; предзаполнение — задача декларатив/engine-трека).
- **A5 — Лимит глубины**: `maxDepth` по умолчанию `10000`, конфигурируется флагом `--max-depth N`; число в тексте ошибки = фактический лимит. Защита от убегающей рекурсии — явный счётчик, не Go-стек.
- **A6 — Go 1.22+**, единый модуль, без CGO; новые пакеты `internal/value`, `internal/eval` и команда `cmd/ladix`; пакет `errors` дополняется типами `СемантическаяОшибка`/`ОшибкаТипа`/`ОшибкаВыполнения` (eval — fail-fast, без накопителя).

## Зафиксированные решения (НЕ переоткрывать)

> Перенесены из брифа и `docs/eval-model.md` §1–§10 как контекст реализации; ни одно не переоткрывается `/speckit-plan`/`/speckit-tasks`.

- **D1 — Источник текстов ошибок — §8.3**: при ЛЮБОМ расхождении §13.4 ↔ §8.3 (точка, плейсхолдеры vs конкретные типы) побеждает `docs/eval-model.md §8.3`; §13.4 в 003 не используется и не синхронизируется (FR-033).
- **D2 — Числа раздельны**: `Целое`=int64, `Дробное`=float64; `/` всегда→`Дробное`; `//` только `Цел○Цел`; `%` — `Цел%Цел` или `Дроб%Дроб` (fmod), смешанное → `ОшибкаТипа`; смешение→промоушен; переполнение int64 в `+ - *`→явная ошибка (не wrap-around) (FR-011).
- **D3 — Функциональный scope**: блоки `если/иначе/пока/для` области НЕ создают; единственные создатели — global и кадр функции; кадр функции имеет `parent = global` (лексическая, не динамическая видимость) (FR-004/FR-005).
- **D4 — Control-flow через `Signal`, не panic**: `вернуть`/`прервать`/`продолжить` — явный возвращаемый сигнал; recover только на границе CLI (FR-015/FR-038).
- **D5 — `Запись` смоделирована, но не конструируется в 003**: `FieldExpr` всегда даёт «не имеет полей»; тестов на успешную непустую `Запись` не требовать (FR-002/FR-014).
- **D6 — Стдлиб = 23 активных + 12 deferred = 35**: закрытый список §6; `длина` в счёте ×1; `булево(x)` — единственная точка мягкого truthy (FR-025/FR-028/FR-029).
- **D7 — period-константы не предопределены**: `ежедневно`…`ежегодно` → «не объявлено» (FR-036, A4).
- **D8 — Два пространства имён**: переменные (`Environment`) vs функции (`funcs`+`builtins`); функция не первоклассна, не `Value` (FR-006).
- **D9 — Лимит глубины 10000, флаг `--max-depth`; recover-барьер и коды возврата 0/1/2** на границе CLI (FR-021/FR-038, A5).
