# Contract: Каталог семантических / типовых / рантайм-ошибок eval (§8.3 — exact-match)

**Feature**: 003-interpreter-eval | **Источники**: docs/eval-model.md §8.1 (формат), §8.2 (привязка позиции), §8.3 (реестр); spec.md FR-031..FR-036, реестр §8.3; контрольный golden `ошибка.ladix`

Каталог дословных сообщений eval для exact-match тестов. Полезная нагрузка воспроизводится **ДОСЛОВНО** из `docs/eval-model.md §8.3` — **без** завершающей точки, **кроме** многофразовых (рекурсия). При любом расхождении `§13.4 ↔ §8.3` побеждает §8.3 (D1). Тире — длинное «—».

Канонический формат вывода (§8.1):

```
Ошибка в строке N, колонка M:
<полезная нагрузка>
```

`N`, `M` с 1; `M` — в **рунах**. Каретка `^` под колонкой — UX, не контракт. Категория в выводе не печатается (различается типом Go-ошибки).

## RE-2. Правила подстановки плейсхолдеров

| Плейсхолдер | Подстановка |
|---|---|
| `<тип>` | `value.TypeName()` значения операнда/цели |
| `<оп>` | строковое имя оператора (`ast.BinOp.String()` / `ast.UnOp.String()`): `или`/`и`/`+`/`-`/`*`/`/`/`//`/`%`/`==`/`!=`/`<`/`<=`/`>`/`>=` |
| `'x'` / `'f'` / `'имя'` / `<имя>` | имя переменной/функции/встроенной (`'…'` — в кавычках-ёлочках по §8.3; `<имя>` без кавычек у стдлиб-сообщений `список пуст`/`индексы вне диапазона`) |
| `N` / `M` / `L` | числа: ожидаемая/переданная арность, длина списка/строки, номер строки объявления, фактический лимит глубины |
| `<X>` | человекочитаемое имя deferred-конструкции |

> Без завершающей точки, **кроме** `RT-DEPTH` (две фразы с точками внутри). `'x' уже объявлено в строке N` и `функция 'f' уже объявлена в строке N` несут номер строки исходного объявления.

## RE-3. Привязка позиции к узлу (§8.2, FR-032)

| Класс ошибки | Позиция |
|---|---|
| деление на ноль / переполнение / тип бинарного / логика | `BinaryExpr.Pos()` (токен **оператора**) |
| тип унарного (`-`/`не`) | `UnaryExpr.Pos()` (оператор) |
| условие не-`Булево` | `Cond.Pos()` |
| `для` не над `Список` | `Iterable.Pos()` |
| индекс / не индексируется | `IndexExpr.Pos()` (начало `target`) |
| нет полей | `FieldExpr.Pos()` (начало `target`) |
| необъявленная переменная / функция-как-значение | `Ident.Pos()` |
| арность / не функция / глубина / рантайм-стдлиб / deferred-вызов | `CallExpr.Pos()` (= `Callee.Pos()`) |
| deferred-узлы (`RunProcessExpr`/`*Action`/`DurationLit`) | `node.Pos()` |

## RE-4. Категории и стадии

- **СемантическаяОшибка** (стадия 3, семпроход `Analyze`): `SEM-*` — повтор объявления, фикс. арность, контекст `вернуть`/`прервать`/`продолжить`, необъявленная функция, deferred-конструкции и deferred-встроенные.
- **ОшибкаТипа** (стадия 4, исполнение): `TY-*` — несовместимые операнды, условие не-`Булево`, `для` не над `Список`, индекс/поле, ошибки преобразования стдлиб.
- **ОшибкаВыполнения** (стадия 4, исполнение): `RT-*` — деление на ноль, переполнение, индекс вне диапазона, лимит рекурсии, рантайм-стдлиб, функция-как-значение/не-функция, period-имя «не объявлено».

Все три — **fail-fast** (накопителя в eval нет); типы в `internal/errors`, несут `Line, Col int` + `Msg`, дружат с `errors.Is/As`.

## RE-5. Контрольный golden (SC-002)

`ошибка.ladix`, строка 5 `печать(всего / делитель)` при `делитель == 0`:

```
Ошибка в строке 5, колонка 14:
деление на ноль
```

Код возврата **1**. Позиция = токен `/` (колонка 14, в рунах). Без Go stack trace.

## RE-6. Чего eval НЕ порождает (границы)

- НЕ печатает завершающую точку (кроме `RT-DEPTH`) и НЕ печатает категорию ошибки в выводе.
- НЕ накапливает ошибки (fail-fast); `ErrorList` — артефакт лексера/парсера, в eval не используется.
- НЕ синхронизирует `§13.4` SPEC (D1) — тексты только из §8.3.
- НЕ выдаёт Go stack trace на пользовательских ошибках; непредвиденная Go-паника → `«внутренняя ошибка интерпретатора»` (дженерик, recover-барьер CLI, не из этого каталога), код 1.
