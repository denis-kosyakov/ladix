# Contract: Модель значений Value (внутренняя поверхность eval / store)

**Feature**: 003-interpreter-eval | **Источники**: ARCHITECTURE §5, §2.1; SPEC §4; docs/eval-model.md §1.3/§3.3/§7; spec.md FR-001..FR-003, FR-011, FR-012, FR-030

Стабильный контракт пакета `internal/value` — модель значений, которой оперирует интерпретатор (фича 003) и будущий `store` (фича 004+). Листовой пакет (только stdlib Go), нейтральная поверхность `eval↔store` (вариант A). AST-вход — отдельный контракт [../../002-parser-ast/contracts/ast.md](../../002-parser-ast/contracts/ast.md).

## C-1. Типы значений (10; в 003 конструируется 6)

| # | Тип (канон) | Go-репрезентация | Конструируется в 003 | Источник |
|---|---|---|---|---|
| C-1.1 | `Целое` | `int64` | ✅ | SPEC §4, §1.3.1 |
| C-1.2 | `Дробное` | `float64` | ✅ | SPEC §4, §1.3.1 |
| C-1.3 | `Строка` | `string` UTF-8 (индексация/длина в рунах) | ✅ | SPEC §4, §1.3 |
| C-1.4 | `Булево` | `bool` | ✅ | SPEC §4 |
| C-1.5 | `Пусто` | синглтон `var None = Пусто{}` | ✅ | §1.3, FR-003 |
| C-1.6 | `Список` | `*[]Value` (ссылочный) | ✅ | SPEC §4, FR-003 |
| C-1.7 | `Запись` | `keys []string` + `fields map[string]Value` (открытая, порядок полей) | ❌ смоделирована | SPEC §4, D5, FR-002 |
| C-1.8 | `Дата` | год-месяц-день | ❌ deferred | §1.2, FR-002 |
| C-1.9 | `Длительность` | `(int64, unit)` | ❌ deferred | §1.2, FR-002 |
| C-1.10 | `Период` | enum 5 констант | ❌ deferred | §1.2, A4 |

> Интерфейс `Value{ TypeName() string }` — `TypeName()` даёт каноническое имя (`«Целое»`/`«Дробное»`/…) для `тип(x)` и подстановки `<тип>` в сообщениях. Функция **не** реализует `Value`.

## C-2. Строковое представление §7 (`строка(x)` / `печать`, едино)

| Тип | Представление | Пример |
|---|---|---|
| `Целое` | десятичная | `42`, `-5` |
| `Дробное` | `strconv.FormatFloat(v,'g',-1,64)`; принудительная `.0`, если «выглядит целым» (нет `.`/`e`/`E`/`n`/`i`) | `2175.0`, `3.14`, `1e+20` |
| `Строка` | текст без кавычек | `привет` |
| `Булево` | `истина` / `ложь` | `истина` |
| `Пусто` | `пусто` | `пусто` |
| `Список` | `[` элементы через `, ` рекурсивно `]` | `[1, две, истина]` |
| `Запись` | `{` `поле: значение` через `, ` в порядке полей `}` | `{номер: 7, сумма: 1000}` |

**Контрольные инварианты (SC-001/SC-004)**:

- `6 / 3` → `Дробное`, печать `3.0` (не `3`).
- `функция.ladix` печатает `2175.0` — принудительная `.0` обязательна.
- Строки внутри `Список`/`Запись` — **без** кавычек, как на верхнем уровне.

## C-3. Равенство `==` / `!=` (§3.3, FR-012)

| Пара | Результат |
|---|---|
| разные типы | `ложь`, **кроме** `Целое↔Дробное` |
| `Целое↔Дробное` | численно (`1 == 1.0` → `истина`) |
| `Строка↔Строка` | по код-поинтам |
| `Булево↔Булево` | по значению |
| `Пусто` | равно только `Пусто` |
| `Список↔Список` | поэлементно; разная длина → `ложь` |
| `Запись↔Запись` | структурно (множество полей + значения) |

## C-4. Упорядочивание `< <= > >=` (§3.3, FR-012)

| Пара | Допустимо |
|---|---|
| `Цел↔Цел`, `Дроб↔Дроб`, `Цел↔Дроб` (промоушен) | ✅ численно |
| `Строка↔Строка` | ✅ лексикографически по код-поинтам |
| прочее (вкл. `Список`/`Запись`/`Булево`/`Пусто`) | ❌ → `«'<оп>' нельзя применить к <тип> и <тип>»` |

## C-5. Арифметика и промоушен (§3.3, FR-011 — реализуется в eval, правила числовые)

| Оператор | Правило | Результат |
|---|---|---|
| `+ - *` | `Цел○Цел` с явной проверкой переполнения int64 | `Целое` (переполнение → `«переполнение целого числа»`) |
| `+ - *` | участвует `Дробное` → промоушен | `Дробное` |
| `/` | любые числовые | **всегда** `Дробное` |
| `//` | только `Цел//Цел` | `Целое` (иначе `ОшибкаТипа`) |
| `%` | `Цел%Цел` | `Целое` |
| `%` | `Дроб%Дроб` (fmod, `math.Mod`) | `Дробное` |
| `%` | смешанное `Цел/Дроб` | `ОшибкаТипа` |
| `/ // %` | правый операнд `0` | `«деление на ноль»` на позиции **оператора** |
| `+` | `Строка+Строка` | конкатенация `Строка` |
| `+` | прочее | `«'+' нельзя применить к <тип> и <тип>»` |

> Списки `+` НЕ складываются (для соединения — `соединить`). Унарный `-` над `Целое`/`Дробное` (для `Целое` — с проверкой переполнения); прочее → `«унарный '-' нельзя применить к <тип>»`.

## C-6. Ссылочность и алиасинг

- `Список` несёт `*[]Value` — `пусть b = a` делит хранилище; `добавить(a, x)` видно в `b` (FR-003, SPEC §4).
- `Запись` — `map` (ссылочный), но в 003 не конструируется (C-7).
- Прочие типы (`Целое`/`Дробное`/`Строка`/`Булево`/`Пусто`) — значимые.

## C-7. Чего модель НЕ делает в 003 (границы)

- НЕ конструирует `Запись` (нет литерала; источники — доменные функции deferred) — `FieldExpr` всегда упирается в `«значение типа <тип> не имеет полей»` (D5).
- НЕ конструирует `Дата`/`Длительность`/`Период` (deferred-ворота закрыты, §1.2).
- НЕ делает неявных приведений, кроме автопромоушена `Целое→Дробное` в арифметике/сравнениях.
- НЕ импортирует `ast`/`errors`/`eval` (листовость, конституция VII) — позицию и тексты ошибок формирует вызывающий eval.
