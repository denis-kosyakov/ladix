# Implementation Plan: Интерпретатор Ladix (tree-walking eval, чистое императивное ядро B)

**Branch**: `003-interpreter-eval` | **Date**: 2026-06-05 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/003-interpreter-eval/spec.md`

## Summary

Третий слой компилятора Ladix — **интерпретатор** (tree-walking eval) чистого императивного ядра подмножества B. Он потребляет AST от парсера (фича 002) как стабильный вход и **исполняет** программу: вычисляет выражения по уже построенному дереву приоритетов (только вычисляет, не переразбирает), исполняет statements (`пусть`/`=`/выражение-оператор/`если`/`пока`/`для`/`прервать`/`продолжить`/`вернуть`), ведёт **функциональные** области видимости, вызывает пользовательские функции с рекурсией, печатает через `печать` и сообщает рантайм- и семантические ошибки с позицией (строка + колонка в рунах) по-русски. Добавляются два новых пакета — листовой `internal/value` (модель из 10 типов значений) и `internal/eval` (семпроход + интерпретатор + стдлиб) — плюс команда `cmd/ladix` и расширение `internal/errors` тремя категориями ошибок. Это **НЕ** декларатив и **НЕ** движок процессов — `store`/`engine`/`serve` остаются будущими фичами (004+); deferred-конструкции, которые парсятся в 002, дают явную ошибку «не поддерживается», а не тихий no-op.

**Технический подход**: чистый Go 1.22+ без внешних зависимостей в `value`/`eval` (конституция I). Интерпретатор — `evalExpr`/`evalStmt`/`evalBlock` как type switch по **указательным** узлам AST; control-flow (`вернуть`/`прервать`/`продолжить`) реализован **явным сигналом** `Signal`, а не `panic/recover` (D4/конституция III); рантайм-ошибки — отдельный канал `error`, fail-fast до границы CLI. Модель значений вынесена в листовой пакет `internal/value` (вариант A, ARCHITECTURE §2.1) — это разрывает потенциальный цикл `eval↔store` и даёт нейтральную поверхность для будущего `store`. Стадия 3 — лёгкий fail-fast `Analyze(prog)` (резолв имён функций, фикс. арность, scope-гарды, deferred-граница); стадия 4 — исполнение. Ключевые зафиксированные решения D1–D9 (тексты ошибок — §8.3; раздельные числа; функциональный scope; control-flow через Signal; `Запись` смоделирована но не конструируется; стдлиб 23+12=35; period-константы не предопределены; два пространства имён; лимит глубины 10000 + recover-барьер) **не переоткрываются** — план их кодирует.

Поставка по приоритетам User Stories: **P1** (US1 выражения + US2 переменные/области/печать + US5 ошибки-слой) даёт минимально исполняемое ядро (`hello`, `арифметика`); **P2** (US3 управляющие/циклы) расширяет до `условие`/`цикл`; **P3** (US4 функции/рекурсия/стдлиб) замыкает учебный чеклист (`функция`, `факториал`). US5 (ошибки + deferred-граница) — сквозной слой, пронизывающий все фазы.

## Technical Context

**Language/Version**: Go **1.22+** (единый модуль `github.com/denis-kosyakov/ladix`, корень — `src/`), без CGO.

**Primary Dependencies**: только стандартная библиотека Go в `internal/value` и `internal/eval` (`fmt`, `strconv`, `math`, `sort`, `io`, `strings`, `unicode/utf8`). `modernc.org/sqlite` в 003 **НЕ** используется (store deferred). `testify/require` — точечно в тестах (конституция VI).

**Storage**: N/A — `internal/store`/`internal/engine` в 003 не вводятся; интерпретатор `run` работает в памяти без персистентности.

**Testing**: `go test` — табличные (table-driven) тесты по слоям (значения, выражения, statements, scope, функции/рекурсия, стдлиб, ошибки), co-located `*_test.go`; golden-прогон 6 обязательных примеров + `ошибка.ladix`; `go test -race` зелёный. Вывод перехватывается через инжектированный `Interpreter.out` (`bytes.Buffer`).

**Target Platform**: один статический бинарник `ladix` (`go build`), кросс-компиляция darwin/linux/windows одной командой (конституция I).

**Project Type**: компилятор/интерпретатор (tree-walking) — CLI `ladix run <файл>`.

**Performance Goals**: учебно-прикладной масштаб; жёстких целей по throughput нет. Защита от убегающей рекурсии — явный счётчик глубины `maxDepth` (по умолчанию 10000, флаг `--max-depth`), а не неперехватываемое переполнение Go-стека.

**Constraints**:

- eval — **fail-fast**, накопителя ошибок нет (накопитель только в лексере/парсере); первая рантайм-ошибка всплывает до CLI.
- В штатных путях паника **ЗАПРЕЩЕНА** (конституция III); `recover`-барьер только на границе CLI-подкоманды → «внутренняя ошибка интерпретатора» без Go stack trace.
- Все пользовательские сообщения — по-русски, двухстрочный формат `Ошибка в строке N, колонка M:`; позиции 1-based, колонка в **рунах**; тексты ДОСЛОВНО из `docs/eval-model.md §8.3`.
- Без изменяемого состояния уровня пакета (конституция V): состояние — поля `Interpreter`, `out` инжектируется.
- Граф пакетов **ацикличен**; `internal/value`, `internal/errors`, `internal/ast` — **листовые**.
- Грамматика/приоритеты/AST 002 **НЕ** меняются (стабильный вход).

**Scale/Scope**: подмножество B; **6** конструируемых типов значений из 10 (`Запись` смоделирована, `Дата`/`Длительность`/`Период` определены — но не конструируются); **23** активных встроенных + **12** deferred-заглушек (= 35); **6** golden-примеров с эталонным stdout + `ошибка.ladix` (код 1). Новое: пакеты `internal/value`, `internal/eval`, команда `cmd/ladix`, расширение `internal/errors` (3 типа).

## Guardrails — контракт реализации (нормативно для tasks/implement)

Фиксирует инварианты как контракт, чтобы код не дрейфовал от спеки и `docs/eval-model.md`. `/speckit-tasks` и `/speckit-implement` ОБЯЗАНЫ соблюдать каждый пункт; research.md и data-model.md дают на них обратные ссылки «Guardrail N».

1. **Раздельность пакетов и листовость.** Вводится листовой `internal/value` (импортирует только stdlib Go). `internal/eval` → `ast`, `value`, `errors` (НЕ `store`/`engine` в 003). `internal/errors` расширяется тремя типами **без** новых внутренних импортов. Граф **ацикличен**; `value`/`errors`/`ast` остаются листовыми. *(FR-001, конституция VII, ARCHITECTURE §2.1)*
2. **РОВНО 10 типов Value, 6 конструируемых.** Интерфейс `Value{ TypeName() string }`; конструируются `Целое`(int64)/`Дробное`(float64)/`Строка`(руны)/`Булево`/`Пусто`/`Список`. `Пусто` — синглтон `var None = Пусто{}`; `Список` несёт `*[]Value` (ссылочная семантика). `Запись` смоделирована полностью (порядок полей, `Get`→`Пусто`, равенство, печать), но в 003 **НЕ конструируется**; `Дата`/`Длительность`/`Период` определены, но не конструируются. Функция — **не** `Value`. *(FR-001/002/003/006, D5/D8)*
3. **Два пространства имён + функциональный scope.** Переменные — в `Environment{vars,parent}` (`Define`/`Assign`/`Lookup`); функции — в `funcs` (пользовательские) + `builtins`. Новую область создают ТОЛЬКО глобал и кадр вызова функции; блоки `если/иначе/пока/для` своей области **НЕ** создают. Кадр функции имеет `parent = ГЛОБАЛЬНАЯ область` (лексическая, не динамическая видимость). *(FR-004/005/006, D3/D8)*
4. **evalExpr — type switch по указательным узлам.** Ветви матчат `*ast.T` (все конструкторы AST возвращают указатели); операнды бинарных, аргументы вызовов и элементы `ListLit` вычисляются **слева направо**; дерево приоритетов от парсера **не переразбирается**. Литералы: `IntLit`→`Целое`, `FloatLit`→`Дробное`, `StringLit`→`Строка`, `BoolLit`→`Булево`, `NoneLit`→`None`, `ListLit`→новый `Список`. *(FR-007, eval §3.1)*
5. **Арифметика по §3.3.** `Цел○Цел` (`+ - *`)→`Целое` с **явной** проверкой переполнения int64 (не wrap-around); участвует `Дробное`→промоушен; `/` (любые числовые)→**всегда** `Дробное`; `//` только `Цел//Цел`→`Целое`, иначе `ОшибкаТипа`; `%` — `Цел%Цел`→`Целое` или `Дроб%Дроб`→`Дробное`(fmod), смешанное→`ОшибкаТипа`; правый операнд `/`/`//`/`%` равен нулю→`«деление на ноль»` на позиции **оператора**; `Строка+Строка`→конкатенация; списки `+` не складываются. *(FR-011, D2)*
6. **Сравнения и логика.** `==`/`!=` над любыми типами (разные→`ложь`, **кроме** `Цел↔Дроб` численно; `Строка` по код-поинтам; `Список` поэлементно; `Запись` структурно); `< <= > >=` — только взаимно-упорядочиваемые. `или`/`и` **короткозамкнуты**, оба операнда строго `Булево`, результат — `Булево` (НЕ возврат операнда). *(FR-010/012)*
7. **Strict-Булево в условиях.** `если/иначе если/пока` требуют `Булево` (truthiness не применяется); `булево(x)` — **единственная** точка мягкого truthy, действует только при явном вызове. *(FR-017/018/028, D6)*
8. **Control-flow через Signal, не panic.** `SignalKind ∈ {SigNormal,SigBreak,SigContinue,SigReturn}`; два канала — `error` (всплывает немедленно) и `Signal` (штатный поток). `evalBlock`: `err≠nil`→наверх; `sig.Kind≠SigNormal`→прекратить блок и вернуть сигнал. Цикл поглощает `SigBreak`/`SigContinue`, пробрасывает `SigReturn`; вызов функции ловит `SigReturn`→значение, `SigNormal`→`None`. *(FR-015/018/019/023, D4)*
9. **`для x в E`.** `E` обязан `Список` (иначе `«'для' требует Список, получено <тип>»` на позиции `Iterable`); `x` привязывается в **охватывающей** области — `Define` при первом элементе **если имени в области ещё нет**, затем `Assign`; на пустом списке `x` не создаётся; после цикла `x` видна со значением последней итерации. Мутация помеченного «итерируется» списка через `добавить`→`«список изменён во время итерации»`. *(FR-019, eval §4.3)*
10. **Резолв вызова.** Порядок переменные→`funcs`→`builtins`→`«функция 'f' не объявлена»`: (1) переменная за `(` → `«'f' — не функция (<тип>), вызов невозможен»`; (2) пользовательская; (3) активная встроенная, deferred-заглушка→`«функция 'f' не поддерживается в этой версии»`; (4) не объявлена. Имя в позиции значения, найденное только в таблице функций → `«'имя' — функция, её нельзя использовать как значение»`. Позиция всех ошибок вызова = `CallExpr.Pos()`. *(FR-022, eval §5.2)*
11. **Вызов пользовательской функции.** Аргументы слева направо; фикс. арность проверена семпроходом; `depth++`, при `depth > maxDepth`→лимит рекурсии (`defer depth--`); кадр `NewEnvironment(global)`, позиционно `Define(param, arg)`; ссылочные аргументы (`Список`/`Запись`) — мутация видна вызывающему. Рекурсия резолвится через `funcs` независимо от кадра. *(FR-023/024, D9)*
12. **Стдлиб = 23 активных + 12 deferred.** Закрытый список (расширять/сокращать **ЗАПРЕЩЕНО**); `длина` в счёте ×1. `печать` — единственный канал вывода (в инжектированный `out`); `добавить` — единственный мутатор, прочие списочные возвращают **новый** список; типы аргументов на семпроходе не проверяются (динамика). Все встроенные **затеняемы** `пусть` того же имени (с предупреждением, не ошибка). *(FR-025/026/027/029, D6)*
13. **Единое строковое представление (§7).** `строка(x)` и `печать` едины: `Целое`→десятичная; `Дробное`→`strconv.FormatFloat(v,'g',-1,64)` с **принудительной** `.0` если выглядит целым (`2175.0`); `Строка`→без кавычек (и **внутри** `Список`/`Запись` тоже); `Булево`→`истина`/`ложь`; `Пусто`→`пусто`; `Список`→`[`…`]`; `Запись`→`{поле: значение, …}` в порядке полей. *(FR-030)*
14. **Ошибки eval.** Три новых типа в `internal/errors` (`СемантическаяОшибка` ст.3; `ОшибкаТипа`/`ОшибкаВыполнения` ст.4) по образцу `LexError`/`ParseError` (поля `Pos Position`, `Msg string`, метод-значение `Error()`, дружат с `errors.As`). eval — **fail-fast** (накопителя нет). Двухстрочный формат; позиции в рунах; тексты ДОСЛОВНО из §8.3 (без завершающей точки, кроме многофразовых); привязка позиции по §8.2. *(FR-031/032/033, D1)*
15. **Семпроход `Analyze(prog) error`.** Лёгкий fail-fast обход AST до исполнения: **шаг 1** — регистрация top-level `FunctionDecl`→`funcs` (forward-вызовы разрешены), повтор→ошибка, top-level декларатив→deferred; **шаг 2** (по областям, блоки область не открывают) — повтор `пусть`, контекст `вернуть`/`прервать`/`продолжить`, резолв `CallExpr` + фикс. арность, reserved-узлы→deferred. **НЕ** проверяет: declaredness переменной в позиции значения, типы, арность вариативных/перегруженных. *(FR-034/035)*
16. **Deferred-граница (не тихий no-op).** Reserved-узлы (`RunProcessExpr`, `AssignAction`/`CallAction`/`NotifyAction`), `DurationLit`, декларатив → `«конструкция ... не поддерживается в этой версии»` на позиции узла; 12 deferred-встроенных → `«функция '<имя>' не поддерживается в этой версии»`; period-константы (`ежедневно`…`ежегодно`) в 003 не предопределены → рантайм `«'<имя>' не объявлено»`. *(FR-036, D7)*
17. **CLI и границы.** `ladix run <файл>` с конвейером лексер→парсер→`Analyze`→`Interpreter.Run`; флаг `--max-depth N` (по умолчанию 10000, число = в тексте ошибки). Граница подкоманды обёрнута `defer recover()`: штатные ошибки→stderr §8/код **1**; Go-паника→`«внутренняя ошибка интерпретатора»` без stack trace/код **1**; ошибка использования CLI→код **2**; успех→код **0**. *(FR-037/038, D9)*
18. **Tests-first + гейты.** Табличные тесты по слоям + golden (6 примеров код 0, `ошибка.ladix` код 1) — часть каждой задачи; печать через `bytes.Buffer`; `go build ./...`, `go vet ./...`, `gofmt` без диффа, `go test -race` — зелёные. *(FR-039/040, конституция I/VI)*

**Structure Decision**:

- **Корень модуля `src/`** (S1, унаследовано 001/002): все `go`-команды от `cd src`; пути в задачах — `internal/value/...`, `cmd/ladix/...`.
- **Листовой `internal/value` отдельно от `eval`** (вариант A, ARCHITECTURE §2.1): разрывает цикл `eval↔store`, даёт стабильную нейтральную поверхность под будущий `store`.
- **Расширение `internal/errors`, а не новый пакет**: три категории eval живут рядом с `LexError`/`ParseError` по единому паттерну (1 тип = 1 файл, поля `{Pos,Msg}`, метод-значение `Error()`); листовость сохраняется (типы не импортируют `ast`/`value` — `<тип>` и привязку позиции подставляет вызывающий eval).
- **Раскладка `eval` по слоям** (выражения / арифметика / statements / вызовы / семпроход / стдлиб) — навигируемость и tests-first по слоям; точное дробление файлов уточнит `/speckit-tasks`.
- **Тесты co-located** (`*_test.go`) — конвенция 001/002 (S2).

## Phasing — порядок поставки по приоритетам User Stories

Порядок следует приоритетам спеки (P1→P2→P3); US5 (ошибки + deferred-граница) — сквозной слой, реализуется вместе с порождающими его конструкциями, плюс собственный набор негативных тестов.

- **Фаза 0 (каркас, до US).** Пакет `internal/value` (10 типов, `None`-синглтон, ссылочный `Список`, строковое представление §7, равенство/упорядочивание); три типа ошибок в `internal/errors`; скелет `Interpreter`/`Environment`/`Signal`. **Гейт:** `go build` зелёный, табличные тесты `value` (печать §7, равенство, `2175.0`-инвариант) проходят.
- **Фаза P1 — US1 + US2 + базовый US5 (MVP).** 🎯 `evalExpr` (литералы, унарные, бинарные: арифметика §3.3/сравнения/короткое замыкание, индексация в рунах); `Environment` + `LetStmt`/`AssignStmt`/`ExpressionStmt`; `печать`; рантайм-ошибки выражений (`деление на ноль`, переполнение, тип, индекс, `не объявлено`). **Гейт:** golden `hello` и `арифметика` (код 0); инварианты SC-004; `ошибка.ladix` стр.5 кол.14 (SC-002).
- **Фаза P2 — US3 (управляющие/циклы).** `IfStmt` (strict-Булево, цепочка `ElseClause` по `IsFinal()`); `WhileStmt`; `ForStmt` (Define-если-нет, видимость после цикла, защита от мутации); поглощение `SigBreak`/`SigContinue`. **Гейт:** golden `условие` и `цикл` (код 0); `прервать` вне цикла → семантическая (SC-005 частично).
- **Фаза P3 — US4 (функции/рекурсия/стдлиб).** Резолв вызова (порядок переменные→funcs→builtins), вызов пользовательской функции с кадром `parent=global`, рекурсия + лимит `maxDepth`; 23 активных встроенных + 12 deferred-заглушек; `булево(x)` truthy. **Гейт:** golden `функция` и `факториал` (код 0); `факториал(5)`→`120`; убегающая рекурсия→лимит; арность→семантическая (SC-006/SC-007).
- **Фаза US5-сквозная + CLI.** `Analyze` (семпроход стадии 3); deferred-граница (reserved-узлы/декларатив/`DurationLit`/period-имена); `cmd/ladix` (конвейер, `--max-depth`, recover-барьер, коды 0/1/2). **Гейт:** весь реестр §8.3 по golden-кейсу на сообщение (SC-003); recover→`внутренняя ошибка интерпретатора` без stack trace (SC-008).
- **Фаза Polish.** Сквозной golden-прогон всех 6 примеров + `ошибка.ladix`; `go vet`/`gofmt`/`-race`. **Гейт:** SC-001/SC-009 зелёные.

**Зависимости фаз**: Фаза 0 блокирует все US (модель значений и ошибки — фундамент). P1 зависит от Фазы 0; P2 — от P1 (условия = выражения, тело = statements в той же области); P3 — от P1–P2; US5-сквозная использует диагностики всех фаз и завершается CLI; Polish — последняя.

## Открытые вопросы и отложенные расхождения

- **D1 (РЕШЁН: §8.3 — источник истины)** — при любом расхождении `§13.4 ↔ §8.3` побеждает `docs/eval-model.md §8.3`; `§13.4` в 003 не используется и не синхронизируется (FR-033). Все тексты тестов eval сверяются с §8.3 байт-в-байт.

- **`Запись`/`Дата`/`Длительность`/`Период`** — смоделированы/определены как стабильная поверхность `eval↔store`, но в 003 ни один путь кода их не конструирует; `FieldExpr` в чистом 003 всегда упирается в «не имеет полей» (граница, не баг, D5).
- **`store`/`engine`/`serve`/декларатив/дата-подсистема** — вне scope 003 (engine 004+); встреча соответствующих узлов даёт явную deferred-ошибку, а не тихий no-op (FR-036, D7).
- **`examples/выручка.ladix` и `examples/онбординг.ladix`** — НЕ в обязательном golden-прогоне 003 (отдельный трек движка).
