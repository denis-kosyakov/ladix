# Быстрый старт: подключаем реальную выгрузку (CSV / NDJSON / JSON со схемой)

Это руководство для пользователя «Уклада». За несколько минут вы подключите реальную
выгрузку заказов как **типизированный источник** и посчитаете поверх неё ту же метрику,
что и в v1 — но уже на CSV, NDJSON или JSON со схемой.

Всё ниже воспроизводимо из свежего клона и опирается на ту же сборку, что и
[основной быстрый старт](../../docs/quickstart.md): бинарник `./ladix` лежит в **корне**
репозитория, команды запускаются оттуда, а файлы данных кладутся рядом — в `data/`.

> Сборка одна на весь проект: `cd src && go build -o ../ladix ./cmd/ladix`, затем `cd ..`.
> Все команды ниже — из **корня** репозитория.

---

## Шаг 1. CSV-выгрузка как источник

Положите реальную выгрузку заказов в `data/orders.csv`. Первая строка — заголовок столбцов,
разделитель `,`, кодировка UTF-8 (`§SC-D-CSV`):

```csv
дата_заказа,сумма_заказа,статус
2026-05-03,1200000,оплачен
2026-05-17,800000,оплачен
2026-05-20,500000,отменён
```

Теперь объявите источник `тип: csv` с **обязательной** для CSV схемой `поля:` (`A1-3`) и
ту же метрику v1 (фильтр `где` + агрегат), что в `examples/метрики.ladix`. Сохраните в
`examples/csv-старт.ladix`:

```ladix
источник заказы:
    файл: "data/orders.csv"
    тип:  csv
    поля:
        дата_заказа: Дата
        сумма_заказа: Дробное
        статус: Строка

# Та же метрика v1: фильтр + агрегат. Можно без периода (дата-независимо),
# либо с уже доступным периодом v1: `период: ежемесячно` + `по_дате: дата_заказа`.
метрика выручка_оплачено:
    источник: заказы
    где:      статус == "оплачен"
    агрегат:  сумма(сумма_заказа)
```

Каждый CSV-столбец читается строкой и коэрсится в объявленный тип (`§SC-D-COERCE`):
`сумма_заказа` → `Дробное`, а поле `Дата` парсится из ISO `ГГГГ-ММ-ДД` **без явного**
`дата(...)` (`A1-7`) — и сразу доступно метрике по оси `по_дате`. Считаем:

```sh
./ladix metric examples/csv-старт.ladix выручка_оплачено
```

Ожидаемый вывод (1200000 + 800000, заказ «отменён» отфильтрован):

```
2000000
```

Источник без `тип:` и `поля:` по-прежнему ведёт себя ровно как v1 — JSON schemaless (`A1-2`),
ничего переписывать не нужно.

## Шаг 2. Те же данные как NDJSON и как JSON со схемой — результат идентичен

Один и тот же набор записей в трёх формах даёт **один и тот же** скаляр метрики (`SC-002`).

**NDJSON** (`data/orders.ndjson`) — один JSON-объект на строку, пустые строки пропускаются
(`A1-9`):

```
{"дата_заказа":"2026-05-03","сумма_заказа":1200000,"статус":"оплачен"}
{"дата_заказа":"2026-05-17","сумма_заказа":800000,"статус":"оплачен"}

{"дата_заказа":"2026-05-20","сумма_заказа":500000,"статус":"отменён"}
```

**JSON со схемой** (`data/orders.json`) — классический массив объектов, но теперь с
объявленной схемой для типизации и валидации:

```json
[
  {"дата_заказа":"2026-05-03","сумма_заказа":1200000,"статус":"оплачен"},
  {"дата_заказа":"2026-05-17","сумма_заказа":800000,"статус":"оплачен"},
  {"дата_заказа":"2026-05-20","сумма_заказа":500000,"статус":"отменён"}
]
```

Декларация отличается только строкой `тип:` и путём — схема `поля:` та же:

```ladix
источник заказы:
    файл: "data/orders.ndjson"
    тип:  ndjson          # или: тип: json + файл: "data/orders.json"
    поля:
        дата_заказа: Дата
        сумма_заказа: Дробное
        статус: Строка
```

`./ladix metric ... выручка_оплачено` для CSV, NDJSON и JSON со схемой печатает одно и то же
`2000000`. Целое `1200000` в поле `Дробное` штатно повышается до дробного — единственный
разрешённый промоушен `Целое→Дробное` (`A1-10`).

## Шаг 3. Как выглядит ошибка данных

Ошибки данных русские и несут позицию: **имя источника, имя поля и номер записи** (N с 1,
`§SC-9.B`). Например, испортите дату во второй записи (`2026-13-40`) — `metric`/`run`
завершится с кодом `1`, а в stderr будет:

```
источник 'заказы': запись 2, поле 'дата_заказа': «2026-13-40» не является датой (ожидался формат ГГГГ-ММ-ДД)
```

Несовпадение типа выглядит так же предметно — например `Дробное` в поле `Целое`:

```
источник 'заказы': запись 1, поле 'сумма_заказа': ожидался Целое, получено Дробное
```

Часть ошибок ловится ещё **до чтения файла**, на анализе (`§SC-9.A`). Если у `csv`/`ndjson`
забыть блок `поля:`:

```
источник 'заказы': тип 'csv' требует объявления полей (поля:)
```

А если CSV-заголовок не содержит объявленный столбец — ошибка при загрузке:

```
источник 'заказы': в заголовке CSV «data/orders.csv» отсутствует поле 'дата_заказа'
```

## Что важно помнить

`тип:` опущен — источник остаётся **JSON schemaless** как в v1 (поведение и вывод не
меняются, `A1-2`); добавляете `тип:` и `поля:` только когда нужны CSV/NDJSON или
типобезопасность со схемой. Оконные периоды (`последние N <ед>`, «последний завершённый») в
A1 ещё **не** входят — это A2 (фича 011); пока для метрик по дате используйте период v1
`ежемесячно` либо обходитесь без `период:`.
