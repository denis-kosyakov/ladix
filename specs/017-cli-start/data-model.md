# Data Model — B5 `ladix start` (Phase 1)

B5 не вводит persisted-сущностей и не меняет схему Store. «Модель данных» здесь — это (1) грамматика
парсера argv-литералов и его выход `value.Value`, (2) сверка арности. Источник: §AU-7.2, §AU-7.3.

## 1. Парсер argv-литералов

### 1.1 Сигнатура
```go
// parseArgLiteral разбирает один позиционный argv-токен в типизированный литерал value.Value.
// Возвращает ошибку ТОЛЬКО при невалидном числовом/датовом литерале распознанной формы
// (целое вне Int64, невалидная ISO-дата). Любой нераспознанный токен → value.Строка (не ошибка).
func parseArgLiteral(argv string) (value.Value, error)
```

### 1.2 Грамматика (порядок проверок — первое совпадение выигрывает)

| # | Форма (§AU-7.2) | Результат | Ошибка-кейс |
|---|------------------|-----------|-------------|
| 1 | `^-?\d+$` | `value.Целое{V}` (int64) | вне диапазона Int64 → `целое вне диапазона типа Целое` |
| 2 | `^-?\d+\.\d+$` или `eE`-экспонента | `value.Дробное{V}` (float64) | вне float64 (теоретич.) → аналог по образцу (data-model п.4) |
| 3 | `истина` / `ложь` | `value.Булево{true}` / `value.Булево{false}` | — |
| 4 | `пусто` | `value.None` (Пусто) | — |
| 5 | `^\d{4}-\d{2}-\d{2}$` (ISO) | `value.Дата{Year,Month,Day}` | невалидный календарь (`2026-13-45`) → ошибка парса даты (как M1) |
| 6 | иначе | `value.Строка{V}` (весь токен) | никогда не ошибка (fallback) |

**Порядок критичен:** числовые формы (1,2) проверяются до строки; булево/пусто (3,4) — точные слова до
строки; дата (5) — до строки. Строка (6) — терминальный fallback. `2 500 000` (с пробелами, одним
токеном из шелла) НЕ матчит форму 1 (есть пробелы) → форма 6 (Строка) — пользователь даёт `2500000` для
числа (§AU-7.2).

### 1.3 Реализация (Constitution II)
Распознавание форм — посимвольными проверками + `strconv.ParseInt(argv, 10, 64)` (форма 1),
`strconv.ParseFloat(argv, 64)` (форма 2), `time.Parse("2006-01-02", argv)` с проверкой re-format (форма 5,
отвергает `2026-13-45`). regexp-формы из §AU-7.2 — спецификационная запись; реализация предпочтительно
ручная/`strconv`, regexp на CLI-уровне допустим (Complexity CT-1; Constitution II касается токенизации
ЯЗЫКА, не CLI-argv). `_`-разделители НЕ обязательны и НЕ поддерживаются в argv (CLI; §AU-7.2).

### 1.4 Примеры (табличный замок US2)

| argv | → value.Value | примечание |
|------|---------------|-----------|
| `2500000` | `Целое{2500000}` | |
| `-42` | `Целое{-42}` | ведущий минус |
| `0` | `Целое{0}` | |
| `3.14` | `Дробное{3.14}` | |
| `-0.5` | `Дробное{-0.5}` | |
| `1e3` | `Дробное{1000}` | экспонента |
| `истина` | `Булево{true}` | |
| `ложь` | `Булево{false}` | |
| `пусто` | `None` | |
| `2026-01-01` | `Дата{2026,1,1}` | ISO |
| `перезвонит` | `Строка{"перезвонит"}` | fallback |
| `2 500 000` | `Строка{"2 500 000"}` | пробелы → не число |
| `99999999999999999999` | ОШИБКА | целое вне диапазона |
| `2026-13-45` | ОШИБКА | невалидная дата |

## 2. Сверка арности (§AU-7.3)

```
name := argv[0-после-файла]          # имя процесса
posArgs := argv[после имени]          # позиционные аргументы → []value.Value
pd, ok := interp.Process(name)
if !ok:    error FR-015 "процесс '<имя>' не объявлен"           exit 2   # CLI формирует САМ
if len(pd.Params) != len(posArgs):
           error FR-014 "процесс '<имя>' ожидает <N> аргументов, получено <M>"  exit 2
           # N = len(pd.Params), M = len(posArgs)
# арность ок → engine.Start(name, parsedArgs)
```

**Инвариант:** обе проверки — ДО `engine.Start` (иначе движок даст текст
`процесс '%s' не найден в определении`, engine.go:69 — не §AU-10). Арность 0=0 проходит (процесс без
параметров, US3-4).

## 3. Поток данных `startMain`

```
argv → разбор флагов (--db/--вебхук/--max-depth) + позиционные (файл, процесс, аргументы)
     → компиляция файла (lex→parse→Analyze); ошибка → диагностика exit 1 (как complete)
     → posArgs[i] = parseArgLiteral(argv_i);  ошибка литерала → FR-016/аналог exit 2
     → openStore(dbPath) → st (SQLite ladix.db по умолчанию), defer close
     → parseWebhookCaller(webhook) → caller; невалидный URL → FR-017 exit 2
     → interp := NewInterpreter(stdout, maxDepth, clock); interp.Analyze(prog)
     → eng := NewEngine(st, interp, stdout, withExternalCallerOpt(caller)...)
     → interp.SetProcessRuntime(eng)
     → interp.Process(name) → проверка арности (раздел 2)  [может идти до Analyze-стека — решение impl,
       но строго ДО engine.Start]
     → id, err := eng.Start(name, posArgs)    # печатает [задача]-строки сам
     → err != nil → CLI-маппинг ошибки exit 2/1
     → fmt.Fprintf(stdout, "запущен инстанс %s\n", id)   # §AU-10.D, startMain печатает сам
     → exit 0
```

## 4. Инвентарь CLI-ошибок B5 (дословно §AU-10.C, exact-match замки)

| Код-замок | Текст (stderr, exit 2) | Триггер |
|-----------|------------------------|---------|
| ERR-ARITY | `ladix: процесс '<имя>' ожидает <N> аргументов, получено <M>` | len(Params)≠len(args) |
| ERR-UNDECL | `ladix: процесс '<имя>' не объявлен` | interp.Process → !ok |
| ERR-INT-RANGE | `ladix: не удалось разобрать аргумент '<argv>': целое вне диапазона типа Целое` | форма 1 вне Int64 |
| ERR-WEBHOOK | `ladix: неверный URL вебхука '<URL>'` | невалидный --вебхук (§AU-4.5) |

> Дробное-вне-диапазона / невалидная-дата — по образцу ERR-INT-RANGE (формулировка
> `не удалось разобрать аргумент '<argv>': <деталь>`); ядро exact-match замка — ERR-INT-RANGE (§AU-10.C
> цитирует именно его). Прочие детали-тексты — решение impl по образцу, без расширения каталога диагностик.

## 5. stdout канон (§AU-10.D, exact-match)

```
[задача] t-000001 → менеджер, шаг 'связаться_с_клиентом', срок до <время>
запущен инстанс p-000001
```
- `[задача]`-строка — печатает движок (`printTaskCreated`); `<время>` маскируется golden как `<DT>`.
- `запущен инстанс <id>` — печатает `startMain` ПОСЛЕ успешного `Start`.
- Терминальный процесс без задач → движок тих → ТОЛЬКО `запущен инстанс <id>`.
- id детерминирован на свежей БД: `p-000001` / `t-000001`.
