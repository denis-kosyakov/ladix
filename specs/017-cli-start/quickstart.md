# Quickstart — `ladix start` (B5)

Ручной прогон подкоманды `start` (= шаг 1 golden §AU-12.B). Демонстрирует запуск инстанса с
типизированными литералами argv над общей `--db`.

## Предусловие

Файл `контроль_плана.ladix` (или `examples/эскалация_плана.ladix`) с процессом, у которого первый шаг —
человеческий (`исполнитель: менеджер`, `срок: 2 дн`):
```
процесс эскалация_плана(факт):
    шаг связаться_с_клиентом:
        исполнитель: менеджер
        срок: 2 дн
    ...
```

## Шаг 1. Запуск с целочисленным аргументом

```
$ ladix start контроль_плана.ladix эскалация_плана 2500000 --db demo.db
[задача] t-000001 → менеджер, шаг 'связаться_с_клиентом', срок до 2026-06-19 12:00
запущен инстанс p-000001
```
- `2500000` → `value.Целое{2500000}` связан с параметром `факт`.
- Инстанс `p-000001` персистнут в `demo.db` → виден `serve`/`complete`/`inspect` (та же БД).

## Шаг 2. Типы литералов

```
$ ladix start f.ladix P 3.14          # → Дробное
$ ladix start f.ladix P истина        # → Булево{true}
$ ladix start f.ladix P пусто          # → None
$ ladix start f.ladix P 2026-01-01    # → Дата{2026,1,1}
$ ladix start f.ladix P перезвонит    # → Строка{"перезвонит"}
```

## Шаг 3. Ошибки (exit 2)

```
$ ladix start f.ladix эскалация_плана
ladix: процесс 'эскалация_плана' ожидает 1 аргументов, получено 0

$ ladix start f.ladix эскалация_плана 100 200
ladix: процесс 'эскалация_плана' ожидает 1 аргументов, получено 2

$ ladix start f.ladix неизвестный 5
ladix: процесс 'неизвестный' не объявлен

$ ladix start f.ladix P 99999999999999999999
ladix: не удалось разобрать аргумент '99999999999999999999': целое вне диапазона типа Целое
```

## Шаг 4. Дефолт `--db` и вебхук

```
$ ladix start f.ladix P 1                       # без --db → SQLite ladix.db (НЕ Memory)
$ ladix start f.ladix P 1 --вебхук http://x/h   # эффекты старта идут на вебхук (если первый шаг авто)
$ ladix start f.ladix P 1 --вебхук ://плохо      # ladix: неверный URL вебхука '://плохо'  (exit 2)
```

## Связь с демо M2 (§AU-12.B)

Шаг 1 — детерминированный старт инстанса для durable-golden эскалации (вместо edge-метрики). Далее:
`serve --db demo.db` (эскалация на просрочке) → `complete --db demo.db` → `inspect --db demo.db` (B6).
Полная сборка end-to-end — на M2-гейте, НЕ в B5.
