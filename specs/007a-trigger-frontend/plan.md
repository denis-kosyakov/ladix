## Summary

Фича добавляет **фронтенд триггеров** `когда …:` — единообразный парсинг и семантическую
валидацию всех трёх форм (`метрика` / `событие` / `расписание`) — плюс **одну** точку исполнения:
метрика-триггер срабатывает разово в команде `run` по принципу **fire-if-true**. Лексер уже несёт
все нужные ключевые слова (`когда`/`метрика`/`событие`/`расписание`/`каждые`/`в`/`значение`/`запустить`)
и 6 единиц длительности — правок не требует. Работа сводится к: новым узлам AST (`TriggerDecl`,
формы-спеки, `ValueExpr`/`EventExpr`); двум независимым швам парсера (top-level диспетчер `когда`
+ Primary `значение`/`событие`); расширению семантического прохода (регистрация триггеров, резолв
метрики, контекст-гарды `значение`/`событие`, переиспользование гардов действий-шага и арности
процесса); одноразовому проходу fire-if-true в `run` после `interp.Run`, до сводки задач.

**Заморожено границей 007a/007b (§TR-11):** демон `serve`, события/`emit`/очередь, edge-детект
ложь→истина и durable `trigger_state`, исполнение расписания (вкл. календарный сдвиг нед/мес),
валидация формата `"ЧЧ:ММ"`, рестарт-скан. Всё это ляжет **аддитивно** в 007b без изменения
синтаксиса, AST и диагностик, зафиксированных здесь: программа, валидная в 007a, остаётся валидной
в 007b без правок. Технический подход: расширить существующие пакеты `ast`/`parser`/`eval`
(новых пакетов нет), исполнение `запустить процесс` идёт штатным путём движка 006.

## Technical Context

**Language/Version**: Go 1.22+ (модуль в `src/`); идиоматичный код, `gofmt`/`go vet` чисто.

**Primary Dependencies**: stdlib только. `modernc.org/sqlite` уже введена фичей 006 (чистый Go,
без CGO) и переиспользуется без изменения — **новых зависимостей 007a не добавляет**.

**Storage**: переиспользует `internal/store` 006 (Memory / SQLite). Процессы и задачи, порождённые
метрика-триггером, персистятся штатно под `--db`. **Состояние самих триггеров не читается и не
пишется** (эфемерная ЛОЖЬ-база, §TR-6.2) — таблицы `trigger_state` в 007a нет.

**Testing**: три стратегии (как 001–006) — table-driven юнит-тесты (AST/парсер/семпроход),
golden байт-точный stdout команды `run` (детерминированная фикстура без окна метрики),
exact-match диагностики (двухстрочный канон). Все регресс-тесты 001–006 остаются зелёными.

**Target Platform**: один статический бинарник `ladix`, кросс-компиляция Windows/macOS/Linux.

**Project Type**: интерпретатор/компилятор DSL с CLI-подкомандами (`run`/`metric`/`complete`/`tasks`).

**Performance Goals**: N/A (учебная фича; конвейер лексер→парсер→семпроход→`run` синхронный).

**Constraints**: CGO запрещён; ручной recursive-descent парсинг (без генераторов/regex);
позиции `Position{Line, Col}` в рунах на каждом новом узле; граф зависимостей ацикличен,
`ast` остаётся листовым; тексты диагностик берутся **дословно** из §TR-7; детерминизм
run-golden — фикстура без `период:`/`по_дате:`, вывод не зависит от `сегодня()`.

**Scale/Scope**: **0 новых пакетов** (расширяются `ast`/`parser`/`eval` + точка врезки в `cmd/ladix`).
Новые узлы AST: **`TriggerDecl`** + интерфейс `TriggerSpec` с 3 формами (`MetricTrigger`/`EventTrigger`/
`ScheduleTrigger`) + интерфейс `ScheduleSpec` с 2 подформами (`EverySchedule`/`AtSchedule`) +
2 первичных выражения (`ValueExpr`/`EventExpr`); доступ `событие.поле` переиспользует `FieldExpr`.
Новых диагностик: **7** (4 семантические: TR-VAL-CTX, TR-EVT-CTX, TR-MET-UNDECL, TR-MET-NOTMETRIC;
3 синтаксические: SE-TRIGGER-KIND, SE-EXPECT-COMPOP, SE-SCHEDULE-SPEC). Переиспользуемых семейств
диагностик: **2** (действия-шага §PM-6.B; запуск процесса §PM-6.C — 4 текста). Точек врезки в `run`: **1**.
Открытых `[NEEDS CLARIFICATION]` **нет**.

## Phasing — порядок поставки

Фазы строго зависимы: A → B → C → D → E. Каждая завершается гейтом `go build ./... && go vet ./...
&& gofmt -l && go test ./...`. Тексты диагностик берутся дословно из contracts/diagnostics.md.

- **Фаза A (AST).** 🎯 Новые узлы `TriggerDecl`, `TriggerSpec`/`MetricTrigger`/`EventTrigger`/
  `ScheduleTrigger`, `ScheduleSpec`/`EverySchedule`/`AtSchedule`, `ValueExpr`/`EventExpr` с
  конструкторами и локальной `Position`. **Гейт:** пакет `ast` компилируется, листовость
  сохранена (нет импорта `errors`), узловые юнит-тесты зелёные. *(FR-001…006, §TR-2)*

- **Фаза B (Парсер, два шва).** 🎯 Шов A: `isUnexpectedTopLevel` минус `KW_WHEN`; диспетчер
  `parseTriggerDecl` (три формы) + `expectCompOp` + `parseScheduleSpec`; пустой блок →
  `msgEmptyBlock`. Шов B: `parsePrimary`/`startsExpression` +`KW_VALUE`/`KW_EVENT`. Синтаксические
  диагностики SE-TRIGGER-KIND/SE-EXPECT-COMPOP/SE-SCHEDULE-SPEC через `msgExpected`. **Гейт:**
  table-driven позитивы (три формы, все 6 единиц, `в "строка"`, `событие.поле`) + негативы
  (нет вида/оператора/`каждые`-`в`, пустой блок, `значение`/`событие`/`{`/`}` на top-level,
  составное условие → ожидание `:`). *(FR-001…004/019/020/021, §TR-3, §TR-7.F)*

- **Фаза C (Семпроход).** 🎯 Регистрация `TriggerDecl` в `Analyze` (Шаг 1); `checkTrigger`:
  резолв метрики (TR-MET-UNDECL/TR-MET-NOTMETRIC), `checkExpr` порога; флаги `inMetricTrigger`/
  `inEventTrigger` в обходе тела; контекст-гарды `значение`/`событие` (TR-VAL-CTX/TR-EVT-CTX);
  переиспользование гарда действий-шага (`inStep=false`) и `checkRunProcess`; полная валидация
  тела событие-триггера, хотя оно не исполняется. **Гейт:** table-driven позитивы+негативы всех
  семантических диагностик байт-точно; `выручка.ladix` проходит семпроход чисто. *(FR-007…011/022/025, §TR-4/§TR-5, §TR-7.A…D)*

- **Фаза D (run fire-if-true).** 🎯 Экспортный проход `eval`: после `interp.Run`, до сводки задач;
  для каждого метрика-триггера в порядке объявления — вычислить метрику, вычислить порог в среде
  верхнего уровня, сравнить существующим оператором; при истине — инжектировать read-only `значение`
  и исполнить тело (`запустить процесс` штатным путём движка 006); событие/расписание → одна
  строка-заглушка. База ЛОЖЬ эфемерно (не читает/не пишет `trigger_state` даже под `--db`).
  **Гейт:** golden stdout на демо-программе, собираемой инлайн в `t.TempDir()`
  (`trigger_golden_test.go`, без testdata-фикстуры): истина → процесс+задача, контр-демо
  (`< 1_000_000` → молчание), повторный `run --db` идентичен. *(FR-012…018, §TR-6/§TR-8)*

- **Фаза E (Синки и регресс).** 🎯 `examples/выручка.ladix`: parse-error → parse-clean (инверсия
  замка `examples_test.go`); negative-набор §TR-10.5 (пустеет → удаляется либо заполняется
  `значение` на top-level); `MANIFEST.md` синк; точечные доковые упоминания формата `"ЧЧ:ММ"`
  приводятся к границе (доковый синк — за архитектор-чатом, FR-023). **Гейт SC-008:**
  `go build/vet/gofmt` чисто, `go test ./...` зелёное включая регресс 001–006. *(FR-023/024, SC-008, §TR-9/§TR-10)*
