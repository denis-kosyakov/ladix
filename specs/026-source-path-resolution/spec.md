# Feature Specification: Разрешение путей источников относительно каталога программы

**Feature Branch**: `026-source-path-resolution`

**Created**: 2026-06-21

**Status**: Draft

**Input**: User description: разрешение относительных путей к файлам-источникам относительно каталога `.ladix`-программы (file-relative) вместо текущего рабочего каталога (cwd); новый CLI-флаг `--source-base` для переопределения базового каталога.

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Запуск программы из любого каталога (Priority: P1)

Автор пишет `.ladix`-программу, которая объявляет источник с относительным путём к файлу данных
(например, `источник продажи файл: "data/sales.json"`), и кладёт файл данных рядом с программой
(в подкаталог `data/` возле `.ladix`-файла). Он запускает `ladix run путь/к/программе.ladix`
из произвольного рабочего каталога. Программа находит свои данные и выполняется — потому что
относительный путь источника разрешается относительно каталога самого `.ladix`-файла, а не
относительно того каталога, из которого запущен `ladix`.

**Why this priority**: это ядро фичи и единственная причина её существования. Сегодня программу
приходится запускать строго из «правильного» каталога (иначе источник не находится), что делает
артефакт непереносимым. Делает `.ladix`-файл самоописательным: данные привязаны к программе, а не
к процедуре запуска. Доставляет ценность независимо от остальных историй.

**Independent Test**: запустить `ladix run` над программой-примером с источником, передав путь к
программе, находясь в постороннем каталоге (например, временном). Программа завершается успешно и
печатает результат метрики — источник найден без смены рабочего каталога.

**Acceptance Scenarios**:

1. **Given** программа `examples/выручка.ladix` с источником `файл: "data/sales.json"` и файл
   данных в `examples/data/sales.json`, **When** пользователь запускает `ladix run` с относительным
   путём к программе из корня репозитория, **Then** источник находится и метрика вычисляется (exit 0).
2. **Given** та же программа, **When** пользователь запускает `ladix run` с **абсолютным** путём к
   программе из произвольного постороннего каталога (не корня репозитория), **Then** источник всё
   равно находится и метрика вычисляется (exit 0) — путь источника разрешён относительно каталога
   программы, а не текущего рабочего каталога.
3. **Given** программа лежит в текущем каталоге и передана без каталога (вида `прог.ladix`),
   **When** пользователь её запускает, **Then** относительный путь источника разрешается
   относительно текущего каталога (поведение для «каталог программы = текущий каталог» совпадает
   с интуицией).

---

### User Story 2 — Переопределение базового каталога флагом (Priority: P2)

Пользователь хочет разрешать относительные пути источников не от каталога программы, а от
указанного им каталога (например, программа и данные разнесены, или данные подменяются для другого
окружения). Он передаёт флаг `--source-base <каталог>` подкоманде. Базовым каталогом для разрешения
относительных путей источников становится `<каталог>`, переопределяя каталог программы.

**Why this priority**: расширяет переносимость для случаев, когда данные не лежат рядом с программой.
Дополняет, но не блокирует основную ценность US1 (по умолчанию работает и без флага).

**Independent Test**: запустить подкоманду с `--source-base <dir>`, где `<dir>` содержит файл данных,
а каталог программы — нет; убедиться, что источник читается из `<dir>`. Проверить обе формы
записи флага (`--source-base dir` и `--source-base=dir`) и поведение при пропуске значения.

**Acceptance Scenarios**:

1. **Given** программа в каталоге A (без файла данных) и каталог B с файлом данных, **When**
   пользователь запускает подкоманду с `--source-base B`, **Then** источник читается из B
   (флаг переопределил каталог программы).
2. **Given** любая подкоманда, грузящая источники, **When** передан `--source-base=B` (форма со
   знаком равенства), **Then** поведение идентично форме `--source-base B`.
3. **Given** любая подкоманда, **When** `--source-base` передан без значения (последний аргумент или
   за ним другой флаг), **Then** программа печатает в stderr `ladix: флаг --source-base требует
   значение` и завершается с кодом 2, ничего не выполняя.

---

### User Story 3 — Абсолютные пути и диагностика (Priority: P3)

Автор указывает в источнике абсолютный путь к файлу данных — он должен использоваться как есть,
независимо от базового каталога. А если файл по итоговому пути не найден, сообщение об ошибке
показывает **итоговый (разрешённый)** путь, чтобы было видно, где именно система искала файл.

**Why this priority**: краевые гарантии корректности и диагностируемости. Не нужны для основного
сценария, но предотвращают сюрпризы и облегчают отладку.

**Independent Test**: (а) источник с абсолютным путём читается при любом базовом каталоге;
(б) запуск с несуществующим файлом источника показывает в тексте ошибки разрешённый путь.

**Acceptance Scenarios**:

1. **Given** источник с абсолютным путём к существующему файлу, **When** программа запущена с любым
   базовым каталогом (или `--source-base`), **Then** файл читается по абсолютному пути, база
   игнорируется.
2. **Given** источник с относительным путём, для которого файл не существует по разрешённому пути,
   **When** программа запущена, **Then** сообщение об ошибке содержит итоговый (разрешённый) путь,
   а категория и код ошибки не меняются.

---

### Edge Cases

- **Каталог программы = текущий каталог**: путь программы без каталога (`прог.ladix`) → базовый
  каталог по умолчанию эквивалентен текущему каталогу; относительный путь источника разрешается
  к текущему каталогу (US1 сценарий 3). Отдельной обработки не требуется.
- **`--source-base` с относительным значением**: значение флага трактуется как каталог и
  используется как база; разрешение остаётся согласованным (относительное значение базы — само
  относительно текущего каталога процесса). Поведение детерминировано выбором пользователя.
- **`--source-base` без значения**: exit 2 + RU-сообщение в stderr (US2 сценарий 3).
- **Абсолютный путь источника при заданной базе**: база игнорируется (US3 сценарий 1).
- **serve, перечитывающий источники на тиках**: разрешение пути на каждом тике идёт через тот же
  механизм с тем же базовым каталогом — источники остаются находимыми на всех тиках без смены
  рабочего каталога.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Относительный путь к файлу данных источника MUST разрешаться относительно **базового
  каталога источников**, а не относительно текущего рабочего каталога процесса.
- **FR-002**: Базовым каталогом источников по умолчанию MUST быть каталог, в котором лежит
  запускаемый `.ladix`-файл (каталог программы).
- **FR-003**: Если путь к файлу данных источника **абсолютный**, он MUST использоваться как есть;
  базовый каталог при этом игнорируется.
- **FR-004**: Система MUST предоставлять CLI-флаг `--source-base <каталог>` во всех подкомандах,
  грузящих источники: `run`, `serve`, `start`, `complete`, `metric`.
- **FR-005**: Если `--source-base` задан, его значение MUST становиться базовым каталогом источников
  с приоритетом над каталогом программы.
- **FR-006**: Флаг `--source-base` MUST поддерживать обе формы записи: `--source-base <значение>` и
  `--source-base=<значение>` — согласованно с разбором остальных флагов CLI.
- **FR-007**: Если `--source-base` указан без значения, система MUST напечатать в stderr
  `ladix: флаг --source-base требует значение` и завершиться с кодом выхода 2, не выполняя программу.
- **FR-008**: Сообщение об ошибке «файл источника не найден» MUST показывать **итоговый
  (разрешённый)** путь к файлу; категория и код ошибки MUST оставаться прежними.
- **FR-009**: Изменение семантики разрешения путей MUST применяться единообразно ко всем форматам
  источников (JSON, CSV, NDJSON) и ко всем подкомандам, грузящим источники, включая перечитывание
  источников демоном `serve` на каждом тике.
- **FR-010**: Файлы данных витрины примеров MUST располагаться внутри `examples/` (каталог
  `examples/data/`), так чтобы примеры были самодостаточны и запускались по пути к программе из
  любого рабочего каталога без переноса данных. Пути внутри `examples/*.ladix` остаются
  относительными (`"data/..."`).
- **FR-011**: Поведение разрешения путей источников MUST НЕ зависеть от текущего рабочего каталога,
  кроме случая, когда базовый каталог сам относителен (каталог программы без каталога-префикса или
  относительное значение `--source-base`).

### Key Entities

- **Базовый каталог источников**: каталог, относительно которого разрешаются относительные пути к
  файлам данных источников. По умолчанию — каталог `.ladix`-программы; переопределяется флагом
  `--source-base`.
- **Объявление источника**: уже существующая декларация в программе, содержащая путь к файлу данных
  (относительный или абсолютный). Синтаксис, ключи и нормализация имён не меняются.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Все примеры с источниками (`выручка.ladix`, `выручка_30д.ladix`, `источник_csv.ladix`,
  `источник_json_схема.ladix`, `источник_ndjson.ladix`, `контроль_плана.ladix`) успешно выполняются
  по пути к программе из произвольного рабочего каталога (как минимум: по абсолютному пути из
  постороннего каталога — exit 0).
- **SC-002**: 100% подкоманд, грузящих источники (5 из 5: run, serve, start, complete, metric),
  принимают `--source-base` в обеих формах; пропуск значения даёт exit 2 с указанным RU-сообщением.
- **SC-003**: Существующий наблюдаемый вывод (`stdout`-байты) примеров и сценариев не меняется —
  смена семантики не вносит регресса в печать.
- **SC-004**: В документации не остаётся утверждений «относительно cwd» / «запускать из корня
  репозитория» / «отложен в v2» применительно к путям источников (проверяется поиском по
  документации — 0 совпадений старой семантики).
- **SC-005**: Сообщение об ошибке при отсутствующем файле источника содержит итоговый разрешённый
  путь (диагностируемость).

## Assumptions

- Программный файл всегда передаётся как путь-аргумент; режима чтения программы из stdin нет, поэтому
  базовый каталог всегда выводим из пути программы (или из `--source-base`).
- Смена семантики по умолчанию с cwd-relative на file-relative — осознанный **breaking change**;
  обратная совместимость с cwd-резолвом как отдельная опция не сохраняется (кроме явного
  `--source-base`). Это отражается в документации.
- Переменная окружения для базового каталога (например, `LADIX_SOURCE_BASE`) **не** вводится —
  только CLI-флаг.
- Синтаксис объявления источника, имена ключей, NFC-нормализация имён событий/полей, форматы и
  лимиты загрузчика — вне области изменений.
- Конституция проекта (9 принципов) сохраняется: библиотека stdlib-only, 0 новых внешних
  зависимостей, детерминированность вывода под фиксированными часами.
