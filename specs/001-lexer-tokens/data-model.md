# Phase 1 — Data Model: Лексер Ladix

**Feature**: 001-lexer-tokens | **Date**: 2026-06-01 | **Plan**: [plan.md](./plan.md)

Сущности лексера и пакета ошибок. Поля описаны концептуально (контракт), без обязательных
Go-сигнатур — те конкретизирует `/speckit-tasks`/реализация. Имена типов — английские (D-R5),
тексты сообщений — русские (SPEC §13).

---

## 1. `Position` (пакет `internal/errors`)

Позиция в исходнике; встраивается в токены и (позже) в AST/ошибки.

| Поле | Тип | Описание |
|---|---|---|
| `Line` | `int` | Номер строки, **1-based** |
| `Col` | `int` | Номер колонки, **1-based**, считается в **рунах** (Unicode code points) |

**Правила валидации/инварианты**:
- `Line ≥ 1`, `Col ≥ 1` для любого реального токена/ошибки.
- Колонка — рунный индекс от начала строки, **не байтовый** (конституция IV, SC-002).
- Размещение в `internal/errors` — решение этого шага (A1/D-R1); D1 (vs локальная в `ast`) отложен.

## 2. `LexError` (пакет `internal/errors`)

Лексическая ошибка: позиция + русское описание без заголовка.

| Поле | Тип | Описание |
|---|---|---|
| `Pos` | `Position` | Позиция первой руны проблемного места |
| `Msg` | `string` | Русское описание БЕЗ заголовка (например `незакрытый строковый литерал`) |

**Поведение**:
- Текстовое представление (`Error()`) даёт **канонический двухстрочный вид** (SPEC §13):
  ```
  Ошибка в строке N, колонка M:
  <описание>
  ```
- Разворачивается через `errors.As` (FR-003); реализует интерфейс `error`.
- В штатных путях паника ЗАПРЕЩЕНА (конституция III).

## 3. `ErrorList` — агрегат ошибок (пакет `internal/errors`)

Коллекция нескольких `LexError` за один прогон (panic-mode).

| Поле/метод | Описание |
|---|---|
| коллекция `LexError` | накопленные ошибки в порядке обнаружения |
| `Unwrap() []error` (или эквивалент) | развёртка стандартными средствами (`errors.As` достаёт отдельные `LexError`) |
| предел накопления | ≈20 сообщений (мягкий, бюджет общий с парсером — A3) |

**Инварианты**:
- Накопление не превышает ≈20 (FR-025, SC-005); поток токенов от лимита НЕ зависит (всегда `EOF`).
- Агрегат — значение, передаётся явно; без пакет-уровневого состояния (FR-029).

## 4. `Warning` (пакет `internal/errors`) — зарезервирован

Заголовок предупреждения «Предупреждение в строке N, колонка M:» зарезервирован как отдельный тип
(FR-004), но **лексер предупреждений НЕ порождает** (только ошибки). Структура существует ради
стабильности контракта формата; на этом шаге не используется (A5).

## 5. `TokenType` (пакет `internal/lexer`)

Перечень всех видов токенов. Имеет `String()` для диагностики/тестов. **Всего 67 видов**:
6 литералов + `IDENT` + 34 ключевых слова + 14 операторов + 8 разделителей/скобок + 4 виртуальных.

### 5.1. Литералы (6)

| TokenType | Лексема-пример | Несёт значение (D-R4) |
|---|---|---|
| `INT` | `42`, `5_000` | нормализованная цифровая строка (без int64) |
| `FLOAT` | `3.14` | предразобранное `float64` |
| `STRING` | `"привет"` | развёрнутая строка (escape раскрыты) |
| `BOOL` | `истина`, `ложь` | готовое булево |
| `NONE` | `пусто` | — (синглтон) |
| `DURATION` | `3дн`, `1_000сек` | единица (`сек`…`мес`) + числовая лексема-строка |

### 5.2. Идентификатор (1)

| TokenType | Описание |
|---|---|
| `IDENT` | Unicode-буква/`_`, далее буквы/цифры/`_`; жадно; периоды/встроенные функции/поля — тоже `IDENT` (FR-010) |

### 5.3. Ключевые слова (34 отдельных вида)

`истина`/`ложь`/`пусто` НЕ входят сюда — они эмитятся как `BOOL`/`NONE` (FR-006). Поэтому из 37
ключевых слов SPEC §2 отдельными видами токенов идут **34**:

| Категория (SPEC §2) | Слова → виды токенов |
|---|---|
| Объявления (3) | `пусть`, `функция`, `вернуть` |
| Управление (6) | `если`, `иначе`, `пока`, `для`, `прервать`, `продолжить` |
| Логика (3) | `и`, `или`, `не` |
| Декларатив (15) | `источник`, `файл`, `метрика`, `где`, `агрегат`, `период`, `по_дате`, `процесс`, `шаг`, `исполнитель`, `срок`, `после`, `присвоить`, `вызвать`, `уведомить` |
| Триггеры (7) | `когда`, `событие`, `значение`, `расписание`, `каждые`, `в`, `запустить` |

Сверка — по **полному совпадению** жадно прочитанного идентификатора (FR-006/FR-012): `тип_клиента`,
`или_нет`, `вход` — это `IDENT`, а не ключевые/зарезервированные слова. Короткие `и`/`или`/`не`/`в` —
только как самостоятельное полное слово.

### 5.4. Операторы (14)

| TokenType | Лексема | | TokenType | Лексема |
|---|---|---|---|---|
| `PLUS` | `+` | | `EQ` | `==` |
| `MINUS` | `-` | | `NEQ` | `!=` |
| `STAR` | `*` | | `LT` | `<` |
| `SLASH` | `/` | | `LE` | `<=` |
| `SLASH_SLASH` | `//` | | `GT` | `>` |
| `PERCENT` | `%` | | `GE` | `>=` |
| `ASSIGN` | `=` | | `DOT` | `.` |

Многосимвольные (`==`,`!=`,`<=`,`>=`,`//`) — жадным максимальным совпадением (FR-019). `!` валиден
только как часть `!=`.

### 5.5. Разделители и скобки (8)

| TokenType | Лексема | | TokenType | Лексема |
|---|---|---|---|---|
| `COMMA` | `,` | | `RPAREN` | `)` |
| `COLON` | `:` | | `LBRACKET` | `[` |
| `LPAREN` | `(` | | `RBRACKET` | `]` |
| `LBRACE` | `{` | | `RBRACE` | `}` |

### 5.6. Виртуальные токены (4)

| TokenType | Позиция (FR-009) | Правило эмиссии |
|---|---|---|
| `NEWLINE` | на месте перевода строки | в конце НЕПУСТОЙ логической строки; подавляется внутри незакрытых `()`/`[]`/`{}` (FR-008/FR-022) |
| `INDENT` | колонка 1 строки | вход на новый уровень отступа (+4 пробела) |
| `DEDENT` | колонка 1 строки | по одному на каждый снятый уровень |
| `EOF` | сразу после последней обработанной руны; пустой ввод → `(1, 1)`; после финального `\n` → следующая строка, колонка 1 | ровно один, всегда последний (FR-008/FR-023) |

> **Синтетические `NEWLINE`/`DEDENT` на `EOF`** (FR-023): при завершении последней логической строки и
> закрытии уровней на `EOF` эмитируемые `NEWLINE` и `DEDENT` несут ТУ ЖЕ позицию, что и `EOF` (сразу
> после последней руны). Хвостовые пустые строки прозрачны для `NEWLINE`/подсчёта отступов (FR-022),
> но руны `\n` поглощаются, поэтому `EOF` встаёт после ФИЗИЧЕСКИ последней руны (`"abc\n\n\n"` → `(4, 1)`).

## 6. `Token` (пакет `internal/lexer`)

Единица потока.

| Поле | Тип | Описание |
|---|---|---|
| `Type` | `TokenType` | вид токена |
| `Lexeme` | `string` | исходный текст лексемы (нормализованный для `INT`: цифры без `_`) |
| `Pos` | `errors.Position` | позиция первой руны лексемы |
| значение | опционально | предразобранное значение для `FLOAT`/`STRING`/`DURATION`/`BOOL` (D-R4); для `INT` значения-int64 НЕТ |

**Инварианты**:
- Виртуальные токены (`NEWLINE`/`INDENT`/`DEDENT`/`EOF`) могут иметь пустую/синтетическую лексему.
- Для `DURATION` хранятся **и** единица, **и** числовая лексема-строка (диапазон проверит парсер).
- Для `INT` — только нормализованная цифровая строка (guardrail 1/2).

## 7. Стек уровней отступа (внутреннее состояние `Lexer`)

Не публичная сущность, но ключевая структура (grammar §10.1).

| Элемент | Описание |
|---|---|
| стек `[]int` | уровни ведущих пробелов; инициализируется `[0]` |
| `cur` | ведущие пробелы текущей логической строки |

**Алгоритм (grammar §10.1, FR-021)**:
1. Стек начинается с `[0]`.
2. В начале каждой логической строки считаем ведущие пробелы → `cur`.
3. `cur` не кратен 4 → ошибка «отступ должен быть кратен 4 пробелам».
4. `cur > top` → `push(cur)` + `INDENT`.
5. `cur < top` → `pop()` с эмиссией `DEDENT`, пока `top == cur`; если не сошлось → ошибка «отступ не
   соответствует ни одному внешнему уровню».
6. `cur == top` → ничего.
7. На `EOF` — завершить логическую строку (`NEWLINE` при необходимости), закрыть все уровни серией
   `DEDENT`, эмитить один `EOF`.

## 8. `Lexer` (пакет `internal/lexer`)

Токенизатор: принимает исходник, выдаёт полный поток токенов (best-effort даже при ошибках) и
агрегат собранных ошибок.

| Аспект | Контракт |
|---|---|
| конструктор | явная инстанциация, исходник через параметры; без пакет-уровневого состояния (FR-029) |
| вход | UTF-8 `[]byte`/`string`; ридер отбрасывает BOM, нормализует `\r\n`/`\r` → `\n` (FR-011) |
| выход | поток `[]Token` (всегда заканчивается `EOF`) + агрегат `ErrorList` |
| зависимости | только `internal/errors` (граф `lexer → errors`); НЕ `ast` (A1) |
| границы | НЕ диагностирует незакрытые скобки/блоки; НЕ резолвит семантику (guardrail 8) |

## Связанные справочники (множества констант)

- **Зарезервированные слова (12, НЕ дают токен — дают `LexError`)**: `параллельно`, `модуль`, `импорт`,
  `экспорт`, `тип`, `повторить`, `выбрать`, `пытаться`, `словить`, `бросить`, `асинхронно`, `ждать`
  (FR-013).
- **Единицы длительности (6)**: `сек`, `мин`, `час`, `дн`, `нед`, `мес` (FR-017).
- **Escape-последовательности в строке (4)**: `\n`, `\t`, `\\`, `\"` (FR-018); любая иная `\X` → ошибка.
