# Contract: Поток токенов лексера (интерфейс лексер → парсер)

**Feature**: 001-lexer-tokens | **Источники**: SPEC §2, docs/grammar.md §10/§11, spec.md FR-005..FR-023

Этот контракт — стабильный интерфейс, который лексер отдаёт парсеру (потребитель класса B). Парсер
вправе на него опираться. Нарушение — регресс, ловится табличным тестом.

## C-1. Гарантии потока

| # | Гарантия | Источник |
|---|---|---|
| C-1.1 | Поток **всегда** завершается ровно одним `EOF` (даже при ошибках, даже на пустом вводе) | FR-008/FR-023, SC-003 |
| C-1.2 | Внутри незакрытых `(`/`[`/`{` токены `NEWLINE`/`INDENT`/`DEDENT` НЕ эмитятся (переводы прозрачны) | FR-008, SC-003 |
| C-1.3 | На возврате уровней число `DEDENT` равно числу снятых уровней; перед `EOF` закрыты все уровни | FR-023, SC-003 |
| C-1.4 | Каждый токен несёт `Type`, `Lexeme`, `Pos` (первая руна лексемы, 1-based, руны) | FR-007, SC-002 |
| C-1.5 | `NEWLINE` — в конце НЕПУСТОЙ логической строки; пустые/комментарные строки прозрачны | FR-022 |
| C-1.6 | Лексер выдаёт best-effort поток токенов даже при лексических ошибках: после ошибки проблемная лексема пропускается (токен не эмитится), но остаток логической строки ТОКЕНИЗИРУЕТСЯ ШТАТНО — токены продолжают поступать в поток; подавляется лишь регистрация новых ОШИБОК до точки синхронизации. Поток не обрывается и завершается `EOF`. | FR-025, US3 |

## C-2. Виды токенов (67) — см. [data-model.md](../data-model.md) §5

6 литералов (`INT`,`FLOAT`,`STRING`,`BOOL`,`NONE`,`DURATION`) · `IDENT` · 34 ключевых слова ·
14 операторов · 8 разделителей/скобок · 4 виртуальных (`NEWLINE`,`INDENT`,`DEDENT`,`EOF`).

## C-3. Контракт значения токена (FR-007, D-R4)

| TokenType | Что несёт |
|---|---|
| `INT` | **нормализованная цифровая строка** (цифры без `_`); int64-значения НЕТ — диапазон у парсера |
| `FLOAT` | предразобранное `float64` |
| `STRING` | развёрнутая строка (escape `\n \t \\ \"` раскрыты) |
| `BOOL` | готовое булево (`истина`→true, `ложь`→false) |
| `NONE` | без значения |
| `DURATION` | единица (`сек`/`мин`/`час`/`дн`/`нед`/`мес`) + **числовая лексема-строка** (диапазон у парсера) |
| ключевые/операторы/разделители | лексема как есть |

## C-4. Разграничения (канонические тест-кейсы, SC-001)

| Вход | Поток токенов | Правило |
|---|---|---|
| `5_000` | `INT("5000")` | `_` между цифрами, нормализуется |
| `3.14` | `FLOAT(3.14)` | точка между цифрами с обеих сторон |
| `5.поле` | `INT("5")` · `DOT` · `IDENT("поле")` | точка-разделитель, не часть числа |
| `5.` (конец/перед не-цифрой) | `INT("5")` · `DOT` | float не образуется |
| `3дн`, `1_000сек` | `DURATION` (значение+единица) | суффикс за ЦЕЛЫМ числом |
| `1.5дн` | `FLOAT(1.5)` · `IDENT("дн")` | за дробным суффикс НЕ читается |
| `пусть мин = 5` | `KW(пусть)` · `IDENT(мин)` · `ASSIGN` · `INT("5")` | `мин` без вплотную идущего числа — `IDENT` |
| `тип_клиента` | `IDENT("тип_клиента")` | сверка по полной строке (не зарезервированное `тип`) |
| `==` / `=` | `EQ` / `ASSIGN` | жадное максимальное совпадение |
| `//` / `/` | `SLASH_SLASH` / `SLASH` | то же |
| `<=` / `<` | `LE` / `LT` | то же |
| `пусть x = 5_000` (целая строка) | `KW(пусть)`·`IDENT(x)`·`ASSIGN`·`INT("5000")`·`NEWLINE`·`EOF` | пример US1.1 |

## C-5. Позиции виртуальных токенов (FR-009)

| Токен | Позиция |
|---|---|
| `NEWLINE` | на месте перевода строки |
| `INDENT` / `DEDENT` | колонка 1 строки |
| `EOF` | сразу после последней обработанной руны (куда встал бы следующий символ); пустой ввод → `(1, 1)`; после финального `\n` → следующая строка, колонка 1 |

> **Синтетические токены на `EOF`**: `NEWLINE` (завершение последней логической строки) и серия
> `DEDENT` (закрытие уровней), эмитируемые на `EOF` (FR-023), несут ТУ ЖЕ позицию, что и `EOF`.
> Хвостовые пустые строки прозрачны для `NEWLINE`/отступов (C-1.5), но их `\n` поглощаются, поэтому
> `EOF` встаёт после ФИЗИЧЕСКИ последней руны (`"abc\n\n\n"` → `(4, 1)`); «финальный `\n`» в правиле
> позиции = физически последний перевод строки.

## C-6. Чего поток НЕ содержит / лексер НЕ делает (границы)

- НЕ диагностирует незакрытые скобки/блоки на `EOF` — отдаёт оставшиеся структурные токены и `EOF`
  (это парсер).
- НЕ резолвит семантику: `ежедневно`…`ежегодно` (периоды), `печать`/`длина` (встроенные функции),
  поля записи — обычные `IDENT` (FR-010).
- Зарезервированные слова (12) токена НЕ дают — дают `LexError` (см. lexical-errors.md, L-11).
- Комментарии (`#`…конец строки вне строки) в поток НЕ попадают (прозрачны).
