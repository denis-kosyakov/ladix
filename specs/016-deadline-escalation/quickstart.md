# Quickstart: B4 эскалация дедлайна

Ручные прогоны для проверки B4a (фронтенд) и B4b (durable, Go-API до B5).

## B4a — синтаксис под `run` (заглушка)

`escal.ladix`:

```ladix
процесс эскалация_плана:
    шаг связаться_с_клиентом:
        исполнитель: "менеджер"
        срок: 2дн

когда задача просрочена в эскалация_плана.связаться_с_клиентом:
    уведомить руководитель(факт)
```

```sh
ladix run escal.ladix
```

Ожидаемо (exit 0):
```text
задача триггер 'эскалация_плана.связаться_с_клиентом' требует serve (фича 007b)
```
Тело `уведомить …` НЕ исполняется под `run`.

### v1 НЕ ломается

```ladix
пусть задача = 10
печать(задача)
```
```sh
ladix run v1.ladix   # exit 0, печатает 10 — 'задача' остаётся IDENT (D-AU-4)
```

### Негативы (диагностики)

| Вход | Диагностика |
|------|-------------|
| `когда задача X:` | `ожидалось 'просрочена', получено 'X'` (SE-EXPECTED) |
| `когда задача просрочена P.S:` | `ожидалось 'в', получено 'P'` |
| `когда задача просрочена в P S:` | `ожидалось '.', получено 'S'` |
| `когда задача просрочена в неизв.шаг:` | `процесс 'неизв' не объявлен` (СемантическаяОшибка) |
| `когда задача просрочена в P.нетшага:` | `шаг 'нетшага' не найден в процессе 'P'` |
| `когда мусор:` | `ожидалось 'метрика, событие, расписание или задача', получено 'мусор'` (SE-TRIGGER-KIND расширен) |

## B4b — durable-эскалация (Go-API тест, до B5)

§AU-12.B на уровне Go (CLI `ladix start` появится в B5; полная CLI-сборка — на M2-гейте).

```text
1. SQLiteStore на demo.db; engine.Start("эскалация_плана", [2500000])
   → инстанс p-000001, переменная факт=2500000, шаг связаться_с_клиентом,
     задача t-000001 со сроком (created + 2дн)
2. Daemon{clock: FixedClock(created)}; d.tick()
   → checkDeadlines: t-000001 НЕ просрочена → тишина
3. clock.Advance(3дн) (за срок); d.tick()
   → t-000001 просрочена, !Escalated, шаг/процесс совпали
   → fireDeadlineBody: stdout "[уведомление] руководитель: 2500000" — РОВНО ОДИН раз
   → t-000001.Escalated=true, SaveTask (UPSERT в SQLite)
4. d.tick() ещё раз (без рестарта)
   → t-000001.Escalated==true → continue → НЕТ повтора
5. ПЕРЕЗАПУСК: новый SQLiteStore на той же demo.db; RunRestartScan(); d.tick()
   → ListPendingTasks читает Escalated=true (точка 4 кодека) → continue → НЕТ повтора
6. assert: уведомление напечатано РОВНО ОДИН раз за все тики/прогоны
```

Замки §AU-12.B: (а) единичность; (б) `Escalated` персистнут между прогонами SQLite;
(в) 4-я фаза не ломает первые три (живой daemon-тест с метрика+расписание+эскалация);
(г) **мутпроба** — снять `if t.Escalated { continue }` → шаг 4/5 эскалируют повторно →
тест КРАСНЕЕТ.

## На M2-гейте (после B5/B6 — НЕ этот прогон)

```sh
ladix start эскалация_плана 2500000 --db demo.db   # B5
ladix serve --db demo.db                            # эскалация под serve
ladix inspect p-000001 --db demo.db                 # B6: снимок + история (эскалирована)
```
End-to-end §AU-12.C (контроль_плана.ladix + реальный CSV + edge метрики + complete --данные +
--вебхук) — терминальный гейт M2.
