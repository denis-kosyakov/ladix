## Summary

Активируем РОВНО 7 ранее отложенных дата/время встроенных функций Ladix —
`вчера`, `завтра`, `длительность`, `в_секундах`, `в_минутах`, `в_часах`, `в_днях` — на
внутренней Go date-math. До фичи они зарегистрированы как `Deferred` и при вызове дают
семантическую диагностику «функция '<имя>' не поддерживается в этой версии»; после фичи они
становятся активными (вызываемыми), а `deferredNames` пустеет — реестр приходит к инварианту
**35 активных + 0 deferred = 35**.

Технический подход (всё зафиксировано в §DB-1..§DB-6, открытых вопросов нет):

- **Новый файл** `src/internal/eval/builtins_duration.go` в стиле `builtins_date.go`: реализация
  7 функций. `вчера()`/`завтра()` — сдвиг `i.now()` на ±1 календарный день через готовые хелперы
  `eval/window.go` (`dateToTime`/`AddDate`/`timeToDate`), без операторной арифметики Ladix.
  `длительность(n, u)` — конструктор `value.Длительность{Amount, Unit}` без нормализации.
  Конвертеры `в_*` — целочисленное частное `totalSec / делитель` с усечением к нулю.
- **Регистрация** в `src/internal/eval/builtins.go`: 7 явных `add(Builtin{...})` с
  `Arity: ArityFixed`; `deferredNames` → пустой срез; удаление цикла-заглушек; переформулировка
  инвариант-комментария.
- **Ретайр** диагностики `SEM-DEFERRED-BUILTIN`: ветки `if b.Deferred` в `analyze.go`/`call.go`
  остаются инертным backstop'ом (поле `Deferred` и механизм НЕ удаляются), комментарии обновляются;
  golden-кейс этой диагностики удаляется, агрегатный счётчик `errors_golden_test.go` декрементится.
- **4 новые строки ошибок** (байт-в-байт, без точки, с гильемами «…») вносятся в слой eval;
  арность и переполнение переиспользуют существующие строки реестра.
- **Тест-замки** в 4 файлах инвертируются СИНХРОННО с кодом (иначе гейт `go test` красный).

Операторная арифметика дат/длительностей (`Дата±Длит`, `Дата−Дата`, `Длит±Длит`, `Длит*X`)
ОСТАЁТСЯ отложенной (v2, §DB-9) — вне скоупа. Появление конструктора `длительность()` без
операторной арифметики — осознанная асимметрия (D-A=A), не дыра.

## Phasing — порядок поставки

Поставка инкрементальна по User Story (P1→P2), но активация реестра атомарна (нельзя
полу-активировать `deferredNames`), поэтому фазы — про порядок РАЗРАБОТКИ внутри одного PR:

1. **US1 (P1) `вчера`/`завтра`** — самый простой срез: нет новых входных типов, наблюдаемый
   результат немедленно. Реализация + golden на `FixedClock`.
2. **US2 (P1) `длительность`** — конструктор; вход для US3. Валидация тип→единица, без нормализации.
3. **US3 (P1) конвертеры `в_*`** — замыкают цикл; матрица 5×4 + усечение + overflow.
4. **US4 (P2) диагностика** — 4 exact-match строки поверх P1-функций (golden-негатив).
5. **Активация реестра + ретайр** — `deferredNames`→[], инвариант-коммент, инверсия 4 тест-замков,
   декремент счётчика `errors_golden`. Делается атомарно, иначе гейт `go test` красный.
