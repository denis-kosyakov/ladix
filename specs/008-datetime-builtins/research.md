## R-1. Go date-math vs внешние пакеты дат

**Decision.** `вчера()`/`завтра()` сдвигают «сегодня» на ±1 календарный день через стандартную
библиотеку Go (`time.AddDate`), используя готовые хелперы `eval/window.go`:
`timeToDate(dateToTime(i.now()).AddDate(0, 0, ∓1))`. Никаких внешних пакетов дат.

**Rationale.** Конституция I запрещает тяжёлые зависимости без явного решения; `time.AddDate`
корректно обрабатывает границы месяца/года/високос (golden: `завтра()` на 2026-05-31 → 2026-06-01).
`dateToTime` даёт полночь UTC, `timeToDate` возвращает обратно `value.Дата` — конверсия без
таймзонной двусмысленности. Хелперы уже существуют и проверены в 004; переиспользование, а не
дублирование. Источник «сегодня» — ТОЛЬКО `i.now()` (инжектируемый `Clock`), что наследует
инвариант serve-демона: `ResetRunState()` обнуляет кеш `i.today`, следующий тик переснимает дату.

**Alternatives considered.** (a) Внешний date-пакет — отвергнут: лишняя зависимость, нарушает I,
не нужен для ±1 дня. (b) Ручная арифметика дней с самостоятельным учётом високоса — отвергнут:
переизобретение `AddDate`, риск ошибок на границах. (c) Операторная арифметика Ladix
(`сегодня() + 1дн`) — отвергнут: операторная арифметика дат отложена в v2 (см. R-6), а реализация
builtin'а не должна зависеть от непостроенного фронтенда.

## R-2. Усечение конвертеров целочисленным делением

**Decision.** Конвертеры `в_*` вычисляют результат как целочисленное частное полной длительности
в секундах: `в_секундах` = totalSec, `в_минутах` = totalSec/60, `в_часах` = totalSec/3600,
`в_днях` = totalSec/86400. При неделимости результат усекается **к нулю** делением Go (`int64 / int64`)
в обе стороны знака: `в_минутах(длительность(90,"сек"))` = 1; `в_минутах(длительность(-90,"сек"))` = -1.

**Rationale.** D-B: усечение к нулю — зеркало уже существующего поведения `целое()` (Дробное→Целое
обрезается к нулю). Деление Go для int64 само усекает к нулю (truncated division), отдельной
логики округления не требуется. Тип результата — `Целое`, что замыкает цикл «длительность → число
для арифметики/сравнений».

**Alternatives considered.** (a) Округление к ближайшему / floor — отвергнут: не зеркалит `целое()`,
вводит расхождение конвенций усечения в языке. (b) Возврат `Дробное` (90/60 = 1.5) — отвергнут:
контракт фиксирует `Целое` (§DB-1), а Дробное-результат сместил бы семантику «сколько целых единиц».
(c) Запрет неделимых конверсий как ошибки — отвергнут: усечение полезнее и предсказуемо.

## R-3. Месяцы (`мес`) в конвертерах → ошибка без даты-якоря

**Decision.** Если `d.Unit == "мес"`, любой из 4 конвертеров выдаёт **ОшибкуВыполнения**
`<имя>: месяцы не приводятся без даты-якоря` (где `<имя>` — имя вызванной функции). Конвертеры НЕ
вызывают календарный `AddDate` для месяцев. `мес` остаётся валидной единицей для КОНСТРУКТОРА
`длительность(1,"мес")` (конструируется без ошибки) — ошибка возникает только при попытке
перевести месяцы в число.

**Rationale.** `мес` — календарная единица переменной длины (28..31 день); число секунд в месяце
не определено без опорной даты. `engine/deadline.go` обрабатывает `мес` через `AddDate(0,n,0)`
именно потому, что там есть якорная дата (дедлайн от «сейчас»); у чистого конвертера якоря нет —
копировать `deadline.go`-логику ЗАПРЕЩЕНО (явная пометка §DB-4). Ошибка честнее молчаливого
выбора «30 дней».

**Alternatives considered.** (a) Зафиксировать месяц = 30 дней (или 2592000 сек) — отвергнут:
произвольная неверная константа, маскирует календарную природу. (b) Тихо вернуть 0 — отвергнут:
скрывает ошибку пользователя. (c) Запретить `мес` и в конструкторе — отвергнут: конструктор хранит
сырое значение без нормализации (D-17), `мес` — легитимная единица для сравнений и литерала `1мес`.

## R-4. Формат строк ошибок: гильемы и exact-match префиксы

**Decision.** 4 новые строки фиксируются байт-в-байт, БЕЗ завершающей точки, с гильемами «…»
вокруг пользовательского строкового значения:

1. `длительность: ожидается Целое и Строка, получено <тип> и <тип>`
2. `длительность: неизвестная единица «<единица>»`
3. `<имя>: ожидается Длительность, получено <тип>`
4. `<имя>: месяцы не приводятся без даты-якоря`

Тип-mismatch конструктора показывает ОБА полученных типа, даже если неверен только один аргумент.
`<тип>` = `TypeName` значения; `<имя>` = имя вызванной функции.

**Rationale.** D-C/D-F: гильемы «…» — конвенция §SM-9, живой паттерн `builtins_date.go:32`
(`дата: «<значение>» не является датой`). Префиксированные exact-match строки — зеркало
`дата:`-конвенции, что делает диагностику узнаваемой и переводимой в golden-тесты «как есть»
(конституция VIII: тексты дословно, переформулировка запрещена). Показ обоих типов в (1) даёт
полную картину аргументов без угадывания, который именно неверен.

**Alternatives considered.** (a) Апострофы `'XYZ'` — отвергнут: расходится с §SM-9 и с §DB-5/§8.3
(в `docs/stdlib.md` апострофы заменяются на гильемы при посадке). (b) Показывать только неверный
тип в (1) — отвергнут: спека (FR-008) явно требует ОБА. (c) Без префикса имени функции — отвергнут:
теряется указание, какая функция дала ошибку (важно для (3)/(4), где текст общий для 4 конвертеров).

## R-5. Инертный backstop диагностики SEM-DEFERRED-BUILTIN

**Decision.** Поле `Builtin.Deferred` и ветки `if b.Deferred { semErr(... "не поддерживается в
этой версии") }` в `analyze.go:592` и `call.go:34` **НЕ удаляются** — остаются инертным backstop'ом
(после активации ни один builtin не `Deferred`, ветка мертва для всех имён). Удаляется только
golden-кейс этой диагностики в `errors_golden_test.go`, обновляются комментарии (что активных
deferred-builtins больше нет), и декрементится агрегатный счётчик кодов 29→28.

**Rationale.** §DB-6: механизм отложенных builtins — переиспользуемая инфраструктура (будущие v2
функции могут снова стать `Deferred`); удалять рабочий backstop ради нулевой строки кода
нецелесообразно. Прецедент: `SEM-DEFERRED-CONSTRUCT` ретайрнут так же в 006 (оставлен инертным).
Декремент счётчика обязателен: после удаления golden-кейса `len(seen)` падает 29→28, а новые
ошибки §DB-5 идут через СУЩЕСТВУЮЩИЕ коды (ОшибкаТипа/ОшибкаВыполнения) и нового golden-кода НЕ
вводят — счёт не восстанавливается, без декремента гейт `go test` красный.

**Alternatives considered.** (a) Полностью удалить поле `Deferred` и ветки — отвергнут: ломает
переиспользуемый механизм, лишний diff, противоречит §DB-6. (b) Оставить golden-кейс — отвергнут:
кейс стал бы ложным (вызов больше не даёт «не поддерживается»), регресс-замок врал бы. (c) Не
трогать счётчик — отвергнут: гейт `go test` красный (детерминированный провал).

## R-6. Почему операторная арифметика отложена (D-A=A)

**Decision.** Операторная арифметика дат и длительностей — `Дата ± Длит`, `Дата − Дата`,
`Длит ± Длит`, `Длит * X` — ОСТАЁТСЯ отложенной в v2 (§DB-9). `eval/arith.go` и `value.Compare`
не трогаются; оператор над датой/длительностью по-прежнему даёт ошибку типа. Активируется ТОЛЬКО
конструктор `длительность()`, конвертеры `в_*` и относительные даты `вчера`/`завтра`.

**Rationale.** D-A=A (решение владельца): фича 008 — узкий срез «сконструировать / сравнить /
перевести в число», без полноценной арифметики типов. Граница: пользователь может построить
`Длительность` (литерал `5мин` или `длительность(...)`), сравнить её (`==`/`!=`, порядок одной
единицы — активно с 006) и перевести в `Целое` (конвертеры), но НЕ может складывать/вычитать/
умножать оператором. Появление конструктора без операторной арифметики — осознанная асимметрия:
конструктор и конвертеры самодостаточны и тестируемы, а операторная арифметика требует решений по
смешанным единицам/нормализации/перегрузке операторов (отдельный объём). Снятие в v2 аддитивно
(новый оператор/значение), фронтенд и программы v1 не ломаются.

**Alternatives considered.** (a) Включить арифметику сейчас — отвергнут: расширяет скоуп за рамки
решения владельца, тянет нормализацию единиц (D-17 отложена) и перегрузку операторов. (b) Не
давать конструктор, пока нет арифметики — отвергнут: конструктор — единственный способ построить
`Длительность` из вычисленных значений (вход US3), сам по себе ценен.

## R-7. Размещение реализации и парность имени файла

**Decision.** Новый файл `src/internal/eval/builtins_duration.go` содержит все 7 функций (включая
`вчера`/`завтра`). Стиль — `builtins_date.go`. Сигнатура Fn:
`func(i *Interpreter, args []value.Value, pos ast.Position) (value.Value, error)`.

**Rationale.** §DB-1: имя `builtins_duration.go` намеренно парно уже существующему тесту
`duration_builtins_test.go` (порядок слов инвертирован — это ок). `вчера`/`завтра` логически
относятся к датам, но их допустимо положить рядом, чтобы вся активируемая семёрка жила в одном
новом файле (меньше точек правки, единый diff). Множители единиц — локальная `int64`-карта в этом
файле (НЕ глобал пакета, конституция V).

**Alternatives considered.** (a) Разнести `вчера`/`завтра` в `builtins_date.go` — допустимо по
§DB-1, но отвергнуто ради единого diff активации. (b) Семь отдельных файлов — отвергнут: избыточное
дробление для ~150 строк.
