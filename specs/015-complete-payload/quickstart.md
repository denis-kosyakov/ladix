# Quickstart: B3 payload через `complete --данные`

Ручной прогон (после реализации). Все команды из корня репо; `<файл>` — `.ladix`
с процессом, где шаг после завершаемого читает `данные`.

## Пример процесса (демо)

```ladix
процесс заявка
  шаг подать
    исполнитель: "оператор"
  шаг учесть
    присвоить факт = данные.итог
```

`подать` — человеческий (создаёт задачу, засыпает). `учесть` — авто-шаг догона:
читает `данные.итог` из payload и сохраняет в переменную процесса `факт`.

## Сценарий 1 — payload виден первому шагу (US1)

```bash
ladix start demo.ladix заявка --db /tmp/q.db          # → инстанс p-000001, задача t-000001
ladix complete demo.ladix t-000001 --данные '{"итог":"одобрено"}' --db /tmp/q.db
ladix inspect p-000001 --db /tmp/q.db                  # переменные: факт = одобрено
```

Ожидаемо: `complete` exit 0; `inspect` показывает `факт = одобрено` (payload дошёл
до шага `учесть`, присвоен в переменную процесса).

## Сценарий 2 — эфемерность (US2)

```bash
# второй complete БЕЗ --данные на следующей задаче
ladix complete demo.ladix t-000002 --db /tmp/q.db      # данные пусто → данные.итог = Пусто
ladix inspect p-000001 --db /tmp/q.db                  # payload "одобрено" НЕ воскрешён
```

Перечтение Store не содержит "одобрено" нигде, кроме переменной `факт` (сохранена
явным `присвоить`). Сам payload не персистирован.

## Сценарий 3 — без флага → пусто (US3)

```bash
ladix complete demo.ladix t-000001 --db /tmp/q.db      # без --данные → пустая Запись
```

Поведение идентично доB3 (регресс не сломан).

## Сценарий 4 — плохой JSON → дословная ошибка (US3)

```bash
ladix complete demo.ladix t-000001 --данные '{не json' --db /tmp/q.db
# stderr: ladix: неверный JSON в --данные: <деталь>
# exit code: 2 ; инстанс/задача в Store без изменений
```

```bash
ladix complete demo.ladix t-000001 --данные '[1,2]' --db /tmp/q.db
# stderr: ladix: неверный JSON в --данные: <деталь>   (массив — не объект)
# exit code: 2
```

```bash
ladix complete demo.ladix t-000001 --данные --db /tmp/q.db
# stderr: ladix: флаг --данные требует значение
# exit code: 2
```

## Проверки инвариантов (для ревью)

- `ProcessRuntime` = 8 методов (не вырос).
- `internal/eval` не импортирует `jsonval`/`store`/`engine`.
- `store.Task`/`store.ProcessInstance`/схема SQLite — без новых полей payload.
- `complete` зовёт `jsonval.PayloadToRecord` (нет второго payload-декодера).
- 0 новых зависимостей модуля; `go vet ./...` чисто; race зелёный; FixedClock в тестах.
