# Quickstart: Фронтенд процессов v1 — процесс, шаг, действия, запуск (005-process-frontend)

**Feature**: 005-process-frontend | **Plan**: [plan.md](./plan.md) | **Якорь**: [../../docs/process-model.md](../../docs/process-model.md) | **Спека**: [spec.md](./spec.md)

Как разработчику собрать, запустить и проверить фичу 005. Это **чистый фронтенд**: парсер + AST + семантический проход. **Исполнение тела шага / запуска процесса НЕ реализуется** — оно остаётся рантайм-deferred до движка 006 ([§PM-0](../../docs/process-model.md), [§PM-5](../../docs/process-model.md)). Фича **расширяет** существующие пакеты (зеркало пути 004, [§SM-0](../../docs/source-metric-model.md)):

- **парсер** 002/004 — снять из `isUnexpectedTopLevel` **только** `KW_PROCESS` (D-6, §PM-3); добавить ветку `parseProcessDecl` в `parseTopLevelItem`; новые `parseProcessDecl`/`parseStepDecl`/`parseAfterList` (`parser/parse_decl.go`), переиспользовать `parseParamList` (из `parseFunctionDecl`), `openAttrBlock`/backstop (из `parseMetricDecl`), `parseStepAction` (уже есть, `parse_stmt.go:68-69`);

- **синк-доки (зона якоря, частично выполнена):** `SPEC §13.4`/`§7.3`/`§7.4`/`§11.4`/`§12`, `ARCHITECTURE §4.4/§4.8` (формы узлов — выполнено), `ast/node.go:24` (doc-комментарий union), `examples/MANIFEST.md` (расщепить строку выручка/онбординг, §PM-7).

## 2. Целевой `examples/онбординг.ladix` (после правки, §PM-7/§PM-5/D-9)

Текущий файл (`examples/онбординг.ladix`) **ещё содержит** последнюю строку
`печать("статус:", статус_процесса(id))`. В 005 её **убрать**: `статус_процесса` остаётся **deferred-builtin** (D-9, остаётся семантической ошибкой `функция 'статус_процесса' не поддерживается в этой версии`), её вызов сделал бы семантику **не чистой** и сломал бы демо «парс+сем чисто». Целевой файл (§PM-7):

```ladix
# Процесс адаптации нового сотрудника: автоматический шаг + два человеческих
процесс онбординг(сотрудник):
    шаг завести_доступы:
        присвоить имя = сотрудник                 # переменная процесса
        уведомить ИТ("создать учётку для " + сотрудник)   # авто-эффект (стаб-лог)
    шаг провести_встречу после завести_доступы:
        исполнитель: "руководитель"
        срок:        3дн
    шаг закрыть_адаптацию после провести_встречу:
        исполнитель: "HR"
        срок:        5дн

# Запуск из императивного кода: захватываем ID инстанса (исполнение — рантайм-deferred до 006)
пусть id = запустить процесс онбординг("Петров")
печать("запущен онбординг, id:", id)
```

**Почему этот файл проходит парс + семантику чисто** (§PM-7 позитив, §PM-4):
- `процесс онбординг(сотрудник)` — имя в общий глобальный namespace (D-5), не сталкивается со встроенной/периодом (`checkReservedDeclName`).
- 3 шага, имена уникальны (D-5); `после завести_доступы` / `после провести_встречу` — ссылки **строго назад** (D-4, §11.2): резолвятся, граф ациклический по построению.
- `срок: 3дн`/`срок: 5дн` сопровождаются `исполнитель:` → правило «срок без исполнитель» не срабатывает (§PM-4 п.3). `DurationLit` (`3дн`/`5дн`) в атрибуте `срок:` **не обходится** семпроходом (D-11: атрибуты шага не попадают в `Body`, их выражения не валидируются) → семантика чиста, deferred литерала длительности **не достигается** (§PM-5).
- Тело шага `завести_доступы` (`присвоить имя = …`, `уведомить ИТ(…)`) — действия **в шаге** → контекст-гард пропускает (`inStep=true`, §PM-4); payload (`Args`/`Value`) семпроходом **не** обходится (action-ветка → `return nil`, D-11).
- `vars` тела шага засевается параметром `сотрудник` (D-12) → чтение `сотрудник` резолвится в рантайм, не даёт «не объявлено».
- top-level `пусть id = запустить процесс онбординг("Петров")` — `checkRunProcess` (§PM-4): имя `онбординг` резолвится против реестра процессов (D-10), арность `1 == 1` сходится → семантика чиста; **исполнение** остаётся рантайм-deferred.

## 3. Позитив: парс + семантика чисто

Сквозной фронтенд (без исполнения) проверяется Go-тестами и наблюдается через `ladix run` (стадии парс→сем до рантайма). Быстрая проверка из CLI — что файл доходит до рантайма без парс-/сем-ошибок:

```bash
cd src
go build -o /tmp/ladix ./cmd/ladix

# Минимальный валидный процесс (US1, §PM-7 позитив, строка 1):
printf 'процесс P:\n    шаг A:\n        печать(1)\n' > /tmp/p.ladix
/tmp/ladix run /tmp/p.ladix
# код 0: процесс ТОЛЬКО объявлен (без top-level запуска) → парс+сем чисто, рантайм пропускает
# объявление (ProcessDecl — Decl, не Statement; Run() его не исполняет), top-level операторов нет → 0
```

**Контракт `ladix run` процессной программы** (§PM-5, демо-контракт): **парс** чисто → **семантика** чисто → **рантайм**. В рантайме top-level операторы исполняются сверху вниз, но **объявление процесса не исполняется** (`ProcessDecl` — `Decl`, `Run()` его пропускает; **тело шага в 005 в рантайме не исполняется** — это движок 006). Программа, которая процесс только **объявляет** (без top-level `запустить процесс`), отрабатывает рантайм без ошибок (**код 0**).

> **Тонкость scope (§PM-5).** Единственная **наблюдаемая** рантайм-граница 005 — top-level `запустить процесс` (`expr.go:49`). Ветка `stmt.go:64` (действие в шаге → deferred) **недостижима** в 005: тело шага в рантайме не исполняется до движка 006. Поэтому не предлагать тест «действие в шаге → рантайм-deferred» — он недостижим (§PM-0).

## 4. Граница deferred: `ladix run` онбординга → код 1 в рантайме (§PM-5)

```bash
cd src
go build -o /tmp/ladix ./cmd/ladix
cd ..                                   # из корня репозитория
/tmp/ladix run examples/онбординг.ladix
# stderr: Ошибка в строке N, колонка M:
#         конструкция запустить процесс не поддерживается в этой версии
# код выхода: 1
```

Конвейер: лексер → парсер → `Analyze` → `Run`. Стадии 2 (парс) и 3 (семантика) — **чисто** (см. §2). В рантайме `Run` исполняет top-level операторы; первая исполняемая процесс-конструкция — `запустить процесс онбординг("Петров")` (внутри `пусть id = …`). Её eval (`expr.go:49`, `i.deferredConstruct`) даёт `СемантическаяОшибку` `конструкция запустить процесс не поддерживается в этой версии`, выполнение останавливается (**код 1**). Это демонстрирует точную рантайм-границу: процесс-синтаксис парсится и проходит семантику, исполнение откладывается до 006.

> **Почему именно эта строка — граница, а не `статус_процесса`.** `запустить процесс` — reserved-узел (не builtin), его deferred уже двусторонний (`expr.go:49`); убрать **семантическую** сторону дёшево (D-10, `checkRunProcess`), и это даёт «парс+сем чисто». `статус_процесса`/`состояние_процесса`/`задачи_пользователя` остаются **deferred-builtins** (D-9, семантическая ошибка `функция '<имя>' не поддерживается в этой версии`) — перенос в рантайм потребовал бы менять механизм builtin и ломать `TestBuiltinDeferredAll` (вне scope). Поэтому строка `печать("статус:", статус_процесса(id))` из онбординга **убирается** (§2) — иначе семантика бы не была чиста.

**Контракт кодов** (как у `run` 003/004): **0** — успех (рантайм без ошибок; только-объявление процесса); **1** — штатная ошибка Ladix (здесь — рантайм-deferred `запустить процесс`; либо парс/сем-ошибка в невалидной программе — §5); **2** — ошибка использования CLI (нет файла-аргумента и т. п.). 005 **не** добавляет подкоманду (D-7): диспетч `realMain` (`cmd/ladix/main.go:35`, `switch args[0] { case "run": …; case "metric": … }`) не расширяется.

## 5. Негативные мини-примеры (точные диагностики §PM-6)

Каждый — отдельный фикстура-вариант; тексты сверяются **байт-в-байт** через `err.Error()` (двухстрочный канонический формат `errors`: `Ошибка в строке N, колонка M:` + payload **без** завершающей точки; одинарные `'…'` для имён; `N` нумеруется **с 1** — §PM-6, конституция VIII). Полная приёмочная таблица — §PM-7; ниже — представительная тройка из §PM-8.

### 5.1. Парсер — не-шаг в блоке процесса (§PM-3 шаг 6, §PM-6.A)

```bash
printf 'процесс P:\n    печать(1)\n' > /tmp/n1.ladix
/tmp/ladix run /tmp/n1.ladix
# stderr: Ошибка в строке 2, колонка 5:
#         неожиданный токен 'печать'
# код 1
```

В блоке процесса допустимы **только** шаги (§PM-3): цикл `parseProcessDecl` на не-`KW_STEP` ведущем токене строки эмитит `p.error(peek().Pos, msgUnexpected(peek()))` (`msgUnexpected` переиспользуется) + backstop `advance()` (гарантия прогресса). `печать` — `IDENT` (не `KW_STEP`) → `неожиданный токен 'печать'`. Позиция указывает на ведущий токен строки.

### 5.2. Парсер — пустой блок шага (§PM-3 шаг 5, §PM-6.A)

```bash
printf 'процесс P:\n    шаг A:\n' > /tmp/n2.ladix      # шаг A: без единой строки
/tmp/ladix run /tmp/n2.ladix
# stderr: Ошибка в строке ..., колонка ...:
#         пустой блок не допускается, добавьте хотя бы один оператор
# код 1
```

`openAttrBlock` для шага: `expect(NEWLINE)`, нет `INDENT` → `msgEmptyBlock` (переиспользуется из 004 §SM-9.A). «Тело шага непусто» = «есть ≥1 атрибут **или** ≥1 оператор» (§PM-2): пустой `INDENT`-блок шага → `msgEmptyBlock`. Тот же текст — для пустого блока процесса (`процесс P:` без шагов).

### 5.3. Семпроход — `срок` без `исполнитель` (§PM-4 п.3, §PM-6.B)

```bash
printf 'процесс P:\n    шаг A:\n        срок: 2дн\n' > /tmp/n3.ladix
/tmp/ladix run /tmp/n3.ladix
# stderr: Ошибка в строке 3, колонка ...:
#         шаг 'A': срок без исполнитель не имеет эффекта
# код 1
```

`checkProcessDecl` п.3 (§PM-4): если `Attrs.DeadlinePos.Line != 0` И `Attrs.AssigneePos.Line == 0` → `semErr(step.Attrs.DeadlinePos, "шаг 'A': срок без исполнитель не имеет эффекта")` (§11.4). Позиция указывает на строку `срок:`. `DurationLit` (`2дн`) тут **не** даёт ошибку «литерал длительности» — атрибут `срок:` семпроходом не обходится (D-11); ошибку даёт **отсутствие** `исполнитель:`.

### 5.4. Другие негативы из §PM-7 (для табличных тестов; не выводятся отдельно здесь)

- **Парсер:** дубль атрибута `исполнитель:`/`срок:` → `атрибут 'исполнитель' уже задан` (D-8: `p.error(...)+break`, **не** `continue` — строго как `parseMetricDecl` parse_decl.go:129-134; `msgDuplicateAttr` переиспользуется); `после` без имени (`шаг A после :`) → `SE-EXPECTED` от `expect(IDENT, "имя шага")`, `After` пуст, восстановление — synchronize.
- **Семпроход (§PM-6.B):** дубль имени шага → `шаг 'A' уже объявлен в строке N`; `после B` на неизвестный шаг → `шаг 'A' после 'B', но шаг 'B' не объявлен`; `после B` вперёд/на себя → `шаг 'A' после 'B', но 'B' объявлен позже`; действие вне шага (top-level `присвоить x = 1`) → `действие 'присвоить' допустимо только в шаге процесса`; `вернуть` в шаге → `'вернуть' допустимо только внутри функции; в шаге процесса используйте 'присвоить'`; имя процесса = ранее объявленная метрика → `'выручка_месяца' уже объявлено в строке N` (D-5, общий namespace).
- **Семпроход — арность/тип `запустить процесс` (§PM-6.C, `checkRunProcess`):** `запустить процесс Q()` (Q не объявлен) → `процесс 'Q' не объявлен`; `запустить процесс f()` (f — функция) → `'f' — функция, не процесс`; `запустить процесс P()` при `процесс P(x)` → `'P' принимает 1 аргументов, передано 0` (формат как у функций, §8.3); P — метрика/источник → `'P' — не процесс`.

## 6. Чек-лист приёмки по user stories

- **US1 (P1, объявить + статически проверить)** — целевой `онбординг.ladix` (§2) парсится с **0** ошибок и проходит семантику чисто (SC-004; позитивная таблица SC-006); структурные нарушения → `ОшибкаРазбора` (§PM-6.A, SC-001: дубль атрибута, пустой блок, не-шаг в блоке процесса); семантически разрешимые → `СемантическаяОшибка` (§PM-6.B, SC-002: дубль шага, `после` вперёд/неизвестный, `срок`-без-`исполнитель`, действие вне шага, `вернуть` в шаге); все с точной позицией (§PM-6, конституция VIII).
- **US2 (P1, действия в шаге)** — `присвоить`/`вызвать`/`уведомить` **в шаге** проходят семантику (контекст-гард `inStep=true`, D-2/D-11); **вне шага** → `действие '<имя>' допустимо только в шаге процесса` (SC-002). Исполнение — **рантайм-deferred** (§PM-5, недостижимо в 005: тело шага не исполняется).
- **US3 (P1, запустить процесс)** — `запустить процесс P(args)` резолвит имя (только против процессов, D-10) и арность (§7.4, `checkRunProcess`, §PM-6.C, SC-003); семантика чиста при сходящейся арности; `ladix run` онбординга → **код 1** рантайм на `запустить процесс` с текстом `конструкция запустить процесс не поддерживается в этой версии` (§4, SC-004).
- **Граница (§PM-0/§PM-8)** — `выручка.ladix` всё ещё не парсится целиком: падает на `неожиданный токен 'когда'` (сдвиг с `'процесс'`), код 1 (SC-005, регресс §PM-3); процессные builtins (`статус_процесса`/…) остаются deferred-builtins (D-9); `internal/engine`/`store`/lifecycle НЕ заведены; новый тип ошибки НЕ введён (D-3).
- **Гейты (SC-007)** — `go build`/`go vet`/`gofmt -l`/`go test ./...`/`-race` зелёные, включая **все** регрессы 001/002/003/004.
