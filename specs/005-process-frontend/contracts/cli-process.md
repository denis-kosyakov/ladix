# Contract: CLI и приёмка слоя процессов (§PM-7)

**Feature**: 005-process-frontend | **Источники**: docs/process-model.md §PM-7 (приёмочная таблица),
§PM-5 (граница deferred / поведение `ladix run`), §PM-3 (регрессы парсера); spec.md
FR-021/FR-023/FR-025/FR-026/FR-027, SC-004/SC-005/SC-006/SC-007. Решения **D-6** (снять cut только с
`KW_PROCESS`; `KW_WHEN`/`KW_VALUE`/`LBRACE`/`RBRACE` остаются отвергаемыми), **D-7** (новой CLI-команды
**нет**), **D-9** (процессные builtins остаются deferred), **D-10** (запуск: семпроход резолвит,
рантайм deferred).

**005 — чистый фронтенд.** CLI **не расширяется** (D-7): нет `ladix check`/`start`/`complete`/`serve`/
`tasks`/`emit` (это 006). Приёмка опирается на существующий `ladix run` (003/004,
`src/cmd/ladix/main.go`) и на Go-тесты парсера/семпрохода. Единственная **наблюдаемая рантайм-граница
005** = top-level `запустить процесс` (`ladix run → код 1`, §PM-5). Golden-чисел нет — фронтенд ничего
не вычисляет (§PM-7); приёмка = «парсится? + семантика чиста? + узлы/диагностика?» + три CLI-кода.

## CP-1. CLI без изменений (D-7)

- **Команды CLI 005 = команды 004:** `ladix run [--max-depth N] <файл>` и
  `ladix metric [--max-depth N] <файл> <имя>` (диспетчер `realMain`, `main.go:35`). Строка `usage`
  (`main.go:31`) **не меняется**.
- `ladix check` **не вводится** (D-7, FR-026): парс/семантику покрывают Go-тесты (CP-5);
  `ladix run` процессной программы демонстрирует границу deferred. Аддитивно `check` можно добавить
  позже без правки фронтенда.
- Подкоманды движка процессов (`start`/`complete`/`serve`/`tasks`/`emit`) — **не в 005** (006); попадают
  в `default` диспетчера → `usage`, exit 2 (как сейчас).
- `ladix metric` процессную программу **не** касается: метрик-онли фикстуры; если файл содержит
  `процесс` — после 005 он распарсится, но `metric`-ветвь ищет именованную метрику (§SM-9.D), а не
  исполняет процесс — поведение 004 не меняется.

## CP-2. Поведение `ladix run` процессной программы (контракт демо, §PM-5)

Конвейер `runFile` (`main.go:140`): `os.ReadFile` → лексер → парсер → (под `guard`) `Run(prog)`,
где `Run` (`interpreter.go:78`) сперва вызывает `Analyze` (семпроход), затем исполняет top-level
`Statement`-ы сверху вниз. **`ProcessDecl` — `Decl`, не `Statement`** → цикл `Run` его **пропускает**
(`interpreter.go:88-91`), **тело шага в рантайме 005 не исполняется** (§PM-5).

| Этап | Поведение для процессной программы | Код на этом этапе |
|---|---|---|
| **1. Парс** | чисто — `процесс`/`шаг`/`после`/`исполнитель`/`срок`/действия/`запустить процесс` парсятся (§PM-3) | (если ошибка парса → exit 1) |
| **2. Семантика** (`Analyze` внутри `Run`) | чисто — процесс валиден: уник шагов, `после` ок, `срок`+`исполнитель` ок; `запустить процесс` арность ок; действия **в шаге** не ошибаются | (если ошибка сем → exit 1) |
| **3. Рантайм** | top-level операторы исполняются; объявление процесса **пропускается**. Первая исполняемая процесс-конструкция (top-level `запустить процесс`) → рантайм-deferred | см. CP-3 |

**Два сценария рантайма (§PM-5, FR-025/FR-023):**
- **Есть top-level `запустить процесс`** → `expr.go:49` → `СемантическаяОшибка`
  `конструкция запустить процесс не поддерживается в этой версии` (двухстрочный формат,
  [diagnostics-process](./diagnostics-process.md) §DP-4) в stderr, выполнение останавливается → **код 1**.
- **Процесс только объявлен** (нет top-level `запустить процесс`) → рантайм отрабатывает без ошибок
  → **код 0** (FR-023).

> **Недостижимая в 005 рантайм-граница.** Действия в теле шага (`stmt.go:64`,
> `присвоить`/`вызвать`/`уведомить` → deferred) **недостижимы** через `ladix run` в 005 (тело шага не
> исполняется, §PM-5). Поэтому контракт **не** предлагает CLI-тест «действие в шаге → рантайм-deferred»
> — он недостижим до движка 006. Единственная наблюдаемая рантайм-граница — top-level
> `запустить процесс`.

## CP-3. Коды возврата `ladix run` (процессная программа)

| Код | Условие |
|---|---|
| **0** | парс чисто + семантика чиста + рантайм чист (процесс **только объявлен**, без top-level `запустить процесс`) — FR-023 |
| **1** | штатные ошибки Ladix: непустой `errList` (лекс/синт); `Analyze`-ошибка (§PM-6.B/C); **рантайм-deferred** `конструкция запустить процесс не поддерживается в этой версии` на top-level `запустить процесс` (наблюдаемая граница 005); Go-паника, пойманная `guard` → `внутренняя ошибка интерпретатора` |
| **2** | ошибки использования: файл не читается (`os.ReadFile` ошибка → `ladix: не удалось прочитать файл %q`); `--max-depth` без значения/неверное; неизвестный флаг; нет позиционного |

- **recover-барьер** — тот же `guard(stderr, fn)` (`main.go:201`): этап `NewInterpreter`+`Run`
  (включая `Analyze`) обёрнут; чтение файла/лексер/парсер — вне барьера. Изменений в `main.go`
  для 005 **нет**.
- **Куда печатается:** `печать(...)` top-level → stdout; все ошибки (синтаксис/семантика/рантайм/
  паника) → stderr через `fmt.Fprintln`.

## CP-4. Целевой `examples/онбординг.ladix` (флагман-демо, §PM-7/§PM-5/D-9)

**Целевой вид файла после правки** (убрана последняя строка с `статус_процесса`, §PM-7):

```ladix
# Процесс адаптации нового сотрудника: автоматический шаг + два человеческих
процесс онбординг(сотрудник):
    шаг завести_доступы:
        присвоить имя = сотрудник                 # переменная процесса
        уведомить ИТ("создать учётку для " + сотрудник)   # авто-эффект (стаб-лог)
    шаг провести_встречу после завести_доступы:
        исполнитель: "руководитель"
        срок:        3дн
    шаг закрыть_адаптацию после провести_встречу:
        исполнитель: "HR"
        срок:        5дн

# Запуск из императивного кода: захватываем ID инстанса (исполнение — рантайм-deferred до 006)
пусть id = запустить процесс онбординг("Петров")
печать("запущен онбординг, id:", id)
```

- **Изменение против текущего файла** (`examples/онбординг.ladix`): убрана последняя строка
  `печать("статус:", статус_процесса(id))` — `статус_процесса` остаётся deferred-builtin (D-9),
  её вызов сделал бы семантику не чистой (нарушил бы SC-004). Это **синк моей зоны** (правка демо).
- **Приёмка демо (SC-004):** `онбординг.ladix` разбирается с **нулём** ошибок, проходит семантику
  чисто, `ladix run` даёт **код 1** в рантайме на `запустить процесс` (наблюдаемая граница 005):
  - AST: `ProcessDecl{Name:онбординг, Params:[сотрудник], Steps:[3 шага]}` + top-level
    `LetStmt{Value: RunProcessExpr{Process:онбординг, Args:[StringLit]}}` + `ExpressionStmt(печать)`.
  - Шаг `завести_доступы`: `Body:[AssignAction, NotifyAction]`, `Assignee:nil`, `Deadline:nil`.
  - Шаг `провести_встречу`: `After:[завести_доступы]`, `Assignee:StringLit`, `Deadline:DurationLit`,
    `Attrs:{AssigneePos≠0, DeadlinePos≠0}`, `Body:nil` (`срок: 3дн` не обходится, D-11 → `DurationLit`
    в `срок:` не упирается в семантический deferred).
  - Шаг `закрыть_адаптацию`: `After:[провести_встречу]`, аналогично.
  - Семантика чиста: уник шагов; `после` назад (`завести_доступы` < `провести_встречу` <
    `закрыть_адаптацию`); `срок`+`исполнитель` у обоих человеческих шагов; `запустить процесс
    онбординг("Петров")` — арность 1==1; действия `присвоить`/`уведомить` в шаге → ok.
- **Полный человеко-в-цикле прогон** (`статус_процесса`, `ladix complete`) возвращается в 006.

## CP-5. Приёмочные сценарии (контракт; зеркало §PM-7 для табличных тестов)

Golden-чисел нет (§PM-7). Приёмка = парсится? + семантика чиста? + точные узлы/диагностика.
Кейсы — для табличных тестов **парсера** (`parser/`) и **семпрохода** (`eval/`), плюс CLI-кейс
демо через `realMain`.

### CP-5.1. Позитив (парс + семантика чисто, SC-006)

| # | Исходник | AST (каноническая форма) | Семантика |
|---|---|---|---|
| P1 | `процесс P:`⏎`  шаг A:`⏎`    печать(1)` | `ProcessDecl{Name:P, Params:nil, Steps:[StepDecl{Name:A, Assignee:nil, Deadline:nil, Body:[ExpressionStmt]}]}` | чисто |
| P2 | `процесс P(x):`⏎`  шаг A:`⏎`    исполнитель: "и"`⏎`    срок: 2дн` | `StepDecl{Assignee:StringLit, Deadline:DurationLit, Attrs:{AssigneePos≠0, DeadlinePos≠0}, Body:nil}` | чисто (`DurationLit` в `срок:` **не обходится**, D-11) |
| P3 | `процесс P:`⏎`  шаг A:`⏎`    присвоить y = 1`⏎`  шаг B после A:`⏎`    исполнитель: "и"` | `Steps:[A{Body:[AssignAction]}, B{After:[A], Assignee:StringLit}]` | чисто (действие в шаге ok; `после A` назад; `исполнитель` есть) |
| P4 | `пусть id = запустить процесс P("Петров")` (P объявлен, 1 параметр) | `LetStmt{Value: RunProcessExpr{Process:P, Args:[StringLit]}}` | чисто (арность 1==1) |
| P5 | `онбординг.ladix` (CP-4) | `ProcessDecl{онбординг(сотрудник), 3 шага}` + top-level `пусть id = запустить процесс…` + `печать` | **чисто** (флагман-демо, SC-004) |

| N7 | `процесс P:`⏎`  шаг A после B:`⏎`    печать(1)`⏎`  шаг B:`⏎`    печать(2)` | семпроход | `шаг 'A' после 'B', но 'B' объявлен позже` (§DP-2) |

### CP-5.4. CLI-уровень (через `realMain`, конвенции 003/004)

- **Демо-кейс (SC-004 на CLI):** `realMain([]string{"run", examplePath("онбординг.ladix")}, &out, &errBuf)`
  ждёт `code == 1` и `errBuf.String()` содержит двухстрочную
  `конструкция запустить процесс не поддерживается в этой версии` (точная вторая строка из §DP-4) —
  парс+сем чисты, рантайм-граница на `запустить процесс`.
- **Регресс-кейс (SC-005 на CLI):** `realMain([]string{"run", examplePath("выручка.ladix")}, …)`
  ждёт `code == 1` и парс-ошибку `неожиданный токен 'когда'` (`golden_test.go` стиль).
- **Код 0 (FR-023):** программа, объявляющая процесс **без** top-level `запустить процесс`
  → `code == 0` (рантайм отрабатывает, объявление процесса пропускается).
- **Конвенции:** белый ящик `package main`, `realMain([]string{"run", …}, &out, &errBuf)` с
  `*bytes.Buffer`, сверка тройки **код / байты stdout / байты stderr** байт-в-байт (как `golden_test.go`).

## CP-6. Синк `examples/MANIFEST.md` (моя зона, §PM-7 нота)

Текущая **совмещённая** строка (`MANIFEST.md:56-60`, абзац :6-7) утверждает, что `выручка.ladix`
**и** `онбординг.ladix` завершаются кодом 1 «уже на стадии парсера (неожиданный токен
`источник`/`процесс`)». После 005 **расщепить**:
- (а) `онбординг.ladix` теперь **парсится и проходит семантику чисто**; `ladix run` даёт код 1 в
  **рантайме** на `запустить процесс` (исполнение — 006);
- (б) `выручка.ladix` **остаётся** парс-ошибкой код 1, но ожидаемый токен сдвигается
  `источник`/`процесс` → **`когда`** (триггеры — 007, регресс §PM-3).

Это **не** трогает функциональный чеклист (обе — демо, не golden; §PM-7).

## CP-7. Границы (§PM-0/§PM-8)

- CLI **не** расширяется: нет `check`/`start`/`complete`/`serve`/`tasks`/`emit`, нет `--db`, нет
  персиста, нет `internal/engine`/`internal/store` (D-7, 006).
- `ladix run` процессной программы **не исполняет** тело шага (рантайм-deferred недостижим в 005,
  §PM-5); единственная наблюдаемая рантайм-граница — top-level `запустить процесс`.
- `examples/выручка.ladix` целиком в 005 **не парсится** (падает на `когда`, ОЖИДАЕМО, D-6, 007).
- Процессные builtins (`статус_процесса`/…) остаются deferred-builtins (D-9) — демо их **не** вызывает.
- Go-build/vet/gofmt/test чисто (SC-007); все 001–004 тесты зелёные (FR-027).
