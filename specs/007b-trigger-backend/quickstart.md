**Feature**: 007b-trigger-backend | **Date**: 2026-06-13 | **Plan**: [plan.md](./plan.md)

> Как собрать, прогнать гейты качества и проверить приёмку US1…US5. Тесты демона используют

## Гейты качества (SC-010, прогонять на каждой фазе)

```bash
cd src
go build ./...        # чисто
go vet ./...          # без замечаний
gofmt -l .            # пусто (без правок)
```

## Детерминированные фикстуры (`src/cmd/ladix/testdata/`)

**НЕ переиспользовать `выручка.ladix`** — он оконный по дате (`период:`/`по_дате:`), вывод зависит от
`сегодня()`, недетерминирован для golden. Делать отдельные фикстуры без окна периода:

- `metric_edge.ladix` + `metric_edge.json` — источник + метрика без `период:` + метрика-триггер
  (`когда метрика M < порог: запустить процесс P()`). Источник управляем тестом (между тиками меняем
  данные → метрика пересекает порог).
- `schedule.ladix` — `когда расписание каждые 1дн:` / `каждые 1мес:` / `в "09:30":` + тело.
- `event.ladix` — `когда событие заявка_создана:` + тело с `событие.клиент`.
- негативная: `bad_time.ladix` — `когда расписание в "25:99":` (→ SE-TIME-FORMAT, exit 1).

Часы: тесты собирают `eval.NewInterpreter(..., FixedClock{дата})` и инъектируют управляемый
`engine.Clock` в `Daemon`; наступление тиков моделируется прямым `d.tick()` с продвижением часов.

## Сценарий US1 — edge ложь→истина ровно один раз + прайминг + рестарт (P1)

```
тик1 (условие ложно): база записана «ложь», тело НЕ исполнено, процесс не создан  (прайминг/edge)
тик2 (условие истинно, источник изменён): persist «истина» ДО тела → 1 срабатывание, процесс создан
тик3 (условие истинно): НЕТ повторного срабатывания (нет перехода)
рестарт демона на той же БД: прайминг НЕ повторяется (база из trigger_state)
мутация: метрика на тике2 — свежий снимок (ResetRunState активен), не снимок тика1
```
Проверяет FR-005/006/007/008/010, SC-001/002. Прогнать на Memory И SQLite (durability — под SQLite).

## Сценарий US2 — грациозная остановка + изоляция сбоя (P1)

```
Run(ctx) + cancel()/SIGINT: демон выходит код 0, тикер-горутина освобождена (счётчик горутин до/после)
тик с двумя триггерами, первый паникует: сбой логирован+изолирован, второй исполнен, демон жив, тикает дальше
сбойный триггер (база сдвинута до тела): следующий тик НЕ зацикливается на повторном ложь→истина
```
Проверяет FR-003/004/008, SC-007.

## Сценарий US3 — расписание `каждые` + `в "ЧЧ:ММ"` + зажим + негатив (P1)

```
каждые 1дн: срабатывает раз/сутки от якоря; LastFire = факт (дрейф не копится)
каждые 1мес от 31 января: следующее срабатывание 28 (29 в високосный) февраля — ЗАЖИМ конца месяца
в "09:30": старт после 09:30 → срабатывание в день старта; повтор в тот же день → 0; далее на след. сутках
в "25:99" / "9:05" / "09:5": SE-TIME-FORMAT при подъёме демона, exit 1
в "09:05" / "14:30": принимаются
```
Проверяет FR-011/012/013/014, SC-004/005. Зажим — ключевой кейс (`shiftEvery` мес, R-6/calendar.go).

## Сценарий US4 — emit → событие FIFO at-least-once (P1)

```
ladix emit заявка_создана '{"клиент":"ООО"}' --db ...: exit 0, событие в очереди «не обработано»
демон тик drainEvents: FIFO, payloadJSON→Запись, событие.клиент="ООО", тело исполнено, MarkEventProcessed ПОСЛЕ тела
два emit подряд: обработаны в порядке поступления (FIFO по CreatedAt)
emit без триггеров: помечено processed + лог «событие <имя> без триггеров»
краш между телом и пометкой: переобработка на следующем старте (at-least-once)
```
Проверяет FR-015/016/017, SC-003/006. Кросс-процесс: `emit` пишет, `serve` читает (WAL+busy_timeout).

## Сценарий US5 — рестарт-скан + дрейф (P2)

```
БД с инстансом «выполняется» + валидный CurrentStep: подъём serve → реактивация (advance) до ожидания/терминала
тот же инстанс, CurrentStep отсутствует в ProcessDecl (дрейф): лог расхождения, инстанс залип, демон стартует штатно
инстансы «ожидает»: рестарт-скан НЕ трогает
```
Проверяет FR-019/020/022 (седьмой метод `ListInstancesByStatus`, deviation), SC-008.

## Паритет Store (SC-009)

Единый контрактный table-driven набор (store-methods.md) прогоняется на `*MemoryStore` И
`*SQLiteStore`: 7 методов, идентичное поведение (load-miss→ErrTriggerStateNotFound, round-trip,
upsert, FIFO, mark идемпотентно, листинг по статусу). 8 методов и 3 таблицы 006 не тронуты.

## Ручная демонстрация (под SQLite, реальный таймер)

```bash
cd src
go build -o /tmp/ladix ./cmd/ladix
/tmp/ladix serve cmd/ladix/testdata/event.ladix --db /tmp/t.db --interval 2s &   # демон
/tmp/ladix emit заявка_создана '{"клиент":"ООО"}' --db /tmp/t.db                  # эмит
# на ближайшем тике демон разберёт событие, привяжет событие.клиент, исполнит тело
kill -INT %1                                                                       # грациозная остановка
```
