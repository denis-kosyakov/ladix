# Feature Specification: Входящие события (HTTP-приём)

**Feature Branch**: `025-inbound-events`

**Created**: 2026-06-20

**Status**: Draft

**Input**: Трек B «Входящие события» — HTTP-приём событий по сети внутри демона `serve`. Источник истины и все архитектурные решения залочены в `docs/inbound-events-model.md` §IE-0..§IE-8 (таблица D-IE-1..D-IE-10).

**Anchor**: `docs/inbound-events-model.md` §IE-0..§IE-8

## User Scenarios & Testing *(mandatory)*

До этой фичи единственный продюсер событий — CLI `ladix emit <имя> [json]`; сеть закрыта. Внешняя система Уклада (или любой источник) не может уведомить процессный движок о факте. Трек B добавляет **входящую** сторону: сетевого продюсера в уже существующую durable-очередь `events`, не меняя ни фронтенд (`когда событие`, грамматику), ни контракт очереди, ни фазу обработки `drainEvents`.

### User Story 1 — Приём события по сети и срабатывание триггера (Priority: P1)

Оператор запускает демон с сетевым приёмником; внешняя система шлёт HTTP POST с именем события и payload; на ближайшем тике тело соответствующего триггера `когда событие E { … }` исполняется ровно так же, как если бы событие было поставлено локальной командой `emit`.

**Why this priority**: Это ядро ценности трека — «`emit` по сети». Без него внешние системы не могут запускать процессы. Реализованная в одиночку, эта история уже даёт работающий продукт (приём + асинхронное исполнение).

**Independent Test**: Поднять `serve … --listen 127.0.0.1:PORT --db D`; отправить `POST /events/<имя>` с JSON-телом; убедиться, что ответ — `202` с ack-строкой, событие попало в durable-очередь, а на ближайшем тике тело триггера сработало с теми же значениями, что и при `emit <имя> <json>`.

**Acceptance Scenarios**:

1. **Given** запущенный `serve` с `--listen` и `--db`, и в исходнике есть `когда событие падение_выручки { … }`, **When** внешняя система шлёт `POST /events/падение_выручки` (имя percent-кодировано) с телом `{"сумма": 100}`, **Then** ответ `202` с телом `событие e-NNNNNN 'падение_выручки' принято`, и на ближайшем тике тело триггера исполняется с записью, построенной из payload.
2. **Given** то же событие, отправленное по сети и через `emit`, **When** оба обработаны, **Then** результат исполнения тела (значения записи `событие`, эффекты) **неразличим** — путь приёма не влияет на семантику ниже точки минта.
3. **Given** `POST` с **невалидным** JSON в теле, **When** запрос принят, **Then** ответ всё равно `202` (приём не валидирует JSON); на тике payload отображается в пустую запись, тело триггера всё равно исполняется, событие помечается обработанным.

### User Story 2 — Защита эндпоинта токеном (Priority: P2)

Поскольку эндпоинт **запускает бизнес-процессы по сети**, оператор должен иметь возможность включить простую аутентификацию: общий секрет в заголовке запроса. По умолчанию аутентификация выключена (локальная разработка, обратная совместимость).

**Why this priority**: Эндпоинт без защиты опасен на не-loopback адресе. Опциональный токен — минимальный барьер, аддитивный поверх P1; усиленная аутентификация (HMAC/mTLS) вынесена наружу.

**Independent Test**: Запустить `serve … --listen … --db … --token СЕКРЕТ`; POST без заголовка / с неверным заголовком → `401`; POST с верным заголовком → `202`. Без `--token` любой POST → `202`.

**Acceptance Scenarios**:

1. **Given** `serve` с `--token СЕКРЕТ`, **When** POST приходит без заголовка токена или с неверным значением, **Then** ответ `401` с телом `ladix: неверный токен`, событие НЕ ставится в очередь.
2. **Given** `serve` с `--token СЕКРЕТ`, **When** POST приходит с верным заголовком, **Then** ответ `202`, событие поставлено в очередь.
3. **Given** `serve` без `--token`, **When** приходит любой корректный POST, **Then** ответ `202` (аутентификация выключена).

### User Story 3 — Безопасные дефолты и детерминированная диагностика запуска (Priority: P3)

Оператор получает предсказуемые ошибки окружения и предупреждения о небезопасной конфигурации **до** того, как приёмник начнёт принимать события: durability-граница (`--listen` требует `--db`), занятый порт, не-loopback без токена.

**Why this priority**: Защищает обещанную гарантию at-least-once и предотвращает «тихую потерю» событий из-за неверной конфигурации. Это барьеры приёмки, а не основной поток.

**Independent Test**: `serve … --listen …` без `--db` → выход с кодом `2` и сообщением; занятый порт → выход `2` с сообщением; не-loopback host без `--token` → предупреждение в stderr, демон всё равно стартует.

**Acceptance Scenarios**:

1. **Given** команда `serve … --listen host:port` **без** `--db`, **When** она запускается, **Then** процесс завершается с кодом `2` и сообщением `ladix: --listen требует --db` — **до** попытки открыть сокет.
2. **Given** порт уже занят, **When** `serve … --listen host:port --db D` пытается открыть сокет, **Then** процесс завершается с кодом `2` и сообщением `ladix: не удалось открыть сокет '<host:port>': <причина>`.
3. **Given** `--listen` на не-loopback адресе **без** `--token`, **When** демон стартует, **Then** в stderr печатается предупреждение об отсутствии аутентификации, но демон **не блокируется** и работает.

### Edge Cases

- **Метод не POST** (`GET /events/x`) → `405` с телом `ladix: метод не поддерживается, только POST`.
- **Пустое имя** (`POST /events/` без сегмента) → `400` с телом `ladix: пустое имя события`.
- **Сбой хранилища при постановке в очередь** → `500` с телом `ladix: сбой хранилища`; событие НЕ теряется молча (ответ ≠ 202).
- **Имя в иной нормализации Unicode** (NFD вместо NFC) → даёт другие байты → событие принято (`202`) и поставлено в очередь, но на тике уходит в ветку «без триггеров» и молча помечается обработанным (граница байтового матча, нормализация отложена).
- **Остановка демона с in-flight POST**: события, уже принятые (`202`), не теряются — приёмник дослуживает in-flight запросы и завершается до закрытия хранилища; принятые события дренятся при следующем старте.
- **`serve` без `--listen`**: сетевой приёмник не стартует совсем; поведение байт-идентично текущему (нулевой регресс).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-IE-1 (нулевой регресс)**: `serve` БЕЗ `--listen` ОБЯЗАН вести себя байт-идентично текущему — сетевой сервер не стартует, сокет не открывается, дополнительные горутины не создаются.
- **FR-IE-2 (изоляция движка)**: обработчик приёма ОБЯЗАН касаться только хранилища и часов; он НЕ ДОЛЖЕН вызывать или зависеть от движка процессов/интерпретатора (они не потокобезопасны).
- **FR-IE-3 (неразличимость источников)**: событие, принятое по сети, и событие, поставленное командой `emit`, ОБЯЗАНЫ быть неразличимы ниже точки минта (одинаковая запись события, одинаковый путь обработки, одинаковая семантика тела триггера). Имя события ОБЯЗАНО корректно проходить URL-декодирование, включая кириллицу (percent-кодирование клиентом).
- **FR-IE-4 (durability-граница)**: `--listen` без `--db` ОБЯЗАН завершиться ошибкой использования (код `2`) с явным сообщением; проверка выполняется ДО открытия сокета.
- **FR-IE-5 (ошибка привязки)**: сбой открытия сокета (занятый порт, нет прав) ОБЯЗАН завершиться кодом `2` с детерминированным сообщением, отражающим адрес и причину.
- **FR-IE-6 (at-least-once и порядок остановки)**: ответ `202` возвращается ТОЛЬКО после успешной постановки события в очередь; сбой хранилища даёт `500`, событие не теряется молча. При остановке демона приёмник ОБЯЗАН прекратить приём, дослужить in-flight запросы и завершиться СТРОГО ДО закрытия хранилища (in-flight запрос не должен писать в закрытое соединение).
- **FR-IE-7 (толерантность к payload)**: невалидный JSON в теле НЕ ДОЛЖЕН ронять приём — событие принимается (`202`) с сырым телом; валидацию выполняет фаза обработки (пустая запись + лог), тело триггера всё равно исполняется.
- **FR-IE-8 (нет утечки горутин)**: после остановки демона (сигнал/отмена) серверная горутина ОБЯЗАНА быть завершена и присоединена до возврата из пути `serve`; число горутин возвращается к исходному уровню.
- **FR-IE-9 (опциональная аутентификация)**: при заданном секрете обработчик ОБЯЗАН сверять заголовок запроса с секретом константно-временным сравнением; несовпадение/отсутствие → `401`. По умолчанию аутентификация выключена (любой POST → `202`).
- **FR-IE-10 (контракт метода и имени)**: не-POST метод → `405`; пустое имя события → `400`. Коды и тексты ответов фиксированы (см. Key Entities → HTTP-контракт).
- **FR-IE-11 (детерминизм времени)**: время создания принятого события ОБЯЗАНО минтиться часами демона (инъектируемыми), а не временем клиента и не прямым системным временем — иначе теряется детерминизм тестов. FIFO-порядок держится монотонным счётчиком идентификаторов, а не временем.

### Key Entities

- **Событие (Event)**: единица очереди — идентификатор `e-NNNNNN` (монотонный счётчик), имя (Unicode-идентификатор, матч строго байтовый), сырой payload-JSON (как есть), время создания (часы демона), признак «обработано». Переиспользуется без изменений; сетевой приём — лишь новый продюсер.
- **HTTP-контракт приёма**:
  - `POST /events/{имя}`, тело — сырой JSON (или пусто); `{имя}` = последний сегмент пути, URL-декодируется.
  - Ответы: `202` (`событие e-NNNNNN '<имя>' принято`), `400` (`ladix: пустое имя события`), `401` (`ladix: неверный токен`), `405` (`ladix: метод не поддерживается, только POST`), `500` (`ladix: сбой хранилища`). Все тексты — на русском, дословно.
- **Конфигурация приёмника**: `--listen host:port` (opt-in), `--token СЕКРЕТ` (опц., env-двойник `LADIX_LISTEN_TOKEN`), заголовок токена `X-Ladix-Token`.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Внешняя система может вызвать срабатывание триггера процесса по сети без доступа к файловой системе хоста — отправкой одного HTTP POST.
- **SC-002**: Событие, принятое по сети, и событие из `emit` дают идентичный наблюдаемый результат исполнения тела триггера (100% совпадение в golden-проверке).
- **SC-003**: Включение приёмника (`--listen`) не меняет ни одного существующего сценария `serve` — все существующие проверки демона остаются зелёными без правки их сути.
- **SC-004**: Ни одно принятое (ответ `202`) событие не теряется при штатной остановке демона; число горутин после остановки возвращается к исходному (нет утечки).
- **SC-005**: Неверная конфигурация (нет `--db`, занятый порт) даёт предсказуемый код выхода `2` с понятным сообщением; небезопасная конфигурация (не-loopback без токена) предупреждается, но не блокирует.
- **SC-006**: При включённом токене ни один запрос без верного секрета не ставит событие в очередь.

## Assumptions

- Имя заголовка токена — `X-Ladix-Token`; env-двойник секрета — `LADIX_LISTEN_TOKEN` (зафиксировано в задаче kickoff; TODO-FACT якоря разрешён).
- Лексер НЕ нормализует Unicode-идентификаторы, поэтому байтовый матч имени корректен; клиент обязан слать имя в той же нормализации, что в исходнике (на практике NFC). Серверная NFC-нормализация отложена (тянет внешнюю зависимость; проект stdlib-only).
- Дедуп входящих (`Idempotency-Key`), push-пробуждение тика, машинно-читаемый `--json`-ответ, лимит размера тела и стабильные ключи триггеров — **вне scope** (бэклог, §IE-0).
- Гарантия доставки — at-least-once (зеркалит `emit`), без дедупа.
- Часы демона инъектируемы (прод — системные; тесты — фиксированные) для детерминизма.
