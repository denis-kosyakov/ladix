# Quickstart — Входящие события (HTTP-приём)

Ручной прогон сценария SC-001/SC-002 (внешний POST → тик → срабатывание триггера).

## 0. Сборка
```sh
cd src && go build -o /tmp/ladix ./cmd/ladix
```

## 1. Исходник с событийным триггером
`/tmp/демо.ladix`:
```
когда событие падение_выручки:
    печать("получено событие, сумма из payload")
```

## 2. Запуск демона с приёмником
```sh
/tmp/ladix serve /tmp/демо.ladix --db /tmp/demo.db --listen 127.0.0.1:8099 --interval 2s &
```
- loopback-адрес → предупреждения о токене нет.
- без `--db` была бы ошибка: `ladix: --listen требует --db` (exit 2).

## 3. Отправка события по сети
```sh
curl -X POST 127.0.0.1:8099/events/падение_выручки -d '{"сумма": 100}'
# → 202: событие e-000001 'падение_выручки' принято
```
Кириллическое имя curl percent-кодирует автоматически; сервер декодирует (`r.URL.Path`).

## 4. Ожидаемый результат
На ближайшем тике (≤ `--interval`) в stdout демона появляется вывод тела триггера. Событие в БД помечено `processed`.

## 5. Эквивалентность с `emit` (SC-002)
```sh
/tmp/ladix emit падение_выручки '{"сумма": 100}' --db /tmp/demo.db
# → событие e-NNNNNN 'падение_выручки' поставлено в очередь
```
Наблюдаемый результат исполнения тела триггера идентичен сетевому пути (различается только ack-текст: «поставлено в очередь» vs «принято»).

## 6. Auth (опционально)
```sh
/tmp/ladix serve /tmp/демо.ladix --db /tmp/demo.db --listen 127.0.0.1:8099 --token СЕКРЕТ &
curl -X POST 127.0.0.1:8099/events/падение_выручки -d '{}'                                  # → 401 ladix: неверный токен
curl -X POST -H 'X-Ladix-Token: СЕКРЕТ' 127.0.0.1:8099/events/падение_выручки -d '{}'       # → 202
```

## 7. Негативные коды
```sh
curl -X GET  127.0.0.1:8099/events/x   # → 405 ladix: метод не поддерживается, только POST
curl -X POST 127.0.0.1:8099/events/    # → 400 ladix: пустое имя события
```

## 8. Грациозная остановка
`Ctrl-C` (SIGINT) → приёмник прекращает приём, дослуживает in-flight, join-ится ДО закрытия БД; принятые события дренятся при следующем `serve`.
