# Contract — `ladix inspect` CLI (B6)

Источник: §AU-8, §AU-9, §AU-10.C, §AU-10.D, D-AU-8, D-AU-10. Все тексты — ДОСЛОВНО.

## Грамматика вызова

```
ladix inspect <id> [--db путь]
```
- `<id>` — единственный позиционный: id инстанса (`p-NNNNNN`).
- `--db путь` / `--db=путь` — путь к SQLite (дефолт `ladix.db`, D-AU-10; SQLite, НЕ Memory — без БД
  инстанса нет).

## Диспетчеризация

`cmd/ladix/main.go` switch: `case "inspect": return inspectMain(args[1:], stdout, stderr)`.
`usage`-строка (main.go) РАСШИРЯЕТСЯ записью inspect: `ladix inspect <id> [--db путь]`.

## Поведение (happy path)

1. Разбор флагов + позиционного `<id>`. Нет `<id>` → usage exit 2.
2. `openStore(dbPath)` → SQLite `ladix.db` по умолчанию (defer close). Ошибка открытия → exit 2.
3. `st.LoadInstance(id)`:
   - `errors.Is(err, store.ErrInstanceNotFound)` → CLI-ошибка `ladix: инстанс '<id>' не найден` exit 2.
   - иная ошибка → `ladix: сбой хранилища: …` (паритет listTasks) exit 2.
4. `st.ListTasksByInstance(id)` → история (открытые + завершённые, ID ASC).
5. Печать снимка + переменных + задач (§AU-10.D). exit 0.
6. Обёртка `guard(stderr, …)` (recover-барьер, конституция III). БЕЗ движка/eval. read-only (Store не пишется).

## stdout канон (§AU-10.D, exact-match; golden маскирует `<время>`)

Инстанс `ожидает` с переменной и одной открытой эскалированной задачей с дедлайном:
```
инстанс p-000001: процесс эскалация_плана, статус ожидает, шаг 'связаться_с_клиентом'
переменные:
  факт = 2500000
задачи:
  t-000001 шаг 'связаться_с_клиентом' → менеджер, срок до <время>, открыта, эскалирована
```

### Структура (дословно)
- **1-я строка**: `инстанс <ID>: процесс <ProcessName>, статус <Status>, шаг '<CurrentStep>'`
  (`<Status>` — рус. значение `inst.Status`, печатается как есть).
- **`переменные:`** + по строке `  <имя> = <value.String(v)>` (отступ 2 пробела, порядок
  `inst.Variables`). Пустые → только заголовок.
- **`задачи:`** + по строке (отступ 2 пробела, порядок `ListTasksByInstance`/ID ASC):
  `  <t-id> шаг '<StepName>' → <Assignee>[, срок до <время>], <открыта|завершена>[, эскалирована]`
  - `, срок до <время>` — только `Deadline != nil` (layout `2006-01-02 15:04`);
  - `, <открыта|завершена>` — `Status`;
  - `, эскалирована` — ТОЛЬКО `Escalated == true`.
  Пустой список задач → только заголовок.

### Варианты строк задач (для инверсионных замков)
| Задача | Строка |
|--------|--------|
| открыта, дедлайн, эскалирована | `  t-000001 шаг 'связаться_с_клиентом' → менеджер, срок до <время>, открыта, эскалирована` |
| открыта, дедлайн, НЕ эскалирована | `  t-000001 шаг 'связаться_с_клиентом' → менеджер, срок до <время>, открыта` |
| завершена, дедлайн | `  t-000001 шаг 'связаться_с_клиентом' → менеджер, срок до <время>, завершена` |
| открыта, БЕЗ дедлайна | `  t-000001 шаг 'связаться_с_клиентом' → менеджер, открыта` |

## CLI-ошибки (§AU-10.C — stderr, exit 2, ДОСЛОВНО)

| Триггер | Текст |
|---------|-------|
| неизвестный инстанс | `ladix: инстанс '<id>' не найден` |
| сбой хранилища | `ladix: сбой хранилища: <деталь>` (паритет listTasks) |
| отсутствует `<id>` | `usage`-строка (exit 2) |
| флаг без значения | `ladix: флаг --db требует значение` (паритет) |
| неизвестный флаг | `ladix: неизвестный флаг <флаг>` (паритет) |

## Exit-коды

| Код | Условие |
|-----|---------|
| 0 | снимок напечатан |
| 2 | CLI-ошибка (неизв.инстанс / usage / флаг / сбой хранилища / открытие БД) |
| 1 | непредвиденная Go-паника (guard-барьер → `внутренняя ошибка интерпретатора`) |

> exit 1 для inspect — только через guard-recover (паритет конституции III); штатных причин exit 1 нет
> (нет компиляции файла, в отличие от `start`).

## Инварианты контракта
- INV-1: `ProcessRuntime`=8 НЕ меняется; inspect не использует движок/eval.
- INV-2: дефолт Store = SQLite `ladix.db` через `openStore` (D-AU-10), НЕ Memory.
- INV-3: каталог `L=11`/`SE=14`/`eval=28` НЕ меняется (CLI-ошибки — stderr cmd).
- INV-4: единая `--db`/`openStore` без регресса остальных команд.
- INV-5: inspect read-only (Store не пишется).
- 0 новых зависимостей; детерминизм id/времени для golden.
