# Data Model: Харденинг числовых путей движка метрик (028)

Фича **не меняет** числовую модель — фиксирует её тестами и разводит имена двух
преобразователей. Семантика прежняя; меняется только покрытие + имена символов.

## Числовое значение

| Сущность | Go-тип | Диапазон / особенности | Печать (`value.String`) |
|---|---|---|---|
| **Целое** | `value.Целое{V int64}` | `[-9223372036854775808, 9223372036854775807]` (MinInt64..MaxInt64) | без `.0` (`2175`) |
| **Дробное** | `value.Дробное{V float64}` | IEEE-754; допускает `+Inf` / `-Inf` / `NaN` | конечное → с `.0` (`2175.0`); спец → `"+Inf"`/`"-Inf"`/`"NaN"` без `.0` (repr.go:80-82) |
| **Пусто (None)** | `value.Пусто{}` (`value.None`) | `TypeName() == "Пусто"` | `"пусто"` |

**Инварианты комбинирования (НЕ меняются, FR-012/FR-013):**

- Целое○Целое арифметика → проверка переполнения (`addInt64`/`subInt64`/`mulInt64`/
  `floorDivInt64`), overflow → `ОшибкаВыполнения` «переполнение целого числа».
- Деление `/` всегда → `Дробное`; знаменатель 0.0 → `ОшибкаВыполнения` «деление на ноль».
- Целочисленные `//`/`mod` с нулевым делителем → `ОшибкаВыполнения` «деление на ноль»;
  `MinInt64 // -1` → «переполнение целого числа» (явная ловушка).
- Промоушен к `Дробное` при смешанном Целое/Дробное; `±Inf`/`NaN` пропагируются IEEE-754
  без перехвата (без паники, без потери).
- Унарный `-` (`combineUnary`): `-MinInt64` → переполнение; `-Дробное` → корректно;
  не-число → `ОшибкаТипа`.
- Операнд `None`/`Пусто` в арифметике/унарном → `ОшибкаТипа` (не паника).
- **Никакого big-int. Никакого нового форматирования `±Inf`** сверх существующего
  декодирования (FR-013).

## Два преобразователя числа (асимметрия — намеренная)

| Атрибут | Строгий | Толерантный |
|---|---|---|
| **Имя (новое)** | `sourceNumberToValue` | `payloadNumberToValue` |
| **Имя (старое)** | `numberToValue` (метод) | `numberToValue` (функция) |
| **Файл** | `eval/source_loader.go:211` | `jsonval/decode.go:135` |
| **Форма** | метод `*Interpreter` (V: не глобал) | свободная чистая функция (V: без состояния) |
| **Подпись** | `(decl, idx, field, n json.Number) (value.Value, error)` | `(n json.Number) value.Value` |
| **Call-site** | `decodeValue` (source_loader.go:158) | `DecodeValue` (decode.go:81) |
| **Канон** | `§SM-9.B` | `§AU-5.2` |
| **Целое без `.eE` в int64** | `Целое` | `Целое` |
| **Целое вне int64** | **ошибка** «целое число вне диапазона» | **`Дробное`** (Float64 fallback; `1e20`-конечное или `±Inf`) |
| **Float overflow (`1e400`)** | **ошибка** (JSON err из `Float64`) | **`Дробное{±Inf}`** (err проигнорирован) |
| **Деградация в None** | возможна ошибка, не None | **никогда** не None |
| **Контракт** | целостность данных источника | надёжность доставки события |

### Переходы / поведенческие правила (характеризуемые тестами)

```
строгий sourceNumberToValue(n):
  n содержит '.'|'e'|'E' → Float64; err → JSON-ошибка §SM-9.B ; иначе Дробное
  иначе → Int64; err → ОшибкаВыполнения «… целое число вне диапазона» (A6) ; иначе Целое

толерантный payloadNumberToValue(n):
  n без '.'|'e'|'E' и Int64 ок → Целое
  иначе → Float64 (err игнор); → Дробное (±Inf при overflow, конечное иначе) (A7) — НИКОГДА None
```

Семантика обоих **байт-в-байт прежняя**; рейминг + перекрёстные комментарии (B3) только
делают асимметрию видимой в именах символов.
