## Сущности

### 1. Строка-explain срабатывания (эфемерная, не персистится)

Одна человеко-читаемая текстовая строка, выводимая в момент срабатывания триггера.

| Компонент | Источник | Представление |
|---|---|---|
| имя метрики `<имя>` | `spec.Metric.Name` | как есть |
| оператор `<оп>` | `BinOp.String()` (`ast/op.go:35`) | текст оператора (`<`, `>`, `<=`, …) |
| снимок `<снимок>` | вычисленное значение метрики (`metricVal`/`snapshot`) | `value.String(v)` (`value/repr.go:20`) — БЕЗ подчёркиваний |
| порог `<порог>` | `threshVal` (run: в области; serve: из расширенного возврата) | `value.String(v)` — БЕЗ подчёркиваний |
| итог | константа | `истина` |
| маркер ребра | только serve | `(ребро ложь→истина)` |

**Формы** (дословно §C-5.3 — см. contracts/explain-strings.md):
- run: `триггер '<имя> <оп> <порог>' сработал: <имя> = <снимок> (снимок) <оп> <порог> (порог) → истина`
- serve: `триггер '<имя> <оп> <порог>' сработал (ребро ложь→истина): <имя> = <снимок> (снимок) <оп> <порог> (порог) → истина`

**Жизненный цикл**: вычисляется в точке fire → выводится в канал (`i.out` для run, `d.logf` для
serve) ДО исполнения тела триггера → не хранится. Детерминирована (FR-013).

**Условие вывода**:
- run: `fired == true` (fire-if-true) — `eval/trigger_run.go:78-92`.
- serve: `fired := ts.LastBool!=nil && !*ts.LastBool && cur` (ребро) — `daemon/metrics.go:72`,
  печать в ветке `if fired {` (`:82`). На тике уже-истина (нет ребра) — НЕ выводится (FR-008).

### 2. Снимок условия метрики — расширенный возврат `EvalMetricCondition`

Свободная функция на `*Interpreter` (`eval/trigger_daemon.go:31`), НЕ метод интерфейса
`ProcessRuntime`.

| Возвращаемое | Было | Станет | Семантика |
|---|---|---|---|
| `cur` | `bool` | `bool` | текущий булев итог сравнения |
| `snapshot` | `value.Value` | `value.Value` | снимок значения метрики |
| **`threshold`** | — | **`value.Value` (НОВОЕ)** | значение порога; во всех ветках; «нет данных» → `value.None` |
| `ok` | `bool` | `bool` | вычислимость (computable) |
| `err` | `error` | `error` | ошибка вычисления |

**Инвариант возврата**: `threshold` возвращается во ВСЕХ ветках (success/пустая метрика/
несравнимые типы). В не-success → `value.None` (`Пусто`). Тогда `fired=false` → explain не
печатается (FR-007/FR-009).

**Call-site**: ЕДИНСТВЕННЫЙ — `daemon/metrics.go:39`. Деструктуризация обновляется на 5 значений.
run-путь порог НЕ берёт из этой функции (у него `threshVal` уже в области `runMetricTrigger`).

## Валидационные правила

- **VR-1**: `threshold` присутствует в каждом возврате `EvalMetricCondition` (тоталь-функция).
- **VR-2**: explain выводится строго ДО тела триггера на обоих путях.
- **VR-3**: serve-explain выводится ТОЛЬКО при ребре `ложь→истина`; не на тике уже-истина.
- **VR-4**: формат строк — точный exact-match §C-5.3; числа без подчёркиваний.
- **VR-5**: `ProcessRuntime`=8, `Store`=18, 0 новых кодов/зависимостей; прод `store`/`engine` дифф
  пустой.
