|---|---|---|

| serve | `d.logf` | `триггер '<имя> <оп> <порог>' сработал (ребро ложь→истина): <имя> = <снимок> (снимок) <оп> <порог> (порог) → истина` |

## Placeholder resolution

| Плейсхолдер | Источник | Замечание |

| маркер ребра | литерал (только serve) | `(ребро ложь→истина)` |

## Canonical examples (для golden-замков)

```
# run (i.out)
триггер 'выручка_30д < 3000000' сработал: выручка_30д = 2500000 (снимок) < 3000000 (порог) → истина

# serve (d.logf)
триггер 'выручка_30д < 3000000' сработал (ребро ложь→истина): выручка_30д = 2500000 (снимок) < 3000000 (порог) → истина
```

## Rules

- **R-фmt-1**: числа рендерятся через `value.String` → БЕЗ разделителей-подчёркиваний
  (`3000000`, не `3_000_000`).
- **R-fmt-2**: семантика различий путей: run = fire-if-true (без ребра); serve = edge
  (`ложь→истина`). Две разные формулировки — НЕ опечатка.
- **R-fmt-3**: строка одна (не двухстрочный канон §13 — explain не ошибка; см. plan Complexity
  Tracking).
- **R-fmt-4**: печать строго ДО тела триггера на обоих путях.
- **R-fmt-5**: детерминизм — тот же снимок/порог/оператор → та же строка (FR-013), пригодна для
  exact-match.

## Locks (new)

- `TestRunTriggerExplain` (eval) — exact-match run-формы в out при fire.
- `TestServeTriggerExplain` (daemon) — exact-match serve-формы в logf при ребре.
- Silence-замок — тик уже-истина (нет ребра) → новой строки НЕТ.
- Inversion — не протянуть порог → serve-строка неверна → краснеет.
