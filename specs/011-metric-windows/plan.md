## Summary

Фича A2 (срез M1 хартии v2) снимает ограничения §12 SPEC для метрик (окна) БЕЗ поломки v1: скользящее
окно `период: последние N <ед>` (`ед` ∈ `дн`/`нед`/`мес`) как полуинтервал `(сегодня − N ед, сегодня]` от
`eval.Clock` и «последний завершённый период» `период: прошлый|прошлая <день|неделя|месяц|квартал|год>` —
тот же календарный период со сдвигом −1. Метрика остаётся **скаляром по окну** (ряд значений ОТЛОЖЕН,
A2-1). **Механизм:** чистый фронтенд (спец-парс ветки `период:` + два листовых AST-узла + статическая
семантика) и вычислитель окна (`window.go` + аддитивно расширенный `value.Период`); при пяти календарных
адвербах v1 поведение и границы побайтно эквивалентны v1, `Store`/`ProcessRuntime`/экспорт `eval`/условие
и тело триггера — НЕ трогаются (A2-7). Окно считается от `i.now()` (заморожен на запуск), НЕ от
`time.Now()` — детерминизм.

- **V (детерминизм)** — окно строится исключительно от `i.now()` (заморожен на запуск через

- **VIII (A2-4 не дублируется)** — требование `по_дате` для оконной метрики покрыто СУЩЕСТВУЮЩЕЙ проверкой
