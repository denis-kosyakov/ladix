# Feature Specification: Окна метрик (период: последние N <ед> + прошлый <период>)

**Feature Branch**: `011-metric-windows`

**Created**: 2026-06-15

**Status**: Draft

**Input**: Снять ограничения §12 SPEC для метрик (окна) БЕЗ поломки v1: скользящее окно `период: последние N <ед>` (`ед` ∈ `дн`/`нед`/`мес`) как полуинтервал `(сегодня − N ед, сегодня]` от `eval.Clock`; «последний завершённый период» `период: прошлый|прошлая <день|неделя|месяц|квартал|год>` — тот же календарный период со сдвигом −1. Это срез M1-A2 хартии v2: реальная CSV-выгрузка (A1) кормит оконную метрику `выручка_30д`. Метрика остаётся **скаляром по окну** — ряд значений ОТЛОЖЕН.

> **Источник истины** — `docs/metric-windows-model.md` (§MW-0…§MW-13 + предрешённые развилки A2-1…A2-7). Спецификация выведена из якоря, не вводит требований сверх него и НЕ содержит NEEDS CLARIFICATION; при любом расхождении источников побеждает якорь. **Несущее свойство (инвариант 3 хартии §5):** изменение — чистый фронтенд (`парсер период:` + AST + семантика) и вычислитель окна (`window.go`/`value.Период`); все программы v1 остаются валидными (5 календарных периодов считаются ровно как раньше). `Store`, `ProcessRuntime`, экспорт `eval`, условие и тело триггера — НЕ трогаются (A2-7). Окно считается от `eval.Clock` (`i.now()`, заморожен на запуск), НЕ от `time.Now()` — детерминизм.

## User Scenarios & Testing *(mandatory)*

Действующие лица: **бизнес-автор** (объявляет оконную метрику над реальной выгрузкой), **аналитик** (сверяет скаляр оконной метрики с эталоном на фиксированную дату), **оператор** (прогоняет `ladix run`/`serve` поверх метрики со скользящим/завершённым окном). Система — **фронтенд + вычислитель окна Ladix**: разбор формы `период:`, построение окна от замороженного `Clock`, фильтрация записей по оси `по_дате`, диагностика недопустимых окон с позицией.

### User Story 1 — Скользящее окно «последние N <ед>» кормит метрику (Priority: P1)

Бизнес-автор объявляет метрику со скользящим окном `период: последние 30дн` поверх CSV-источника (A1) с осью `по_дате`. Метрика считает агрегат (например `сумма(сумма_заказа)`) только по записям, попавшим в окно `(сегодня − 30 дн, сегодня]` от замороженного `eval.Clock`, и даёт детерминированный скаляр. Единицы окна — `дн`, `нед`, `мес`. Сегодня это невозможно: `период:` принимает только пять адверб-констант v1 (`ежемесячно`…), а `последние 30дн` — два соседних токена `IDENT("последние")` + `DURATION("30дн")`, на которых generic-парсер падает.

**Why this priority**: Это срез Definition of Done вехи M1 (хартия §2/§4, A2-1): «`выручка_30д` = `последние 30дн` + `по_дате` на CSV-источнике даёт корректный скаляр на фикс-Clock». Без скользящего окна M1 не сдвигается — поэтому P1 и MVP фичи.

**Independent Test**: На фикс-`Clock{2026,6,15}` объявить источник с `по_дате` и метрику `период: последние 30дн`, разложить записи ровно по границам окна (`нижняя_искл`, `нижняя_искл+1`, `конец`, `конец+1`). Метрика даёт скаляр, агрегирующий ровно записи окна; запись на нижней границе исключена, на `сегодня` включена; exit 0. Проверяется парсером/семантикой/вычислителем окна, без участия движка процессов/Store.

**Acceptance Scenarios**:

1. **Given** метрика с `период: последние 30дн` и `по_дате` над источником (A2-1, A2-2), **When** выполняется прогон метрики на фикс-`Clock`, **Then** агрегат считается ровно по записям окна `(сегодня − 30 дн, сегодня]`, результат — скаляр, exit 0.
2. **Given** фикс-`Clock{2026,6,15}` и записи на датах `2026-05-16` (= нижняя_искл), `2026-05-17` и `2026-06-15` (A2-3), **When** считается `последние 30дн`, **Then** запись `2026-05-16` ИСКЛЮЧЕНА, записи `2026-05-17` и `2026-06-15` ВКЛЮЧЕНЫ (полуинтервал).
3. **Given** две эквивалентные метрики `последние 7дн` и `последние 1нед` (A2-2), **When** обе считаются на одной выборке, **Then** мембершип записей идентичен, скаляры равны.
4. **Given** метрика `период: последние 30дн` БЕЗ `по_дате` (A2-4), **When** программа анализируется, **Then** выдаётся существующее сообщение «период требует по_дате» с позицией, exit 1 (новой проверки не вводится).
5. **Given** метрика с оконным `период:` и триггер `когда метрика <оконная> < N` (A2-7), **When** идёт прогон, **Then** триггер сравнивает скаляр окна как обычно — код условия/тела триггера не меняется.

### User Story 2 — «Последний завершённый период» прошлый <период> (Priority: P2)

Бизнес-автор объявляет метрику `период: прошлый месяц` (или `прошлая неделя`/`прошлый квартал`/`прошлый год`/`прошлый день`) и получает агрегат за полный предыдущий календарный период относительно замороженного `Clock`: на дате-середине месяца `прошлый месяц` — это весь прошлый календарный месяц целиком, а не «месяц назад от сегодня». Форма — натуральный русский: `прошлый|прошлая <noun>`, где `noun` маппится на базовый адверб со сдвигом −1.

**Why this priority**: Завершённый период — частый бизнес-вопрос («выручка за прошлый месяц»), ценность авторинга поверх P1 (скользящее окно уже даёт MVP среза DoD). Логически вторая по важности, поэтому P2.

**Independent Test**: На фикс-`Clock{2026,6,15}` объявить `период: прошлый месяц` — окно `[2026-05-01, 2026-05-31]`; записи внутри прошлого месяца включены, записи текущего месяца (`2026-06-15`) исключены. Аналогично `прошлая неделя`/`прошлый квартал`/`прошлый год`/`прошлый день` — каждый даёт полный предыдущий календарный период. Проверяется вычислителем окна на фикс-`Clock`, без движка.

**Acceptance Scenarios**:

1. **Given** фикс-`Clock{2026,6,15}` и метрика `период: прошлый месяц` (A2-6), **When** считается метрика, **Then** окно равно `[2026-05-01, 2026-05-31]` — полный прошлый календарный месяц; запись `2026-06-15` исключена.
2. **Given** `период: прошлая неделя` / `прошлый квартал` / `прошлый год` / `прошлый день` (A2-6), **When** каждая считается на фикс-`Clock`, **Then** окно — соответствующий полный предыдущий календарный период (базовый адверб со сдвигом −1).
3. **Given** метрика `период: прошлый век` (noun вне множества, A2-6), **When** программа анализируется, **Then** ошибка «метрика '<имя>': неизвестный период 'век' (допустимо: день, неделя, месяц, квартал, год)» с позицией, exit 1.
4. **Given** существующая v1-метрика `период: ежемесячно` (A2-5), **When** она соседствует с `прошлый месяц`/`последние 30дн` в одной программе, **Then** обе формы валидны — `период:` принимает адверб-константу ЛИБО `последние N <ед>` ЛИБО `прошлый <noun>` (аддитивно).

### User Story 3 — Границы окна, детерминизм и валидация единиц (Priority: P3)

Аналитик полагается на детерминизм и честность границ: окно строится исключительно от замороженного `eval.Clock` (одинаковый прогон → одинаковый скаляр), полуинтервал `(сегодня − N, сегодня]` зафиксирован golden-таблицей у границ, а недопустимые формы (почасовая единица, неположительный размер, неизвестный noun) отвергаются с дословным русским сообщением и позицией. Нормализация переполнения дня в арифметике месяцев (Go `AddDate`) принята и зафиксирована честным golden на дате конца месяца.

**Why this priority**: Гарантии границ/детерминизма/валидации защищают корректность P1/P2 и регресс-замки, но сами по себе не дают пользовательской функции. Поэтому P3 — несущий слой приёмки.

**Independent Test**: Golden-таблица на фикс-`Clock` пиннит инклюзивность у каждой границы окна (`нижняя_искл` искл / `нижняя_искл+1` вкл / `конец` вкл / `конец+1` искл); негативные фикстуры `последние 5час` / `последние 0дн` / `прошлый век` дают точные §13-сообщения, exit 1; кейс конца месяца (`Clock{2026,5,31}`) фиксирует нормализованный результат. Проверяется вычислителем окна и семантикой, без движка.

**Acceptance Scenarios**:

1. **Given** фикс-`Clock` и запись ровно на `нижняя_искл` (= сегодня − N), на `нижняя_искл+1` и на `сегодня` (A2-3), **When** считается окно, **Then** запись на `нижняя_искл` ИСКЛЮЧЕНА, на `нижняя_искл+1` и на `сегодня` — ВКЛЮЧЕНЫ.
2. **Given** метрика `период: последние 5час` (единица вне `дн`/`нед`/`мес`, A2-2), **When** программа анализируется, **Then** ошибка «метрика '<имя>': единица 'час' недопустима для окна (допустимо: дн, нед, мес)» с позицией, exit 1.
3. **Given** метрика `период: последние 0дн` (A2-2), **When** программа анализируется, **Then** ошибка «метрика '<имя>': размер окна должен быть положительным» с позицией, exit 1.
4. **Given** один и тот же прогон оконной метрики на одном фикс-`Clock` (A2-3), **When** он повторяется, **Then** результат побайтно идентичен (окно от `i.now()`, не от `time.Now()`).
5. **Given** фикс-`Clock{2026,5,31}` (конец месяца) и метрика `последние 1мес` / `прошлый месяц` (§MW-D-WINDOW-EDGE), **When** считается окно, **Then** результат равен нормализованному (Go `AddDate`) golden-значению — честная фиксация, не «округлённая красиво».

---

### Edge Cases

- Запись ровно на `нижняя_искл` (= сегодня − N) — ИСКЛЮЧЕНА; на `нижняя_искл+1` — включена; на `сегодня` — включена (полуинтервал `(сегодня − N, сегодня]`).
- `последние 7дн` ≡ `последние 1нед` (14дн ≡ 2нед) — одинаковая мембершип записей; единицы взаимозаменяемы по длительности.
- Пустое окно (0 записей в окне) — существующий путь `emptyWindowResult` (сумма/количество → 0, иначе Пусто); триггер сравнивает скаляр без изменений.
- Спейсовая форма `последние 30 дн` (с пробелом) — НЕ поддержана: `30` лексится как `INT`, `expect(DURATION)` даёт парс-ошибку «ожидался период вида N<ед>, например 30дн». Поддержана только контигуальная `30дн`.
- Конец месяца + арифметика месяцев: Go `AddDate` нормализует переполнение дня (`2026-05-31.AddDate(0,-1,0)` = `2026-05-01`). Принято и документировано; golden DoD пиннится на дате-не-конце-месяца (`{2026,6,15}`), плюс один явный кейс конца месяца с зафиксированным нормализованным результатом.
- Переменная пользователя `последние`/`прошлый`/`прошлая` в v1-программе — безопасна: матч этих слов идёт контекстно в ветке `период:` (как A1 матчит `тип`/`поля`), они остаются `IDENT`, не ключевыми словами.
- Адверб-константа `период: ежемесячно` и прочие 4 календарных периода — путь `parseExpression` не меняется, поведение и golden v1 неизменны.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Метрика ДОЛЖНА поддерживать скользящее окно `период: последние N <ед>`, где `N` — положительное целое, `<ед>` — единица из множества `дн`, `нед`, `мес` (A2-1, A2-2). Форма `последние 30дн` контигуальна: `N<ед>` — один токен `DURATION`.
- **FR-002**: Скользящее окно `последние N <ед>` ДОЛЖНО трактоваться как полуинтервал `(сегодня − N ед, сегодня]` от `eval.Clock`: запись на верхней границе `сегодня` ВКЛЮЧЕНА, запись на нижней границе `сегодня − N ед` ИСКЛЮЧЕНА (A2-3).
- **FR-003**: Единица окна ДОЛЖНА принадлежать `дн`/`нед`/`мес`; почасовые единицы `сек`/`мин`/`час` ДОЛЖНЫ давать семантическую ошибку «метрика '<имя>': единица '<ед>' недопустима для окна (допустимо: дн, нед, мес)» с позицией атрибута `период:`, exit 1 (A2-2).
- **FR-004**: Размер окна `N` ДОЛЖЕН быть положительным (`N ≥ 1`); `N = 0` (и неположительный) ДОЛЖЕН давать семантическую ошибку «метрика '<имя>': размер окна должен быть положительным» с позицией, exit 1.
- **FR-005**: Метрика со скользящим окном ДОЛЖНА требовать ось `по_дате` — это покрывается существующей проверкой «период требует по_дате» (`analyze.go`); НОВАЯ проверка НЕ вводится, добавляется лишь golden, что `последние 30дн` без `по_дате` даёт существующее сообщение (A2-4).
- **FR-006**: Метрика ДОЛЖНА поддерживать «последний завершённый период» `период: прошлый|прошлая <noun>`, где `noun` ∈ `день`, `неделя`, `месяц`, `квартал`, `год` (A2-6). Форма натуральная: `прошлый месяц`, `прошлая неделя` и т. п.
- **FR-007**: `прошлый <noun>` ДОЛЖЕН вычислять полный предыдущий КАЛЕНДАРНЫЙ период: `noun` маппится на базовый адверб (день→ежедневно, неделя→еженедельно, месяц→ежемесячно, квартал→ежеквартально, год→ежегодно) со сдвигом якорной даты на −1 период, затем применяется существующая календарная логика окна (A2-6).
- **FR-008**: Неизвестный `noun` в `прошлый <noun>` ДОЛЖЕН давать семантическую ошибку «метрика '<имя>': неизвестный период '<noun>' (допустимо: день, неделя, месяц, квартал, год)» с позицией, exit 1.
- **FR-009**: Атрибут `период:` ДОЛЖЕН принимать ровно одну из трёх форм: адверб-константу v1 (`ежедневно`…`ежегодно`), `последние N <ед>`, либо `прошлый <noun>` — аддитивно; обе новые формы сосуществуют с пятью календарными адвербами без поломки (A2-5).
- **FR-010**: Метрика над оконным периодом ДОЛЖНА оставаться СКАЛЯРОМ (агрегат по окну); ряд значений (временной ряд) НЕ вводится — он явно ОТЛОЖЕН вне A2 (A2-1). Value-модель и сравнение в триггере не меняются.
- **FR-011**: Триггер по оконной метрике (`когда метрика <оконная> < N`) ДОЛЖЕН работать БЕЗ изменений: окно даёт скаляр, `trigger_run.go` читает метрику как есть; условие и тело триггера НЕ изменяются (A2-7).
- **FR-012**: Окно ДОЛЖНО вычисляться детерминированно от `eval.Clock` (`i.now()`, заморожен на запуск), НИКОГДА от `time.Now()`; golden-приёмка — на инъектированном `FixedClock` (НЕ пиннинг `сегодня()`) (A2-3, конституция V).
- **FR-013**: Все программы v1 ДОЛЖНЫ оставаться валидными: пять календарных периодов (`ежедневно`…`ежегодно`) считаются с тем же поведением и теми же границами; существующие `examples/*.ladix` и golden-тесты (`выручка.ladix`/`метрики.ladix`, `период: ежемесячно`) проходят без изменения вывода (инвариант 5 хартии §5).
- **FR-014**: Сообщения об ошибках ДОЛЖНЫ быть дословным русским каноном §MW-8: без точки в конце; `'…'` — идентификаторы/единицы/nouns; позиция — атрибут `период:` (`Attrs.PeriodPos`) либо декларация. Парс-ошибки формы — «ожидался период вида N<ед>, например 30дн» / «ожидался период: день/неделя/месяц/квартал/год».
- **FR-015**: Фича ДОЛЖНА добавить 0 новых зависимостей (арифметика дат — стандартный `time.AddDate`; окно — чистая функция от даты).
- **FR-016**: Изоляция фронтенда/бэкенда ДОЛЖНА быть сохранена: лексер НЕ трогается; парсер/AST/семантика расширяются только аддитивно (`ast` остаётся листовым, без импорта `errors`); вычислитель окна — в `eval`; `Store`, `ProcessRuntime`, экспорт интерпретатора, условие и тело триггера — НЕ изменяются (A2-7, инвариант 3 хартии §5).
- **FR-017**: `value.Период` ДОЛЖЕН расширяться АДДИТИВНО (пакет `value` остаётся листовым, без новых импортов): пять календарных констант сохраняют нулевые новые поля (обратная совместимость регистрации в `interpreter.go`); скользящее окно несёт `N` и единицу; завершённый период несёт базовый адверб и сдвиг −1. Структурное равенство `Период` ДОЛЖНО учитывать все поля.
- **FR-018**: Семантические проверки оконных форм (единица ∈ `дн`/`нед`/`мес`; `N ≥ 1`; `noun` ∈ множества) ДОЛЖНЫ выполняться статически на этапе анализа (обход `m.Period` AST), с точной позицией атрибута `период:`.
- **FR-019**: Срез M1 DoD (`выручка_30д`) — метрика `период: последние 30дн` + `по_дате` поверх реального CSV-источника (A1) ДОЛЖНА давать корректный скаляр на фикс-`Clock`, зелёный в `ladix run` и через golden-harness.

### Key Entities *(include if feature involves data)*

- **Период**: значение, описывающее окно метрики, в трёх вариантах. (1) *Календарный* — одна из пяти констант v1 (`ежедневно`…`ежегодно`), окно текущего календарного периода. (2) *Скользящий* — `последние N <ед>`: несёт размер `N` и единицу (`дн`/`нед`/`мес`), окно — полуинтервал `(сегодня − N, сегодня]`. (3) *Последний завершённый* — `прошлый <noun>`: несёт базовый адверб и сдвиг −1, окно — полный предыдущий календарный период. Расширяется аддитивно; пять констант сохраняют нулевые новые поля.
- **Окно**: пара дат `[начало, конец]` (инклюзивно, для переиспользования существующего инклюзивного фильтра записей), построенная от замороженного `Clock`. Для скользящего — инклюзивный эквивалент полуинтервала `(сегодня − N, сегодня]`; для завершённого — полный предыдущий календарный диапазон. Запись попадает в метрику, если её дата `по_дате` лежит в `[начало, конец]`.
- **Метрика**: агрегат по окну, остаётся СКАЛЯРОМ (сумма/количество/… → одно значение; пустое окно → 0 или Пусто). Ряд значений по окну — вне сущности (отложено). Метрика течёт в `run`/`serve`/триггер как обычный скаляр.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: `последние 7дн` и `последние 1нед` над одной выборкой дают идентичную мембершип записей и равные скаляры (единицы взаимозаменяемы по длительности).
- **SC-002**: `прошлый месяц` на фикс-`Clock{2026,6,15}` (середина месяца) даёт окно `[2026-05-01, 2026-05-31]` — весь предыдущий календарный месяц; запись `2026-06-15` исключена.
- **SC-003**: На фикс-`Clock` для `последние N <ед>` запись на нижней границе (`сегодня − N`) исключена, запись на `нижняя_искл+1` включена, запись на `сегодня` включена (полуинтервал пиннится golden-таблицей у каждой границы).
- **SC-004**: Срез M1 DoD: `выручка_30д` = `период: последние 30дн` + `по_дате` над реальным CSV-источником даёт корректный скаляр на фикс-`Clock`, exit 0 (зелёный в `run` и через harness).
- **SC-005**: Все пять календарных периодов и существующие v1 golden-тесты проходят без изменения вывода (0 регрессов; `период: ежемесячно` golden зелёный, поведение неизменно).
- **SC-006**: `последние 5час` (и любая `сек`/`мин`/`час`) даёт ошибку «единица '<ед>' недопустима для окна …», exit 1; `последние 0дн` даёт «размер окна должен быть положительным», exit 1; `прошлый век` даёт «неизвестный период 'век' …», exit 1 — каждое с позицией, §13-канон.
- **SC-007**: `прошлая неделя` / `прошлый квартал` / `прошлый год` / `прошлый день` на фикс-`Clock` каждый дают полный соответствующий предыдущий календарный период (отдельный golden на форму).
- **SC-008**: На фикс-`Clock{2026,5,31}` (конец месяца) `последние 1мес` и `прошлый месяц` дают зафиксированный нормализованный результат Go `AddDate` (честный golden, не «округлённый красиво»).
- **SC-009**: Триггер по оконной метрике (`когда метрика <оконная> < N`) срабатывает на скаляр окна на фикс-`Clock` БЕЗ изменения кода условия/тела триггера; повторный прогон на том же `Clock` побайтно детерминирован.
- **SC-010**: Фича добавляет 0 новых зависимостей; `Store`, `ProcessRuntime`, экспорт `eval`, условие и тело триггера остаются неизменными (изоляция фронтенда/бэкенда сохранена).

## Assumptions

- **A2-1 (скоуп) РЕШЕНО**: скользящее `последние N <ед>` + «последний завершённый период». Метрика-как-РЯД (временной ряд значений) **ОТЛОЖЕНА** — меняет Value-модель и сравнение в триггере, не нужна золотому сценарию; метрика остаётся скаляром по окну (§MW-0, §MW-12).
- **A2-2 (единицы окна) РЕШЕНО**: ровно `дн`, `нед`, `мес`; `сек`/`мин`/`час` — семантическая ошибка (бессмысленны для оси-даты). Форма контигуальна (`30дн` — один токен).
- **A2-3 (граница окна) РЕШЕНО**: `последние N дн` = полуинтервал `(сегодня − N, сегодня]` от `eval.Clock`; инклюзивность пиннится golden-таблицей §MW-10. Детерминизм — от `i.now()` (заморожен), не `time.Now()`.
- **A2-4 (`последние N` требует `по_дате`) РЕШЕНО**: да, БЕСПЛАТНО — существующая проверка «период требует по_дате» (`analyze.go`) уже покрывает; новой проверки не вводить.
- **A2-5 (сосуществование с адвербами) РЕШЕНО**: `период:` принимает адверб-константу v1 ЛИБО `последние N <ед>` ЛИБО `прошлый <noun>` — аддитивно, путь адвербов не меняется.
- **A2-6 («последний завершённый», синтаксис) РЕШЕНО**: `период: прошлый|прошлая <день|неделя|месяц|квартал|год>` (натуральный русский); маппинг noun→базовый адверб, сдвиг −1.
- **A2-7 (триггер по оконной метрике) РЕШЕНО**: работает БЕЗ изменений — окно даёт скаляр; `trigger_run.go` читает `evalMetricByName` как есть; НЕ трогать.
- **Только `дн`/`нед`/`мес`**: ось окна — дата; иные единицы вне A2.
- **Контигуальная форма `30дн`**: спейсовая `30 дн` не поддержана (документированный edge); срез DoD использует `30дн`.
- **Нормализация месяцев принята**: Go `AddDate` нормализует переполнение дня (конец месяца) — принято и зафиксировано честным golden; «снап на последний день месяца» — backlog (вне A2).
- **`value.Период` расширяется аддитивно** (инвариант листового пакета `value`); регистрация пяти констант в `interpreter.go` не меняется (нулевые новые поля).
- **Время не вводится заново**: `Clock` уже инжектируется (детерминизм 008/007b); окно — чистая функция от `i.now()`.

## Out of Scope

Согласно §MW-0/§MW-12 якоря, A2 осознанно НЕ делает:

- **Метрика-как-РЯД** (временной ряд значений) — ОТЛОЖЕНА (A2-1): меняет Value-модель и сравнение в триггере; backlog M-next. Метрика остаётся скаляром по окну.
- **Почасовые окна** `сек`/`мин`/`час` — вне A2 (A2-2); бессмысленны для оси-даты.
- **Снап месяц-окна на последний день** (обход Go-нормализации) — backlog.
- **Мультиисточник на метрику**, дополнительные агрегаты, ось не-дата, `ДатаВремя`/таймзоны — вне M1.
- **Кастомные произвольные окна** `[дата1, дата2]` — вне A2.
- **Спейсовая форма** `последние 30 дн` — не поддержана (только контигуальная `30дн`).
