# Phase 1 — Data Model: окна метрик (011-A2)

**Назначение.** A2 — чистый фронтенд (`парсер период:` + AST + семантика) +
вычислитель окна (`window.go`/`value.Период`). Эта модель фиксирует **структуры
данных**, которые A2 вводит или расширяет: расширение `value.Период`, новые
листовые узлы AST, таблицу вычисления окна, golden-границу, поток eval, каталог
семантических сообщений и инварианты. Источник истины — `docs/metric-windows-model.md`
§MW-0..§MW-13 (+ решения §MW-D-*); любой пробел закрывается ТАМ. При расхождении
источников побеждает якорь.

Нормативные термины: **ИНВАРИАНТ** — должно выполняться всегда; **АДДИТИВНО** —
существующая структура расширяется без изменения старых полей/сигнатур/поведения.
**Несущее свойство (§MW-0, инвариант 3 хартии §5):** все программы v1 валидны —
пять календарных периодов (`ежедневно`…`ежегодно`) считаются ровно как раньше;
`Store`, `ProcessRuntime`, экспорт `eval`, условие и тело триггера — НЕ трогаются
(A2-7). Окно строится от `eval.Clock` (`i.now()`, заморожен на запуск), НЕ от
`time.Now()` — детерминизм (конституция V).

## 1. `value.Период` — аддитивное расширение (§MW-3, §MW-D-VALUE)

`value.Период` (`value/deferred.go:28`) сегодня несёт только `Name`. A2 расширяет его
**аддитивно** — пакет `value` остаётся листовым (без новых импортов; `Период`
буквально моделирует период). Дословно из §MW-3:

```go
type Период struct {
    Name   string  // "ежедневно".."ежегодно" (календарный) | "последние" (скользящий)
    Amount int64   // скользящий: N; иначе 0
    Unit   string  // скользящий: "дн"/"нед"/"мес"; иначе ""
    Offset int     // «последний завершённый»: -1 к календарному Name; иначе 0
}
```

**Три формы значения `Период`.**

| Форма | Конструкция | `Name` | `Amount` | `Unit` | `Offset` |
|---|---|---|---|---|---|
| *Календарный* (v1) | `период: ежемесячно` (адверб-константа) | `ежедневно`…`ежегодно` | `0` | `""` | `0` |
| *Скользящий* (A2) | `период: последние N <ед>` | `"последние"` | `N` | `дн`/`нед`/`мес` | `0` |
| *Последний завершённый* (A2) | `период: прошлый\|прошлая <noun>` | базовый адверб (`noun→адверб`) | `0` | `""` | `-1` |

- 5 календарных констант (`value.PeriodNames`) → `{Name:X, Amount:0, Unit:"", Offset:0}`:
  нулевые новые поля ⇒ обратная совместимость; регистрация в `interpreter.go:77-79`
  (read-only глобалы) **не меняется**.
- `последние N <ед>` → `{Name:"последние", Amount:N, Unit:ед, Offset:0}`.
- `прошлый <noun>` → `{Name:<базовый адверб>, Amount:0, Unit:"", Offset:-1}`, где
  `noun→адверб`: день→ежедневно, неделя→еженедельно, месяц→ежемесячно,
  квартал→ежеквартально, год→ежегодно (§MW-5).

**Точечные правки пакета `value` (верифицировано, §MW-D-VALUE-EQ — ровно 3 файла).**

| Файл | Сегодня | A2 (аддитивно) |
|---|---|---|
| `deferred.go:28` | `Период{Name}` | `+Amount int64`, `+Unit string`, `+Offset int` |
| `equal.go:71-73` | `case Период` сравнивает только `Name` | сравнивать ВСЕ поля: `ok && x.Name==y.Name && x.Amount==y.Amount && x.Unit==y.Unit && x.Offset==y.Offset` |
| `repr.go:49-50` | `case Период` печатает `x.Name` | `Name=="последние"`→`fmt.Sprintf("последние %d%s", Amount, Unit)`; `Offset!=0`→`"прошлый "+nounFromAdverb(Name)`; иначе `Name` (v1) |

- ИНВАРИАНТ (§MW-D-VALUE-EQ): структурное равенство `Период` ДОЛЖНО учитывать все
  поля (`Name`/`Amount`/`Unit`/`Offset`); пять констант с нулевыми новыми полями
  сравниваются как раньше.
- ИНВАРИАНТ (`store/codec.go:92` НЕ трогать, обосновано §MW-3): кодек сериализует
  `Период` только по `Name`. Скользящие/завершённые `Период` **недостижимы как
  first-class значения** — парсер спец-парсит `последние`/`прошлый` ТОЛЬКО в ветке
  `период:` (§MW-4); в общем выражении (`присвоить x = последние 30дн`) `последние` —
  обычный `IDENT` (undefined→ошибка), `DURATION` остаётся → скользящий `Период` не
  порождается. Персистятся лишь 5 календарных адвербов (read-only глобалы) с нулевыми
  `Amount/Unit/Offset` → `Name`-only round-trip корректен. Контракт `Store` и
  сериализация НЕ меняются (инвариант §5).
- ИНВАРИАНТ (`window_test.go:42` keyed): построение `Период{Name:c.period}` keyed
  даёт нулевые новые поля — существующие тесты не ломаются.

## 2. Новые узлы AST — `WindowPeriodLit` / `LastCompletedPeriodLit` (§MW-4, §MW-D-PARSE-3)

Два новых узла-выражения в `ast/literal.go` рядом с прочими литералами. Оба —
**листовые** (несут локальную `ast.Position`, НЕ импортируют `errors`; пакет `ast`
остаётся листовым — конституция IV/VII), оба реализуют `Expression` через
встроенный `exprBase`. Eval каждого даёт `value.Период` (§MW-5).

```go
// WindowPeriodLit — литерал скользящего окна «последние N <ед>».
// Amount — строка из DurationValue лексера; парсится в int в семантике/eval.
type WindowPeriodLit struct {
    exprBase
    Amount string    // цифры N из токена DURATION ("30")
    Unit   string    // единица из токена DURATION ("дн"/"нед"/"мес"/…); валидность — семантика
    Pos    Position  // позиция (= позиция токена `последние`)
}

// LastCompletedPeriodLit — литерал последнего завершённого периода «прошлый <noun>».
type LastCompletedPeriodLit struct {
    exprBase
    Noun string    // день/неделя/месяц/квартал/год; валидность — семантика
    Pos  Position  // позиция (= позиция токена `прошлый`/`прошлая`)
}
```

**Поля.**
- `WindowPeriodLit.Amount string` — цифры `N` из `DurationValue.Amount` (хранятся как
  строка; `atoi` — в eval/семантике, как §MW-5). `WindowPeriodLit.Unit string` —
  `DurationValue.Unit`; принадлежность `{дн,нед,мес}` проверяется **семантически**
  (§MW-SEM-1), не парсером (любая лексически-валидная единица `сек/мин/час/дн/нед/мес`
  пройдёт парс).
- `LastCompletedPeriodLit.Noun string` — лексема `IDENT` после `прошлый`/`прошлая`;
  принадлежность `{день,неделя,месяц,квартал,год}` проверяется **семантически**
  (§MW-SEM-3), не парсером.
- `Pos Position` — локальная позиция узла; используется как позиция семантической
  ошибки (с подстановкой имени метрики; источник позиции атрибута — `Attrs.PeriodPos`).

**Инварианты.**
- ИНВАРИАНТ (§MW-D-PARSE-3, листовость): оба узла несут **локальную** `ast.Position`,
  не импортируют `errors`; `ast` остаётся листовым.
- ИНВАРИАНТ (§MW-D-PARSE-1, контекстный матч): `последние`/`прошлый`/`прошлая` и nouns
  остаются `IDENT` (НЕ ключевые слова) — лексер НЕ трогается; парсер матчит по
  `Lexeme` ТОЛЬКО в ветке `период:` (как A1 матчит `тип`/`поля`); v1-программа может
  иметь переменную с таким именем — безопасно.
- ИНВАРИАНТ (§MW-D-PARSE-4): путь `parseExpression` для адверб-констант не меняется ⇒
  `период: ежемесячно` валиден как раньше; `WindowPeriodLit`/`LastCompletedPeriodLit`
  порождаются ТОЛЬКО спец-парсом `parsePeriodValue()` в ветке `период:`.

## 3. Вычисление окна — таблица `periodWindow` (§MW-6, §MW-D-WINDOW-*)

`periodWindow(p value.Период, d value.Дата) (начало, конец value.Дата, ok bool)`
(`window.go:17`) — `d = i.now()` (заморожен). Существующий switch на `p.Name`
расширяется ДВУМЯ ветвями. Все границы возвращаются ИНКЛЮЗИВНО `[начало, конец]` —
чтобы переиспользовать инклюзивный фильтр `recordSurvives` БЕЗ его изменения.
Арифметика — служебная Go `time.AddDate` через `dateToTime`/`timeToDate`
(UTC-полночь, как существующие случаи).

### §MW-D-WINDOW-SLIDE (`p.Name == "последние"`)

Скользящее окно — инклюзивный эквивалент полуинтервала `(d − N ед, d]`:

| Шаг | Формула |
|---|---|
| `конец` (incl) | `d` |
| `нижняя_искл` (= `d − N ед`) | `дн`→`d.AddDate(0,0,-N)`; `нед`→`d.AddDate(0,0,-7*N)`; `мес`→`d.AddDate(0,-N,0)` |
| `начало` (incl) | `нижняя_искл.AddDate(0,0,+1)` (инклюзивная нижняя граница ≡ полуинтервал `(нижняя_искл, d]`) |

- `нед` ≡ `7·N` дней; ⇒ `последние 7дн` ≡ `последние 1нед` (§MW-9 п.2, SC-001).
- `N` берётся из `Amount` (уже `int64` в `value.Период`); единица из `Unit`.

### §MW-D-WINDOW-COMPLETED (`p.Offset != 0`, календарный `Name`)

Сдвинуть якорь `d` назад на `|Offset|` периодов базовой единицы, затем вычислить
КАЛЕНДАРНОЕ окно сдвинутой даты **существующей** логикой (5 ветвей):

| `Name` | сдвиг якоря на `Offset` (= −1) | затем |
|---|---|---|
| `ежедневно` | `d.AddDate(0,0,Offset)` | `periodWindow({Name, Offset:0}, сдвинутая_d)` |
| `еженедельно` | `d.AddDate(0,0,7*Offset)` | то же |
| `ежемесячно` | `d.AddDate(0,Offset,0)` | то же |
| `ежеквартально` | `d.AddDate(0,3*Offset,0)` | то же |
| `ежегодно` | `d.AddDate(Offset,0,0)` | то же |

Результат — полный предыдущий календарный период (напр. `прошлый месяц` на
`d=2026-06-15` → сдвиг к `2026-05-15` → календарное окно мая → `[2026-05-01, 2026-05-31]`).

### §MW-D-WINDOW-EDGE (нормализация месяцев — принята)

Go `AddDate` нормализует переполнение дня: `2026-05-31.AddDate(0,-1,0)` = `2026-05-01`
(апрель — 30 дней; 31 апр → 1 мая). Для `последние N мес` и `прошлый месяц/квартал/год`
на датах конца месяца это даёт неинтуитивные границы. **Решение:** принять нормализацию
Go (документировать); golden-таблицу DoD пиннить на дате-НЕ-конце-месяца
(`FixedClock{2026,6,15}`) + ОДИН явный golden конца месяца (`FixedClock{2026,5,31}`) с
зафиксированным НОРМАЛИЗОВАННЫМ результатом (честный golden, не «округлённый красиво»).
«Снап на последний день месяца» — backlog (вне A2, §MW-12).

**Детерминизм:** всё от `d = i.now()` (заморожен, `eval.Clock`); НИКОГДА `time.Now()`
(конституция V; golden на `FixedClock`).

## 5. Поток eval (§MW-2, §MW-5, §MW-6)

Eval оконной метрики переиспользует существующий конвейер `evalMetric`
(`metric_engine.go:45-60`); новые узлы добавляют ровно две ветви в `evalExpr`
(`eval/expr.go`), фильтр записей НЕ трогается:

```
период-выражение (m.Period) ──evalExpr──▶ value.Период
   ├─ Ident (адверб-константа v1) → env.Lookup → value.Период{Name:…} (путь v1, БЕЗ изменений)
   ├─ WindowPeriodLit            → value.Период{Name:"последние", Amount:atoi(lit.Amount), Unit:lit.Unit, Offset:0}
   └─ LastCompletedPeriodLit     → value.Период{Name:nounToAdverb(lit.Noun), Amount:0, Unit:"", Offset:-1}
        │
        ▼  тип-чек pv.(value.Период) (metric_engine.go:54), период вычислен ОДИН раз глобально
   periodWindow(per, i.now())  (window.go:17, i.now() заморожен от eval.Clock)
        │  → [начало, конец] инклюзивно (§MW-D-WINDOW-SLIDE / -COMPLETED / 5 календарных ветвей)
        ▼
   recordSurvives(rec, …, начало, конец)  (metric_engine.go:108-153, по_дате per-record;
        Compare(d,winStart)<0→reject, Compare(d,winEnd)>0→reject ⇒ INCLUSIVE [winStart,winEnd])
        │  НЕ ТРОГАЕТСЯ — окно сделано инклюзивно-эквивалентным
        ▼
   агрегат по выжившим записям → СКАЛЯР (пустое окно → emptyWindowResult: сумма/количество→0, иначе Пусто)
        │
        ▼  течёт в run / serve / триггер как обычный скаляр (trigger_run.go:64 — БЕЗ изменений, A2-7)
```

- ИНВАРИАНТ (§MW-2): период вычисляется ОДИН раз глобально (`evalExpr(i.global,
  m.Period)`, recordCtx=nil), затем тип-чек `pv.(value.Период)`, затем
  `periodWindow(per, i.now())`.
- ИНВАРИАНТ (§MW-7): `recordSurvives` инклюзивен — A2 делает окно инклюзивно-
  эквивалентным полуинтервалу, фильтр НЕ меняется.

## 6. Каталог семантических сообщений (§MW-8, дословно)

Конвенция §SM-9 (расширение §SM-9.A/C): **без точки в конце**; `'…'` — идентификаторы/
единицы/nouns; позиция = атрибут `период:` (`Attrs.PeriodPos`) либо декларация.
Дословный канон (конституция VIII); реализация берёт byte-identical.

**§MW-8.A — Семантика/парсер (Analyze, статически; обход `m.Period` AST):**

```
метрика '<имя>': единица '<ед>' недопустима для окна (допустимо: дн, нед, мес)
метрика '<имя>': размер окна должен быть положительным
метрика '<имя>': неизвестный период '<noun>' (допустимо: день, неделя, месяц, квартал, год)
```

| Сообщение | Триггер | §MW-SEM | FR |
|---|---|---|---|
| `единица '<ед>' недопустима для окна …` | `WindowPeriodLit.Unit ∉ {дн,нед,мес}` (`сек/мин/час`) | §MW-SEM-1 | FR-003 |
| `размер окна должен быть положительным` | `atoi(WindowPeriodLit.Amount) < 1` (N=0/неположит.) | §MW-SEM-2 | FR-004 |
| `неизвестный период '<noun>' …` | `LastCompletedPeriodLit.Noun ∉ {день,неделя,месяц,квартал,год}` | §MW-SEM-3 | FR-008 |

**Парс-ошибки формы (через `expect`):**

```
ожидался период вида N<ед>, например 30дн
ожидался период: день/неделя/месяц/квартал/год
```

(Спейсовая `последние 30 дн`: `30` лексится `INT`, `expect(DURATION)` найдёт `INT` →
первая парс-ошибка; §MW-D-PARSE-2.)

- ИНВАРИАНТ (§MW-SEM-4, A2-4): «период требует по_дате» (`analyze.go:167`)
  ПЕРЕИСПОЛЬЗУЕТСЯ для оконных форм — НОВОЙ проверки НЕ вводится; добавляется лишь
  golden, что `последние 30дн` без `по_дате` даёт существующее сообщение (FR-005).
- ИНВАРИАНТ: семантика статическая (без чтения файла), на этапе Analyze; позиция —
  атрибут `период:`.

2. ИНВАРИАНТ (ast-лист): новые узлы `WindowPeriodLit`/`LastCompletedPeriodLit` несут
   локальную `ast.Position`, не импортируют `errors`; лексер НЕ трогается; парсер/AST/
   семантика — только аддитивно. ✓ (§MW-4)
3. ИНВАРИАНТ (Store/movement untouched, A2-7): `store/codec.go` НЕ трогается (скользящие/
   завершённые `Период` недостижимы как first-class значения); `Store`/`ProcessRuntime`/
   экспорт `eval`/условие и тело триггера (`trigger_run.go:64`) — НЕ изменяются. ✓ (§MW-7)
4. ИНВАРИАНТ (детерминизм, конституция V): окно от `i.now()` (заморожен, `eval.Clock`);
   `time.Now()` НЕ используется; golden на инъектированном `FixedClock` (НЕ пиннинг
   `сегодня()`). ✓ (§MW-6)
5. ИНВАРИАНТ (обратная совместимость): пять календарных периодов считаются с тем же
   поведением и теми же границами; существующие `examples/*.ladix`/golden

   `recordSurvives` инклюзивен и НЕ меняется. ✓ (§MW-11 п.5)
6. ИНВАРИАНТ (0 зависимостей): арифметика дат — стандартный `time.AddDate`; окно —
   чистая функция от даты. ✓ (FR-015)
