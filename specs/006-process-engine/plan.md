## Summary

Шестой слой Ladix — **движок исполнения процессов + человек-в-цикле**. До 006 язык полностью
**парсит и семантически проверяет** процессы (005), но не исполняет их: `запустить процесс` упирается
в рантайм-границу «не поддерживается в этой версии». Фича 006 включает реальное исполнение: вводит
**хранилище состояния** (`internal/store`: контракт из 8 методов с двумя реализациями — эфемерная
`MemoryStore` в памяти и персистентная `SQLiteStore` файл-БД), **движок lifecycle** (`internal/engine`:
`Start`/`advance`/`Complete`, фаза атрибутов до тела, машина статусов SPEC §11.1, засыпание на
человеческом шаге и пробуждение через `complete`), **активирует deferred-ветки 005** (действия шага
`присвоить`/`вызвать`/`уведомить`, литерал длительности `3дн`, три процессные встроенные), даёт
**новый CLI-разрез** (`run --db` мост в SQLite, `complete <file.ladix> <task-id>`, `tasks
[исполнитель]`) и **байт-точные** stdout (§EN-7, 11 форматов) и диагностики (§EN-8.A — 9 текстов
программы, §EN-8.B — 10 CLI-текстов).

**Технический подход**: единственный связывающий источник истины — `docs/engine-model.md`
(§EN-0…§EN-10). Граница `eval↔engine` разрывается интерфейсом `ProcessRuntime`, **объявленным в
`eval`** и инжектируемым сеттером (`eval НЕ импортирует store/engine`, D-1); движок его реализует.
Вводится **первая внешняя зависимость проекта** — `modernc.org/sqlite` (чистый Go, без CGO; прямо
названа конституцией I); go.mod + go.sum оформляются **отдельным коммитом** (FR-041). Часы движка —
отдельный `engine.Clock` (D-2), не затрагивающий дневные часы интерпретатора (golden 004 не меняется).
Все системные строки и диагностики — дословно из §EN-7/§EN-8 (конституция VIII). Поставка по
приоритетам User Stories: US1 (запуск до точки ожидания, P1) и US2 (персистентная цепочка
`run --db` → `tasks` → `complete`, P1) — флагман; US3 (гарды `complete`, P2) и US4 (длительности и
процессные встроенные, P2) — поверх движка.

## Technical Context

**Language/Version**: Go **1.22+** (модуль `github.com/denis-kosyakov/ladix`, корень — `src/`),
без CGO. Подтверждено `src/go.mod`: `go 1.22`.

**Primary Dependencies**: **`modernc.org/sqlite`** — чистый Go, **без CGO**; это **первая внешняя
зависимость проекта** (до 006 — только stdlib). Зависимость прямо названа и разрешена конституцией I
(«единственная внешняя зависимость для хранилища»). Подключение (`go.mod` + `go.sum`) оформляется
**отдельным коммитом** (FR-041). Остальной новый код опирается на stdlib (`database/sql`,
`encoding/json`, `time`, `fmt`, `io`, `sync`, `strconv`, `errors`) и существующие пакеты
`internal/{lexer,parser,ast,value,errors,eval}`. `testify/require` — точечно в тестах (конституция VI).

**Storage**: SQLite-файл (персист, `SQLiteStore` — `run --db`/`tasks`/`complete`) + in-memory
(эфемерно, `MemoryStore` — `run` без `--db`, `metric`, тесты). Обе реализации — за одним контрактом
`Store` из 8 методов (D-3). Внутри SQLite значения кодируются **type-tagged JSON** (D-5/D-6/D-21),
времена — RFC3339 секундной точности; движок о формате хранения не знает (путь замены бэкенда открыт,
EM-4). Схема — `instances`/`tasks`/`counters` (DDL §EN-2), режимы конкурентности EM-7 (WAL,
busy-timeout, foreign keys).

**Testing**: `go test ./...` — три стратегии: (1) **table-driven** юнит-тесты по слоям (кодек
round-trip 10 типов значений, mint id, `MemoryStore` без алиасинга; lifecycle движка с фиксированными
часами; точечные приёмки слоя §EN-9 — литерал, сравнения Длительности, процессные встроенные,
тип-гарды атрибутов; два фабрикованных кейса гардов D-8 на уровне движка); (2) **golden / exact-match**
(сценарий А — байт-точный stdout из 5 строк с `WithClock(2026-05-31)`; сценарий Б — CLI-цепочка из
6 команд на свежей БД, маска только `<время>`; все 11 stdout-форматов §EN-7 и 19 текстов §EN-8.A/B
байт-в-байт); (3) **регресс** (все тесты 001–005 зелёные, golden 004 не меняется ни на байт; замки
инвентаря §EN-0 перевёрнуты). `testify/require` точечно; вывод — через инжектированный `out`
(`bytes.Buffer`); часы — через `WithClock`.

**Target Platform**: один статический бинарник `ladix` (`go build`), кросс-компиляция
darwin/linux/windows одной командой; `modernc.org/sqlite` — чистый Go, кросс-сборка сохраняется
(конституция I).

**Project Type**: компилятор/интерпретатор (tree-walking) — CLI `ladix run`/`metric`/`complete`/`tasks`
(single project, стандартная Go-раскладка).

**Performance Goals**: домен-специфично — **N/A**. Корректность важнее пропускной способности;
исполнение синхронное в одном потоке; персист — мелкие записи на каждую смену статуса/шага и каждое
`присвоить` (гранулярность EM-9), WAL их тянет (батчинг — v2). Жёстких числовых целей нет.

**Constraints**:

- **Байт-точность (конституция VIII, критично):** stdout — **11 форматов** §EN-7 (разделители,
  условные хвосты `срок до <время>`/`ПРОСРОЧЕНА`, отсутствие сообщений из списка «чего в stdout нет»);
  диагностики — **9 текстов §EN-8.A** (канон §13, позиция, exit 1) + **10 текстов §EN-8.B** (одна
  строка `ladix: <текст>`, exit 2). Переформулировать запрещено.
- **CGO запрещён** (конституция I): `modernc.org/sqlite` — чистый Go; иных тяжёлых зависимостей не
  вводить.
- **Без глобального состояния** (конституция V): `Store` — интерфейс (инъекция); `engine.Clock`
  инъектируется `WithClock`; `time.Now()` — только в реализациях Clock (D-2); package-level
  переменных нет.
- **Позиции в рунах** (конституция IV): новые runtime-ошибки §EN-8.A несут позицию узла-инициатора
  (вызова builtin / выражения атрибута / литерала длительности / узла-инициатора `присвоить`/запуска).
- **Граф без циклов** (конституция VII): `eval` НЕ импортирует `store`/`engine`; цикл `eval↔engine`
  разорван интерфейсом `ProcessRuntime` в `eval` (D-1); `engine → eval, store, ast, value, errors`.
- **Дневные часы интерпретатора не трогаем** (D-2): golden 004 (`2026-05-31`) не меняется;
  `engine.Clock` — вторая легальная реализация Clock-интерфейса, отдельная от `eval.Clock`.

**Scale/Scope**: single-file `.ladix`-программы, синхронное исполнение в одном потоке. **2 новых
пакета** (`internal/store`, `internal/engine`); **8 методов** контракта `Store` + 2 реализации; кодек
**10 типов** значений; **1 интерфейс** `ProcessRuntime` (7 методов) + **6 новых экспортов** `eval`;
**8 deferred-веток** активируются (§EN-5); реестр встроенных **25 + 10 → 28 + 7**; **3 новые
CLI-команды/флага** (`--db`, `complete`, `tasks`); реестр текстов — **11 stdout + 9 + 10 = 30**
байт-точных строк. **0 изменений** лексера/парсера/AST/синтаксиса (005 готов; §EN-10 путь отступления).

Открытых `[NEEDS CLARIFICATION]` **нет** — все развилки закрыты якорем (Q1–Q3, D-1…D-22).

`examples/` — на **корне репозитория**, СИБЛИНГ `src/`; используется приёмкой **как есть**
(005-редакция), правок примеров не требуется — синкается только `MANIFEST.md`:

```text
examples/                            # корень репозитория (рядом с src/, не внутри)
├── онбординг.ladix                 #   БЕЗ изменений — канонический вход сценария А/Б (как есть, 005-редакция)
├── hello.ladix                     #   БЕЗ изменений — негатив §EN-9 (файл без процесса 'онбординг')
└── MANIFEST.md                     #   ИЗМЕНЯЕТСЯ — строка онбординга (код 0, golden сценария А, маска <время>, FR-042)

src/internal/.../testdata/           # testdata-фикстуры негативов §EN-9 (зона impl-чата, FR-042)
├── онбординг-дрейф.ladix            #   НОВЫЙ — процесс есть, шаг 'закрыть_адаптацию' переименован (дрейф Q3)
└── сломанный.ladix                  #   НОВЫЙ — файл с ПАРС-ошибкой (complete файл не исполняет, компиляция падает)

.gitignore                           #   ИЗМЕНЯЕТСЯ — +ladix.db (GAP-9/FR-040)
```

**Structure Decision**:

- **Single project, стандартная Go-раскладка** (конституция VII): два новых листовых-совместимых
  пакета `internal/store` и `internal/engine` рядом с существующими `internal/{lexer,parser,ast,value,
  errors,eval}`; точка входа `cmd/ladix/`.
- **Граф без циклов**: `store` зависит от `value` (типы значений в `Variables`) и stdlib; `engine`
  зависит от `eval`, `store`, `ast`, `value`, `errors`; `eval` **НЕ** импортирует `store`/`engine` —
  цикл `eval↔engine` разорван интерфейсом `ProcessRuntime`, объявленным в `eval` и инжектируемым
  сеттером (D-1). `value`/`errors`/`ast` остаются листовыми.
- **`Store` — интерфейс с двумя реализациями** (D-3): `MemoryStore` (эфемерно) и `SQLiteStore`
  (персист); кодек type-tagged JSON — внутреннее дело `SQLiteStore`, движок про JSON/SQL не знает
  (путь замены бэкенда открыт, EM-4).
- **Аддитивное расширение `value`/`eval`/`cmd`**: case Длительность в `value.Equal`/`Compare` (D-17);
  активация deferred-веток и экспорт поверхности в `eval` (§EN-4/§EN-5); 3 команды/флага в CLI (§EN-6).
- **Тесты co-located** (`*_test.go`) — конвенция 001–005; golden/exact-match для §EN-7/§EN-8/§EN-9.
