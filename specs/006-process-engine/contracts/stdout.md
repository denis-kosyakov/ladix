# Контракт: реестр stdout §EN-7 (exact-match)

**Фаза**: 1 (design) | **Якорь**: `docs/engine-model.md §EN-7` | **Решения**: D-13, D-14, D-22 |
**FR**: FR-035, FR-036

> **Это байт-точный канон** stdout движка 006 (тесты сверяют **байт-в-байт**, SC-005). Тексты перенесены
> **дословно** из §EN-7 — не переформулировать. При расхождении побеждает §EN-7.

## Соглашения (§EN-7)

Все строки — в **stdout**, каждая завершается `\n`. `<арг>` = `value.String(аргумент)` (`repr.go`;
Длительность — `3дн`). `<время>` = `Deadline.Format("2006-01-02 15:04")` (локальная зона). Печатает:
1–2 — стабы действий (через engine); 3–4 — `advance` (создание Task); 5–6 — сводка `run` и `tasks`;
7–10 — `complete`; 11 — `tasks` при пустом списке. Exact-match: тесты сверяют байт-точно.

## Реестр 11 форматов (дословно §EN-7)

```
[уведомление] <получатель>: <арг1 арг2 …>                      // 1. уведомить с ≥1 аргументом; разделитель аргументов — один пробел (как печать)
[уведомление] <получатель>                                      // 1а. уведомить без аргументов (без двоеточия и хвостовых пробелов)
[вызов] <имя>(<арг1, арг2, …>)                                  // 2. вызвать; разделитель — ", "; без аргументов — "[вызов] <имя>()"
[задача] <t-id> → <исполнитель>, шаг '<шаг>', срок до <время>    // 3. создание Task со сроком (advance, фаза 3)
[задача] <t-id> → <исполнитель>, шаг '<шаг>'                     // 4. создание Task без срока
открытых задач: <N>                                              // 5. заголовок сводки run (печатается ТОЛЬКО при N ≥ 1, после последнего top-level)
<t-id>  <p-id>  '<шаг>'  <исполнитель>  срок до <время>  ПРОСРОЧЕНА   // 6. строка задачи (FormatTaskLine, D-22): разделитель полей — ДВА пробела; хвост "срок до <время>" только при дедлайне; хвост "ПРОСРОЧЕНА" только при Overdue
задача <t-id> завершена                                          // 7. complete, сразу после MarkTaskCompleted (до продвижения)
задача <t-id> уже была завершена, инстанс до-продвинут            // 8. complete, ветка гард-догона D-4 (вместо строки 7)
инстанс <p-id>: ожидает, шаг '<имя>'                              // 9. итог complete: снова заснул (после строки 3/4 нового Task)
инстанс <p-id>: выполнен                                          // 10. итог complete: терминальный успех
открытых задач нет                                                // 11. tasks при пустом списке (канон README, раздел `ladix tasks`)
```

## Привязка к коду / FR

| № | Формат | Печатает | Условие | FR |
|---|---|---|---|---|
| 1 | `[уведомление] <получатель>: <арг1 арг2 …>` | `Notify` (через engine) | `уведомить` с ≥1 аргументом; разделитель — **один пробел** (как `печать`) | FR-021/FR-035 |
| 1а | `[уведомление] <получатель>` | `Notify` | `уведомить` без аргументов: **без двоеточия и хвостовых пробелов** | FR-021/FR-035 |
| 2 | `[вызов] <имя>(<арг1, арг2, …>)` | `CallExternal` | `вызвать`; разделитель — `", "`; без аргументов — `[вызов] <имя>()` | FR-021/FR-035 |
| 3 | `[задача] <t-id> → <исполнитель>, шаг '<шаг>', срок до <время>` | `advance` (фаза 3) | создание Task **со сроком** | FR-013/FR-035 |
| 4 | `[задача] <t-id> → <исполнитель>, шаг '<шаг>'` | `advance` | создание Task **без срока** | FR-013/FR-035 |
| 5 | `открытых задач: <N>` | сводка `run` | заголовок; **только при N ≥ 1**, после последнего top-level | FR-029/FR-035 |
| 6 | `<t-id>  <p-id>  '<шаг>'  <исполнитель>  срок до <время>  ПРОСРОЧЕНА` | `FormatTaskLine` (D-22) | строка задачи: разделитель полей — **ДВА пробела**; хвост `срок до <время>` только при дедлайне; хвост `ПРОСРОЧЕНА` только при `Overdue` | FR-031/FR-035 |
| 7 | `задача <t-id> завершена` | `complete` | сразу после `MarkTaskCompleted` (до продвижения) | FR-030/FR-035 |
| 8 | `задача <t-id> уже была завершена, инстанс до-продвинут` | `complete` | ветка гард-догона D-4 (**вместо** строки 7) | FR-016/FR-035 |
| 9 | `инстанс <p-id>: ожидает, шаг '<имя>'` | `complete` | итог: снова заснул (после строки 3/4 нового Task) | FR-030/FR-035 |
| 10 | `инстанс <p-id>: выполнен` | `complete` | итог: терминальный успех | FR-030/FR-035 |
| 11 | `открытых задач нет` | `tasks` | пустой список (канон README, раздел `ladix tasks`) | FR-031/FR-035 |

- Строка 6 — **единственный источник** формата строки задачи (`engine.FormatTaskLine`, D-22): используется
  и `ladix tasks`, и сводкой `run` (строки 5–6).
- Аргументы — каноническим строковым представлением значений (`value.String`/`repr.go`; Длительность —
  `3дн`); `<время>` дедлайна — формат `2006-01-02 15:04` локальной зоны.
- **Владелец печати строк 7–10** — сам `engine.Complete` (пишет в `e.out`); CLI ничего не печатает.

## Чего в stdout НЕТ (осознанно; D-13/D-14; FR-036)

- Сообщения о **запуске** процесса — запуск **тихий** (D-13); строку `запущен онбординг, id: p-…` в демо
  печатает **ПРОГРАММА** (`печать`), а не движок.
- Сообщения о **терминале** внутри `run`.
- Строки о **провале** — провал это диагностика stderr (D-14), не stdout.
- **Заголовка** у `tasks` при непустом списке (заголовок строки 5 — только у сводки `run`).

## Сценарий А — байт-точный golden (§EN-9; SC-001)

`ladix run examples/онбординг.ladix` (MemoryStore, фикс. часы 2026-05-31 00:00:00) → exit 0, stdout
дословно (5 строк):

```
[уведомление] ИТ: создать учётку для Петров
[задача] t-000001 → руководитель, шаг 'провести_встречу', срок до 2026-06-03 00:00
запущен онбординг, id: p-000001
открытых задач: 1
t-000001  p-000001  'провести_встречу'  руководитель  срок до 2026-06-03 00:00
```

Порядок строк отражает синхронное исполнение: строки 1 (`уведомить`) и 3 (создание Task) — из `advance`;
`запущен онбординг, id: p-000001` — печать **программы** (после `запустить процесс` вернул id); строки 5–6
— сводка `run` после top-level. Строка 3 (создание Task) идёт **до** печати программы, т.к. запуск
синхронно доводит инстанс до ожидания внутри `запустить процесс`.

## Тесты (exact-match, SC-005)

- Все 11 форматов воспроизводятся байт-точно (разделители: один пробел / `", "` / два пробела; условные
  хвосты строки 6).
- Отсутствие сообщений из списка «чего в stdout нет» (запуск/терминал/провал/заголовок `tasks`).
- Сценарий А — байт-точный golden (engine-тест с `WithClock`); CLI-тест маскирует только `<время>`.
- Строка 6 — единый формат для `run`-сводки и `tasks` (один `FormatTaskLine`).
