## Соглашения (§EN-8; eval-model §8.3)

Payload **без** завершающей точки; `'…'` — идентификаторы/имена; позиция в заголовке канона §13.
Существующие тексты §8.3 (003) / §SM-9 (004) / §PM-6 (005) **продолжают действовать без изменений**
(runtime-ошибки тела шага — это они и есть, FR-039). Ниже — **только новый слой 006**.

## §EN-8.A. Ошибки программы (канон §13, двухстрочные, stderr, exit 1; FR-037)

Двухстрочный формат (заголовок с позицией `Pos()` + payload):

```
Ошибка в строке N, колонка M:
<payload>
```

Payload'ы (дословно §EN-8.A):

```
процесс '<id>' не найден                                  // ОшибкаВыполнения; статус_процесса/состояние_процесса с неизвестным id (D-15, EM-16); поз. вызова
статус_процесса: ожидается Строка, получено <тип>          // ОшибкаТипа; поз. вызова (стиль «дата: ожидается …», §8.3)
состояние_процесса: ожидается Строка, получено <тип>       // ОшибкаТипа; поз. вызова
задачи_пользователя: ожидается Строка, получено <тип>      // ОшибкаТипа; поз. вызова
шаг '<имя>': исполнитель должен быть Строка, получено <тип> // ОшибкаТипа; движок, фаза атрибутов (D-18); поз. выражения атрибута; инстанс → провален
шаг '<имя>': срок должен быть Длительность, получено <тип>  // ОшибкаТипа; то же
литерал длительности вне диапазона типа Целое               // ОшибкаВыполнения; ParseInt(DurationLit.Amount) за int64 (D-16); поз. литерала
сбой хранилища: <причина>                                  // ОшибкаВыполнения; ошибка Store из хука присвоить/запуска (обёртка %w, EM-16); поз. узла-инициатора
внутренняя ошибка: движок процессов не подключён            // ОшибкаВыполнения; runtime==nil (защитная, в CLI 006 недостижима — все исполняющие команды, включая metric, собирают стек §EN-6); поз. узла
```

| # | Payload (дословно) | Категория | Условие-триггер | Позиция (`Pos()`) |
|---|---|---|---|---|
| A1 | `процесс '<id>' не найден` | ОшибкаВыполнения | `статус_процесса`/`состояние_процесса` с неизвестным id (D-15, EM-16); `<id>` — аргумент | поз. вызова |
| A2 | `статус_процесса: ожидается Строка, получено <тип>` | ОшибкаТипа | аргумент не-Строка (стиль `дата: ожидается …`, §8.3) | поз. вызова |
| A3 | `состояние_процесса: ожидается Строка, получено <тип>` | ОшибкаТипа | аргумент не-Строка | поз. вызова |
| A4 | `задачи_пользователя: ожидается Строка, получено <тип>` | ОшибкаТипа | аргумент не-Строка | поз. вызова |
| A5 | `шаг '<имя>': исполнитель должен быть Строка, получено <тип>` | ОшибкаТипа | движок, фаза атрибутов (D-18); инстанс → провален | поз. выражения атрибута |
| A6 | `шаг '<имя>': срок должен быть Длительность, получено <тип>` | ОшибкаТипа | то же | поз. выражения атрибута |
| A7 | `литерал длительности вне диапазона типа Целое` | ОшибкаВыполнения | `ParseInt(DurationLit.Amount)` за `int64` (D-16) | поз. литерала |
| A8 | `сбой хранилища: <причина>` | ОшибкаВыполнения | ошибка Store из хука `присвоить`/запуска (обёртка `%w`, EM-16) | поз. узла-инициатора |
| A9 | `внутренняя ошибка: движок процессов не подключён` | ОшибкаВыполнения | `runtime==nil` (защитная; в CLI 006 недостижима — все исполняющие команды, включая `metric`, собирают стек §EN-6) | поз. узла |

**Провал инстанса (D-14) НЕ добавляет своего текста:** stderr несёт **исходную** ошибку тела/атрибута
(любой текст §8.3/§EN-8.A), статус `провален` виден через `статус_процесса`/БД. Категория «Процесса»
(SPEC §13.1) в 006 **не порождается** — `вызвать` всегда успешен.

## §EN-8.B. CLI-ошибки (одна строка `ladix: <текст>`, stderr, exit 2 — D-20; FR-038)

Payload'ы (дословно §EN-8.B):

```
ladix: задача '<id>' не найдена                                       // LoadTask → ErrTaskNotFound
ladix: задача '<id>' уже завершена                                    // завершена И догон D-4 неприменим
ladix: инстанс '<id>' не найден                                       // LoadInstance → ErrInstanceNotFound (битая/чужая БД)
ladix: инстанс '<p-id>' не ожидает (статус '<статус>')                 // гард D-8: Status != ожидает
ladix: задача '<t-id>' не соответствует текущему шагу инстанса '<p-id>' // гард D-8: CurrentStep != task.StepName
ladix: процесс '<имя>' не найден в определении                         // дрейф Q3: ProcessName инстанса отсутствует в файле
ladix: шаг '<имя>' не найден в определении процесса '<имя>'            // дрейф Q3: CurrentStep отсутствует в ProcessDecl
ladix: не удалось открыть хранилище '<путь>': <причина>                // открытие/инициализация SQLite (README:195 + префикс D-20)
ladix: сбой хранилища: <причина>                                       // не-сентинельная ошибка Store на CLI-путях complete/tasks (включая ▼ advance из Complete и декод кодека битой БД; §EN-3)
ladix: флаг --db требует значение                                      // разбор флага (стиль --max-depth)
```

| # | Текст (дословно, с префиксом `ladix: `) | Условие-триггер |
|---|---|---|
| B1 | `ladix: задача '<id>' не найдена` | `LoadTask` → `ErrTaskNotFound` |
| B2 | `ladix: задача '<id>' уже завершена` | задача `завершена` И гард-догон D-4 неприменим |
| B3 | `ladix: инстанс '<id>' не найден` | `LoadInstance` → `ErrInstanceNotFound` (битая/чужая БД) |
| B4 | `ladix: инстанс '<p-id>' не ожидает (статус '<статус>')` | гард D-8: `Status != ожидает` |
| B5 | `ladix: задача '<t-id>' не соответствует текущему шагу инстанса '<p-id>'` | гард D-8: `CurrentStep != task.StepName` |
| B6 | `ladix: процесс '<имя>' не найден в определении` | дрейф Q3: `ProcessName` инстанса отсутствует в файле |
| B7 | `ladix: шаг '<имя>' не найден в определении процесса '<имя>'` | дрейф Q3: `CurrentStep` отсутствует в `ProcessDecl` |
| B8 | `ladix: не удалось открыть хранилище '<путь>': <причина>` | открытие/инициализация SQLite (README:195 + префикс D-20) |
| B9 | `ladix: сбой хранилища: <причина>` | не-сентинельная ошибка Store на CLI-путях `complete`/`tasks` (включая ▼ `advance` из `Complete` и декод кодека битой БД; §EN-3) |
| B10 | `ladix: флаг --db требует значение` | разбор флага (стиль `--max-depth`) |

Существующие CLI-тексты (`не удалось прочитать файл`, `неверное значение --max-depth`, `лишний аргумент`,
usage) — **без изменений** (FR-032).

## Существующие реестры (без изменений; FR-039)

`eval-model §8.3` (003), `source-metric-model §SM-9` (004), `process-model §PM-6` (005) **действуют без
изменений** — runtime-ошибки тела шага это они и есть. В частности, разные единицы Длительности в
порядковом сравнении дают существующий текст §8.3 `'<оп>' нельзя применить к Длительность и Длительность`
(`Compare ok==false`, D-17); deferred-граница 7 дата-имён сохраняет прежний текст
`функция '<имя>' не поддерживается в этой версии` (FR-027).

## Тесты (exact-match, SC-006)

- Все 9 текстов §EN-8.A — байт-точно в каноне §13 (двухстрочный, позиция обязательна, stderr, exit 1).
- Все 10 текстов §EN-8.B — байт-точно одной строкой `ladix: <текст>` (stderr, exit 2).
- Существующие реестры 003/004/005 не изменились ни на байт.
- Провал инстанса несёт исходную ошибку тела/атрибута (не добавляет своего текста).
