# Implementation Plan: M-DX «Диагностика и восстановление парсера»

**Branch**: `012-mdx-diagnostics` | **Date**: 2026-06-16 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/012-mdx-diagnostics/spec.md`

## Summary

Веха M-DX поднимает качество диагностик для бизнес-автора `.ladix` двумя независимыми срезами. **DX1 (US1, P1)** — подавление фантомного каскада: ведущее sync-lead-ключевое слово в позиции выражения сегодня даёт 2–4 диагностики на одну сломанную конструкцию; цель — ровно одна, без регресса легитимного «N независимых ошибок → N». Технический подход: **единственная точечная правка default-ветки `parsePrimary` (`parse_expr.go:209`)** — потреблять (`advance`) ошибочный токен ДО `error()`, зеркально уже существующему `parse_stmt.go:29` (top-level unexpected). Это устраняет ре-диспетч у самого истока (understand-трассировка подтвердила: `parse_expr.go:209` — единственная колыбель всех фантомов A/B) и, как структурное следствие, поглощает тело блок-владеющих заголовков (если/пока/для) — bleed уходит. `synchronize`/suppress-reset не трогаются, поэтому контроль `значение⏎{` остаётся = 2. **DX2 (US2, P2)** — бизнес-понятные формулировки scope A (лексика L-*, синтаксис SE-*), полный проверяемый инвентарь каталога с count-locks, дешёвые подсказки (Левенштейн), расширенная витрина отдельными файлами. Канон новых текстов размещается в `docs/diagnostics-model.md`; код берёт дословно оттуда.

## Technical Context

**Language/Version**: Go 1.25 (`src/go.mod`). Идиоматичный Go: `gofmt`, `go vet ./...` без замечаний (Принцип I).

**Primary Dependencies**: 0 новых. Существующая единственная внешняя — `modernc.org/sqlite` (не затрагивается). DX1/DX2 — чистый stdlib (парсер, строки, тесты).

**Storage**: N/A для вехи (фронтенд; хранилище заморожено, пустой дифф `src/internal/store`).

**Testing**: `cd src && go test ./... -count=1` (+ `-race` на пакетах с конкурентностью). Tests-first для лексера/парсера (Принцип VI): red→green каскадные замки ДО правки.

**Target Platform**: один статический бинарник `ladix` (кросс-платформенный, без CGO).

**Project Type**: интерпретатор DSL (compiler/CLI), ручной recursive-descent (Принцип II).

**Performance Goals**: N/A (диагностики на статике; правка не меняет горячий путь по сложности — тот же один проход с одним токеном предпросмотра).

**Constraints**: детерминизм (нет `time.Now()`/`map`-итерации в порядке-зависимых местах в новом коде); позиции в рунах с 1 (Принцип IV); двухстрочный канон сообщений (Принцип VIII / SPEC §13); Go stack trace и сводка «Найдено K ошибок» запрещены; мягкий бюджет накопителя ≈20.

**Scale/Scope**: ~1 поведенческая правка парсера (parse_expr.go) + опц. вторичный рычаг decl-сайтов; ~25 переформулируемых текстов (11 L + 14 SE) с согласованным golden-проходом по 9 тест-файлам; 1 новый тест-хелпер; инвентарь-тесты с count-locks; модуль подсказок (Левенштейн); 1 модель-док; новые примеры витрины.

## Constitution Check

*GATE: проверено до Phase 0 и повторно после Phase 1. Итог: **9/9 PASS** (одно согласование зафиксировано в Complexity Tracking).*

- **I. Язык и сборка** — PASS. Go 1.25, `gofmt`/`go vet` чисто; 0 новых зависимостей; CGO не вводится.
- **II. Парсинг — ручной** — PASS. Правка внутри существующего ручного recursive-descent; генераторы/regex не вводятся; восстановление — ручное (panic-mode).
- **III. Ошибки — явные типы** — PASS. Используются существующие `ParseError`/`LexError` с встроенной `Position`; новый накопитель не вводится; паник в штатных путях нет; recover-барьер CLI и запрет Go stack trace сохранены (FR-005).
- **IV. Позиции — сквозные** — PASS. Диагностики сохраняют обязательную `Position{Line,Col}` (с 1, в рунах); двухстрочный формат не меняется (FR-011).
- **V. Без глобального состояния** — PASS. Парсер — значение, передаётся явно; новое состояние (если потребуется) — поле инстанса `Parser`, не пакет-уровневое. Левенштейн/словарь KW — чистые функции/локальные данные.
- **VI. Тесты — вперёд** — PASS. Red→green каскадные замки и golden обновляются tests-first; мутант-доказательство (SC-005); табличные тесты лексера/парсера расширяются, не ослабляются.
- **VII. Раскладка проекта** — PASS. Все правки в `internal/parser`, `internal/lexer` (+ их тесты, `cmd/ladix` golden); граф зависимостей без циклов; листовые `value`/`errors`/`ast` не меняются.
- **VIII. Язык сообщений** — PASS **с согласованием** (см. Complexity Tracking). Сообщения остаются на русском, двухстрочный канон §13 сохранён, коды наружу не выводятся. Буква принципа («тексты — дословно из SPEC §13, переформулировать запрещено») в части scope A разрешается через размещение нового канона в `docs/diagnostics-model.md` («дословно из docs») с последующим переносом в SPEC §13 архитектором.
- **IX. Спека — источник истины** — PASS. Поведение фиксируется размещёнными доками: spec.md + новый `docs/diagnostics-model.md`; открытые развилки разрешены явно (Assumptions), не молча; транзиторный синк больших доков делегирован архитектору письменно (FR-013).

**Структурные инварианты хартии v2 §5** (дрейф-аудит на гейте): `ProcessRuntime` = 7 методов, `Store` = 15 методов, ребро `engine→eval` не меняется; пустой дифф `src/internal/eval`, `src/internal/engine`, `src/internal/store` (FR-021, SC-009). DX1 — единственное санкционированное исключение из чистой аддитивности (модифицирует panic-mode), риск M, митигируется инверсией-замками (SC-005).
