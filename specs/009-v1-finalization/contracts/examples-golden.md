# Контракт приёмки: витрина примеров (examples-golden)

**Что контрактует.** Какие примеры витрины присутствуют, какой у каждого ожидаемый
stdout/stderr, и каким замком он закрыт. Это контракт наблюдаемого вывода CLI на
существующих формах языка — НЕ новый интерфейс. Источник: §VF-5, §VF-6,
FR-008..011, SC-004/SC-005.

## Позитивы — байт-точный stdout (или exit+маркеры)

| Файл | Команда запуска | Ожидаемый вывод | Замок | Детерминизм |
|------|------------------|-----------------|-------|-------------|
| `событие.ladix` | `./ladix run examples/событие.ladix` (или emit-сценарий) | байт-точный stdout (уведомление о запуске процесса) | `cmd/ladix` golden | `FixedClock` / `t.TempDir()` |
| `расписание.ladix` | `./ladix run …` / serve-тик | байт-точный stdout либо exit+маркеры | `cmd/ladix` golden | `FixedClock` |
| `метрики.ladix` | `./ladix run …` | parse-clean; вывод метрик (если дата-зависимо — exit+маркеры) | `examples_test` + при возможности golden | фикс-данные |
| `процесс.ladix` | `run --db <tmp>` → `tasks` → `complete` → пробуждение | id `p-000001`/`t-000001`, маска `<время>` | `cmd/ladix` golden | `--db` во временной директории |
| `выручка.ladix` (БЕЗ правки) | `./ladix run examples/выручка.ladix` | **дата-зависим** → пиннинг exit 0 + отсутствие маркеров диагностик | `main_test.go` (exit-only) + run-golden на `FixedClock` (`trigger_golden_test.go`) | run-golden фикс-`Clock`+данные |

**ИНВАРИАНТ.** Пиннинг по `сегодня()` запрещён. Дата-зависимый stdout пинится по
exit; строгий байт-точный stdout метрика-триггерного сценария закрывается ОТДЕЛЬНЫМ
run-golden с фикс-`Clock` (§VF-6) — зелёным в любой день.

## Негативы — точный двухстрочный stderr + код 1

| Файл | Класс | Ожидаемый stderr (форма SPEC §13) | Код |
|------|-------|-----------------------------------|-----|
| `ошибка_синтаксис.ladix` | синтаксическая (parse) | `Ошибка в строке N, колонка M:` + текст | 1 |
| `ошибка_тип.ladix` | тип/семантическая | `Ошибка в строке N, колонка M:` + текст | 1 |
| `ошибка_процесс.ladix` | ошибка процесса | `Ошибка в строке N, колонка M:` + текст | 1 |
| `ошибка.ladix` (существует) | runtime деление-на-ноль | без изменений | 1 |

**ИНВАРИАНТ.** Каждый негатив печатает РОВНО двухстрочный формат строка/колонка
(руны, с 1) и завершается кодом 1; тексты — дословно из SPEC §13 / существующих
диагностик (не переформулируются).

## Регистрация и компиляция

- ИНВАРИАНТ: каждый новый `examples/*.ladix` имеет запись в `examples/MANIFEST.md`
  (файл / назначение / golden-stdout, либо пометка дата-зависимости + ссылка на run-golden).
- ИНВАРИАНТ: `src/internal/parser/examples_test.go` (компиляция всех `examples/*.ladix`) — зелёный.

## Критерий «контракт выполнен»

В витрине ≥1 файл на каждый из 7 классов (событие / расписание / мультиисточник /
полный цикл / 3 ошибки); каждый зарегистрирован в `MANIFEST.md` и покрыт golden- или
негатив-замком; метрика-триггерный сценарий имеет run-golden, дающий идентичный
байт-точный stdout в любой день; `examples_test.go` зелёный.
