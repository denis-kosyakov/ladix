## Implementation Strategy

### MVP (User Story 1)

1. Phase 1 Setup → Phase 2 Foundational (T004).
2. Phase 3 US1: выровнять README/src/README + smoke-замок.
3. **STOP & VALIDATE**: чистый клон по README из корня → exit 0; `hello` → `Привет, Уклад!`; `go test ./...` из `src/` → 10/10. Это поставляемый минимум воспроизводимости.

### Инкрементальная поставка

1. Setup + Foundational → каркас готов.
2. US1 (воспроизводимость) → MVP.
3. US2 (CHECKLIST 50/50) + US3 (витрина 7 классов) — параллельно (P1).
4. US4 (quickstart) + US5 (выравнивание доков) — P2.
5. US6 (финальная приёмка) — замыкает конвейер.

### Гарантия достижимости гейта `go test` зелёный из `src/`

- Каждый пример витрины создаётся ДО/ВМЕСТЕ со своим замком (пара (а)→(б) в одной фазе, без разрыва) — нет промежуточного состояния «замок есть, примера нет».
- Позитивы добавляются в `TestExamplesParseCleanSet`; негативы НЕ добавляются (они должны падать) — парс-сет остаётся зелёным.
- `src/internal/errors/aggregate_test.go` (замок «Найдено») НЕ ТРОГАЕТСЯ.
- Детерминизм всех golden — `t.TempDir()`/прогон-во-tmp/`maskIDs` (эквивалент `FixedClock`), пиннинг по `сегодня()` запрещён → зелёные в любой день.
- 0 строк прод-кода языка → существующие 10 пакетов не ломаются.
