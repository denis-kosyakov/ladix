# Phase 1 — Data Model: артефакты финализации v1 (009)

**Назначение.** Финализация не вводит данных языка. «Сущности» здесь — это
**артефакты финализации** (доки, витрина, тесты), каждый со своими полями,
инвариантами и критерием «закрыто» (что считается приёмлемым). Источник —
`docs/v1-finalization-model.md` §VF-0..§VF-8.

Нормативные термины: **ИНВАРИАНТ** — должно выполняться всегда; **ЗАКРЫТО** —
критерий приёмки артефакта.

---

## 1. README.md (корневой) — контракт воспроизводимости

**Поля (что должно присутствовать).**
- Версия Go: фактический минимум из `src/go.mod` (`go 1.25`), без «1.22+».
- Блок сборки: `cd src && go build -o ../ladix ./cmd/ladix` (мост «в корень»).
- Блоки запуска примеров: `./ladix run examples/...` из корня (+ `serve`/`emit`/`metric` тем же мостом).
- Блок тестов: `cd src && go test ./...`.
- §9/раздел тестов: указание, что тесты в `src/internal/`.
- Описание агрегации ошибок: накопление блоков БЕЗ строки «Найдено K ошибок.».

**Инварианты.**
- ИНВАРИАНТ: ни одна команда сборки/проверки/тестов не идёт из корня без `cd src`.
- ИНВАРИАНТ: ни одной bare-команды `ladix ` (всегда `./ladix`).
- ИНВАРИАНТ: ОДИН канонический мост (`-o ../ladix`), проведён сквозь все примеры.

**ЗАКРЫТО.** Дословное исполнение блоков README из корня чистого клона даёт exit 0
на каждом блоке; `./ladix run examples/hello.ladix` → `Привет, Уклад!`; `cd src &&
go test ./...` → 10/10 пакетов `ok`. Закреплено smoke-замком (D-1, §VF-1). Grep по
докам сборки на `1.22` / «Найдено K ошибок» — пусто (FR-014/FR-015/FR-019).

## 2. src/README.md — вспомогательный документ каталога

**Поля.** Либо краткий блок dev-команд из `src/` (`go build`/`go test`/`go vet`),
либо явная отсылка «команды разработчика — в корневом README, выполнять из этого
каталога».

**Инварианты.** ИНВАРИАНТ: не голая заглушка «Переехало» без инструкций.

**ЗАКРЫТО.** Пользователь, оказавшийся в `src/` (единственный каталог с `go.mod`),
находит рабочие dev-команды или явную отсылку (FR-004, §VF-1, US1 сценарий 4).

## 3. CHECKLIST.md — документ готовности

**Поля.** 50 пунктов-чекбоксов рубрики; для каждого `[x]` — доказательство
файл:строка (рядом с пунктом или в сопроводке).

**Инварианты.**
- ИНВАРИАНТ: текст пунктов рубрики побайтно совпадает с исходным (правка рубрики — вне скоупа).
- ИНВАРИАНТ: `grep -c '^- \[ \]' CHECKLIST.md` = 0; `grep -c '^- \[x\]' CHECKLIST.md` = 50.
- ИНВАРИАНТ: пункт `hello.lang` закрыт `[x]` со сноской `.lang→.ladix`.
- ИНВАРИАНТ: доказательства-прогоны (рекурсия, ошибка строка/колонка) пинятся
  фикс-входом/фикс-`Clock`, не текущей датой.

**ЗАКРЫТО.** Все 50 отмечены `[x]`; каждое доказательство файл:строка верифицируемо
(файл/строка существует и содержит заявленный факт); тексты пунктов неизменны
(FR-006/FR-007, §VF-4, SC-003).

## 4. examples/*.ladix — витрина демо-программ

**Поля (минимальный набор новых файлов — 7 классов).**
| Файл | Класс | Вид вывода |
|------|-------|------------|
| `событие.ladix` | событие-триггер | позитив (golden или exit+маркеры) |
| `расписание.ladix` | расписание-триггер | позитив |
| `метрики.ladix` (≥2 источника + ≥2 метрики) | мультиисточник/мультиметрика | parse-clean (+позитив) |
| `процесс.ladix` | полный цикл процесса (`run --db`→`tasks`→`complete`) | позитив, `--db` во временной директории |
| `ошибка_синтаксис.ladix` | синтаксическая ошибка | негатив: stderr + код 1 |
| `ошибка_тип.ladix` | тип/семантическая ошибка | негатив: stderr + код 1 |
| `ошибка_процесс.ladix` | ошибка процесса | негатив: stderr + код 1 |

**Инварианты.**
- ИНВАРИАНТ: каждый файл компилируется (`internal/parser/examples_test.go` зелёный).
- ИНВАРИАНТ: формы уже поддержаны парсером/семантикой — новой функциональности нет.
- ИНВАРИАНТ: детерминизм через `FixedClock` + `t.TempDir()`; пиннинг по `сегодня()` запрещён.
- ИНВАРИАНТ: негатив печатает двухстрочный stderr (строка/колонка) + код 1.

**ЗАКРЫТО.** Все 7 классов присутствуют как файлы, каждый зарегистрирован в
`MANIFEST.md` и покрыт замком (golden-stdout для позитивов / точный stderr для
негативов); `examples_test.go` зелёный (FR-008/FR-009/FR-010, §VF-5, SC-004/SC-005).

## 5. examples/MANIFEST.md — реестр витрины

**Поля.** Запись на каждый новый пример: файл / назначение / golden-stdout (или
пометка «дата-зависимо → пиннинг exit + run-golden»). Явное пояснение, почему на
`выручка.ladix` нет строгой stdout-фикстуры и где живёт детерминированный замок.

**Инварианты.**
- ИНВАРИАНТ: каждый новый `examples/*.ladix` имеет запись в `MANIFEST.md`.
- ИНВАРИАНТ: согласован с правленым комментом `онбординг.ladix:13` (исполнение движком 006).

**ЗАКРЫТО.** Реестр полон (7 новых записей + пояснение `выручка.ladix`); согласован
с витриной и комментами (FR-009/FR-011/FR-017, §VF-5/§VF-6).

## 6. docs/quickstart.md — пользовательский гайд

> Это **пользовательский** артефакт (создаёт implement, US4) — НЕ путать с плановым
> `specs/009-v1-finalization/quickstart.md` (как проверять фичу).

**Поля.** Русский, не архитектурный. Путь: установка/сборка (ссылка на выровненный
README) → первая программа `hello` → первая метрика (источник + метрика, прогон) →
первый процесс (объявление + `run`/`run --db` → `tasks` → `complete` → пробуждение).
Все команды — из канонического набора US1 (`./ladix` из корня, рабочие пути к `data/`/`examples/`).

**Инварианты.**
- ИНВАРИАНТ: путь «метрика + процесс» проходится БЕЗ обращения к `*-model.md`.
- ИНВАРИАНТ: каждая команда воспроизводима из чистого клона (после US1).
- ИНВАРИАНТ: дата-зависимые шаги помечены «вывод зависит от даты» (пиннинг exit, не stdout).

**ЗАКРЫТО.** Файл существует; каждая команда исполняется дословно из чистого клона с
показанным результатом (exit 0); покрыт smoke-каналом README или отдельным замком
(FR-012/FR-013, §VF-7, SC-006).

## 7. Doc-набор выравнивания — README/ARCHITECTURE/SPEC/docs/онбординг

**Поля (точки выравнивания, §VF-2/§VF-3).**
| Цель | Файл | Было → Стало |
|------|------|--------------|
| Версия Go | README, ARCHITECTURE | «Go 1.22+» → `go 1.25` (`src/go.mod`) |
| Агрегация ошибок | SPEC §13, README | «Найдено K ошибок.» → накопление блоков без сводки |
| Расположение тестов | README/§9 | → `src/internal/` + `cd src && go test ./...` |
| Стейл-коммент | `examples/онбординг.ladix:13` | «deferred до 006» → исполнение движком 006 |
| `тип(x)` | `docs/stdlib.md`, SPEC §220/§343/§12, `docs/eval-model.md`, `builtins.go`-коммент | «активна» → «зарезервировано v1»; сноска достижимости (34) |

**Инварианты.**
- ИНВАРИАНТ: тест-замок отсутствия строки «Найдено» (`aggregate_test.go`) НЕ трогается, остаётся зелёным.
- ИНВАРИАНТ: `тип(x)` НЕ активируется; регистрация/реализация НЕ удаляются; reserved-word поведение неизменно.
- ИНВАРИАНТ: код выравнивается доками (не наоборот), кроме случаев, где код — истина (версия Go из `go.mod`).

**ЗАКРЫТО.** Grep по докам после выравнивания не находит снятых утверждений (`1.22`
в командах сборки, «Найдено K ошибок», «deferred до 006» в онбординге, доступность
`тип(x)` в v1) — 0 совпадений; каждое выровненное утверждение подтверждено
файл:строкой кода; `печать(тип(5))` остаётся reserved-word ошибкой
(FR-014..FR-019, §VF-2/§VF-3, SC-007).

## 8. Golden/smoke-тесты — приёмочные замки

**Поля.**
- Байт-точный stdout (позитивы витрины) — `src/cmd/ladix/main_test.go`/golden.
- Exit + маркеры (дата-зависимые: `выручка.ladix`) — пиннинг exit 0, отсутствие маркеров диагностик.
- Точный двухстрочный stderr + код 1 (негативы) — golden-замки.
- Компиляция витрины — `src/internal/parser/examples_test.go`.
- Run-golden метрика-триггера на `FixedClock` + фикс-данных — `src/cmd/ladix/trigger_golden_test.go`.
- Smoke блоков README/quickstart из корня — smoke-канал/CI-шаг.

**Инварианты.**
- ИНВАРИАНТ: все замки детерминированы — зелёные в любой день (`FixedClock`, `t.TempDir()`, фикс-данные).
- ИНВАРИАНТ: `--db` во временной директории, id `p-000001`/`t-000001`, маска только `<время>`.

**ЗАКРЫТО.** Метрика-триггерный сценарий имеет run-golden с байт-точным stdout,
зелёный независимо от даты; каждый класс витрины покрыт замком; `go test ./...` из
`src/` — 10/10 пакетов `ok` (FR-005/FR-009/FR-010/FR-011, §VF-5/§VF-6, SC-002/SC-005).
