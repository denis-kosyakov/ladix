# Feature Specification: Финализация продукта v1 Ladix

**Feature Branch**: `009-v1-finalization`

**Created**: 2026-06-15

**Status**: Draft

**Input**: Закрыть подтверждённые разрывы «док↔реальность», «чеклист↔факт» и «витрина↔скоуп» БЕЗ добавления новой языковой функциональности: воспроизводимость README из чистого клона; честная простановка `CHECKLIST.md`; полнота витрины примеров против скоупа §3; пользовательский `docs/quickstart.md`; выравнивание доков под фактическое поведение; финальная приёмка против рубрики §1–§9.

> **Источник истины** — `docs/v1-finalization-model.md` (§VF-0…§VF-8 + «Предрешённые развилки» + «Вне скоупа»). Спецификация выведена из якоря и не вводит требований сверх него; при любом расхождении источников побеждает якорь. Это **конвейер финализации, а не достройки фич**: ни одна история ниже не вводит новую языковую функциональность.

## User Scenarios & Testing *(mandatory)*

Действующие лица: **новый пользователь** (клонирует репозиторий и идёт по README/quickstart дословно), **оператор CLI** (собирает и запускает `ladix`), **приёмщик** (сверяет продукт с рубрикой §1–§9 и `CHECKLIST.md`). Система — **репозиторий Ladix как поставляемый продукт v1**: исходники в `src/`, документация (README/SPEC/ARCHITECTURE/`docs/`), витрина `examples/` и приёмочные тесты.

### User Story 1 — Воспроизводимость из чистого клона по README (Priority: P1)

Новый пользователь клонирует репозиторий и из **корня** выполняет команды README **дословно, блок за блоком**: собрать бинарник, запустить пример, прогнать тесты. Сегодня это невозможно: `go.mod` лежит в `src/`, а README даёт команды без `cd src` и с bare-командой `ladix` — сборка, тесты и запуск падают (`cannot find main module`, `command not found: ladix`). Финализация выравнивает README (и `quickstart`/`src/README.md`) под фактическое расположение модуля: всем командам сборки/проверки/тестов предпослано `cd src`; выбран ОДИН канонический мост между каталогом сборки и каталогом запуска — «собрать в корень» (`cd src && go build -o ../ladix ./cmd/ladix`), затем запуск `./ladix` из корня (ради `data/`, `data/sales.json`, `examples/`); тесты — `cd src && go test ./...`. Текст команд запуска примеров приведён к `./ladix run examples/...` из корня.

**Why this priority**: Воспроизводимость из чистого клона — главный внешний контракт продукта v1. Если README не собирается дословно, продукт не поставляем независимо от внутреннего качества. Это фундамент всех остальных историй (quickstart, приёмка ссылаются на него), поэтому P1.

**Independent Test**: На свежем клоне выполнить ровно блоки команд README из корня без единого ручного `cd src`, не упомянутого в README. Каждый блок завершается exit 0; `./ladix run examples/hello.ladix` печатает `Привет, Уклад!`; `cd src && go test ./...` даёт 10/10 пакетов `ok`.

**Acceptance Scenarios**:

1. **Given** свежий клон репозитория, **When** пользователь дословно выполняет блок сборки из README, **Then** появляется работающий бинарник `./ladix` в корне, exit 0; никаких не упомянутых в README ручных переходов между каталогами.
2. **Given** собранный бинарник в корне, **When** выполняется `./ladix run examples/hello.ladix` дословно из README, **Then** stdout = `Привет, Уклад!`, exit 0 (данные `data/`/`examples/` найдены, т.к. запуск из корня).
3. **Given** свежий клон, **When** выполняется блок запуска тестов из README, **Then** 10/10 пакетов `ok`, ноль «no test files», exit 0.
4. **Given** пользователь, оказавшийся в каталоге `src/` (единственный каталог с `go.mod`), **When** он читает `src/README.md`, **Then** он находит либо краткий блок dev-команд из `src/`, либо явную отсылку к корневому README, а не голую заглушку «Переехало».

### User Story 2 — Честная простановка CHECKLIST.md с доказательством (Priority: P1)

Приёмщик открывает `CHECKLIST.md` и видит фактическое состояние готовности. Сегодня отмечено **0 из 50** пунктов-чекбоксов (все строки `- [ ]`), хотя **49** подтверждаются кодом/тестами/примерами. Финализация проставляет `[x]` КАЖДОМУ подтверждённому пункту (всем строкам `- [ ]`), **с доказательством файл:строка** для каждого (название/идея в README; переменные/типы/области/ошибки в SPEC и `eval`; управляющие конструкции и их тесты; функции, рекурсия и примеры; пять классов ошибок и golden-замки; структура пакетов). Текст самих пунктов рубрики НЕ меняется. Единственный пункт-рассинхрон — «Есть `examples/hello.lang`»: реальное расширение `.ladix` (`examples/hello.ladix`), поэтому пункт закрывается по намерению с явной сноской `.lang→.ladix`.

**Why this priority**: `CHECKLIST.md` — официальный документ готовности v1; «0 из 50» при фактически готовом ядре делает приёмку недостоверной и блокирует §VF-8. Дешёвая, но критичная для поставки правка, поэтому P1.

**Independent Test**: После правки все 50 пунктов-чекбоксов `CHECKLIST.md` отмечены `- [x]` (`grep -c '^- \[ \]' CHECKLIST.md` = 0; `grep -c '^- \[x\]' CHECKLIST.md` = 50, из них пункт `hello.lang` закрыт `[x]` со сноской о фактическом `.ladix`-расширении); для каждого `[x]` указанное доказательство файл:строка верифицируемо (файл и строка существуют и содержат заявленное); тексты пунктов рубрики побайтно совпадают с исходными.

**Acceptance Scenarios**:

1. **Given** `CHECKLIST.md` с 0 отмеченными пунктами, **When** финализация проставляет `[x]` подтверждённым пунктам, **Then** отмечены все 50 пунктов-чекбоксов (49 кодовых + пункт `hello.lang` по намерению со сноской), формулировки пунктов не изменены.
2. **Given** любой отмеченный `[x]` пункт, **When** приёмщик открывает приложенное доказательство файл:строка, **Then** строка существует и содержит заявленный факт (например, `печать("Привет, Уклад!")` в `examples/hello.ladix`).
3. **Given** пункт «Есть `examples/hello.lang`», **When** приёмщик его читает, **Then** он видит `[x]` со сноской, что фактический пример — `examples/hello.ladix` (расширение в рубрике не адаптировано намеренно).
4. **Given** пункты, чьё доказательство — прогон (рекурсия, ошибка строка/колонка), **When** доказательство перепроверяется, **Then** оно пинится фикс-входом/фикс-Clock и остаётся зелёным, не завися от текущей даты.

### User Story 3 — Полная витрина примеров против скоупа (Priority: P1)

Пользователь, изучающий возможности языка через `examples/`, находит демонстрацию каждого класса возможностей скоупа. Сегодня витрина неполна: нет демо событие-триггера, расписание-триггера, мультиисточника/мультиметрики, полного жизненного цикла процесса и дополнительных классов ошибок (есть только runtime деление-на-ноль). Финализация добавляет недостающие демо (формы уже поддержаны парсером/семантикой — новой функциональности нет): событие-триггер (`когда событие …`), расписание-триггер (`когда расписание каждые Nдн` и/или `в "HH:MM"`), мультиисточник/мультиметрика (≥2 источника и ≥2 метрики в одном файле), полный цикл процесса (`run --db` → `tasks` → `complete` → пробуждение), и **три отдельных** негатива-ошибки: синтаксическая, тип/семантическая, ошибка процесса. Каждый новый пример регистрируется в `examples/MANIFEST.md` (файл / назначение / golden-stdout) и закрывается golden-замком; детерминизм обеспечивается фикс-`Clock` и/или встроенным прогоном во временной директории. `выручка.ladix` дата-зависим — его детерминизм закрывается отдельным run-golden с фикс-`Clock` (см. US ниже по тексту критериев).

**Why this priority**: Витрина — основной способ показать охват языка пользователю и доказать §3 рубрики «реализован весь скоуп». Пробелы витрины означают недоказанный скоуп. Параллельно ценно с US1/US2, поэтому P1.

**Independent Test**: В `examples/` присутствуют файлы для событие-триггера, расписание-триггера, мультиисточника/мультиметрики, полного цикла процесса и трёх классов ошибок; каждый зарегистрирован в `MANIFEST.md`; `parser/examples_test.go` (компиляция всех `examples/*.ladix`) зелёный; каждый позитив покрыт байт-точным golden-stdout (или exit+маркеры там, где вывод дата-зависим), каждый негатив — точным двухстрочным stderr (строка/колонка) + код 1.

**Acceptance Scenarios**:

1. **Given** запрос «покажи триггер по событию», **When** пользователь открывает `examples/`, **Then** есть файл с формой `когда событие <Ident>: запустить процесс …`, зарегистрированный в `MANIFEST.md` и покрытый замком в `cmd/ladix`.
2. **Given** запрос «покажи триггер по расписанию», **When** пользователь открывает `examples/`, **Then** есть файл с формой `когда расписание каждые Nдн` и/или `в "HH:MM"`, зарегистрированный и покрытый замком.
3. **Given** запрос «покажи несколько источников и метрик», **When** пользователь открывает `examples/`, **Then** есть демо с ≥2 `источник` и ≥2 `метрика` в одном файле, parse-clean, зарегистрирован.
4. **Given** запрос «покажи процесс целиком», **When** пользователь проходит демо полного цикла, **Then** прогон `run --db` → `tasks` → `complete` приводит к пробуждению процесса; детерминизм через `--db` во временной директории, id `p-000001`/`t-000001`.
5. **Given** три демо-негатива, **When** каждый запускается, **Then** один даёт синтаксическую ошибку, другой — тип/семантическую, третий — ошибку процесса; каждый печатает точный двухстрочный stderr (строка/колонка) и завершается кодом 1.
6. **Given** метрика-триггерный сценарий (дата-зависимый `выручка.ladix`), **When** прогоняется детерминированный run-golden с фикс-`Clock` и фикс-данными во временной директории, **Then** stdout пинится байт-точно и зелёный независимо от текущей даты; `MANIFEST.md` честно объясняет, почему на самом `выручка.ladix` строгой stdout-фикстуры нет.

### User Story 4 — Пользовательский docs/quickstart.md (Priority: P2)

Новый пользователь хочет «первую метрику и первый процесс за 5 минут», не погружаясь в архитектурные `*-model.md`. Финализация пишет `docs/quickstart.md` (русский, пользовательский, не архитектурный): установка/сборка (ссылка на выровненный README из US1) → первая программа `hello` → первая метрика (объявить источник + метрику, прогнать) → первый процесс (объявить + `run`/`run --db` → `tasks` → `complete` → пробуждение). Все команды — из канонического набора US1 (рабочий бинарник `./ladix` из корня, рабочие пути к `data/`/`examples/`), воспроизводимы из чистого клона.

**Why this priority**: Quickstart резко снижает порог входа и демонстрирует ценность продукта, но он надстройка над уже выровненным README (US1) и не блокирует поставку ядра, поэтому P2.

**Independent Test**: `docs/quickstart.md` существует; каждая его команда дословно исполняется из чистого клона (после US1) и даёт показанный результат; путь «метрика + процесс» проходится без обращения к архитектурным докам; шаги покрыты тем же smoke-каналом, что README (US1), либо отдельным замком — exit 0 на каждом шаге.

**Acceptance Scenarios**:

1. **Given** свежий клон и выровненный README, **When** пользователь идёт по `docs/quickstart.md` дословно, **Then** доходит от установки до первой метрики и первого процесса без обращения к `*-model.md`, каждая команда exit 0.
2. **Given** шаг «первая метрика», **When** пользователь выполняет показанную команду, **Then** получает показанный результат (детерминированный вывод, либо exit 0 с пометкой «вывод зависит от даты» там, где окно неизбежно).
3. **Given** шаг «первый процесс», **When** пользователь выполняет `run`/`run --db` → `tasks` → `complete`, **Then** наблюдает пробуждение процесса; id детерминированы, `--db` во временной директории.

### User Story 5 — Выравнивание документации под фактическое поведение (Priority: P2)

Пользователь, читающий README/SPEC/ARCHITECTURE/`docs/`, не встречает утверждений о несуществующем поведении или версии. Финализация выравнивает доки под код (не код под доки): (а) «Go 1.22+» → фактический минимум `go 1.25` из `src/go.mod`; (б) обещанная сводка «Найдено K ошибок.» в SPEC §13 и README, которой в коде нет, — снять/переписать под фактическое накопление блоков ошибок без итоговой строки (тест-замок отсутствия этой строки НЕ трогать); (в) `tests/` пуст, реальные тесты живут в `src/internal/` — задокументировать структуру и `cd src && go test ./...`; (г) стейл-коммент в `онбординг.ladix:13` («deferred до 006») — переписать под фактическое исполнение движком 006, согласовав с `MANIFEST.md`; (д) `тип(x)` документирован активным, но зарезервирован лексером и недостижим в рантайме — пометить в доках «зарезервировано v1» и добавить честную сноску к инварианту «РОВНО 35 builtins» о фактической достижимости (34), **без активации функции**.

**Why this priority**: Рассинхроны подрывают доверие к докам и ломают воспроизводимость (например, Go 1.22 не соберётся). Важно для качества поставки, но текстово и надстраивается над US1, поэтому P2.

**Independent Test**: Grep по докам не находит снятых утверждений (`1.22`, «Найдено K ошибок», «deferred до 006» в онбординге, утверждения о доступности `тип(x)` в v1); каждое выровненное утверждение подтверждается файл:строкой кода; существующий тест-замок отсутствия строки «Найдено» остаётся зелёным; прогон `печать(тип(5))` по-прежнему даёт reserved-word ошибку (поведение `тип` не меняется).

**Acceptance Scenarios**:

1. **Given** README/ARCHITECTURE с «Go 1.22+», **When** доки выровнены, **Then** указан фактический минимум `go 1.25` (по `src/go.mod`), grep по `1.22` в доках сборки пуст.
2. **Given** SPEC §13 и README, обещающие «Найдено K ошибок.», **When** доки выровнены под код, **Then** обещание снято/переписано под фактическое накопление блоков без итоговой сводки; тест-замок отсутствия строки «Найдено» остаётся зелёным.
3. **Given** README/§9 без указания расположения тестов, **When** доки выровнены, **Then** задокументировано, что тесты в `src/internal/` и запускаются `cd src && go test ./...`; `tests/`-заглушка остаётся честной отсылкой.
4. **Given** `онбординг.ladix:13` со стейл-комментом «deferred до 006», **When** коммент выровнен, **Then** он описывает фактическое исполнение движком 006 и согласован с `MANIFEST.md`.
5. **Given** доки, заявляющие `тип(x)` активной, **When** они выровнены, **Then** каждое место помечено «зарезервировано v1» либо `тип` внесён в §12-список отложенного; инвариант-коммент «РОВНО 35 builtins» получает честную сноску о достижимости (34); регистрация/реализация `тип` НЕ удаляются, функция НЕ активируется.

### User Story 6 — Финальная приёмка против рубрики §1–§9 (Priority: P3)

Приёмщик проводит сквозную приёмку продукта v1 против рубрики §1–§9 после закрытия US1–US5. Это сводный шаг (без собственных разрывов): он подтверждает воспроизводимость из чистого клона по README, 100% `CHECKLIST.md` с доказательствами, присутствие всех классов витрины, прохождение `quickstart` за 5 минут, выровненность доков (grep не находит снятых утверждений) и зелёные гейты из `src/` (build/vet/test, 10/10 пакетов), при чистом рабочем дереве (собранный бинарник `src/ladix`/`./ladix` не закоммичен).

**Why this priority**: Финальная сводка ценна только после закрытия предыдущих историй и не вводит самостоятельной функциональности, поэтому P3 — она замыкает конвейер, но зависит от всего остального.

**Independent Test**: Каждый из 9 пунктов рубрики имеет доказательство файл:строка или зелёный прогон; финальный smoke (блоки README + quickstart из корня чистого клона) и `go test ./...` из `src/` дают exit 0; рабочее дерево чистое (нет незакоммиченного собранного бинарника).

**Acceptance Scenarios**:

1. **Given** закрытые US1–US5, **When** приёмщик прогоняет финальный smoke (README + quickstart из корня чистого клона), **Then** каждый блок exit 0.
2. **Given** репозиторий после финализации, **When** выполняется `cd src && go build ./... && go vet ./... && go test ./... -count=1`, **Then** build/vet PASS, тесты 10/10 пакетов `ok`, exit 0.
3. **Given** `CHECKLIST.md` и рубрика §1–§9, **When** приёмщик сверяет, **Then** 50/50 пунктов-чекбоксов `CHECKLIST.md` отмечены с доказательствами и каждый из 9 пунктов рубрики закрыт доказательством или зелёным прогоном.
4. **Given** рабочее дерево, **When** проверяется `git status`, **Then** оно чистое; собранный бинарник игнорируется/удалён и не закоммичен.

### Edge Cases

- Сборка из корня без `cd src` (исходное поведение) — `go: cannot find main module`; README не должен оставлять ни одной такой команды.
- Bare `ladix run …` без префикса `./` или PATH — `command not found: ladix` (exit 127); все команды запуска приведены к `./ladix … ` из корня.
- Клон на Go 1.22–1.24 — не соберётся из-за директивы `go 1.25.0`; доки указывают фактический минимум, чтобы пользователь не получил неожиданную ошибку тулчейна.
- `выручка.ladix` и любая метрика с периодом `ежемесячно`/окном от `сегодня()` — stdout дата-зависим; для таких сценариев пинится exit 0, а детерминизм проверяется отдельным run-golden на фикс-`Clock`, не текущей датой.
- Пункт `CHECKLIST.md` «`hello.lang`»: расширение в рубрике (`.lang`) не совпадает с реальным (`.ladix`); закрывается `[x]` со сноской, текст пункта не редактируется (правка рубрики — вне скоупа).
- `печать(тип(5))` — остаётся reserved-word ошибкой; доки выравниваются под этот статус, поведение не меняется.

## Assumptions

- **`go.mod` НЕ переносится в корень**: воспроизводимость обеспечивается README-инструкциями «из `src/`»; перенос — churn по дереву импортов и истории, вне скоупа. `go.work` не используется (из корня даёт 0 пакетов).
- **Мост между каталогами — «собрать в корень»** (`cd src && go build -o ../ladix ./cmd/ladix`), запуск `./ladix` из корня ради `data/`/`examples/`; опциональный корневой `Makefile` (цели `build`/`test`/`vet` делают `cd src && go …`) допустим, но не обязателен.
- **`CHECKLIST.md` — только простановка `[x]` с доказательством**; текст пунктов рубрики (включая `.lang` в пункте `hello.lang`) НЕ редактируется — это правка внешней generic-рубрики, вне скоупа.
- **Пункт `hello.lang` (§VF-3 анкора)** закрывается по умолчанию `[x]` + сноска `.lang→.ladix`.
- **Детерминизм примеров обязателен**: любое новое демо с golden-проверкой строится на фикс-`Clock`/фикс-данных или встроенно во временной директории; пиннинг по `сегодня()` запрещён. Дата-зависимый stdout пинится по exit, детерминизм — отдельным run-golden.
- **Язык всех новых/правленых доков — русский** (README/quickstart/MANIFEST/model); английский только в Go-коде.
- **Доки выравниваются под код** (не код под доки), кроме случаев, где код — истина; версия Go берётся из `src/go.mod` по умолчанию (порог не понижается).
- **`тип(x)` остаётся зарезервированным**: финализация только выравнивает доки под этот статус, регистрация/реализация не удаляются (путь будущей активации), функция не активируется.
- **Целевые гейты прогоняются из `src/`** (там лежит `src/go.mod`); вход в финализацию — все гейты зелёные (HEAD `348ee64`).

## Вне скоупа

- **Новая языковая функциональность** любого рода — конвейер только закрывает разрывы «док↔реальность», не достраивает фичи.
- **Активация `тип(x)`** как достижимого builtin (в финализации только доковое выравнивание под зарезервированный статус).
- **Бонусы**: REPL, массивы, словари, статическая типизация, модули, компиляция в байткод/нативно, отладчик.
- **v2-границы**: parallel-шаги процессов, полные интеграции `вызвать`/`уведомить` (внешние эффекты), cron-планирование, `--json`-вывод, команда `ladix start`, период «последние N дней», HTTP-приём событий, операторная арифметика дат/длительностей (`Дата±Длит`, `Дата−Дата`, `Длит±Длит`, `Длит*X` — остаётся deferred v2).
- **Процедурное**: редактирование `TASK.md`/конституции; перенос `go.mod` в корень; наполнение `tests/` реальными тестами (остаётся плейсхолдером/отсылкой).
