# Feature Specification: B2 «Реальные эффекты `вызвать` / `уведомить` через HTTP-вебхук»

**Feature Branch**: `014-real-effects`

**Created**: 2026-06-17

**Status**: Draft

**Input**: User description: B2 (веха M2) — реальные внешние эффекты `вызвать` / `уведомить` через HTTP-вебхук, активируемый Option движка. Интерфейс драйвера `ExternalCaller{ Call(...); Notify(...) }`; Option `WithExternalCaller(...)`; дефолт-драйвер = печать-стаб `printCaller` (держит §EN-7 golden байт-точно); реальный драйвер `webhookCaller{ baseURL, httpClient }` — POST JSON на вебхук. CLI-проводка: флаг `--вебхук` и env `LADIX_WEBHOOK` → активируют `webhookCaller`, иначе `printCaller`. Активация `runtimeErrWrap` (TODO D-14). Источник истины — `docs/automation-model.md` §AU-4 (решение D-AU-2).

## Контекст и роли

Целевой пользователь — **бизнес-автор `.ladix`** и **оператор демо**: автор описывает шаги процесса с внешними эффектами (`вызвать crm(клиент)`, `уведомить ИТ`), а оператор запускает их так, чтобы эффекты **реально доставлялись** во внешнюю систему, а не только печатались стабом. Логическое имя цели (`crm`, `ИТ`) остаётся в `.ladix`; куда физически идёт доставка — задаётся СНАРУЖИ (CLI-флаг / env), `.ladix` остаётся чистым (цель = логическое имя, не URL).

Веха M2-подфича **B2** (`docs/automation-model.md` §AU-0, §AU-4): слой — **движок (engine) + CLI-проводка**. B2 **зависит от B1** (метод шва `CallExternalResult` уже поставлен фичей 013, шов 7→8 закрыт), и **мягко гейтит** durable-доставку B4b. Решение залочено владельцем — **D-AU-2** (§AU-1): канал B2 = HTTP-вебхук (не файл, против рекомендации kickoff); драйвер инжектится Option'ом движка; дефолт-драйвер = печать-стаб (держит §EN-7 golden, ≥6 пинов); реальный = `POST` JSON `{"цель": target, "данные": [args]}`; базовый URL — CLI-флаг `--вебхук` / env `LADIX_WEBHOOK`; детерминизм тестов — `httptest`. Спецификация переносит это решение, не пересматривает.

B2 **не вводит новой языковой функциональности**: грамматика, AST, лексер, парсер не меняются; шов `ProcessRuntime` остаётся 8 методов (B1 уже дал `CallExternalResult`). Изменения — внутри `engine` (драйвер + Option + два кодека тела/ответа вебхука) и в корне композиции CLI (проводка флага/env). Дефолт без `--вебхук` — печать-стаб, наблюдаемый вывод не меняется (главный инвариант B2).

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Дефолт-драйвер печать-стаб (без `--вебхук`) держит §EN-7 golden (Priority: P1)

Оператор запускает программу с `вызвать` / `уведомить` **без** флага `--вебхук` и без env `LADIX_WEBHOOK`. Эффекты по-прежнему печатаются стабом в stdout байт-в-байт как в v1 — никакого сетевого обращения, никакого изменения наблюдаемого вывода. Текущая печать-логика движка переносится в дефолт-драйвер `printCaller`, который ставится Option'ом по умолчанию.

**Why this priority**: Это ГЛАВНЫЙ несущий инвариант B2. Введение Option-драйвера НЕ должно изменить наблюдаемый вывод по умолчанию — иначе ломаются ≥6 золотых пинов §EN-7 (`TestNotifyCallFormats` и семья), и регрессирует весь v1-демо. Без этой гарантии B2 нельзя влить. Поэтому дефолт-стаб — P1, проверяется первым.

**Independent Test**: Запустить программу с `вызвать имя(арг)` и `уведомить получатель: арг` без `--вебхук`/env и убедиться, что stdout содержит ровно строки `[вызов] имя(арг)` и `[уведомление] получатель: арг` (§AU-4.2 / §EN-7 байт-точно), сеть не трогается, `вызвать`-выражение под стабом возвращает `Пусто` (`value.None`), а все существующие golden-пины §EN-7 зелёные.

**Acceptance Scenarios**:

1. **Given** движок, сконструированный БЕЗ `WithExternalCaller`, **When** исполняется `уведомить ИТ: создать учётку для Петров`, **Then** в stdout печатается ровно `[уведомление] ИТ: создать учётку для Петров\n` (формат 1, §AU-4.2/§EN-7), без обращения к сети.
2. **Given** движок без `WithExternalCaller`, **When** исполняется `уведомить ИТ` (без аргументов), **Then** печатается ровно `[уведомление] ИТ\n` — без двоеточия и хвостовых пробелов (формат 1а).
3. **Given** движок без `WithExternalCaller`, **When** исполняется `вызвать crm(клиент, 5)`, **Then** печатается ровно `[вызов] crm(клиент, 5)\n` (разделитель `", "`, формат 2), и `вызвать`-выражение возвращает `Пусто` (`value.None`).
4. **Given** существующие golden-сценарии v1 (`engine_test`, `main_test`), **When** они исполняются под B2 без `--вебхук`, **Then** все ≥6 пинов §EN-7 проходят байт-в-байт без изменения ожидаемого текста (дефолт-драйвер = перенесённая текущая логика).

### User Story 2 — Реальная доставка эффекта через HTTP-вебхук (`--вебхук` / env) (Priority: P2)

Оператор передаёт `--вебхук https://приёмник/hook` (или ставит env `LADIX_WEBHOOK`). Движок активирует `webhookCaller`: `вызвать` и `уведомить` делают `POST` на базовый URL с телом-JSON `{"цель": <логическое имя>, "данные": [<аргументы как JSON>]}` и заголовком `Content-Type: application/json`. Для `вызвать` тело ответа декодируется в значение (результат внешней системы доступен автору). Для `уведомить` ответ игнорируется (best-effort).

**Why this priority**: Это функциональное ядро B2 — без реальной доставки фича бессмысленна. P2, потому что её корректность опирается на уже-зелёный дефолт-инвариант (US1): сначала гарантируем «дефолт не сломан», затем включаем реальный драйвер.

**Independent Test**: Поднять `net/http/httptest`-сервер, сконструировать движок с `WithExternalCaller(webhookCaller{...})` на его URL, исполнить `вызвать crm(клиент)` и `уведомить ИТ: x`; убедиться, что сервер получил `POST` с `Content-Type: application/json` и телом `{"цель":"crm","данные":["клиент"]}` (соответственно для уведомить), а результат `вызвать` равен декодированному ответу сервера.

**Acceptance Scenarios**:

1. **Given** `httptest`-сервер и движок с `webhookCaller` на его URL, **When** исполняется `вызвать crm(клиент)`, **Then** сервер получает `POST` на базовый URL с `Content-Type: application/json` и телом `{"цель":"crm","данные":["клиент"]}`.
2. **Given** `httptest`-сервер, возвращающий тело `{"статус":"ок"}`, **When** исполняется `присвоить ответ = вызвать crm(клиент)`, **Then** переменная `ответ` получает декодированную `Запись` `{статус: "ок"}` (ответ декодируется через декодер B2, §AU-4.3).
3. **Given** `httptest`-сервер, возвращающий ПУСТОЕ тело (или статус без тела), **When** исполняется `присвоить r = вызвать сервис()`, **Then** `r` = `Пусто` (`value.None`) — пустое тело проверяется ДО декодера (декодер на пустом потоке вернул бы ошибку).
4. **Given** `httptest`-сервер и движок с `webhookCaller`, **When** исполняется `уведомить ИТ: создать учётку`, **Then** сервер получает `POST` с телом `{"цель":"ИТ","данные":["создать учётку"]}`, ответ сервера игнорируется (best-effort), эффект исполнен без захвата результата.
5. **Given** `webhookCaller` и аргументы разных типов (`Целое`, `Дробное`, `Строка`, `Булево`, `Пусто`, `Список`, `Запись`), **When** кодируется тело запроса, **Then** каждый тип сериализуется в plain-JSON (число / quoted-строка / `true`/`false` / `null` / array / object), БЕЗ тегированной обёртки `{"т","зн"}` (тегированный кодек `store` не годится).

### User Story 3 — Сбой реального вызова → `ОшибкаВыполнения` (активация `runtimeErrWrap`) (Priority: P2)

При активном `webhookCaller` сетевой или HTTP-сбой внешнего вызова возвращает ошибку, которая на стороне eval заворачивается в `errors.ОшибкаВыполнения` с цепочкой `Cause` (через `runtimeErrWrap`). Это ЕДИНАЯ категория сбоя внешнего вызова (statement-форма `вызвать`/`уведомить` и `вызвать`-выражение — все три точки). Под дефолт-стабом ошибки нет (стаб всегда успешен).

**Why this priority**: Закрывает TODO(D-14, §AU-4.4): без обёртки реальный сбой драйвера потерял бы цепочку причины (`errors.As/Is`). P2 — сопутствует US2: реальный драйвер впервые делает возможным сбой, который раньше был недостижим под стабом.

**Independent Test**: Сконструировать `webhookCaller` на неотвечающий/возвращающий 5xx адрес, исполнить `вызвать crm(x)`, убедиться, что eval вернул `errors.ОшибкаВыполнения` с непустой цепочкой `Cause` (через `errors.As`), а не голую строковую ошибку без причины.

**Acceptance Scenarios**:

1. **Given** `webhookCaller`, чей `httpClient` упирается в сетевой сбой, **When** исполняется `вызвать crm(x)` (выражение), **Then** eval возвращает `errors.ОшибкаВыполнения`, чья цепочка `Cause` содержит исходную ошибку драйвера (проверяемо `errors.As`/`errors.Is`).
2. **Given** тот же сбойный драйвер, **When** исполняется statement-форма `вызвать crm(x)` и `уведомить ИТ`, **Then** обе точки (`evalCallAction`, `evalNotifyAction`) тоже дают `errors.ОшибкаВыполнения` через `runtimeErrWrap` — единая категория (не «категория Процесса», не голая строка).
3. **Given** дефолт-стаб (`printCaller`), **When** исполняется любой `вызвать`/`уведомить`, **Then** ошибки НЕТ; `вызвать`-выражение возвращает `Пусто`; печать-стаб сохраняет наблюдаемый вывод.

---

### User Story 4 — CLI-проводка `--вебхук` / `LADIX_WEBHOOK` и ошибка неверного URL (Priority: P2)

CLI-команды, участвующие в эффектах (`run`, `serve`, `complete`, `start`), принимают `--вебхук <URL>` или env `LADIX_WEBHOOK`. Заданный валидный URL → движок строится с `WithExternalCaller(webhookCaller{...})`; не задан → дефолт-стаб. Невалидный URL → диагностика `ladix: неверный URL вебхука '<URL>'` в stderr, exit 2. Под `serve` вебхук проводится в ТОТ ЖЕ экземпляр движка, чьи `Notify`/`Call` зовёт догон дедлайнов и тело триггеров.

**Why this priority**: Без CLI-проводки реальный драйвер недостижим из командной строки (только из тестов). Критично для DoD §AU-12.C: эскалация под `serve` обязана идти на реальный вебхук, а не печатать стаб. P2 — опирается на US2 (сам драйвер) и US1 (дефолт без флага).

**Independent Test**: Запустить `run`/`serve`/`complete`/`start` с `--вебхук <валидный httptest-URL>` и убедиться, что эффекты идут `POST` на этот URL; запустить с `--вебхук '://мусор'` и убедиться, что stderr = `ladix: неверный URL вебхука '://мусор'\n`, exit 2; запустить без флага — дефолт-стаб.

**Acceptance Scenarios**:

1. **Given** `run <файл> --вебхук <httptest-URL>` с программой, делающей `уведомить ИТ: x`, **When** команда исполняется, **Then** `httptest`-сервер получает `POST` с телом `{"цель":"ИТ","данные":["x"]}` (стаб НЕ печатается).
2. **Given** env `LADIX_WEBHOOK=<httptest-URL>` без флага `--вебхук`, **When** исполняется `run <файл>`, **Then** эффект идёт на URL из env (флаг и env — оба источника активации).
3. **Given** `run <файл> --вебхук '<невалидный URL>'`, **When** команда исполняется, **Then** в stderr печатается ровно `ladix: неверный URL вебхука '<невалидный URL>'\n` и процесс завершается с кодом 2; stdout пуст; движок не запускается.
4. **Given** `serve <файл> --db <путь> --вебхук <httptest-URL>` с процессом, эскалирующим задачу по дедлайну, **When** догон дедлайнов вызывает тело эскалации с `уведомить`/`вызвать`, **Then** эффект идёт `POST` на вебхук (тот же экземпляр движка), а не печатается стабом — §AU-4.5 / §AU-12.C.
5. **Given** любая из четырёх команд (`run`/`serve`/`complete`/`start`) БЕЗ `--вебхук` и без env, **When** она исполняется, **Then** активен дефолт-стаб `printCaller`, наблюдаемый вывод §EN-7 байт-точно прежний.

### Edge Cases

- **Имя цели — логическое, не URL**: `.ladix` содержит `crm`/`ИТ` как логические имена; физический URL приходит ТОЛЬКО снаружи (`--вебхук`/env). Тело запроса несёт логическое имя в поле `цель`, путь отступления к реестру интеграций — через это имя (§AU-4.3 / D-AU-2). `.ladix` остаётся чистым.
- **Энкодер тела — НОВЫЙ (value → plain-JSON)**: существующий `store/codec.encodeValue` даёт ТЕГИРОВАННЫЙ `{"т","зн"}` (не валиден для внешней системы); `value.String` — дисплей-репр, не JSON. Парный энкодер тела вебхука пишется с нуля: `Целое/Дробное`→число, `Строка`→quoted, `Булево`→`true`/`false`, `Пусто`→`null`, `Список`→array, `Запись`→object; `Дата/Длительность/Период` → строковая форма (решение impl, задокументировать). Это структурное требование, не опция.
- **Декодер ответа — лифт существующего `decodeValue`**: ответ `Call` декодируется через `decodeValue` (одно значение любого типа), НЕ `payloadToRecord` (тот жёстко требует объект). JSON-объект → `Запись`, скаляр → `Value`. Декодер и энкодер живут в нейтральном к слоям пакете `internal/jsonval` (НЕ в `eval`, иначе утечка JSON во фронтенд; НЕ в `internal/value`).
- **Пустое тело ответа**: `decodeValue` на пустом потоке вернёт `io.EOF` (не Пусто). Поэтому `webhookCaller` проверяет пустое тело ДО `decodeValue` и возвращает `Пусто`.
- **`Notify` best-effort**: ответ `уведомить`-вебхука игнорируется (нет захвата результата у statement-формы). Сетевой/HTTP-сбой `Notify` всё равно → `error` → `ОшибкаВыполнения` через `runtimeErrWrap`.
- **Тайм-аут клиента — конечный**: `httpClient` имеет конечный тайм-аут (напр. 10с); конфигурируемость — путь отступления в M3. Реальный POST в тестах — только под `net/http/httptest` (stdlib), без живой сети.
- **`serve` — единый экземпляр движка**: критично, что `--вебхук` под `serve` проводится в ТОТ ЖЕ движок, чьи `Notify`/`Call` зовёт догон дедлайнов и тело триггеров (§AU-4.5). Иначе эскалация печатает стаб вместо доставки — тихий разрыв §AU-12.C.
- **§EN-7 golden цел дефолтом**: дефолт-драйвер `printCaller` — это перенесённая текущая печать-логика движка байт-в-байт; пины `engine_test 108/167/176/185/194` и `main_test 117/200/235` НЕ ломаются. Option-дефолт не меняет наблюдаемый вывод без `--вебхук`.
- **Шов eval↔engine не расширяется**: B1 уже дал `CallExternalResult` (8-й метод). B2 — внутри engine; `ProcessRuntime` остаётся 8 методов; `eval` по-прежнему не импортирует `store`/`engine`.
- **`метрика`/`tasks`/`emit` не получают `--вебхук`**: проводка только в командах, выполняющих программу с эффектами (`run`/`serve`/`complete`/`start`, §AU-4.5 / §AU-9). `metric` остаётся MemoryStore без вебхука.

## Requirements *(mandatory)*

### Functional Requirements

**Драйвер и Option движка (§AU-4.1):**

- **FR-001**: Система ОБЯЗАНА определить интерфейс драйвера внешних эффектов `ExternalCaller` с методами `Call(target string, args []value.Value) (value.Value, error)` (вызвать → результат) и `Notify(target string, args []value.Value) error` (уведомить → эффект).
- **FR-002**: Движок ОБЯЗАН получить поле-драйвер, инжектируемое Option'ом `WithExternalCaller(c ExternalCaller) Option` (паттерн `WithClock`). По умолчанию (без Option) поле = `printCaller{out: e.out}`.
- **FR-003**: Методы движка `CallExternalResult` / `CallExternal` / `Notify` ОБЯЗАНЫ делегировать драйверу (`e.caller`); `CallExternal` = `CallExternalResult` с отбросом значения (эффект не дублируется).

**Дефолт-драйвер `printCaller` (§AU-4.2 / §EN-7):**

- **FR-004**: Дефолт-драйвер `printCaller` ОБЯЗАН печатать те же байт-точные форматы, что текущая логика движка: `[вызов] %s(%s)\n` (аргументы через `", "`, `parts[k]=value.String(args[k])`), `[уведомление] %s\n` при `len(args)==0`, `[уведомление] %s: %s\n` при `len(args)>=1` (аргументы через один пробел `" "`). `Call` возвращает `(value.None, nil)`.
- **FR-005**: Все существующие golden-пины §EN-7 (`TestNotifyCallFormats` и семья; `engine_test 108/167/176/185/194`, `main_test 117/200/235`) ОБЯЗАНЫ проходить байт-в-байт без изменения ожидаемого текста: дефолт-драйвер = текущая логика, перенесённая в `printCaller`. Конструкция движка БЕЗ `WithExternalCaller` даёт наблюдаемый вывод, идентичный v1.

**Реальный драйвер `webhookCaller` (§AU-4.3):**

- **FR-006**: Реальный драйвер `webhookCaller{ baseURL, httpClient }` ОБЯЗАН делать `POST <baseURL>` с заголовком `Content-Type: application/json` и телом JSON `{"цель": <target>, "данные": [<args как JSON>]}` (логическое имя цели — в payload).
- **FR-007**: Кодирование `args` (value → plain-JSON) ОБЯЗАНО выполняться НОВЫМ энкодером (НЕ тегированный `store/codec.encodeValue`, НЕ дисплей `value.String`): `Целое/Дробное`→число, `Строка`→quoted, `Булево`→bool, `Пусто`→`null`, `Список`→array, `Запись`→object; `Дата/Длительность/Период` → строковая форма (решение impl, задокументировать).
- **FR-008**: Ответ `Call` ОБЯЗАН декодироваться через `decodeValue` (одно значение любого типа): JSON-объект → `Запись`, скаляр → `Value`. ПУСТОЕ тело ответа ОБЯЗАНО проверяться в `webhookCaller` ДО `decodeValue` и давать `Пусто` (`value.None`) — `decodeValue` на пустом потоке вернул бы ошибку.
- **FR-009**: `Notify` ОБЯЗАН игнорировать тело ответа (best-effort); эффект исполняется без захвата результата.
- **FR-010**: Декодер ответа и энкодер тела ОБЯЗАНЫ жить в нейтральном к слоям пакете (целевой — `internal/jsonval`), импортируемом `engine`. Пакет НЕ ОБЯЗАН импортироваться из `eval` (иначе утечка JSON во фронтенд) и НЕ кладётся в `internal/value`. **Почему лифт, а не вызов на месте:** декодер сейчас живёт в `daemon`, но `engine` НЕ может импортировать `daemon` — ребро `daemon→engine` уже существует (`daemon/daemon.go:19`, `daemon/restart.go:6`), импорт в обратную сторону дал бы циклическую зависимость. Поэтому декодер ОБЯЗАН переехать в нейтральный `internal/jsonval`, импортируемый и `engine`, и `daemon` (§AU-4 / §AU-5.2).
- **FR-010a (создание пакета — за B2)**: Пакет `internal/jsonval` СОЗДАЁТСЯ в B2 (014): лифт декодера (`DecodeValue` + зависимости) из `daemon` + НОВЫЙ энкодер тела. B3 (015 — payload задачи через `complete`) этот пакет НЕ создаёт и НЕ лифтит повторно — он ТОЛЬКО потребитель (`PayloadToRecord` для `--данные`→`Запись` + CLI/инжект payload, §AU-5.3). Мнимое дублирование scope B2↔B3 этим снимается.
- **FR-011**: `httpClient` драйвера ОБЯЗАН иметь конечный тайм-аут. Реальный сетевой POST в тестах ОБЯЗАН выполняться только под `net/http/httptest` (stdlib); живая сеть в тестах не используется.

**Обёртка ошибок исполнения (§AU-4.4 — активация D-14):**

- **FR-012**: Сетевой/HTTP-сбой реального драйвера (`Call` или `Notify`) ОБЯЗАН возвращать `error`, который на стороне eval заворачивается в `errors.ОшибкаВыполнения` с цепочкой `Cause` через `runtimeErrWrap` — ЕДИНАЯ категория сбоя внешнего вызова (не «категория Процесса»).
- **FR-013**: Все три точки исполнения внешних эффектов ОБЯЗАНЫ использовать `runtimeErrWrap`: `evalCallAction` (statement `вызвать`, `eval/stmt.go:118`), `evalNotifyAction` (statement `уведомить`, `eval/stmt.go:138`), `evalExpr(*CallExternalExpr)` (выражение, уже стоит из B1). Сопутствующие TODO(D-14)-комментарии (`eval/stmt.go:113-115` / `:133-136`) удаляются; сбой реального драйвера несёт цепочку `Cause` (для `errors.As/Is`).
- **FR-014**: Под дефолт-стабом (`printCaller`) ОБЯЗАНО НЕ быть ошибки внешнего вызова: `Call` всегда `(value.None, nil)`, `Notify` всегда `nil`.

**CLI-проводка (§AU-4.5 / §AU-9):**

- **FR-015**: Команды `run`, `serve`, `complete`, `start` ОБЯЗАНЫ принимать `--вебхук <URL>` ИЛИ env `LADIX_WEBHOOK`. Заданный валидный URL → движок строится с `WithExternalCaller(webhookCaller{baseURL, httpClient})`; не задан → дефолт-стаб `printCaller`.
- **FR-016**: Невалидный URL вебхука ОБЯЗАН давать диагностику ровно `ladix: неверный URL вебхука '<URL>'` в **stderr**, exit 2 (§AU-10.C / §EN-8.B); движок не запускается, stdout пуст.
- **FR-017**: Под `serve` `--вебхук` ОБЯЗАН проводиться в ТОТ ЖЕ экземпляр движка, чьи `Notify`/`Call` зовёт догон дедлайнов (`checkDeadlines → fireDeadlineBody`) и тело метрика/событие-триггеров (§AU-4.5 / §AU-12.C). Иначе эскалация под `serve` напечатает стаб вместо реальной доставки.

**Границы и инварианты:**

- **FR-018**: B2 НЕ ОБЯЗАН менять шов `ProcessRuntime` (остаётся 8 методов; B1 уже дал `CallExternalResult`); пакет `eval` по-прежнему НЕ импортирует `store`/`engine`.
- **FR-019**: B2 НЕ ОБЯЗАН добавлять внешних зависимостей (go.mod: единственная `modernc.org/sqlite`; `net/http/httptest` — stdlib). Исполнение детерминировано; реальный HTTP только под `httptest`.
- **FR-020**: B2 НЕ ОБЯЗАН менять грамматику/AST/лексер/парсер и НЕ вводит новых синтаксических/семантических диагностик; единственная новая диагностика — CLI-ошибка неверного URL (FR-016).

### Key Entities

- **`ExternalCaller`** (новый интерфейс engine): драйвер внешних эффектов. Методы: `Call(target, args) (value, error)`, `Notify(target, args) error`. Инжектируется Option'ом, дефолт — `printCaller`.
- **`WithExternalCaller`** (новый Option движка): ставит поле-драйвер (паттерн `WithClock`). Без Option → `printCaller{out: e.out}`.
- **`printCaller`** (дефолт-драйвер): печать-стаб §AU-4.2; держит §EN-7 golden байт-точно; `Call` → `(value.None, nil)`, `Notify` → печать + `nil`.
- **`webhookCaller`** (реальный драйвер): `{ baseURL string, httpClient *http.Client }`; `POST` JSON `{"цель","данные"}` на вебхук; `Call` декодирует ответ (или `Пусто` при пустом теле), `Notify` best-effort.
- **Энкодер тела (`value → plain-JSON`)** (новый, `internal/jsonval`): сериализует аргументы без тегированной обёртки.
- **Декодер ответа** (`decodeValue`, лифт в `internal/jsonval`): JSON → `value.Value`; объект → `Запись`, скаляр → `Value`.
- **CLI-флаг `--вебхук` / env `LADIX_WEBHOOK`**: источник базового URL; активирует `webhookCaller` в `run`/`serve`/`complete`/`start`. Невалидный URL → CLI-ошибка (FR-016).

- **SC-001**: Движок, сконструированный БЕЗ `WithExternalCaller`, печатает `вызвать`/`уведомить` байт-в-байт по §AU-4.2/§EN-7; все существующие golden-пины §EN-7 (≥6: `engine_test 108/167/176/185/194`, `main_test 117/200/235`) проходят без изменения ожидаемого текста.

- **SC-003**: `присвоить ответ = вызвать crm(клиент)` под `webhookCaller` с ответом-объектом даёт `ответ` = декодированную `Запись`; с пустым телом ответа — `Пусто` (`value.None`).
