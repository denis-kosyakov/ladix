# Contract: Движок метрики (конвейер вычисления §SM-8)

**Feature**: 004-source-metric | **Источники**: docs/source-metric-model.md §SM-8 (конвейер), §SM-8.1 (загрузчик), §SM-8.2 (окна), D-9 (контексты), §SM-9.B/C (ошибки), §SM-10 (golden); SPEC §10.2/§10.3/§10.4/§10.5, §9. Решения **R2** (нет store), **R3** (проекция поверх агрегатов), **R4** (Clock), **R6** (Ident→метрика).

**Чистая функция** от данных источника и `Clock.Now()`: чтение метрики `M` (из CLI `metric`, из императива по имени — D-8/R6, из триггера в будущем) запускает конвейер `SPEC §10.2` дословно. Никакого `internal/store`/`internal/engine` (§SM-12, R2): движок живёт в `internal/eval` (либо подпакете), переиспользует существующий `Interpreter`/`Environment`/билтины-агрегаты.

## ME-1. Сигнатура чистой функции

```go
// Вычисляет одну метрику. Чистая по входам: тот же источник + та же Clock.Now() → тот же результат.
func (i *Interpreter) evalMetric(m *ast.MetricDecl) (value.Value, error)
```

Вход (всё доступно через `*Interpreter`, R2 — без отдельного store):
- `m *ast.MetricDecl` — узел метрики (поля `Name, Source Ident, Where Expression?, Aggregate Expression, Period Expression?, ByDate Expression?, Attrs MetricAttrPos`, §SM-2);
- **реестр источников** — `i.sources map[string]*ast.SourceDecl` (заполнен `Analyze`, §SM-4); `m.Source.Name` уже провалидирован семпроходом как зарегистрированный источник;
- **загрузчик** — `i.loadSource(name) ([]value.Запись, error)` (ME-5, ленивый + кеш на запуск);
- **clock** — `i.clock` (R4, [clock](./clock.md)); `D = i.clock.Now()`.

Выход: `(value.Value, error)`. Успех → скаляр (`Целое`/`Дробное`/`Пусто`/…); ошибка → `ОшибкаВыполнения`/`ОшибкаТипа` с позицией подвыражения (§SM-9.B/C).

> **R6 / D-8 (Ident-как-значение).** `evalIdent` после промаха `env.Lookup` и **до** ветки «функция/не объявлено» проверяет реестр источников (→ `ОшибкаВыполнения «'<имя>' — источник, его нельзя использовать как значение»`) и реестр метрик (найдено → `i.evalMetric(...)` с защитой от цикла, ME-7). См. [cli-metric](./cli-metric.md) и §SM-9.B.

## ME-2. Контексты вычисления атрибутов (D-9 — критично)

| Атрибут | Когда вычисляется | Область (scope) | Ожидаемый тип |
|---|---|---|---|
| `источник` | не вычисляется | — (имя источника, D-1) | — |
| `период` | **один раз**, до записей | глобальная (предопр. периоды + глобали) | `Период` (иначе §SM-9.B `«'период' должно давать Период, получено <тип>»`) |
| `по_дате` | **на каждой записи** | scope полей записи (§6 + §9.5) | `Дата` или `Пусто` (иначе §SM-9.C) |
| `где` | **на каждой записи** | scope полей записи | `Булево` (иначе §SM-9.C) |
| `агрегат` | один раз; **аргументы агрегатных функций — проекции на каждой записи** | агрегат-узлы: scope полей; вне их: глобаль/константы/др. метрики | скаляр |

**Scope полей записи** — окружение, в котором голое имя `x` резолвится: глобаль/функция/встроенное → как обычно ([eval-core](/tmp/ladix004map/eval-core.md) §3); иначе известное поле схемы → значение записи (нет в данной записи → `Пусто`); иначе → §SM-9.C `«неизвестное поле»`. Реализация — дочерний `Environment` поверх `i.global` с предзаполненными полями записи, либо спец-резолвер. Доступ `запись.поле` (`FieldExpr`) — толерантный (`Запись.Get` → `None` без проверки схемы, [values](../../003-interpreter-eval/contracts/values.md)).

## ME-3. Конвейер (§SM-8, шаги §10.2)

1. **Загрузка источника** (ME-5). 0 записей → короткое замыкание на пустой результат (шаг 5).
2. **Окно периода.** Если `период:` задан → вычислить `Период` глобально (ME-2); по нему и `D = Clock.Now()` построить `[начало, конец]` (включительно) календарной арифметикой (ME-6). Нет `период:` → окна нет (фильтр по дате тривиально проходит).
3. **Фильтрация** (в порядке записей источника). Для каждой записи в scope полей:
   1. если `период:` задан: вычислить `по_дате` → `d`. `d == Пусто` → **исключить** (без `где`, без ошибки, §10.4). `d` не `Дата` → §SM-9.C `«'по_дате' должно давать Дата или Пусто, получено <тип>»`. Иначе оставить, если `начало ≤ d ≤ конец` (через `value.Compare`, §SM-5), иначе исключить;
   2. вычислить `где` (если задан) → `Булево` (иначе §SM-9.C `«'где' должно давать Булево, получено <тип>»`); `ложь` → исключить. `где` отсутствует → `истина`.
4. **Агрегат** (§10.3, R3 — ME-4). Вычислить выражение `агрегат`.
5. **Пустой результат** (§10.5, ME-8). Нет выживших → `Целое 0` (корневой единичный `сумма`/`количество`) либо `Пусто` (иначе).

## ME-4. Агрегат-проекция поверх существующих билтинов (R3)

Существующие агрегаты `сумма/количество/среднее/мин/макс` — `ArityFixed N=1`, принимают готовый `value.Список` через `requireList` ([builtins-карта](/tmp/ladix004map/builtins.md) §4); механизма проекции у них НЕТ. Движок метрики **строит проекцию сам** и зовёт существующий `Builtin.Fn`:

Для каждой агрегатной функции `f(arg)` внутри выражения `агрегат`:
1. вычислить `arg` (выражение-аргумент) **на каждой выжившей записи** в scope полей;
2. собрать `value.Список`, **пропуская записи, где `arg` дал `Пусто`** (§10.3);
3. вызвать существующий `Builtin.Fn` агрегата с этим списком (`b.Fn(i, []value.Value{проекция}, pos)`).

Правила §10.3 (ловит движок при вычислении выражения `агрегат`, не парсер/семпроход — D-6):
- **Голое поле вне агрегатной функции** (`агрегат: сумма_заказа`) → §SM-9.C `«поле '<имя>' использовано вне агрегатной функции»`;
- **Вложенный агрегат** (`сумма(среднее(...))`) → §SM-9.C `«вложенный агрегат недопустим»`;
- `количество(запись)` / иное не-полевое выражение-аргумент — проекция даёт по элементу на запись (для `количество` важна длина выжившего списка).

> Существующие билтины-агрегаты **переиспользуются как есть**: их пустой-список-поведение (`сумма`/`количество` → `0`; `среднее`/`мин`/`макс` → `«<имя>: список пуст»`) перекрывается правилом §10.5 на уровне движка (ME-8) — до вызова `Fn` при нуле выживших.

## ME-5. Загрузчик источника (§SM-8.1)

```go
func (i *Interpreter) loadSource(name string) ([]value.Запись, error) // ленивый, кеш на запуск
```

- **Путь:** `SourceDecl.File` (строковый литерал, §SM-2) относительно **cwd** процесса (§9.1); абсолютный — как есть.
- **Лень + кеш на запуск** (§9.6): файл читается при первом обращении любой метрики; результат кешируется до конца `run`/`metric`/тика `serve` (`i.sourceCache map[string][]value.Запись`).
- **Разбор JSON** (§9.2): верхний уровень — массив объектов. Используется `json.Decoder` с `UseNumber()`, затем разбор `json.Number` (различение целое/дробное по форме токена).
- **Маппинг JSON→`Value`** (§9.3): `null→Пусто`; `bool→Булево`; строка→`Строка` (**даты НЕ распознаются**); число без `.`/`e`/`E`→`Целое` (вне `int64` → §SM-9.B); число с `.`/экспонентой→`Дробное`; массив→`Список`; объект→`Запись` (рекурсивно, через `value.NewRecord(keys, fields)`).
- **Схема (§9.5):** объединение ключей по **всем** записям; в сообщении «неизвестное поле» список известных полей — **отсортирован по возрастанию** (детерминизм golden). На **пустом** источнике схема пуста → опечатку поля не поймать (§9.7) — осознанная цена.

**Ошибки загрузки (§SM-9.B, дословно, поз. объявления `источник`):**
```
источник '<имя>': файл «<путь>» не найден
источник '<имя>': не удалось прочитать файл «<путь>»
источник '<имя>': ожидался JSON-массив объектов в «<путь>»
источник '<имя>': запись N не является объектом
источник '<имя>': некорректный JSON в «<путь>» (<деталь>)
источник '<имя>': запись N, поле '<поле>': целое число вне диапазона
```
`N` — номер записи **с 1**.

## ME-6. Календарные окна (§SM-8.2, дословно, `D = Clock.Now()`)

Окно — **полный** календарный период, содержащий `D` (не усечён по `D`):

| `Период` | `[начало, конец]` (включительно) |
|---|---|
| `ежедневно` | `[D, D]` |
| `еженедельно` | ISO-8601 неделя пн–вс, содержащая `D` |
| `ежемесячно` | `[Дата(Y,M,1), Дата(Y,M,послед_день)]` |
| `ежеквартально` | Q1 `[1.01,31.03]`, Q2 `[1.04,30.06]`, Q3 `[1.07,30.09]`, Q4 `[1.10,31.12]` (по `M`) |
| `ежегодно` | `[Дата(Y,1,1), Дата(Y,12,31)]` |

- Послед. день месяца — с учётом високосного (фев = 29 в високосный, григорианское правило).
- ISO-неделя: понедельник — первый день; `начало = D − (ISO_номер_дня(D) − 1)` дней, `конец = начало + 6`. Реализация — `time.Time.Weekday()` (Go Sun=0 → преобразовать к ISO Mon=1…Sun=7) или `ISOWeek` + смещения; окно может пересекать границу месяца.
- Граница **включительна** с обеих сторон: `по_дате == начало` или `== конец` — внутри.
- Арифметика границ — служебная Go (`time.Date(...)` UTC, обратно в `value.Дата`); `Длительность` Ladix тут ни при чём (§SM-0). Границы — `value.Дата`, сравниваются `value.Compare`.

## ME-7. Цикл зависимостей метрик (D-8/R6)

- Чтение метрики по имени запускает пересчёт (ME-1). Движок ведёт стек активных метрик; повторный вход в уже считающуюся → §SM-9.B `«цикл зависимостей метрик: <имя> → … → <имя>»` (цепочка имён через ` → `).
- Реализация — `i.metricStack []string` (push на входе `evalMetric`, pop на выходе); при повторе имени собрать срез от первого вхождения до текущего.

## ME-8. Пустой результат (§10.5, перекрывает поведение билтинов)

Нет выживших записей:
- корневой `агрегат` — единичный `сумма(...)` / `количество(...)` → `value.Целое{V: 0}`;
- иначе (единичные `среднее`/`мин`/`макс`, деривативные выражения) → `value.None` (`Пусто`).

**Короткое замыкание ДО вызова агрегата** (R3): при нуле выживших движок **не** зовёт `Fn` агрегата (иначе `среднее`/`мин`/`макс` дали бы `«<имя>: список пуст»` §8.3, что в контексте метрики §10.5 запрещено). Правило §10.5 перекрывает поведение функций общего назначения.

## ME-9. Реестр ошибок вычисления (§SM-9.C, дословно — без завершающей точки)

```
неизвестное поле '<имя>' (известные: <поле1>, <поле2>, …)   // голое имя ∉ схема/глобаль/функция (поля отсортированы)
'по_дате' должно давать Дата или Пусто, получено <тип>
'где' должно давать Булево, получено <тип>
поле '<имя>' использовано вне агрегатной функции            // §10.3 голое поле
вложенный агрегат недопустим                                // §10.3 сумма(среднее(...))
'период' должно давать Период, получено <тип>               // §SM-9.B, период: не Период
```
`<тип>` = `value.TypeName()`; позиция = `Pos()` подвыражения; одинарные `'…'` — имена атрибутов/полей.

## ME-10. Границы (§SM-12)

- Один источник на метрику; второй источник, `тип:`-атрибуты, кеш значения метрики, скользящие/«последний завершённый» окна — v2.
- Авто-распознавание дат-строк, NDJSON/CSV, live-reload, таймзоны — v2 (`SPEC §12`).
- Движок не печатает записи (`repr` `Запись` нерелевантен метрикам) и не мутирует источник.
- `процесс`/`шаг`/`когда`, `internal/engine`/`internal/store` — 005/006 (R2).
