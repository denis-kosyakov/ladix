## D-R1. Решения архитектора D-1…D-9 (§SM-1) — приняты, не переоткрываются

- **Decision**: девять развилок зафиксированы дословно по [§SM-1](../../docs/source-metric-model.md):
  - **D-1** — `метрика.источник:` читается парсером как **`Ident`-only** (ровно один `IDENT` через
    `parseSourceRef`), не общее `Expression`. Это **синтаксис**, не семантика (имя не резолвится в
    парсере) → guardrail 7 (парсер не разрешает имена) не нарушен. Прочие атрибуты
    (`где`/`агрегат`/`период`/`по_дате`) — полноценные `Expression`.
  - **D-2** — атрибуты хранятся **типизированными полями** на `SourceDecl`/`MetricDecl`
    (nullable-указатели для опциональных) **плюс** структура `MetricAttrPos` с позицией ключевого
    слова каждого присутствующего атрибута (для точной диагностики), а не узлами-обёртками.
  - **D-3** — **дубликат / неизвестный атрибут ловит парсер структурно** (`ОшибкаРазбора`): набор
    имён фиксирован грамматикой `MetricAttr ::= (источник|где|агрегат|период|по_дате)`, поэтому
    неизвестное имя и повтор — структура блока, не разрешение имён → guardrail 7 соблюдён.
  - **D-4** — **обязательность `источник`/`агрегат` и связку `период↔по_дате` ловит семпроход**
    (стадия 3, `СемантическаяОшибка`): это кросс-атрибутные правила, парсер их не проверяет.
  - **D-5** — **поля записи как идентификаторы разрешаются eval-time**: `где`/`агрегат`/`по_дате`
    парсятся как обычные `Expression`, неопределённое имя трактуется как поле текущей записи **на
    исполнении** (после загрузки источника, когда известна схема §9.5).
  - **D-6** — **голое поле вне агрегата и вложенный агрегат — eval-time** (§10.3), не парсер:
    парсер принимает любой `Expression` в `агрегат:`, нарушение проекции ловит движок метрики.
  - **D-7** — **детерминизм `сегодня()` — через `Clock`-инъекцию** (см. D-R3); прямой `time.Now()`
    в `eval`/движке запрещён, в тестах — фикс-дата `2026-05-31`.
  - **D-8** — **имя метрики как значение разрешается eval-time через `Ident`**: отдельного узла
    `MetricRef` нет, при вычислении `Ident`, не найденного среди переменных/функций/встроенных,
    движок проверяет реестр метрик и, найдя, **запускает пересчёт** (цикл → ошибка).
  - **D-9** — **`период:` вычисляется один раз, в глобальной области** (не per-record): даёт
    значение `Период`. `где`/`по_дате`/проекции агрегата — per-record в scope полей.
- **Rationale**: §SM-1 помечает эти решения «обязательны к исполнению». Они закрывают ровно те
  дыры, что `SPEC §9/§10` оставляет открытыми (формы AST, граница парсер↔семпроход↔eval, контексты
  вычисления атрибутов). Дублировать их обсуждение в коде/задачах нельзя — это породило бы дрейф;
  research лишь фиксирует их как вход. D-2 (`MetricAttrPos` отдельной структурой) важна именно для
  позиционной диагностики «дубликат `где`» / «`период` без `по_дате`» на строке конкретного
  атрибута, а не на начале блока ([§SM-2](../../docs/source-metric-model.md)).
- **Alternatives considered**: каждая развилка имеет отвергнутую альтернативу в §SM-1 —
  `источник:` как `Expression` (D-1, отвергнут: тянет разрешение имён в парсер), узлы-атрибуты
  вместо полей (D-2, отвергнут: избыточные обёртки), ловить дубликат/тип в семпроходе/eval (D-3,
  отвергнут: имена атрибутов статичны), узел `MetricRef` (D-8, отвергнут: лишний AST-узел при том,
  что `Ident` достаточно). Переоткрытие любой из них — нарушение §SM-1.
- **Статус**: РЕШЕНЫ архитектором. FR-001…FR-012, FR-031/032. Источник — §SM-1.

## D-R2. Формат `Дробное` — Вариант A: фиксированная запись для бизнес-диапазона (R1)

- **Decision**: переписать `value/repr.go::formatFloat`
  ([repr.go:208-214](../../src/internal/value/repr.go)). Сейчас он отдаёт
  `strconv.FormatFloat(f,'g',-1,64)` и для `1000000.0` даёт `"1e+06"` — баг для бизнес-диапазона
  (наличие `e` гасит достройку `.0`). Новая политика (**Вариант A**, одобрен владельцем):
  - `|f| ∈ [1e-4, 1e16)` → **фиксированная** запись (`'f'`, минимальная точность без потери), для
    integer-looking результата добавить `.0`;
  - очень большие/малые (`|f| ≥ 1e16`, `0 < |f| < 1e-4`) → научная `'g'`;
  - `0`, `NaN`, `±Inf` — штатно (`0.0`; `g`-представление).
  - Итог: `2175→"2175.0"`, `3.4→"3.4"`, `1000000→"1000000.0"`, `1000000.5→"1000000.5"`,
    `1e20→"1e+20"`. Достройка `.0` сохраняется по прежнему предикату (нет `.`/`e`/`E`/`n`/`i`).
- **Rationale**: порог `1e16` — точка, за которой `float64` теряет целочисленную точность (мантисса
  53 бита ≈ `9.007e15`), поэтому фиксированная запись осмысленна именно в `[1e-4, 1e16)`; за ней
  sci честнее. Сохранность регресса `repr_test.go:20` доказуема: `1e20 ≥ 1e16` → ветка `'g'` →
  `"1e+20"` (поведение не меняется); все существующие кейсы `< 1e16` уже были фиксированными
  (`3.4`, `2175.0`), их вывод стабилен. Метрика `среднее` в golden-таблице
  ([§SM-10](../../docs/source-metric-model.md)) даёт `1000000.0` — без R1 напечаталось бы `1e+06`,
  SC-001 строка «среднее» падала бы. Синхронно правятся **`eval-model.md §7`** (политика формата —
  добавить порог `1e16`) и **`source-metric-model.md §SM-5`** (снять оговорку «repr не трогаем»);
  в `repr_test.go` добавить кейсы `1000000.0→"1000000.0"`, `1000000.5→"1000000.5"`.
- **Alternatives considered**:
  - Оставить чистый `'g'` (статус-кво) — **отвергнут**: даёт `1e+06` для миллиона, ломает SC-001 и
    различимость бизнес-чисел (карта `value.md:237` фиксирует баг).
  - Всегда `'f'` без верхней границы — **отвергнут**: `1e20` напечатался бы как
    `100000000000000000000.0` с накопленным мусором младших разрядов (потеря обратимости), ломает
    `repr_test.go:20`.
  - Трогать `строка()`/`печать` отдельно от `repr` — **отвергнут**: §7/FR-030 требуют **единое**
    представление; `formatFloat` — единственная точка.
- **Статус**: РЕШЁН (R1, Вариант A одобрен владельцем). Edge Case «различение целого/дробного».

## D-R3. Инъекция `Clock` — третий параметр `NewInterpreter`, не предопределённый ident (R4)

- **Decision**: расширить `eval.NewInterpreter(out io.Writer, maxDepth int)`
  ([interpreter.go:28-42](../../src/internal/eval/interpreter.go)) **третьим** параметром
  `clock Clock`; добавить поле `i.clock` рядом с `out io.Writer`
  ([interpreter.go:17-26](../../src/internal/eval/interpreter.go)). Интерфейс
  `Clock interface{ Now() Дата }` (усечение `time.Time` до `Y/M/D` — в реализации). `сегодня()`
  читает **только** `i.clock`; вычисление окна периода — тоже. Реализации: `SystemClock{}`
  (прод — `time.Now()` в `time.Local`, усечён до даты) и `FixedClock{Дата{2026,5,31}}` (тесты).
  Значение фиксируется на запуск (§10.6). Обновить **всех** вызывающих: `cmd/ladix`
  ([main.go runFile:108](../../src/cmd/ladix/main.go)) и **все** eval-тесты, дёргающие
  `NewInterpreter`, — добавить clock-аргумент.
- **Rationale**: в `Interpreter` **нет** готового канала (нет `store`-параметра), через который
  `Clock` прошёл бы неявно (карта `eval-core.md:51` это подтверждает) — значит нужен явный
  параметр конструктора. Билтины получают `*Interpreter` первым аргументом
  (`b.Fn(i, args, c.Pos())`, [call.go callBuiltin:81-94](../../src/internal/eval/call.go)),
  поэтому `Clock`-поле `i` **автоматически** доступно `builtinSegodnya` без отдельного протаскивания.
  Запрет прямого `time.Now()` в `eval`/движке — зеркало того, как вывод идёт только через
  инъектированный `out`, а не `os.Stdout`: единая дисциплина детерминизма
  ([§SM-7](../../docs/source-metric-model.md)). Без инъекции golden недетерминирован (май ≠ июнь),
  SC-006 невыполним.
- **Alternatives considered**:
  - Предопределённый ident `сегодня` в `global` со значением даты — **отвергнут**: глобальная
    область (`parent=nil`) хранит **только** переменные; функции/встроенные живут в отдельных map
    (`eval-core.md:158`), а дата-как-ident потеряла бы перевычисление и нарушила «нет
    предопределённых идентов в global» (кроме периодов §SM-5).
  - Скрытый пакетный `var now = time.Now` с подменой в тестах — **отвергнут**: глобальное
    состояние, не `-race`-чистое, ломает конституцию III (явная инъекция вместо неявной).
  - Передавать `Clock` в каждый билтин отдельным аргументом — **отвергнут**: дублирует то, что уже
    несёт `*Interpreter`; меняет сигнатуру `BuiltinFn` ([builtins.go:21-23](../../src/internal/eval/builtins.go)).
- **Статус**: РЕШЁН (R4). FR-019/020, D-7, SC-006.

## D-R4. Проекция агрегатов поверх существующих builtin; короткое замыкание пустого окна (R3)

- **Decision**: существующие агрегаты `сумма/количество/среднее/мин/макс` —
  `ArityFixed N=1`, принимают готовый `value.Список` через `requireList`
  ([builtins_aggregate.go:9-14](../../src/internal/eval/builtins_aggregate.go)); механизма проекции
  **нет** (`builtins.md:177`). Движок метрики **переиспользует** их, а не дублирует:
  1. для вызова агрегатной функции **внутри** выражения `агрегат:` движок вычисляет
     аргумент-выражение **на каждой выжившей записи** (scope полей), строит проекцию-`Список`,
     **пропуская** записи, где оно дало `Пусто` ([§10.3 / §SM-8 шаг 4](../../docs/source-metric-model.md));
  2. затем зовёт **существующий** `b.Fn(i, []value.Value{проекция}, pos)`.
  - **Голое поле вне агрегатной функции** и **вложенный агрегат** (`сумма(среднее(...))`) — ошибки
    eval-time (§SM-9.C: `поле '<имя>' использовано вне агрегатной функции`,
    `вложенный агрегат недопустим`), движок различает контекст «внутри агрегат-узла» vs «вне».
  - **Короткое замыкание пустого окна** (§10.5): если выживших записей нет — результат
    определяется **до** вызова агрегата: корневой единичный `сумма(...)`/`количество(...)` →
    `Целое 0`; иначе (`среднее`/`мин`/`макс` и деривативы) → `Пусто`. Это замыкание **обязательно**
    срабатывает раньше вызова `Fn`.
- **Rationale**: реестр встроенных закрыт инвариантом «23 активных + 12 deferred = 35»
  ([builtins.go:54-55](../../src/internal/eval/builtins.go), `TestBuiltinRegistryClosed`) — добавлять
  «агрегаты с проекцией» как новые встроенные нельзя; единственный путь — обернуть **снаружи**
  (движок строит список, существующий `Fn` его сворачивает). Короткое замыкание нужно, потому что
  `среднее/мин/макс` на пустом списке дают `ОшибкаВыполнения «<имя>: список пуст»`
  ([builtins_aggregate.go:65-67, 95-97](../../src/internal/eval/builtins_aggregate.go)), а §10.5
  требует `пусто`/`0` **без** этой ошибки — правило метрики **перекрывает** поведение функций общего
  назначения. Замыкание ставится **до** `Fn`, чтобы «список пуст» физически не достижим в контексте
  метрики (golden строки «неделя/день=0», «среднее на пустом=пусто»).
- **Alternatives considered**:
  - Добавить параллельные агрегаты-с-проекцией в реестр — **отвергнут**: ломает инвариант 23/12/35
    и `TestBuiltinRegistryClosed`, дублирует логику суммы/переполнения.
  - Дать `сумма/среднее` принимать выражение-проекцию вторым аргументом — **отвергнут**: меняет их
    арность (`ArityFixed N=1`) и регресс-тесты 003; проекция — забота движка, не встроенной.
  - Ловить «список пуст» постфактум и подменять результат — **отвергнут**: `среднее` на пустом
    возвращает `error`, а не значение; перехват ошибки по тексту хрупок. Замыкание до вызова чище.
- **Статус**: РЕШЁН (R3). FR-028/029/030, §10.3/§10.5, golden §SM-10.

## D-R5. Отсутствие `Store` — ветвь `metric` не заводит хранилище (R2)

- **Decision**: типов `Store`/`MemoryStore` в кодовой базе **нет** (поиск по `src/` — ноль
  совпадений, `cli.md:7-9`), а [§SM-12](../../docs/source-metric-model.md) **запрещает** создавать
  `internal/store` в 004. Поэтому CLI-ветвь `metric` **не заводит** store: конвейер
  лексер→парсер→`Analyze`→вычислить указанную метрику через `eval.Interpreter`. Формулировка
  README «`MemoryStore` безусловно» трактуется как **нет персиста, нет `--db`**: метрика не трогает
  инстансы процессов, хранилище переменных — это `eval.Environment`, который `NewInterpreter`
  создаёт сам (`global: NewEnvironment(nil)`). Никакого нового store-пакета.
- **Rationale**: единственная точка входа исполнения — `eval.NewInterpreter(out, maxDepth[, clock])`,
  окружение строится безусловно внутри неё (`cli.md:147,174`); метрике дополнительная абстракция
  хранилища не нужна (она чистая функция от данных источника и `Clock.Now()`,
  [§SM-8](../../docs/source-metric-model.md)). Заведение `internal/store` ради формулировки
  «MemoryStore» было бы прямым нарушением границы §SM-12 (store → 005/006) и раздуло бы граф пакетов
  без потребителя.
- **Alternatives considered**:
  - Завести `internal/store.MemoryStore` сейчас — **отвергнут**: §SM-12 явно откладывает store на
    005/006; у метрики нет инстансов для хранения.
  - Хранить загруженные источники в новом store-объекте — **отвергнут**: лень+кеш на запуск
    реализуется полем движка/интерпретатора (§SM-8.1), отдельный пакет избыточен.
- **Статус**: РЕШЁН (R2). FR-033, §SM-12.

## D-R6. Политика повторного имени — функция-функция vs участие источника/метрики (R5)

- **Decision**: имена источников, метрик и функций делят **одно** глобальное пространство (§6/§SM-4).
  Шаг 1 `Analyze` объединяется в **один упорядоченный проход** по `FunctionDecl + SourceDecl +
  MetricDecl` (сейчас Шаг 1 итерирует только `*ast.FunctionDecl`,
  [analyze.go:15-51](../../src/internal/eval/analyze.go)). Тексты повтора **различаются по составу**:
  - **функция↔функция** — оставить существующий текст
    `функция '<имя>' уже объявлена в строке N` ([analyze.go:386](../../src/internal/eval/analyze.go)),
    это регресс 003;
  - **любая коллизия с участием источника/метрики** (новые имена делят глобаль) — общий текст
    [§SM-9.A](../../docs/source-metric-model.md): `'<имя>' уже объявлено в строке N` (без слова
    «функция»), он же совпадает с текстом повтора **переменной** ([analyze.go:79/86]).
- **Rationale**: упорядоченный единый проход нужен, чтобы «уже объявлено в строке N» указывало на
  **первое** объявление в порядке файла независимо от вида (функция/источник/метрика). Сохранение
  старого текста для функция↔функция — требование регресса 003 (тесты на точный байт
  `функция '…' уже объявлена…`); ослабить его до общего текста нельзя без поломки 003. Общий текст
  §SM-9.A для смешанных коллизий — потому что «функция» в нём была бы ложью, когда сталкиваются,
  например, метрика и источник.
- **Alternatives considered**:
  - Единый текст `'<имя>' уже объявлено…` для всех коллизий, включая функция↔функция —
    **отвергнут**: ломает регресс 003 (`builtins.md`/analyze 003 ожидают слово «функция»).
  - Раздельные реестры (функции отдельно от источников/метрик) — **отвергнут**: §6/§SM-4 требуют
    общее пространство, иначе `Ident`-резолв (D-8/D-R-источник) не смог бы единообразно найти имя.
- **Статус**: РЕШЁН (R5). FR-008, §SM-9.A.

## D-R7. Загрузчик JSON — `UseNumber`, int64-диапазон, схема-объединение, лень+кеш (FR-021…024)

- **Decision**: загрузчик источника (§SM-8.1) реализует:
  - **Различение `Целое`/`Дробное` по форме токена JSON**: `json.Decoder` с **`UseNumber()`**, затем
    разбор `json.Number` — наличие `.`/`e`/`E` → `Дробное` (`strconv.ParseFloat`), иначе → `Целое`
    (`strconv.ParseInt`). `1200000`→`Целое`, `1200000.0`/`1.2e6`→`Дробное`.
  - **int64-диапазон**: целое вне `int64` (`ParseInt` ошибка `ErrRange`) →
    `источник '<имя>': запись N, поле '<поле>': целое число вне диапазона` (§SM-9.B, N **с 1**).
  - **Маппинг** (§9.3): `null→Пусто`, `bool→Булево`, строка→`Строка` (даты НЕ распознаются),
    массив→`Список`, объект→`Запись` через
    `value.NewRecord(keys, fields)` ([record.go:88](../../src/internal/value/record.go)) рекурсивно.
  - **Схема = объединение ключей по всем записям** (§9.5); в сообщении «неизвестное поле» список
    известных полей — **отсортированный по возрастанию** (`sort.Strings`) для детерминизма golden
    (`§SM-10`: `известные: дата_заказа, клиент, статус, сумма_заказа`).
  - **Лень + кеш на запуск** (§9.6): файл читается при первом обращении любой метрики к источнику,
    результат кешируется до конца запуска; путь — относительно **cwd** процесса.
- **Rationale**: `encoding/json` по умолчанию декодирует **все** числа в `float64`, теряя различие
  `1200000` vs `1200000.0` — `UseNumber()` единственный способ сохранить форму токена (FR-022, Edge
  Case «различение по форме»). Сортировка списка полей нужна, потому что объединение ключей по map
  даёт недетерминированный порядок, а SC-002 требует exact-match сообщения об опечатке поля. Лень+кеш
  — FR-021: источник может не читаться вовсе (если метрика отфильтрована), а перечитывание на каждой
  записи недопустимо.
- **Alternatives considered**:
  - Стандартный `json.Unmarshal` в `map[string]any` — **отвергнут**: все числа станут `float64`,
    `Целое`/`Дробное` неразличимы (нарушает FR-022).
  - Не сортировать список полей (порядок map) — **отвергнут**: недетерминизм, SC-002 падает.
  - Загружать источник на старте безусловно — **отвергнут**: FR-021 требует лень (метрика без
    обращения к источнику не должна падать на отсутствующем файле раньше времени).
- **Статус**: РЕШЁН. FR-021/022/023/024, §SM-8.1, Edge Cases.

## D-R8. Календарные окна — `time.Date` (UTC) как служебная Go-арифметика, не `Длительность` (FR-025)

- **Decision**: границы окна (§SM-8.2) считаются **календарной арифметикой через `time.Date(...)`**
  в **UTC**, с обратной конвертацией в `value.Дата{Y,M,D}`. Это **служебная Go-арифметика**, а не
  язык Ladix; тип `Длительность` Ladix тут **ни при чём** (его конструктора в 004 нет, §SM-0). Окно —
  **полный** календарный период, содержащий `D = Clock.Now()` (не усечён по `D`):
  - `ежедневно` → `[D, D]`; `ежемесячно` → `[Дата(Y,M,1), Дата(Y,M,послед_день)]`;
    `ежеквартально` → квартал по `M`; `ежегодно` → `[Дата(Y,1,1), Дата(Y,12,31)]`.
  - **Послед. день месяца** — через `time.Date(Y, M+1, 0, …).Day()` (Go нормализует «0-й день» в
    последний день предыдущего месяца), что **автоматически** учитывает високосный год (фев=29).
  - **ISO-неделя пн–вс**: `начало = D − (ISO_номер_дня − 1)` дней, `конец = начало + 6`; Go
    `time.Weekday()` даёт Sun=0 — преобразовать к ISO Mon=1…Sun=7 (`(wd+6)%7+1`). Окно может
    пересекать границу месяца — это нормально.
  - Граница **включительна** с обеих сторон; проверка `начало ≤ d ≤ конец` через **`Дата.Compare`**
    (встраивается в `value.Compare`, см. ниже).
- **Rationale**: `time.Date` с переполнением полей (`M+1`, `день 0`) — идиоматичный Go-приём для
  «последнего дня месяца» и нормализации, он корректен для всех месяцев и високосных лет без ручной
  таблицы дней. UTC выбран, чтобы исключить влияние таймзоны/летнего времени на чисто календарную
  арифметику (таймзоны — v2, §SM-0). Главное — **результат-границы суть `Дата`**, сравниваемые
  `Дата.Compare`, поэтому в `eval` не протекает `time.Time`. `Дата.Compare` встраивается в
  существующую `value.Compare` ([equal.go:116-138](../../src/internal/value/equal.go)) добавлением
  `case Дата:` (лексикографически по `(Year, Month, Day)`, поля `int` — нужен `cmpInt`, т.к.
  `cmpInt64` не подходит без конверсии, `value.md:163`); пара с не-`Дата` остаётся
  `return 0, false` → `ОшибкаТипа` через штатный `evalOrder`.
- **Alternatives considered**:
  - Считать окна через `value.Длительность` и арифметику `Дата ± Длительность` — **отвергнут**:
    §SM-0 явно исключает конструктор `Длительность` и дата-арифметику из 004; окна — календарные,
    не «D минус N дней» в общем случае (месяц/квартал — переменной длины).
  - Ручная таблица дней месяца + собственная високосная проверка — **отвергнут**: `time.Date`
    нормализация делает это надёжнее и короче (меньше места для off-by-one).
  - Использовать локальную зону вместо UTC — **отвергнут**: вносит DST-сдвиги в чисто календарный
    расчёт; «сегодня» уже усечено до даты в `Clock`.
- **Статус**: РЕШЁН. FR-013/025, §SM-8.2, golden окна (`ежемесячно/квартал/год/неделя/день`).

## D-R9. Расширение парсера — узлы строятся; регресс `examples_test.go` (R7)

- **Decision**: вопреки заметке `eval-model §9` (что в подмножестве B декларатив не доходит до
  `Analyze`), 004 **расширяет** парсер так, что `Analyze` видит `SourceDecl`/`MetricDecl`:
  - в `isUnexpectedTopLevel` ([parse_stmt.go:30-38](../../src/internal/parser/parse_stmt.go)) **снять**
    `KW_SOURCE` и `KW_METRIC` из множества отвергаемых; `KW_PROCESS`/`KW_WHEN`/`KW_VALUE`/`LBRACE`/
    `RBRACE` **остаются** отвергаемыми;
  - в `parseTopLevelItem` ([parse_stmt.go:12-25](../../src/internal/parser/parse_stmt.go)) добавить
    `if p.check(lexer.KW_SOURCE) { return p.parseSourceDecl() }` и
    `if p.check(lexer.KW_METRIC) { return p.parseMetricDecl() }` **до** проверки `isUnexpectedTopLevel`
    (по образцу ветви `KW_FUNC`);
  - `parseSourceDecl`/`parseMetricDecl` — по образцу `parseFunctionDecl`
    ([parse_decl.go:10-20](../../src/internal/parser/parse_decl.go)): потребить ведущий KW →
    `expect(IDENT, …)` → `expect(COLON, ":")` → собственный цикл `NEWLINE→INDENT→SourceAttr+/
    MetricAttr+→DEDENT` (нельзя переиспользовать `parseBlock`, он зовёт `parseStatement`), с
    переиспользованием `msgEmptyBlock` для пустого тела и `parseExpression()` для значений атрибутов.
    `источник:` — `parseSourceRef` (один `IDENT`, D-1).
  - **Регресс** `examples_test.go::TestDeclarativeExamplesUnexpected`
    ([examples_test.go:35-54](../../src/internal/parser/examples_test.go)): кейс `выручка.ladix`
    сейчас ждёт `неожиданный токен 'источник'`. После 004 `источник`/`метрика` парсятся, но
    `выручка.ladix` всё равно падает **позже** — на `процесс` (`KW_PROCESS` остаётся отвергаемым).
    Обновить ожидание кейса `выручка.ladix` на **`неожиданный токен 'процесс'`**; кейс
    `онбординг.ladix → 'процесс'` — **без изменений**. Добавить позитивный parse-тест: метрик-онли
    фикстура (§SM-10) парсится с нулём ошибок.
- **Rationale**: 004 — первая фича, где декларатив **исполняется**, поэтому AST-узлы обязаны
  строиться и доходить до `Analyze`/движка (иначе метрику не вычислить). Снятие только `KW_SOURCE`/
  `KW_METRIC` (а не всех декларативных KW) держит `процесс`/`когда`/`значение` отвергаемыми — граница
  004 (§SM-0/FR-007). Регресс `выручка.ladix` обязан сместиться с `'источник'` на `'процесс'`, иначе
  тест 002 станет ложным: `KW_SOURCE` больше не первый отвергаемый токен в файле (§SM-3, FR-038,
  SC-004). Собственный цикл атрибутов (а не `parseBlock`) — потому что тело декларации это
  `атрибут: выражение`, не `Statement+`.
- **Alternatives considered**:
  - Парсить декларатив в no-op/deferred-узел без полей (как намекает 003) — **отвергнут**: движку
    нужны `Source`/`Where`/`Aggregate`/`Period`/`ByDate` для вычисления; пустой узел бесполезен.
  - Снять все декларативные KW сразу (`процесс`/`когда`) — **отвергнут**: §SM-0/FR-007 держат их
    отвергаемыми до 005+; `выручка.ladix` обязана падать на `процесс`.
  - Оставить ожидание `выручка.ladix → 'источник'` — **отвергнут**: после снятия `KW_SOURCE` тест
    немедленно «покраснеет» (источник стал валиден), SC-004/FR-038 требуют exact `'процесс'`.
- **Статус**: РЕШЁН (R7). FR-001…007, FR-038, §SM-3, SC-004.
