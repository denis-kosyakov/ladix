# Implementation Plan: Декларативный слой v1 — источники и метрики

**Branch**: `004-source-metric` | **Date**: 2026-06-07 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/004-source-metric/spec.md`

## Summary

Четвёртый слой Ladix — **декларативный v1**: язык учится описывать *откуда* брать данные
(`источник`) и *что считать* (`метрика`), а не писать цикл вручную. Фича **расширяет** уже
готовый стек 001→003 (лексер, парсер, AST, интерпретатор чистого ядра B), а не строит новый:
снимает запрет на `KW_SOURCE`/`KW_METRIC` в парсере и добавляет узлы `SourceDecl`/`MetricDecl`
(R7); расширяет семпроход `Analyze` регистрацией и статической валидацией деклараций (R5);
активирует из deferred ровно две встроенные — `дата(...)`/`сегодня()` (минимум для оси времени);
вводит детерминизм времени через инъекцию `Clock` (R4); реализует **движок метрики** —
конвейер `окно→фильтр→агрегат` (`SPEC §10.2`) поверх ленивого JSON-загрузчика источника
(`json.Decoder` + `UseNumber()`); добавляет подкоманду `ladix metric <файл> <имя>` в существующий
диспетчер `cmd/ladix`. Конструируемые типы `Дата`/`Период`/`Запись` в `internal/value` уже
смоделированы 003 — 004 добавляет только недостающее: `Дата.Compare` (порядок), регистрацию
5 предопределённых `Период`-идентов и **починку `formatFloat`** для бизнес-диапазона (R1).

**Технический подход**: только stdlib (`encoding/json` с `UseNumber`, `time`, `strconv`,
`strings`, `math`) — конституция I. Парсер деклараций — ручной recursive descent в том же стиле,
что 002 (конституция II); атрибуты — типизированные поля на узлах + структура позиций
`MetricAttrPos` для точной диагностики (D-2). Дубликат/неизвестный атрибут — структурно в парсере
(`ОшибкаРазбора`, D-3); обязательность `источник`/`агрегат` и связка `период↔по_дате` —
семпроход (`СемантическаяОшибка`, D-4); резолв полей записи, типы, голое поле, цикл метрик —
eval-time (D-5/D-6/D-8). Детерминизм метрик с `период:` — `Clock`-инъекция: `сегодня()` и
календарные окна читают **только** `i.clock`, прямой `time.Now()` в `eval`/движке запрещён
(D-7, аналогично инъекции `out` вместо `os.Stdout`). Имя источника/метрики как значение
ловит `evalIdent` после промаха `env.Lookup` (R6). Ключевые решения R1–R7 и D-1…D-9
**не переоткрываются** — план их кодирует.

Поставка по приоритетам User Stories: **P1** (US1 объявить+статически проверить + US2
посчитать метрику) даёт сквозной вертикальный срез «объявил → посчитал»; **P2** (US3 даты в
выражениях, `дата`/`сегодня`) поддерживает ось времени; **P3** (US4 диагностика вычисления —
опечатка поля, не-`Булево` `где`, голое поле, цикл метрик) замыкает опыт автора. US1/US2 — P1,
US3 — P2, US4 — P3 (как в spec).

## Technical Context

**Language/Version**: Go **1.22** (модуль `github.com/denis-kosyakov/ladix`, корень — `src/`),
без CGO. Подтверждено `src/go.mod`: `go 1.22`.

**Primary Dependencies**: только стандартная библиотека Go. Новое для 004:
`encoding/json` (`json.Decoder` + **`UseNumber()`** — различение `Целое`/`Дробное` по форме
токена JSON, §9.3) и `time` (служебная календарная арифметика окон — `time.Date`/`Weekday`/
`ISOWeek`, **не** язык Ladix; `Длительность` тут ни при чём). Плюс уже используемые
`strconv`, `strings`, `math`, `fmt`, `io`, `os`, `sort` (сортировка списка известных полей в
сообщении об опечатке, §SM-8.1). **`modernc.org/sqlite` НЕ используется** — store deferred (R2).
`testify/require` — точечно в тестах (конституция VI).

**Storage**: N/A. Типов `Store`/`MemoryStore` в кодовой базе **нет**, и §SM-12 запрещает
заводить `internal/store`. «`MemoryStore` безусловно» (README §metric) = нет персиста, нет
`--db`: ветвь `metric` строит обычный конвейер лексер→парсер→`Analyze`→вычисление метрики через
`eval.Interpreter` (R2). Источник читается лениво из JSON-файла и кешируется на запуск (§9.6) —
это кеш данных, не хранилище инстансов.

**Testing**: `go test` — три стратегии:
(1) **табличные** (table-driven) тесты по слоям (AST decl, parse decl, `Дата.Compare`, `repr` R1,
`дата`/`сегодня`, движок метрики, контексты атрибутов);
(2) **golden** — 12-строчная таблица §SM-10 байт-в-байт при `FixedClock{Дата{2026,5,31}}` и
`data/sales.json` (3 записи мая 2026); CLI-golden `ladix metric` (код 0/`2000000`);
(3) **exact-match текстов ошибок** — 7 краевых сообщений §SM-10 сверяются с §SM-9 байт-в-байт
(переформулировать запрещено, конституция VIII). Co-located `*_test.go`; вывод — через
инжектированный `out` (`bytes.Buffer`), время — через `FixedClock`; `go test -race` зелёный;
**все** регресс-тесты 001/002/003 остаются зелёными (FR-038, обновляется один кейс
`выручка.ladix`).

**Target Platform**: один статический бинарник `ladix` (`go build`), кросс-компиляция
darwin/linux/windows (конституция I).

**Project Type**: компилятор/интерпретатор (tree-walking) — CLI `ladix run` + `ladix metric`.

**Performance Goals**: учебно-прикладной масштаб; жёстких целей нет. Источник загружается лениво
и кешируется на запуск (две метрики над одним источником не перечитывают файл, §9.6).

**Constraints**:

- **Детерминизм времени**: ни один путь `eval`/движка не вызывает `time.Now()` напрямую — только
  через инъектированный `Clock`; `сегодня()` фиксируется один раз на запуск (R4, FR-019/020,
  SC-006).
- eval/движок — **fail-fast** (накопителя нет; накопитель только лексер/парсер); первая
  рантайм-ошибка всплывает до CLI.
- В штатных путях паника **ЗАПРЕЩЕНА** (конституция III); `recover`-барьер `guard` на границе
  CLI-подкоманды (общий для `run`/`metric`) → «внутренняя ошибка интерпретатора» без Go stack
  trace, код 1.
- Все пользовательские сообщения — по-русски, двухстрочный формат `Ошибка в строке N, колонка M:`;
  позиции 1-based, колонка в **рунах**; тексты ДОСЛОВНО из §SM-9 (новый слой) и `eval-model §8.3`
  (слой eval, строки `дата:`).
- Без изменяемого состояния уровня пакета (конституция V): `clock`/реестры источников и метрик —
  поля `Interpreter`; `out`/`clock` инжектируются.
- Граф пакетов **ацикличен**; `internal/value`, `internal/errors`, `internal/ast` — **листовые**.
- Грамматика/AST 002 расширяются **строго аддитивно** (`SourceDecl`/`MetricDecl`), существующие
  узлы и приоритеты не меняются; `KW_PROCESS`/`KW_WHEN`/`KW_VALUE` остаются отвергаемыми (R7).

**Scale/Scope**: декларатив v1 — `источник` (атрибут `файл:`) + `метрика` (5 атрибутов
`источник/где/агрегат/период/по_дате`). 2 новых AST-узла; +2 активных встроенных (теперь 25
активных + 10 deferred = 35); 3 конструируемых типа добиваются до боевого состояния
(`Дата.Compare`, 5 `Период`-идентов, `Запись` через загрузчик); движок метрики + JSON-загрузчик;
1 новая подкоманда CLI; 12 golden-строк + 7 exact-match ошибок; синк 3 doc-файлов.

## Guardrails — контракт реализации (нормативно для tasks/implement)

Фиксирует инварианты как контракт, чтобы код не дрейфовал от спеки и `docs/source-metric-model.md`.
`/speckit-tasks` и `/speckit-implement` ОБЯЗАНЫ соблюдать каждый пункт.

1. **Аддитивность 002.** Парсер расширяется, не ломается: убрать `KW_SOURCE`/`KW_METRIC` из
   `isUnexpectedTopLevel` (`parser/parse_stmt.go:30-38`), добавить ветви `parseSourceDecl`/
   `parseMetricDecl` в `parseTopLevelItem` **до** проверки `isUnexpectedTopLevel`. `KW_PROCESS`/
   `KW_WHEN`/`KW_VALUE`/`LBRACE`/`RBRACE` **остаются** отвергаемыми. Грамматика/приоритеты
   выражений и существующие AST-узлы не меняются. *(R7, FR-001/006/007, §SM-3)*
2. **AST-узлы (D-1/D-2).** `SourceDecl{Name Ident; File StringLit; FilePos Position}` (`Pos()`=
   токен `источник`); `MetricDecl{Name Ident; Source Ident; Where/Aggregate/Period/ByDate
   Expression; Attrs MetricAttrPos}` (`Pos()`=токен `метрика`). Оба встраивают `declBase` первым
   полем → автоматически `Decl`/`TopLevelItem`. `Source` — `Ident`, не `Expression` (синтаксис,
   не семантика, D-1); `Aggregate` обязателен (не-nil); `Where`/`Period`/`ByDate` — nil при
   отсутствии. `MetricAttrPos` несёт позицию ключевого слова каждого присутствующего атрибута. *(§SM-2)*
3. **Структурная диагностика парсера (D-3).** Имя атрибута ∉ `{источник,где,агрегат,период,по_дате}`
   → `ОшибкаРазбора «неизвестный атрибут '<имя>'»` (поз. имени); повтор любого атрибута →
   `«атрибут '<имя>' уже задан»` (поз. повтора); `источник:` не `IDENT` → `«ожидается имя
   источника»`; пустой блок — переиспользовать `msgEmptyBlock`. Обязательность/связку парсер
   НЕ проверяет. *(FR-003/005, §SM-3, §SM-9.A)*
4. **Семпроход (D-4) — расширение `Analyze`.** Шаг 1 объединить в **один упорядоченный** проход по
   `FunctionDecl`+`SourceDecl`+`MetricDecl` (общее глобальное пространство): повтор имени с участием
   источника/метрики → `«'<имя>' уже объявлено в строке N»` (§SM-9.A); функция↔функция оставить
   существующий `«функция '<имя>' уже объявлена в строке N»` (регресс 003, R5). Шаг 1b: метрика —
   `источник`/`агрегат` обязательны; `период` ⇔ `по_дате`; `Source` → зарегистрированный источник
   (не найдено → «не объявлен»; занято функцией/метрикой → «не источник»). НЕ резолвит поля/типы/
   голое поле/цикл — eval-time (D-5/D-6/D-8). *(FR-008..012, §SM-4, §SM-9.A)*
5. **Типы (§SM-5).** `Дата.Compare` встроить в `value.Compare` (`equal.go`): `case Дата↔Дата` →
   лексикографически `(Year,Month,Day)` (поля `int`, нужен `cmpInt`), `true`; `Дата` с не-`Дата` →
   `0,false` (→ `ОшибкаТипа` через `evalOrder`). 5 `Период`-идентов (`ежедневно`…`ежегодно`) —
   read-only в `global` инстанса при инициализации. `Запись` — через `value.NewRecord` из
   загрузчика. `repr`/`Equal`-ветви Дата/Период при необходимости добить параллельно. *(FR-013/014, §SM-5)*
6. **R1 — formatFloat.** `value/repr.go::formatFloat`: фиксированная запись (без экспоненты) для
   `|f|∈[1e-4,1e16)`, integer-looking → `+".0"`; sci `g` для очень больших/малых. Итог:
   `2175→"2175.0"`, `3.4→"3.4"`, `1000000→"1000000.0"`, `1000000.5→"1000000.5"`, `1e20→"1e+20"`.
   Инвариант `repr_test.go:16` (`2175.0`) сохраняется; добавить кейсы `1000000.0`/`1000000.5`.
   Синхронно: `docs/eval-model.md §7` (политика формата) и `§SM-5` (снять «repr не трогаем»). *(R1)*
7. **Встроенные `дата`/`сегодня` (§SM-6).** Убрать `"дата"`/`"сегодня"` из `deferredNames`
   (`builtins.go:48`), зарегистрировать активными → счётчики **25 активных + 10 deferred = 35**
   (обновить `TestBuiltinRegistryClosed`/`TestBuiltinDeferredAll`). `сегодня()` — `ArityFixed N=0`,
   читает `i.clock` (не `time.Now()`). `дата(...)` — `overloaded`: `дата(Строка)` парсит ровно
   `YYYY-MM-DD` (валидный календарь, високосный фев, `T…`→невалидно); `дата(Пусто)`→`Пусто`;
   `дата(Целое×3)`→сборка с валидацией. Тексты ошибок дословно §SM-9.C. Прочие 9 дата/3 процессных
   — остаются deferred. *(FR-015/016/017/018, §SM-6)*
8. **Clock-инъекция (D-7/R4).** `NewInterpreter(out io.Writer, maxDepth int, clock Clock)` — третий
   параметр; поле `i.clock`. `Clock interface{ Now() value.Дата }`; `SystemClock` (прод, `time.Now()`
   в `time.Local`, усечён до Y/M/D); `FixedClock{Дата{2026,5,31}}` (тесты). Билтины получают `i`
   первым аргументом → `сегодня()` читает `i.clock` без отдельного протаскивания. Обновить **ВСЕХ**
   вызывающих `NewInterpreter` (`cmd/ladix`, все eval-тесты). `сегодня()` фиксируется на запуск. *(FR-019/020, §SM-7, SC-006)*
9. **evalIdent (R6/D-8).** После промаха `env.Lookup` и ДО ветки «функция/не объявлено`:
   имя в реестре источников → `ОшибкаВыполнения «'<имя>' — источник, его нельзя использовать как
   значение»` (FR-032); имя в реестре метрик → запуск пересчёта метрики; цикл → `«цикл
   зависимостей метрик: <имя> → … → <имя>»` (FR-031, D-8). *(§SM-4/§SM-8, §SM-9.B)*
10. **Движок метрики — контексты атрибутов (D-9).** `период:` вычисляется **один раз** в
    глобальной области → `Период` (иначе §SM-9.B); `где`/`по_дате`/проекции агрегата — **per-record**
    в scope полей (`Запись` поверх `global`). `источник:` не вычисляется (имя). Конвейер §10.2:
    загрузка → окно (`D=clock.Now()`, полный календарный, не усечён) → фильтр (`по_дате`∈окно И
    `где`=истина; `по_дате=Пусто`→исключить без ошибки/без `где`) → агрегат-проекция. *(FR-025/026/027, §SM-8)*
11. **Агрегат-проекция (R3/§10.3).** Существующие `сумма/количество/среднее/мин/макс` —
    `ArityFixed N=1`, берут готовый `Список` через `requireList`; проекции нет. Движок для **вызовов
    агрегатных функций** внутри `агрегат:` вычисляет аргумент-выражение НА КАЖДОЙ выжившей записи
    (scope полей), строит проекцию-`Список` (пропуская записи, где даёт `Пусто`, §10.3), затем зовёт
    существующий builtin `Fn`. Голое поле вне агрегата → `«поле '<имя>' использовано вне агрегатной
    функции»`; вложенный агрегат → `«вложенный агрегат недопустим»`. *(FR-028/029, §SM-8, §SM-9.C)*
12. **Пустой результат (R3/§10.5).** Нет выживших записей → **короткое замыкание ДО** вызова
    агрегата (чтобы `«<имя>: список пуст»` НЕ срабатывало в контексте метрики): корневой единичный
    `сумма`/`количество` → `Целое 0`; иначе (`среднее`/`мин`/`макс`/деривативы) → `Пусто`. Это
    правило §10.5 перекрывает поведение функций общего назначения. *(FR-030, §SM-8.5)*
13. **JSON-загрузчик источника (§SM-8.1).** `json.Decoder` + **`UseNumber()`**; верхний уровень —
    массив объектов (не массив → §SM-9.B; элемент не объект → §SM-9.B с N с 1; битый JSON →
    §SM-9.B). Маппинг §9.3: `null→Пусто`, `bool→Булево`, строка→`Строка` (даты НЕ распознаются),
    `json.Number` без `.`/`e`/`E`→`Целое` (вне int64 → §SM-9.B), с `.`/экспонентой→`Дробное`,
    массив→`Список`, объект→`Запись`. Путь — относительно **cwd** (§9.1). Лень + кеш на запуск.
    Схема = объединение ключей всех записей; список известных полей в сообщении — **отсортирован**. *(FR-021/022/023/024, §SM-8.1)*
14. **Календарные окна (§SM-8.2).** `D=clock.Now()`; окно — **полный** период, содержащий `D`,
    включительно с обеих сторон, через `Дата.Compare`: `ежедневно [D,D]`; `еженедельно` ISO пн–вс
    (через `time.Weekday`/`ISOWeek`, окно может пересекать границу месяца); `ежемесячно`
    `[1, послед_день]` (високосный фев=29); `ежеквартально` по `M`; `ежегодно [1.1,31.12]`. Арифметика
    через `time.Date(...)` (служебная Go, не Ladix). *(FR-025, §SM-8.2)*
15. **CLI `metric` (R2/§SM-11).** Диспетчер `cmd/ladix/main.go::realMain`: ввести ветвление по
    `args[0]` (`run` как есть; `metric`). `ladix metric <файл> <имя> [--max-depth N]`: лексер→парсер→
    `Analyze`→вычислить метрику→`value.String(результат)` в stdout + `\n`. Нет двух позиционных →
    usage, код **2**; неизвестная метрика / имя-не-метрика → §SM-9.D, код **1**; ошибки загрузки/
    вычисления → stderr, код **1**. `SystemClock` (прод). `guard`-барьер — общий с `run`. Без store,
    без `--db`. `run` работает без изменений. *(FR-033..037, §SM-11, §SM-9.D)*
16. **Тексты ошибок — байт-точно.** Новый слой — ДОСЛОВНО из §SM-9 (A: парсер/семпроход; B:
    загрузка/имя-как-значение; C: вычисление/конструкторы дат; D: CLI). Строки `дата:` (слой eval) —
    перенести в `eval-model §8.3`; декларативные/движковые — держать в `§SM-9`; **важно** —
    байт-идентичность. Соглашения §8.3: payload без завершающей точки; `'…'` для идентификаторов;
    `«…»` для строковых значений; `N` с 1. *(FR-039, §SM-9, конституция VIII)*
17. **Регрессы + синк доков.** `parser/examples_test.go::TestDeclarativeExamplesUnexpected`: кейс
    `выручка.ladix` — обновить ожидание на `«неожиданный токен 'процесс'»` (источник/метрика теперь
    парсятся, падение позже — на `процесс`); `онбординг.ladix` — без изменений. Метрик-онли фикстура
    (§SM-10) — позитивный parse-тест (ноль ошибок) + golden, лежит как тест-фикстура (НЕ в
    `examples/`, вывод дата-зависим). Doc-синк: `stdlib.md` (`дата`/`сегодня` доступны, прочие v2),
    `eval-model §8.3` (строки `дата:`), `source-metric-model §SM-5/§SM-9`. *(FR-038/039, §SM-3/§SM-6/§SM-10)*

**Structure Decision**:

- **Без новых пакетов** (R2/§SM-12): движок метрики, загрузчик, окна, Clock — файлы внутри
  `internal/eval`; `internal/store`/`internal/engine` НЕ заводятся. Это держит граф минимальным и
  не вводит мёртвую абстракцию.
- **Аддитивное расширение `ast`/`value`/`parser`/`eval`**: новые узлы/методы добавляются рядом с
  существующими по «домашнему» паттерну (`declBase`-встраивание, `value.Compare`-ветви,
  `parseFunctionDecl`-образец, `BuiltinFn`-сигнатура). `errors` **не меняется** — 4 готовых типа
  покрывают весь новый слой.
- **`value` остаётся листовым**: `Дата.Compare`/`formatFloat`/периоды используют только stdlib;
  загрузчик (`encoding/json`) и окна (`time`) живут в `eval`, не в `value` — `value` не узнаёт о
  JSON/времени.
- **Метрик-онли фикстура — тест-фикстура, не пример**: её вывод дата-зависим (`FixedClock`),
  поэтому она в `testdata/`/`tests/`, а не в `examples/` (golden CLI с фиксированной датой).
- **Тесты co-located** (`*_test.go`) — конвенция 001/002/003.

## Риски и точки внимания

- **Контексты атрибутов (D-9)** — главная бывшая «дыра»: `период:` считается раз в глобальной
  области, `где`/`по_дате`/проекции — per-record в scope полей. Перепутать область → неверные
  результаты или ложные «неизвестное поле». Тест: метрика, где `период:` ссылается на глобаль, а
  `где` — на поле.
- **ISO-неделя через границу месяца** — `еженедельно` при `D=2026-05-31` (воскресенье) даёт
  `[05-25,05-31]`; неделя может пересекать границу месяца/года. Go `Weekday` Sun=0 → преобразовать
  в ISO Mon=1…Sun=7. Тест: D на границе недели/месяца.
- **`json.Number` различение Целое/Дробное** — по форме токена (`.`/`e`/`E`), не по значению:
  `1200000`→`Целое`, `1200000.0`/`1.2e6`→`Дробное`. Обязателен `UseNumber()`; без него
  `encoding/json` теряет форму. Целое вне int64 → §SM-9.B.
- **Пустое окно vs «список пуст»** — короткое замыкание ДО вызова агрегата (R3/§10.5): иначе
  `среднее`/`мин`/`макс` дадут `«<имя>: список пуст»` (§8.3), что в контексте метрики запрещено
  (должно быть `Пусто`). Сумма/количество на пустом → `Целое 0`.
- **Порог формата Дробного (R1)** — граница `|f|∈[1e-4,1e16)` для фиксированной записи; integer-
  looking добавляет `.0`. Проверить, что `1e20`→`"1e+20"` (sci) и `repr_test.go:16` (`2175.0`)
  не сломаны; добавить кейсы `1000000.0`/`1000000.5`.
- **Регресс счётчиков builtins** — активация 2 функций смещает `23/12/35`→`25/10/35`; жёсткие
  тесты `TestBuiltinRegistryClosed`/`TestBuiltinDeferredAll` править вместе с реестром.
- **Обновление всех вызывающих `NewInterpreter`** — третий параметр `clock` затронет `cmd/ladix` и
  ВСЕ eval-тесты; пропуск → провал компиляции (это и есть страховка).
