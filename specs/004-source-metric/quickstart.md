gofmt -l .          # пусто = ок (любой вывод = нужен gofmt -w)

**Критерий готовности SC-005:** `go build ./...` и `go vet ./...` — чисто; `gofmt -l .` — без правок; `go test ./...` — зелёное, включая **все** регресс-тесты 001/002/003. Тесты — часть **каждой** задачи (table-driven, co-located `*_test.go`), пишутся первыми, обязаны падать до реализации (конституция VI). Печать `печать()` перехватывается инжектированным `Interpreter.out` (`bytes.Buffer`); текущая дата — инжектированным `Clock` (`FixedClock`).

## 2. Метрик-онли фикстура (§SM-10) — где лежит и почему не в examples/

`examples/выручка.ladix` в 004 **не парсится целиком** (содержит `процесс`/`когда` → `KW_PROCESS` остаётся отвергаемым, R7/§SM-3). Golden-метрику берём из **метрик-онли** фикстуры (источник `продажи` + метрика `выручка_месяца`, без `процесс`/`когда`):

```ladix
источник продажи:
    файл: "data/sales.json"

метрика выручка_месяца:
    источник: продажи
    где:      статус == "оплачен"
    агрегат:  сумма(сумма_заказа)
    период:   ежемесячно
    по_дате:  дата(дата_заказа)
```

**Куда кладётся.** Как тест-фикстура — `src/internal/eval/testdata/` (каталога ещё нет, создаётся в этой фиче) или `tests/`; данные — `data/sales.json` (3 майские записи 2026: `1 200 000 оплачен 05-03`, `800 000 оплачен 05-17`, `500 000 отменён 05-20`).

**Почему НЕ в `examples/`.** Метрика с `период:` считается относительно `сегодня()` → её вывод **дата-зависим** (май ≠ июнь). `examples/` прогоняется golden-тестом `run` на **системной** дате (`SystemClock`) и обязан быть детерминированным байт-в-байт — фикстура с `период:` это нарушила бы. Поэтому она живёт под `testdata/`, где golden инъектирует `FixedClock{Дата{2026,5,31}}` (§SM-7, R4), а в `examples/MANIFEST.md` исполнимость `выручка.ladix` обещана только с 006+.

**Путь к данным (§SM-8.1).** `SourceDecl.File` (`"data/sales.json"`) резолвится относительно **cwd процесса**. Для CLI это значит: запускать из каталога, где виден `data/sales.json` (корень репозитория). Для golden-тестов — либо нормализовать cwd на корень репо, либо инъектировать загрузчик так, чтобы `data/sales.json` резолвился к `repo-root/data/sales.json` (абсолют — как есть). Зафиксировать выбор в тесте, чтобы он не зависел от каталога запуска `go test`.

## 3. Запуск CLI: `ladix metric`

```bash
cd src
go build -o /tmp/ladix ./cmd/ladix

# Из корня репозитория (чтобы виден data/sales.json относительно cwd, §SM-8.1):
cd ..
/tmp/ladix metric <путь-к-фикстуре>.ladix выручка_месяца
# stdout: 2000000   (ровно value.String(результат) + \n), код выхода 0
```

> **Оговорка о дате.** В проде `metric` строит `SystemClock` и фиксирует `сегодня()` на запуск (§SM-11). Значение `2000000` верно **только** при дате внутри мая 2026 (окно `ежемесячно` = `[05-01, 05-31]`). Вне мая 2026 живой запуск даст `0` (пустое окно) или `2500000` и т. п. — это не баг, а зависимость от системной даты. **Детерминизм даёт только golden-тест**, инъектирующий `FixedClock{Дата{2026,5,31}}` (см. §4). SC-003 формулируется на фикс-дате.

```bash
# Неизвестная метрика → stderr, код 1 (§SM-9.D):
/tmp/ladix metric <фикстура>.ladix несуществующая
# stderr: неизвестная метрика 'несуществующая'   ; код выхода 1

# Имя — переменная/функция/источник, а не метрика → код 1:
# stderr: '<имя>' — не метрика

# Нет двух позиционных аргументов → ошибка использования, код 2 (FR-034):
/tmp/ladix metric                 # код 2
```

**Контракт кодов** (как у `run`, §SM-11, R2): **0** — успех (печать `value.String` в stdout); **1** — штатные ошибки Ladix (неизвестная метрика/не-метрика §SM-9.D; загрузка/вычисление §SM-9.B/C в stderr; Go-паника → `внутренняя ошибка интерпретатора` без стектрейса через `guard`-барьер, FR-036); **2** — ошибка использования (нет двух позиционных, плохой `--max-depth`, нечитаемый файл). Конвейер: лексер → парсер → `Analyze` → вычислить метрику через `eval.Interpreter` — **без** `store`/`--db` (R2). Точка диспетча — начало `realMain`, рядом с текущим `args[0] != "run"` (см. карту cli.md): `switch args[0] { case "run": …; case "metric": … }`.

## 4. Golden-приёмка: таблица 12 строк + 7 краевых ошибок (§SM-10)

Все метрик-golden-тесты инъектируют **`FixedClock{Дата{2026,5,31}}`** (R4/§SM-7) и читают `data/sales.json`. Прогон: лексер → парсер → `Analyze` → движок метрики (§SM-8) с фикс-Clock → `value.String(результат)`. Сверяется **байт-в-байт** строковое представление результата.

```bash
cd src
go test ./internal/eval/... -run TestMetricGolden    # таблица 12 значений (§SM-10)
go test ./internal/eval/... -run TestMetricErrors     # 7 краевых exact-match ошибок
go test ./cmd/ladix/...     -run TestMetricCLI         # сквозной CLI metric (код/stdout/stderr)
```

**Таблица значений (SC-001), все при `D=2026-05-31`** — варьируем один атрибут фикстуры:

| Вариант метрики | Окно | Выжило | `value.String` |
|---|---|---|---|
| `сумма(сумма_заказа)`, `где оплачен`, `ежемесячно` | `[05-01,05-31]` | 2 | `2000000` |
| то же, `ежеквартально` | `[04-01,06-30]` | 2 | `2000000` |
| то же, `ежегодно` | `[01-01,12-31]` | 2 | `2000000` |
| то же, `еженедельно` | `[05-25,05-31]` | 0 | `0` (пустое окно, §10.5 → R3) |
| то же, `ежедневно` | `[05-31,05-31]` | 0 | `0` |
| `сумма(...)`, `где оплачен`, **без периода** | все | 2 | `2000000` |
| `сумма(...)`, **без `где`**, `ежемесячно` | месяц | 3 | `2500000` |
| `количество(запись)`, `где оплачен`, `ежемесячно` | месяц | 2 | `2` |
| `среднее(сумма_заказа)`, `где оплачен`, `ежемесячно` | месяц | 2 | `1000000.0` (R1!) |
| `мин(сумма_заказа)`, `где оплачен`, `ежемесячно` | месяц | 2 | `800000` |
| `макс(сумма_заказа)`, `где оплачен`, `ежемесячно` | месяц | 2 | `1200000` |
| `среднее(...)`, `где оплачен`, `ежедневно` | `[05-31,05-31]` | 0 | `пусто` (§10.5) |

> Строки 4/5/12 проверяют короткое замыкание пустого результата (R3): корневой `сумма`/`количество` на пустом окне → `Целое 0` **до** вызова агрегата (чтобы `«<имя>: список пуст»` НЕ сработало в контексте метрики); `среднее`/`мин`/`макс` → `Пусто`. Строка 9 (`1000000.0`) — прямой регресс R1 (`formatFloat`): без починки было бы `1e+06`.

**7 краевых ошибок (SC-002), exact-match по §SM-9** — каждая своим фикстура-вариантом:

| Кейс | Точное сообщение |
|---|---|
| `период: ежемесячно` без `по_дате:` | `метрика '…': 'период' требует 'по_дате'` |
| `источник: несуществующий` | `метрика '…': источник 'несуществующий' не объявлен` |
| `файл: "нет.json"` (битый путь) | `источник '…': файл «нет.json» не найден` (поз. объявления `источник`) |
| `где: статус` (Строка, не Булево) | `'где' должно давать Булево, получено Строка` |
| `агрегат: сумма_заказа` (голое поле) | `поле 'сумма_заказа' использовано вне агрегатной функции` |
| `где: статус_опечатка == "x"` | `неизвестное поле 'статус_опечатка' (известные: дата_заказа, клиент, статус, сумма_заказа)` |
| `дата("2026-13-40")` | `дата: «2026-13-40» не является датой` |

Список известных полей в сообщении «неизвестное поле» — **отсортирован по возрастанию** (детерминизм golden, §SM-8.1). Сообщения сверяются **байт-в-байт** через `err.Error()` (двухстрочный канонический формат `errors`, как RE-1 в 003). Парсерные кейсы из §SM-10 (дубликат/неизвестный атрибут) — в `parser/*_test.go`; семантические — в `eval/analyze_test.go`; движковые/датовые — в `eval/*_test.go`.

## 5. Демонстрация `дата`/`сегодня` в обычном выражении (`ladix run`)

`дата(...)` и `сегодня()` доступны не только в метриках, но и в любом выражении (US3). Быстрая проверка без фикстуры — через `run`:

```bash
cd src
printf 'печать(дата("2026-05-03"))\nпечать(дата(2026, 5, 3))\nпечать(дата(пусто))\n' > /tmp/d.ladix
go run ./cmd/ladix run /tmp/d.ladix
# 2026-05-03
# 2026-05-03
# пусто
```

- `дата(Строка)` парсит ISO `YYYY-MM-DD` (репр — `2026-05-03`); `дата(Целое,Целео,Целое)` собирает ту же дату; `дата(Пусто)→Пусто` (ключ к §10.4: запись без поля даты выпадает из окна без ошибки).
- `сегодня()` в `run` читает **`SystemClock`** (прод-дата, фиксирована на запуск, §10.6) — поэтому её вывод **не** golden-стабилен и **не** входит в `examples/`-golden. Детерминированный тест `сегодня()` — отдельный, с `FixedClock{Дата{2026,5,31}}` → `2026-05-31` (SC-006).
- Невалид: `дата("2026-13-40")` → `дата: «2026-13-40» не является датой`; `дата(2026,13,1)` → `дата: некорректные год/месяц/день`; високосный учитывается (`дата("2026-02-29")` — невалидна, 2026 не високосный).

## 6. Чек-лист приёмки по user stories

- **US1 (P1, парс + статика)** — фикстура парсится с 0 ошибок (SC-004); дубликат/неизвестный атрибут → `ОшибкаРазбора` (§SM-9.A); `период` без `по_дате`, необъявленный источник, отсутствие `источник`/`агрегат` → `СемантическаяОшибка` (§SM-4); повтор имени источник/метрика/функция → `'<имя>' уже объявлено в строке N` (R5, общий проход).
- **US2 (P1, счёт)** — 12 строк golden (SC-001); проекция агрегата на выживших записях + пустой результат R3 (§SM-8); CLI `metric` печатает `2000000`/код 0, неизвестная → код 1, нет аргументов → код 2 (SC-003).
- **US3 (P2, даты)** — `дата`/`сегодня` активированы из deferred (§SM-6); `value.Compare` для `Дата` (§SM-5); `Clock` инъекция (R4, SC-006).
- **US4 (P3, диагностика)** — 7 краевых exact-match (SC-002); `Ident`-как-значение: источник → ошибка, метрика → пересчёт, цикл → `цикл зависимостей метрик: …` (R6, §SM-9.B/C).
- **Гейты** — `go build`/`go vet`/`gofmt -l`/`go test ./...`/`-race` зелёные (SC-005), включая регрессы 001/002/003.

## 7. Границы (НЕ делать на этом шаге, §SM-0/§SM-12)

- НЕ парсить/исполнять `процесс`/`шаг`/`когда` — `KW_PROCESS`/`KW_WHEN`/`KW_VALUE` остаются отвергаемыми (R7).
- НЕ заводить `internal/store`/`internal/engine`; ветвь `metric` идёт через `eval.Interpreter`, без персиста и `--db` (R2).
- НЕ реализовывать `длительность`/`в_*`/`вчера`/`завтра`, арифметику `Дата±Длительность`/`Дата−Дата` (окна — служебная Go-арифметика дат, §SM-8.2); остаются deferred.
- НЕ авто-распознавать даты-строки, NDJSON/CSV, `тип:`, таймзоны, скользящие окна, кеш значения метрики (v2, `SPEC §12`).
- НЕ паниковать в штатных путях; control-flow — через `Signal` (003), не `panic/recover`. `Analyze` — fail-fast (первая ошибка).
